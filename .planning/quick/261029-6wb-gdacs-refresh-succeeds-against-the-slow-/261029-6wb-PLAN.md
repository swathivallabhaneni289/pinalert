<decisions>
Planning decisions (Claude's discretion, record each in the SUMMARY):
- P-1 First error wins. FetchHazards derives a cancel context from the caller's, runs each Search in its own goroutine, records only the first failure (sync.Once or a mutex) and cancels the sibling at that moment; the sibling's later "context canceled" error is discarded, so a fast B status error is never replaced by A's cancellation. Both goroutines are always waited for (sync.WaitGroup) before returning, so nothing writes after return and nothing leaks.
- P-2 A panic in a feed goroutine of RefreshAll is recovered in that goroutine. Its slot gets Result{Feed: feed, ErrorClass: "network"} ("network" is in the door's closed word set, refreshWord), and the log line is `official: refresh feed=<feed> class=panic` (feed name and one word, nothing else).

# The 85 globe pictures ship in the project, so the server never fetches from NASA

Closes the 7.1 UAT gap for test 1. Runs in parallel with quick 261118-saj (the Critical mark) and
quick 261118-uoe (the review ask box and account deletion). Stay out of their areas.

## Why

7.1 UAT test 1: "earth is taking long time to actually load", fast after a reload. Cause: the
server fetches each globe picture from NASA GIBS on the first request after it starts, so the
first visitor after a start (or after a free host wakes) waits 3 to 4 seconds. On 2026-11-18 the
owner suggested adding the pictures to the project once: "Maybe we can just like add it once in
the GitHub and it's gonna like, you know, use it again and again", asked whether all 85 are
needed (told: the same Earth at 4 sharpness levels, 1 + 4 + 16 + 64, the globe loads the level
that fits), and agreed: "Yeah, use it, I guess." This is an owner approved exception to the "no
images in the project" rule for these 85 app pictures only (about 0.75 MB). NASA Blue Marble is
CC0; the Policy already carries NASA's acknowledgement.

## What changes

1. **Download once.** Fetch the 85 tiles (zoom 0 to 3, every y and x in 0..2^z-1) from the exact
   upstream the code uses today (`globeUpstreamBase` in internal/api/handlers/globe.go, path
   `/{z}/{y}/{x}.jpeg`), with curl or a throwaway `go run` outside the repo. Check each is a JPEG
   (starts with FF D8 FF), 256 by 256, and under 1 MB. Save them in the project in the place that
   fits how the server already embeds files (for example `web/static/globe/{z}/{y}/{x}.jpg`
   under the existing `//go:embed static` in web/embed.go, or a `//go:embed` of its own beside
   globe.go). Add nothing else to the repo: no screenshots, no other pictures.
2. **Serve from the project.** `/globe/tiles/{z}/{y}/{x}.jpg` keeps its address, its closed set of
   85 paths (anything else 404), `image/jpeg`, the month long `Cache-Control`, no cookie and no
   session. The handler reads the embedded bytes; it never opens a network connection. Remove the
   upstream fetching code and everything only it used (the upstream base, the HTTP client, the
   timeout, the failure memory, the per tile lock, `GlobeTilesConfig.Upstream`, the user agent
   wiring in cmd/server/main.go), keeping the router's single list `GlobeTilePaths` so routes and
   the session bypass cannot drift.
3. **Provenance.** One short comment at the top of globe.go (in the file's style) says where the
   pictures came from (the layer and URL pattern), their licence (CC0, NASA acknowledged on the
   Policy page and under the globe), the download date, and how to fetch them again if ever needed.
4. **Docs.** docs/OFFICIAL-ALERTS.md (the "Also on the sign in page" paragraph and the source
   table row) says the pictures ship with Pinalert and the server never contacts NASA. The Policy
   line "Earth pictures from Pinalert, which keeps a copy of pictures from NASA GIBS" stays true;
   do not edit the Policy.

# Quick 261118-v75: the 85 globe pictures ship in the project

The sign in globe's 85 Earth pictures are now part of Pinalert, built into the server, so the
server never contacts NASA and the first visitor after a start waits for nothing (7.1 UAT test 1).

## What changed

- **Pictures.** The 85 NASA Blue Marble tiles (zoom 0 to 3) were downloaded once on 2026-11-18
  from the exact upstream the code used, into the scratchpad first, and checked there: all 85
  answered 200 image/jpeg, each starts FF D8 FF, decodes as 256 by 256, sizes 1652 to 20908 bytes,
  746373 bytes in all. They sit in `internal/api/handlers/globetiles/{z}/{y}/{x}.jpg` with a
  `//go:embed globetiles` in globe.go. Not under `web/static`: that would break
  `TestNoRasterImagesUnderWeb` and give every tile a second, session-carrying address under
  `/static/`. Two polar tiles (3/0/0 and 3/0/7) have identical bytes, as upstream sends them.
- **Serving.** `/globe/tiles/{z}/{y}/{x}.jpg` keeps its address, the closed set of 85 (anything
  else is not a route), `image/jpeg`, `public, max-age=2592000`, `nosniff`, no cookie, no session.
  `NewGlobeTiles()` reads the 85 embedded files once and returns an error on a build defect
  (missing, empty, over 1 MB or not a JPEG); the router panics on that like it does for the app
  assets.
- **Removed.** The upstream constant, HTTP client, fetch timeout, 60 second failure memory,
  per tile in-flight lock, `GlobeTilesConfig` (all its fields were fetch only),
  `Deps.GlobeUpstream`, `Deps.GlobeUserAgent`, and the user agent block in cmd/server/main.go.
  `GlobeTilePaths` stays the one list for routes and the session bypass.
- **Provenance.** The comment at the top of globe.go names the layer, the URL pattern, CC0 with
  NASA acknowledged on the Policy and under the globe, the download date, and how to fetch again.
- **Docs.** docs/OFFICIAL-ALERTS.md source table row and the "Also on the sign in page" paragraph
  say the pictures ship with Pinalert and the server never contacts NASA. The Policy is untouched.

## Deviations

- The pictures live beside globe.go (`internal/api/handlers/globetiles`), one of the two places
  the plan offered, for the reasons above.
- `GlobeTilesConfig` was removed whole rather than only its `Upstream` field, because every field
  served only the fetch; `NewGlobeTiles` now takes no argument and returns an error.
- Observation, not changed (out of scope): at 390 the bottom of the Earth sits under the frosted
  card in both themes, as before this change; no CSS or script was touched.

own popup chrome through the exact same `--severity-tint` custom property the row reads, rather
than inventing a second colour system for this surface.

flat black or plain white box that "doesn't specify properly of like what the situation is". They
were offered severity tint reuse versus a glass and blur treatment and explicitly chose tint reuse.

addition in map.js, one amended contract test and two new ones.

**Leaflet 1.9.4 popup DOM** (read from `https://unpkg.com/leaflet@1.9.4/dist/leaflet-src.js`,
`Popup._initLayout`, and `https://unpkg.com/leaflet@1.9.4/dist/leaflet.css`):

- The outer container is `div.leaflet-popup`, created as
  `'leaflet-popup' + ' ' + (this.options.className || '') + ' leaflet-zoom-animated'`.
- Its children are `div.leaflet-popup-content-wrapper` (which holds `div.leaflet-popup-content`,
  which holds map.js's own `div.map-popup`), `div.leaflet-popup-tip-container` (holding
  `div.leaflet-popup-tip`), and the close `a.leaflet-popup-close-button`.
- So `.map-popup` is a DESCENDANT of the wrapper. Custom properties set on `.map-popup` can never
  reach the wrapper's own background. The classes must go on `.leaflet-popup`, which is an
  ancestor of the wrapper, the tip and the close button all three.
- `DivOverlay.onAdd` calls `_initLayout()` only when `this._container` is falsy, and `onRemove`
  never nulls `_container`. So the container is built once on first open and reused forever after,
  and `options.className` is read exactly once, at that first open.
- `DivOverlay.getElement()` is documented public API returning `this._container`. It returns a
  falsy value before the popup has ever been opened.
- Leaflet's own vendor rules: `.leaflet-popup-content-wrapper, .leaflet-popup-tip` set
  `background: white; color: #333; box-shadow: ...` at specificity (0,1,0), and
  `.leaflet-container a.leaflet-popup-close-button` sets `color: #757575` at (0,2,1), with its
  `:hover, :focus` pair at (0,3,1) setting `#585858`.
- No Leaflet class name begins with `sev-`, `age-` or `vis-`, so prefix scoped class swapping on
  the container cannot clobber Leaflet's own classes.

**This app's existing system:**

- `main.css` `.report-row` reads `background: var(--severity-tint, transparent)`.
- `body` declares `background: var(--color-bg)`, and neither `.pane--list` nor `#report-list`
  declares a background. So the row's `transparent` tint renders as `--color-bg`.
- `.sev-low/.sev-medium/.sev-critical` set `--severity-tint` to `--color-severity-low-bg`,
  `--color-severity-medium-bg`, `--color-severity-critical-bg`. All six theme values are opaque.
- `.age-fresh/.age-aging/.age-stale` touch `--severity-current` and `--badge-glyph-fg` only, never
  `--severity-tint`. Adding the age class to the popup therefore changes nothing about its tint,
  which is exactly the required behaviour.
- `trust.css` `.vis-provisional` sets `--severity-tint: var(--color-surface)`; `.vis-hidden` and
  `.vis-retracted` set it to `transparent`.
- Nothing inside `.map-popup` consumes `--severity-current` or `--badge-glyph-fg`, and there is no
  `.icon-badge` inside a popup, so carrying those classes has no other visual side effect there.
- `parseCSSRules` in `web/css_contract_test.go` calls `stripCSSComments` itself, so a long comment
  block naming Leaflet selectors or the word `background` cannot leak into a following rule's
  `selectorHead` or `declBody`.

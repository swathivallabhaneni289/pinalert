# Quick 261113-l9x: send the sign in emails through Gmail, drop Resend, add a send check

## Why

On 2026-11-13 the owner asked how to be sure sign up works with a real inbox before letting other people in, said another app of theirs sends its codes through a Google account with no Resend, and decided: "lets do the Gmail thing", then "lets not have resend". Gmail needs no paid domain (the Resend free plan only delivers to the account owner until a domain is DNS verified), which fits the free tiers only budget. The owner will make a NEW Gmail account just for Pinalert (never a personal one), turn on 2-Step Verification and create an app password.

Known trade off, to state in the README: some free hosts block outgoing mail ports (465 and 587); the host must allow one of them, which becomes part of the hosting choice. Gmail also caps a free account at a few hundred recipients a day; the existing daily ceiling (90 a day, 20 kept for Forgot password) stays as it is and is now well under that cap.

## Task F1: the Gmail (SMTP) mailer, the loader, and Resend removed (one commit)

1. internal/mailer/smtp.go: `NewSMTPMailer(cfg SMTPConfig) Mailer` implementing `SendAuthEmail` with the standard library only (net, net/smtp, crypto/tls, mime, mime/multipart or a hand built multipart, mime/quotedprintable). No new module.
   - Settings: host, port, username, password, from. Port 465 means TLS from the first byte (tls.Dialer); any other port (587 by default) means STARTTLS, and the send is refused if the server does not offer STARTTLS. Never send AUTH before TLS. TLS 1.2 or newer, server name checked (no InsecureSkipVerify anywhere in non test code; tests inject a root pool through an unexported hook).
   - Time limits: dial and the whole exchange bounded by the context deadline, or 20 seconds when the context has none (set the connection deadline).
   - The message: From, To, Subject (Q encoded when not ASCII), Date, Message-ID (random, at the From domain), MIME-Version, multipart/alternative with the text part and the HTML part from `AuthEmailContent`, both UTF-8 quoted-printable. Refuse any To, From or Subject holding CR or LF (header injection), and check To is one plain address (net/mail.ParseAddress, no display name smuggling).
   - Errors keep their kind and drop their text, like resendFailureKind did: context cancelled or deadline, a network failure, a temporary refusal (4xx), an authentication refusal (535 or any AUTH failure) and a permanent refusal (other 5xx), with the reply code but never the server's words (they can repeat the address). Never put the password, the code, the username or the recipient in an error or a log line.
2. internal/mailer/loader.go: `LoadMailer(env)` reads SMTP_HOST, SMTP_PORT (default 587), SMTP_USERNAME, SMTP_PASSWORD and MAIL_FROM (default `Pinalert <SMTP_USERNAME>`; validate with net/mail). If SMTP_HOST is set, SMTP_USERNAME and SMTP_PASSWORD are required (the error names the missing setting, never a value) and the SMTP mailer is returned. If none is set and env is development, the log mailer as today, with the warning naming SMTP_HOST. Otherwise an error naming the settings. A half set group (for example SMTP_PASSWORD without SMTP_HOST) is an error, not a silent log mailer, outside development; in development warn and use the log mailer.
3. Delete internal/mailer/resend.go and resend_test.go; drop github.com/resend/resend-go from go.mod and go.sum (go mod tidy). Reword every comment and log line that names Resend as the email provider (mailer.go, logmailer.go, ceiling.go, cmd/server/main.go). Be careful: the word Resend also names the Resend code button and its routes (/api/auth/code/resend and friends) in handlers, services, queries, migrations, swagger and tests; those are NOT the provider and must not change. Never edit a migration file.
4. cmd/server/main.go: the startup comments and the fail fast message name the SMTP settings. The ceiling comment says it stays well under Gmail's daily cap.
5. Tests (internal/mailer/smtp_test.go, loader_test.go): an in process fake SMTP server on a random localhost port (with a test TLS certificate made in the test) that records the conversation. Pin: STARTTLS happens before AUTH PLAIN; a server without STARTTLS gets no AUTH and the send fails; port 465 style implicit TLS works; the message has both parts, the right headers, UTF-8, quoted-printable, the code, and no link; CR or LF in To or Subject is refused before connecting; a 535 maps to the auth kind, a 4xx to temporary, a 5xx to permanent; a hung server is cut at the context deadline; no error string contains the password, the username, the address or the code. Loader: each branch above, including the half set group, and that an error never holds a setting's value.

## Task F2: the send check command (one commit)

cmd/mailcheck/main.go: `go run ./cmd/mailcheck -to someone@gmail.com [-kind signup|reset]`.
- Loads the mailer with `mailer.LoadMailer("production")` semantics so the log mailer is never used: with the SMTP settings missing it exits non zero, naming the settings to set.
- Validates -to with net/mail (one plain address). Makes a random 6 digit sample code with crypto/rand. Sends one `AuthEmail` of the chosen kind with the real lifetime from the service limits (import the constant if exported, else 10 minutes with a comment pointing at credentials.go CodeTTL).
- Touches no database, needs no DATABASE_URL, starts no server.
- Prints only "Sent. Check the inbox and the spam folder." on success, or the error kind on failure; never the password, the address or the code.
- cmd/mailcheck/main_test.go: refuses a missing -to, a bad -to, missing settings; runs a send against the fake SMTP server (share the test helper through an internal test package or duplicate a small one).

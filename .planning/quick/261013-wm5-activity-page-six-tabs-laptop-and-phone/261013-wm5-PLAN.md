## Disposable database runner (create once, in your session scratchpad, outside the repo)

The sandbox refused a top level `env -i` for the 261013-lrw executor, so the scrub lives inside a script. Save this as
`run-suite.sh` in your session scratchpad directory and run it from the repo (or worktree) root as
`bash <your scratchpad>/run-suite.sh <db_name> [packages] [run_regex]`:

```bash
#!/usr/bin/env bash
set -u
DB="${1:?db name}"; PKGS="${2:-./...}"; RUN="${3:-}"
case "$DB" in pinalert|pinalert_test|postgres|template0|template1) echo "REFUSED: $DB"; exit 2;; esac
case "$DB" in p_act_*) ;; *) echo "REFUSED: name must start with p_act_"; exit 2;; esac
if psql -lqt | cut -d'|' -f1 | tr -d ' ' | grep -qx "$DB"; then echo "REFUSED: $DB already exists"; exit 2; fi
ROOT="$(git rev-parse --show-toplevel)" || exit 2
LOG="$(cd "$(dirname "$0")" && pwd)/$DB.log"
createdb "$DB" || exit 2
cd "$ROOT"
if [ -n "$RUN" ]; then
  env -i PATH="$PATH" HOME="$HOME" DATABASE_URL="postgres://localhost:5432/$DB?sslmode=disable" go test $PKGS -p 1 -count=1 -v -run "$RUN" > "$LOG" 2>&1
else
  env -i PATH="$PATH" HOME="$HOME" DATABASE_URL="postgres://localhost:5432/$DB?sslmode=disable" go test $PKGS -p 1 -count=1 -v > "$LOG" 2>&1
fi
CODE=$?
dropdb "$DB"
echo "EXIT $CODE PASS $(grep -c -- '--- PASS' "$LOG") FAIL $(grep -c -- '--- FAIL' "$LOG") SKIP $(grep -c -- '--- SKIP' "$LOG") LOG $LOG"
exit $CODE
```

A run passes only with EXIT 0, FAIL 0 and SKIP 0 (a SKIP means a database test silently did not run). macOS has no
`timeout`, so do not wrap the command in it. Known flaky test: `TestCastVoteConcurrentSameAccountKeepsEveryRow` fails about
1 run in 40; if it is the only failure, rerun once with a new database name and say so in the SUMMARY.

## Decisions this plan locks (owner defaults of 2026-10-13 plus planner choices)

The 03.2 open points are decided as the owner's defaults said. Each task cites these IDs.

- **W-01 Tab keys and the address.** Keys and labels in this order: `all` All, `posts` My posts, `votes` My votes,
  `disputes` My disputes, `resolved` Resolved, `not-resolved` Not resolved. All lives at `/profile` (the default is left out
  of the address); the others at `/profile?tab=<key>`. The server matches the key exactly and case sensitively; anything
  else (empty, unknown, upper case, trailing space) renders All. (03.2 open point 3.)
- **W-02 All carries a count** (03.2 open point 2), the number of distinct reports on the page.
- **W-03 Membership.** posts: the account's own reports (ReportsByAccount). votes: reports whose latest content vote by
  the account is confirm or dispute. disputes: the votes whose latest value is dispute (so My disputes is inside My
  votes). resolved: display state Resolved (visibility retracted), expired or not, because Resolved wins over Expired
  (State Matrix 10a and 10b). not-resolved: not expired and not retracted, so Live, Unconfirmed and Disputed (hidden)
  while they are still active. A Past report (expired, not resolved) and an expired Hidden report sit only under All and
  their kind tab (My posts, or My votes and My disputes) (03.2 open point 1). Resolved and Not resolved cover every card,
  own posts and voted reports, as picture 1's six top level tabs show (owner question 1). Resolve and reopen votes on
  other people's reports are not listed, because the picture defines My votes as confirmed or disputed (owner
  question 2).
- **W-04 Distinct reports.** Every report is on exactly one card. A report that is both the account's post and voted on
  by the account (the self vote block makes that impossible today) is a post; the service drops it from the votes.
- **W-05 Order.** Newest event first: a post's event is the report's created_at, a vote's event is that vote's created_at;
  ties by report id, highest first.
- **W-06 Card content.** Round icon (post: the report's category glyph, which gives the picture's flame for a fire
  report; vote: the check glyph; dispute: a chat bubble glyph), tag (Your post, Your vote, Your dispute), title (the
  description), a sub line "action · when · detail" with the action phrases "You posted this report", "You confirmed this
  report", "You disputed this report", the app's own relative time words ("4 min ago", "1 hour ago") and the detail
  (category label, plus shelter capacity and headcount when present, as the meta line builds them today). Then the kept
  state line, trust block (both counters and the panel) and Reopen, mounted by activity.js as today. A chip on the right.
- **W-07 Chip rule.** The chip holds three server written words and CSS shows exactly one, chosen by the card's display
  state class, so it follows a Reopen with no script: `vis-retracted` shows Resolved, `vis-hidden` shows Not resolved,
  anything else (`vis-live`, `vis-provisional`, `vis-expired`) shows the severity word Critical, Medium or Low. Where the
  chip says Resolved, the state word Resolved is not drawn (one fact once). A Disputed state word and a Not resolved chip
  are both drawn (two facts).
- **W-08 No arrow and no card link.** Nothing handles `/?report=ID` today: the only address value the app reads is
  `show_disputed` (feed.js readDisputedFromURL). So the arrow is not drawn and the card opens nothing. 03.2 open point 4
  is recorded as the rule for later: the whole card opens the report once that link works (Phase 3.1).
- **W-09 Reopen stays on the card** for the account's own resolved, unexpired posts (so 03.2 open point 5 needs no new
  home). A voted card never offers it. After a Reopen the chip and state word update at once from the response; counts
  and tab membership stay as rendered until the next load.
- **W-10 Record card at both widths,** built from the account's own posts (`page.Posts[0].Trust.Reporter`), never from the
  merged, time sorted card list, whose first card can be someone else's report. No posts, no card. Reporter words are
  hidden on own post cards at both widths (the record card shows the account's label once) and shown on voted cards
  (they are another person's record).
- **W-11 Tabs are links** in a `nav` with `aria-current="page"`, each its own address, so they work with no script.
  activity-tabs.js switches in place and calls `history.replaceState` (the feed.js precedent: a filter adds no Back
  steps), so Back from another page and a bookmark land on the same tab. No arrow key roving.
- **W-12 Laptop (900px and up)** copies variant B at 80 percent with one variable `--u: 0.8px`. Not built, because each
  would be a dead control or needs the app wide shell (backlog 999.10): the top bar, the side menu, the address pill, the
  bell and the avatar. The existing account button, back link, email line and theme toggle stay. The help line is kept on
  laptop.
- **W-13 Phone (under 899.98px)** copies picture 05 in tokens, as 261013-lrw did. The action phrase is hidden on phone, as
  the picture's phone example draws shorter sub lines; the tag carries the same fact. The help line is hidden on phone.
- **W-14 Fixes, not copies** (the 03.2 reference names them): every text and background pair clears 4.5 to 1 in light and
  dark (the picture's Medium chip text is about 3.0 to 1), every tab is 44px tall (the picture's are 35px at 80 percent),
  and the dark theme maps the Activity colours to the app's dark tokens (the picture is light only).
- **W-15 Not built and recorded:** System update rows (Phase 3.2's updates table does not exist), Comment added (Phase 8),
  and the distance on the sub line (the server stores no reader location).
- **W-16 Migration 00006** reaches only disposable databases in this plan. The page works before the owner applies it: the
  index only makes the votes by account read an index scan.

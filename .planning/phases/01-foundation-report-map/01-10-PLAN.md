Close the last entry in `01-UAT.md`'s `## Gaps` section: a **cosmetic** quality follow-up on UAT

**The gap.** `tile.openstreetmap.org` — the tile server used by both the primary map
(`web/static/js/map.js:25`) and the report-submission modal's own separate Leaflet instance
(`web/static/js/modal.js:319`) — serves only standard-resolution 1x, 256px raster tiles. It has no
`{r}`/@2x retina variant. Neither `L.tileLayer(...)` call sets Leaflet's `detectRetina` option, so on
a Retina/HiDPI display (confirmed: the user's own screen) the browser upscales those 1x tile images by
the device pixel ratio. That upscale is what makes street names and place labels look soft.

**The fix, already confirmed against Leaflet's own reference documentation — do not re-derive or
second-guess it.** Add `detectRetina: true` to the options object of both existing `L.tileLayer(...)`
calls. Nothing else. Leaflet's own option doc reads: *"If `true` and user is on a retina display, it
will request four tiles of half the specified size and a bigger zoom level in place of one to utilize
the high resolution."* That compositing is entirely internal to Leaflet. It specifically does **not**
require manually setting `tileSize` or `zoomOffset` (an older manual technique that would be redundant
and wrong layered on top of this option), and it does **not** require an `{r}` placeholder in the URL
template — the tile URL string stays completely unchanged in both files.

**Decided and out of scope — do not re-litigate in code, in a comment, or in the SUMMARY.** The user
was offered Google Maps and declined it (Google now requires a billing account/card even for its free
tier, contradicting this project's "no paid map API" budget constraint in CLAUDE.md). The user was
offered MapTiler (vector tiles, best visual quality) and Stadia Maps (retina raster, nicer styling) and
explicitly chose this zero-dependency fix instead, specifically to avoid adding a new vendor or API
key. Do not propose switching tile providers, do not add an API key, and do not touch the tile URL
string in either file.

**Two consequences you must expect rather than "fix".** Verified directly against Leaflet 1.9.4's
`TileLayer.initialize()` — the exact version this app loads from unpkg (`index.html.tmpl:97`):

  1. **Highest reachable zoom drops by one on a retina display.** The retina branch does
     `tileSize = floor(tileSize / 2)` (256 to 128), `zoomOffset++` (0 to 1), and
     `maxZoom = max(minZoom, maxZoom - 1)` (19 to 18). Since `L.map(container)` is constructed with no
     max-zoom of its own, the map derives its ceiling from the layer, so on a retina display the user
     can zoom to 18 rather than 19 — while the *tiles* being fetched are still z19, OSM's real maximum.
     This is inherent and correct. **Do not compensate by raising the max-zoom option to 20: OSM serves
     no z20 tiles, so that would trade a sharp map for empty grey squares.**
  2. **The retina branch is guarded on the max-zoom option being greater than zero.** The whole
     behaviour is conditional on `options.detectRetina && Browser.retina && options.maxZoom > 0`. If
     anyone later removes or zeroes that option, the retina option silently becomes a no-op and the
     blur returns with every other check still green. That is why this plan gates on the max-zoom
     option still being present in both files — it is a load-bearing invariant here, not decoration.

**One accepted cost, stated honestly.** On a retina display Leaflet fetches four tiles where it
previously fetched one — roughly 4x the tile requests against OSM's free community tile servers.
CLAUDE.md already notes OSM's tile-usage policy and that a portfolio demo sits well inside it; at this
project's traffic that remains true. Recorded in the threat register below rather than left implicit.

Purpose: make the map legible at the pixel density it is actually being viewed at, at zero cost and
zero new dependencies, and lock the option in so a future refactor cannot silently drop it.

Output: one inserted line in each of two JavaScript files, and one new Go test file.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client browser to third-party tile host | Every tile request tells `tile.openstreetmap.org` roughly where the visitor is looking. Any change to the tile URL would redirect that location signal to a different, unvetted third party — which is precisely why this plan pins the URL byte-for-byte rather than merely "not intending" to change it |

| client-side option value to library behaviour | Leaflet's retina branch is conditional on a *second*, unrelated-looking option (max-zoom greater than zero). A future edit to that option silently disables this fix with no error, no test failure from the option's own presence check, and no visible signal except returning blur |

<objective>
Close the two gaps `/gsd-verify-work 01` recorded in `01-UAT.md`. This is surgical repair of an
already-shipped, mostly-verified phase — not new scope.

**Gap 1 (blocker, UAT Test 1).** `.modal-backdrop` in `web/static/css/main.css:549` declares
`display: flex` with no `:not([hidden])` guard. `#report-modal` carries the `hidden` attribute in
the template and `modal.js` only clears it inside `openModal()`, but the browser's native
`[hidden] { display: none }` rule is user-agent-origin, so it loses to an author-origin rule at
equal specificity. The modal therefore renders open on every page load and its full-viewport
`rgb(0 0 0 / 55%)` scrim hides the map and the list underneath — the user saw a black viewport and
reported "i dont see any map". This exact bug class was already found and fixed elsewhere in this
codebase for `#shelter-fields` and `#discard-confirm` (modal.css:139, 222) and for the four feed
elements (feed.css:12-27, which carries a comment block explaining the specificity reasoning).
`.modal-backdrop` was the one shell selector that was missed. The fix is one selector, plus a
durable Go regression test so it cannot silently come back.

**Gap 2 (cosmetic, UAT Test 3 preview).** The user looked at the severity slider and said the
visuals are "too basic level" and asked for the control to feel "more smooth". The cause is
structural, not taste: `.severity-slider` sets `min-height: var(--touch-target-min)` (44px) and
`height: var(--space-sm)` (8px) on the same element — `min-height` wins, and with
`appearance: none` the background gradient paints the entire 44px box. Track and thumb end up the
same size, which is exactly why it reads as a flat fat pill. This plan thins the *track* (moving
the visible bar onto the track pseudo-elements) while keeping the 44px *thumb*, adds a real
unfilled trough plus a value-aligned fill, and makes the colour/fill change animate — per D-05 and
D-11.

While reading the reduced-motion handling for Gap 2, a latent accessibility bug surfaced that is
squarely inside the gap's own stated constraint ("must respect `prefers-reduced-motion`):
`modal.css:101-108` groups `#severity-readout`, `.severity-slider`,
`.severity-slider::-webkit-slider-thumb` and `.severity-slider::-moz-range-thumb` into a single
selector list. A selector list containing an unrecognised pseudo-element is invalid as a whole, so
Chrome drops the rule (it does not know the `-moz-` pseudo-element) and Firefox drops it too (it
does not know the `-webkit-` one). The reduced-motion override is currently dead code in every
browser, including for `#severity-readout`, which is a standard selector that is being taken down
with it. Task 2 fixes this as part of closing Gap 2.

Purpose: restore the primary map/list view that Gap 1 made unreachable, and deliver the visual
polish the user asked for without touching the accessibility contract 01-05 established.

Output: a guarded backdrop rule, a restyled severity control, and one narrow regression test.

**Test 3 is NOT closed by this plan.** UAT Test 3's full accessibility checklist (screen-reader
announcement, keyboard Home/End, reduced-motion behaviour) has never been formally run — only the
pre-emptive visual note was captured. After this plan lands, Test 3 must be re-run from scratch via
`/gsd-verify-work 01`, along with the seven other still-pending tests that Gap 1 blocked.

**Geometry changes in `main.css`** (replacing the current `.severity-slider` /
`::-webkit-slider-thumb` / `::-moz-range-thumb` block):

1. On the host `.severity-slider`: keep `appearance: none` / `-webkit-appearance: none`,
   `width: 100%`, `min-height: var(--touch-target-min)` and `cursor: pointer`. Remove the
   conflicting `height: var(--space-sm)` (min-height already wins over it, which is the whole
   defect) and remove the host's `border-radius` and its `linear-gradient` background — the visible
   bar moves onto the track pseudo-elements. Give the host a transparent background so the track
   shows through.
2. Add a `::-webkit-slider-runnable-track` rule and a separate `::-moz-range-track` rule with the
   same body: `height: var(--space-sm)`, `border-radius: 999px`, `background-color:
   var(--color-border)` as the unfilled trough, and a fill layer drawn as
   `background-image: linear-gradient()` between two stops of
   `var(--severity-current, var(--color-severity-low))` with `background-repeat: no-repeat` and a
   `background-size` whose width is the fill expression described below and whose height is `100%`.
   The track's border-radius clips both layers, so the trough and the fill both get rounded ends.
3. **Fill alignment.** The input runs `min="1" max="3"`, so the thumb's centre is inset from each
   end by half the thumb width and a naive `0% / 50% / 100%` fill would visibly miss the thumb at
   both extremes — on the one control you are polishing. Compute the fill width as
   `calc(var(--touch-target-min) / 2 + var(--severity-fill-ratio, 0.5) * (100% - var(--touch-target-min)))`,
   where `--severity-fill-ratio` is a unitless 0 / 0.5 / 1 supplied by the wrapper class (see the
   modal.css section below). At ratio 0 the fill ends exactly at the thumb centre when the thumb is
   parked at the left edge; at ratio 1 it ends at the thumb centre at the right edge. Do not
   substitute plain percentages for this expression.
4. Keep both thumb rules in **separate blocks** — one for `::-webkit-slider-thumb`, one for
   `::-moz-range-thumb`. Never group a `-webkit-` and a `-moz-` pseudo-element in one selector
   list: the engine that does not recognise one of them discards the entire rule. Both keep
   `width: var(--touch-target-min)`, `height: var(--touch-target-min)`, `border-radius: 50%`,
   `background: var(--color-bg)`, `border: 3px solid var(--severity-current,
   var(--color-severity-low))`, `cursor: pointer`, and gain `box-sizing: border-box` plus a subtle
   depth shadow such as `box-shadow: 0 1px 3px rgb(0 0 0 / 18%)`.
5. **The one place the two thumb rules differ.** The WebKit thumb must also carry
   `-webkit-appearance: none` / `appearance: none` and
   `margin-top: calc((var(--space-sm) - var(--touch-target-min)) / 2)` to centre the 44px thumb on
   the 8px runnable track, because WebKit positions the thumb relative to the track's top edge. The
   Firefox thumb is auto-centred on `::-moz-range-track` and must **not** get that negative margin —
   adding it there pushes the thumb visibly above the track. Do not copy-paste one block into the
   other.
6. Optionally add an `:active` treatment on each thumb (a slightly stronger shadow or a wider
   border) for tactile feedback while dragging. Keep it per-pseudo-element, in its own rule.

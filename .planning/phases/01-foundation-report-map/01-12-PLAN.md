<objective>
Swap both Leaflet basemaps from OpenStreetMap raster tiles to the OpenFreeMap **liberty** vector style,
rendered by MapLibre GL through the `@maplibre/maplibre-gl-leaflet` bridge — **keeping Leaflet itself
and every Leaflet-based behaviour intact**. Markers, badge pins built with a div icon, popups bound from
DOM elements, the modal's draggable location marker, tap-to-place, fly-to, and the element-class
highlight all stay exactly as they are. Only the basemap layer construction changes, in exactly two
places.

Plan 01-11 already loaded and integrity-pinned the vendor scripts, so `L.maplibreGL` exists by the time
these modules run. This plan is a pure JavaScript change plus a test rewrite.

**The WebGL fallback is a deliberate, explicit requirement — not a default, and not optional.**
Pinalert's whole value proposition is being a reliable information source *during an emergency*. A
visitor on an older Android device, in a locked-down in-app browser opened from a shared link, or on a
privacy-hardened browser losing the map entirely — rather than seeing a slightly plainer but working
map — is unacceptable for this specific app. So when the vector basemap cannot be built, both maps must
fall back to **exactly the raster tile layer plan 01-10 shipped**: same URL template, same retina
detection, same maximum zoom, same attribution string, per file. Not a stripped-down fallback.

**Settled, do not re-litigate anywhere.** The user was shown and declined Google Maps (needs a billing
card even for the free tier), MapTiler raster at double density (prefers a genuinely free, no-signup
option), and a full Leaflet-to-MapLibre rewrite (prefers the small bridge integration). The user chose
OpenFreeMap, the liberty style, migrating now, and a required fallback. Do not propose another provider,
another style, or dropping the fallback.

**Three facts from `01-11-RESEARCH.md` that shape the code — verified against library source, do not
re-derive:**

  1. **The maximum zoom must move onto the map object.** Leaflet derives a map's maximum zoom from its
     zoom-bound layers, and only grid-based layers register as one. The bridge's layer extends the bare
     Leaflet layer base and registers nothing, so deleting the raster layer's maximum-zoom option
     without moving it leaves both maps with unbounded pinch-zoom. It goes into the map's own options.
  2. **No deferral, no animation-frame wrapper, and no visibility check around the modal's map.**
     Leaflet's layer-add path routes through its ready mechanism, so the bridge's add hook — and
     therefore the renderer's own map construction — does not run until the map's first view is set,
     which in both files happens inside an asynchronous geolocation callback, by which point the modal
     is open and its container has real dimensions. The existing invalidate-size calls run *after* the
     first view is set and must be left exactly where they are. Do not add speculative timing code.
  3. **No pane, z-index or stylesheet change is needed.** The bridge appends its canvas to the same
     Leaflet pane the raster tiles occupied, below markers, popups, controls and the floating action
     button, and it marks that canvas as non-interactive so marker clicks and map click handlers behave
     identically. **This plan touches no stylesheet at all**, and a gate enforces that.

**One correction this plan makes to the research, discovered while designing the fallback — implement
it, do not skip it.** The research assumed the raster layer disappears entirely, so it did not consider
what happens when the maximum zoom sits on the *map* while a retina-adjusted raster layer is *also*
present. Leaflet's retina branch decrements the raster layer's own maximum zoom by one (19 to 18) when
the option is enabled on a display with a device pixel ratio above one — which is most low-end Android,
i.e. most of the fallback audience. Leaflet's grid layer then renders **no tiles at all** at a zoom
above the layer's own maximum. So a map fixed at 19 plus a retina-adjusted layer capped at 18 gives a
fallback visitor a blank map at full zoom. The fix is one line in the fallback branch: after adding the
layer, re-derive the map's maximum zoom from the layer's own post-construction value. That reads 18 on a
high-density display and 19 elsewhere, automatically, with no second branch and no hardcoded number.
This is a new adjacent line — the raster layer's own construction call stays byte-identical to 01-10, as
required.

**Expected, not a defect.** The vector source's own tiles stop at zoom 14, and the bridge runs the
renderer one level below Leaflet, so from roughly Leaflet zoom 15 upward the renderer is drawing z14
data. Vector data re-renders crisply at any zoom rather than pixel-upscaling, so streets stay sharp —
but no new labels or points of interest appear as you zoom past that band. That is normal for every
basemap on this tile schema. Do not "fix" it and do not lower the fly-to or modal zoom levels.

Purpose: a genuinely sharper, free, no-signup basemap at every zoom and pixel density, without giving up
a working map for the visitors least able to afford losing one.

Output: a rewritten basemap construction in each of two JavaScript files, and a rewritten contract test.

**This plan closes no UAT test.** It does, however, change what Tests 2 and 5 will be looking at, so
both should be run against this new basemap when `/gsd-verify-work 01` resumes.
</objective>

**Step 1 — add a capability probe to each module, inside that module's own function wrapper.**

a WebGL1 context as a last resort but its renderer targets WebGL2, so a WebGL1-only device that passed a

is the whole point of having a probe.

Do not turn this into a general feature-detection library. It is one small function per file.

**Do NOT wrap the vector construction in a try/catch as a second safety net** — it would not work and
would only look like it does. Leaflet defers the layer's add hook until the map's first view is set, so

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client browser to tile provider | Every basemap request tells the tile host roughly where the visitor is looking — an approximation of where a person physically is during an emergency. This plan changes *which* third party receives that signal, from the OpenStreetMap tile servers to OpenFreeMap's static-file host. It does not change *whether* one does |
| developer-authored attribution string to the DOM | Leaflet's attribution control inserts its credit as markup, not text — a deliberate exception to this app's rule that report-authored content only ever reaches the DOM as text or elements |
| client WebGL capability to basemap availability | The vector renderer needs a WebGL2 context. Without the fallback this plan requires, a visitor lacking one loses the map entirely rather than getting a plainer one |
| basemap layer zoom bounds to what the map lets a visitor reach | Leaflet renders no grid tiles above the layer's own maximum zoom, so a map ceiling set above a retina-adjusted layer's ceiling produces a blank map at full zoom rather than an error |

# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Source of truth for visual direction:** `.planning/phases/01-foundation-report-map/assets/01-theme-reference.png` (approved light/dark theme reference, canonical for the whole product — see 01-CONTEXT.md `<specifics>`). This document translates that reference plus 01-CONTEXT.md decisions D-01 through D-17 into exact, implementable values.

**Scope note:** The reference image shows "Confirmed by N nearby" and "Unconfirmed · expires soon" strings — those are Phase 2 (Trust Engine) behavior. Phase 1 has no voting yet. Section "Copywriting Contract" below prescribes the actual Phase 1 substitute strings.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — no shadcn, no component framework. Stack is Go `html/template` (server-rendered) + vanilla JS + hand-written CSS, no npm build step (per `.planning/research/STACK.md`). The shadcn initialization gate does not apply: this is not a React/Next.js/Vite project. |
| Preset | not applicable |
| Component library | none — all components (modal, slider, FAB, list row, map popup) are hand-built HTML/CSS/vanilla JS |
| Icon library | **Lucide** (outline style, D-12/Claude's-discretion). Self-hosted, not CDN-loaded at runtime: download the 9 category SVGs once from `lucide-static`, commit under `/static/icons/*.svg`, serve via Go's embed/static file handler. Rationale: avoids an external runtime dependency and a render-blocking CDN request on every page load, consistent with this being a no-build-step, resilience-minded stack (a later phase adds a low-bandwidth mode; not depending on a third-party icon CDN now avoids rework). Glyphs use `fill="currentColor"` / `stroke="currentColor"` so badge color is controlled purely by the wrapping element's CSS `color`, per D-12's "white glyph on solid color-coded circular badge" pattern. |
| Font | System UI font stack — `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif`. No web-font request: zero added network dependency, consistent with the no-build-step architecture and the "neutral utility, credible monitoring tool" tone (D-10) rather than a branded display face. |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, inline padding |
| sm | 8px | Category grid gap, compact element spacing |
| md | 16px | Default element spacing, modal field spacing |
| lg | 24px | Section padding, modal internal padding |
| xl | 32px | Layout gaps (map/list split gutter) |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

**Touch targets:** FAB, category grid tiles, and severity slider thumb are minimum 44×44px (WCAG 2.5.5) — this is not an exception to the 8pt scale (44 = 4 × 11), but call it out explicitly since it's an accessibility floor, not a spacing convenience.

Exceptions: none.

## Color

Every color has a Light and Dark value plus a CSS variable name (D-13: dark mode ships from Phase 1 via CSS variables, and is a genuinely distinct palette, not an inverted light theme — variable naming is Claude's discretion, named here for consistency).

### Base surfaces & text

| Role | CSS variable | Light | Dark | Usage |
|------|-------------|-------|------|-------|
| Dominant (60%) | `--color-bg` | `#FFFFFF` | `#0B0D10` | Page background, modal background, map container background |
| Secondary (30%) | `--color-surface` | `#F1F3F4` | `#16181C` | Category grid tile background, alternating list-row background, panel dividers/header bars |
| Border | `--color-border` | `#E1E4E8` | `#2A2D31` | Hairline dividers, input borders, card outlines |
| Text primary | `--color-text` | `#1A1D21` | `#F3F4F6` | Report titles, form labels, primary copy |
| Text muted | `--color-text-muted` | `#6B7280` | `#9CA3AF` | Meta line ("4 min ago"), placeholder text, helper copy |
| Focus ring | `--color-focus-ring` | `#1A1D21` (2px solid, 2px offset) | `#F3F4F6` (2px solid, 2px offset) | Keyboard focus outline on every interactive element |

Focus ring is deliberately neutral (matches `--color-text`, not a new hue) — see "Accent reserved for" below on why no 4th color is introduced for focus states, and D-05's non-negotiable accessibility requirement for why a visible ring is mandatory regardless.

### Severity palette (the accent — 10%, D-11 traffic-light mapping)

| Severity | CSS variable (dot/fill) | Light dot | Dark dot | CSS variable (tint bg) | Light tint bg | Dark tint bg |
|----------|------------------------|-----------|----------|------------------------|---------------|--------------|
| 1 · Low | `--color-severity-low` | `#2F9E64` | `#34D399` | `--color-severity-low-bg` | `#E7F5EC` | `#123524` |
| 2 · Medium | `--color-severity-medium` | `#C98A1A` | `#E5A93B` | `--color-severity-medium-bg` | `#FCF3DC` | `#3A2C10` |
| 3 · Critical | `--color-severity-critical` | `#C0392B` | `#E5695C` | `--color-severity-critical-bg` | `#FBE9E7` | `#3A1512` |

**Dark mode rule (D-13):** severity dots get *brighter/more saturated* in dark mode (not simply the light-mode hex on a dark background) and tint backgrounds get *darker*, not lighter — confirmed against the reference's dark-mode severity swatches. This is why dark values aren't a simple opacity/brightness filter on light values.

### Destructive

| Role | CSS variable | Light | Dark | Usage |
|------|-------------|-------|------|-------|
| Destructive | `--color-severity-critical` (reused) | `#C0392B` | `#E5695C` | Discard-draft confirmation button only (see Copywriting Contract — Phase 1 has no delete/retract flow yet) |

**Accent reserved for** (explicit list — the severity palette *is* the accent, and is used ONLY here, per D-10 "color reserved almost entirely for severity signaling, not decoration"):
- Category icon-badge circular fill (badge color = report's severity, NOT a fixed per-category hue — see "Badge color resolution" below)
- Report list row left-border accent + row background tint (D-16)
- Severity slider track fill, thumb, and live numeric/label readout (D-05)
- Map pin fill/ring color
- Age-ramp desaturation target (see below)

**Explicitly NOT used for:** the FAB, "Post report" submit button, links, category grid tile backgrounds, or any other decorative/branding purpose. Those use the neutral `--color-text` / `--color-bg` / `--color-surface` roles only — see "Neutral (non-severity) interactive elements" below.

**Badge color resolution (D-12 ambiguity, resolved):** D-12 says badge color "follows category or severity context as shown in the reference." The reference image uses the same red/amber/green traffic-light hues for icon-badges as for the severity swatches below it — not 9 distinct per-category hues. Per-category fixed colors would require 9 new hues, directly contradicting D-10's "color reserved almost entirely for severity." **Resolution: category icon-badge circle fill = the report's severity color. The Lucide glyph (white, `currentColor` inverted) conveys category identity; the badge color conveys severity.** This applies to both the map pin badge and the category-grid selection tile once a severity is chosen (before severity is chosen, tiles use the neutral `--color-surface` background with `--color-text` glyph, per "Neutral" below).

### Neutral (non-severity) interactive elements

| Element | CSS variables | Light | Dark |
|---------|---------------|-------|------|
| FAB ("+" report button) | bg: `--color-text` on `--color-bg` icon | `#1A1D21` bg / `#FFFFFF` icon | `#F3F4F6` bg / `#0B0D10` icon |
| Primary submit button ("Post report") | same as FAB | `#1A1D21` bg / `#FFFFFF` text | `#F3F4F6` bg / `#0B0D10` text |
| Category tile (unselected) | bg `--color-surface`, glyph `--color-text-muted` | `#F1F3F4` / `#6B7280` | `#16181C` / `#9CA3AF` |
| Category tile (selected, no severity chosen yet) | bg `--color-text`, glyph `--color-bg` | `#1A1D21` / `#FFFFFF` | `#F3F4F6` / `#0B0D10` |

High-contrast neutral, inverted-role buttons — deliberately not accent-colored, matching D-10's "not a heavily-branded consumer look."

### Age/desaturation ramp (D-17 — desaturation toward gray, NOT opacity)

Three discrete stages (matches the reference's 3-swatch "Age ramp" panel, not a continuous gradient), computed from time-remaining-until-expiry as a fraction of the report's total lifetime (24h for critical, 8h for low/medium per D-14):

| Stage | Trigger (time remaining) | Formula |
|-------|--------------------------|---------|
| Fresh | > 25% of lifetime remaining | `var(--color-severity-{level})` — full saturated severity color, unmodified |
| Aging | 12.5%–25% of lifetime remaining | `color-mix(in srgb, var(--color-severity-{level}) 50%, var(--color-age-stale) 50%)` |
| Stale | < 12.5% of lifetime remaining | `var(--color-age-stale)` — same neutral gray regardless of original severity, signaling "about to disappear regardless of urgency" |

| CSS variable | Light | Dark |
|--------------|-------|------|
| `--color-age-stale` | `#C9CDD1` | `#4B4F55` |

Applies to: list row left-border accent + icon-badge fill for aging/stale reports. Native CSS `color-mix()` is used for the Aging midpoint rather than hardcoding a separate hex per severity — avoids 6 extra hardcoded values while staying exactly implementable.

## States & Interactions

The template's baseline sections cover tokens; this section covers the interaction contract the reference image doesn't show (Phase 1 is a submit → store → view loop, not a static screen).

**Focal points:** Primary — the FAB (+ button), persistently visible over the map for one-tap report entry from anywhere in the view. Secondary — the severity slider during modal composition, since it's the one control with real-time animated feedback (color ramp + live numeric readout) and carries the report's most safety-critical field.

### Report submission modal (D-02, D-03)
1. **Open:** FAB tap opens modal over the map (map stays visible/dimmed behind, per D-03 — visitor never loses spatial context).
2. **Location:** GPS pre-fills a draggable marker on the modal's embedded map. Dragging updates a coordinate readout live. **If geolocation is denied/unavailable:** show the inline notice above; map centers on a sensible default (e.g. last-known IP-derived city center or a fixed fallback center) with the marker requiring a manual tap-to-place before the marker exists — do not block submission on GPS.
3. **Category:** 3×3 icon grid (D-04), single tap selects (tile inverts to the neutral-selected style above).
4. **Severity:** slider (D-05) — dragging/keyboard-arrow updates the live numeric+label readout ("1 · Low" / "2 · Medium" / "3 · Critical") and animates the slider fill through the severity color ramp in real time. Fully keyboard-operable (arrow keys change value, `Tab` reaches it, value is announced via `aria-valuetext`).
5. **Description:** free-text field, inline validation on blur (see Copywriting Contract).
6. **Submit:** button shows "Posting…" and disables on click; on success, modal closes, toast fires, new pin drops with pulse; on failure, modal stays open with an inline error and the button re-enables.
7. **Close/Cancel with unsaved input:** triggers the discard-confirmation prompt; closing an untouched (empty) modal does not.

### Feed ↔ Map linkage (D-06)
- **Wide screens:** map and list are side-by-side and always in sync. Clicking a list row pans/flies the map to that report's coordinates (fixed zoom level, e.g. 16) and opens/highlights that pin's popup. Clicking a map pin opens its popup AND scrolls the corresponding list row into view with a brief highlight ring.
- **Narrow screens (D-07):** default view is Map. A persistent toggle (see Copywriting Contract) reveals the List in its place (not an overlay — a full view swap). Selecting a list row switches back to Map view automatically so the highlighted pin is visible.

### Feed list ordering & row rendering
- Sorted severity-first (critical → medium → low), then newest-first within each band (D-08).
- Each row: colored left-border accent + tinted background keyed to current severity/age-stage (D-16, D-17), category icon badge, heading (description first line), meta line, all per the tables above.

### Loading / empty / error states
- **Initial load:** 3–4 skeleton rows (pulsing gray placeholders using `--color-surface`) in the list; map shows tile layer immediately (Leaflet loads independently of the reports fetch).
- **Background refresh (polling):** silent update, no skeleton — avoid flicker on a live view.
- **Empty (no nearby reports):** show the empty-state heading/body above; this is a real, expected Phase 1 state (the seeded-demo fix that guarantees a populated map is Phase 5, not yet built) — do not write copy that implies data exists.
- **Fetch error:** show the error heading/body + Retry button in place of the list; map keeps last-successfully-loaded pins rather than clearing them.

## Phase Goal

A visitor can submit a location-tagged emergency report and see it alongside other nearby reports
on a live map, without creating an account.

> **User-story format not locked.** ROADMAP.md's `**Goal:**` line for this phase states an actor
> and a capability but no `so that` outcome, so it does not satisfy the three-slot MVP user-story
> form. Per MVP-mode rules the planner must not invent the missing outcome clause. The goal above
> is reproduced verbatim from ROADMAP.md. Run `/gsd mvp-phase 1` to lock a canonical user story if
> the strict form is wanted before execution.

<objective>
Stand up the Pinalert Go repository from nothing: module, schema, migration runner, shared test
database helper, and CI. Nothing here is user-visible — this is the Walking Skeleton's scaffold
step (see `01-SKELETON.md`), and it exists so that plan 01-03's first end-to-end test has a real
migrated Postgres to run against and OPS-02's CI gate is green before any feature code lands.

Every decision this plan makes is load-bearing for the whole project: `TIMESTAMPTZ` columns and a
materialised `expires_at` (FOUND-05, PITFALLS.md Pitfall 5), an indexed `(latitude, longitude)`
bounding box (FOUND-03, PITFALLS.md Pitfall 1), the nullable shelter-capacity column pair
(FOUND-06), and migrations that run as an explicit command and never on app boot.

Purpose: OPS-02 is a Phase 1 requirement, not an afterthought — CI must be green before feature
code exists, or "every push runs tests" is never actually true.
Output: A compiling, migratable, CI-covered empty Go service.
</objective>

|----------|-------------|
| developer machine → managed Postgres | `DATABASE_URL` carries a real credential to a third-party host (Neon/Supabase) |
| GitHub Actions runner → service container | Ephemeral, network-isolated; no production data crosses it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Information Disclosure | `.github/workflows/ci.yml`, committed env files | high | mitigate | CI uses only the ephemeral `postgres:16` service-container DSN; real Neon/Supabase credentials live in GitHub repository secrets or a local `.env`, and `.env`/`.env.local` are added to `.gitignore` in Task 1 |
| T-01-10 | Tampering | schema migration application | medium | mitigate | Migrations run exclusively from `cmd/migrate` or `internal/testutil`, never on app boot — two concurrent server instances cannot race two concurrent `goose.Up` runs |
| T-01-11 | Repudiation | time-sensitive `expires_at` semantics | high | mitigate | All four time columns are `TIMESTAMPTZ` with server-side `now()` defaults; a bare `TIMESTAMP` column would silently change meaning between an IST developer machine and a UTC CI runner or host (PITFALLS.md Pitfall 5), making expiry decisions unreproducible |
| T-01-12 | Denial of Service | unbounded proximity scan | medium | mitigate | `idx_reports_lat_lon` and `idx_reports_expires_at` are created in the first migration, so FOUND-03's feed query never degrades to a full-table Haversine computation (PITFALLS.md Pitfall 1) |
| T-01-SC | Tampering | Go module dependency supply chain | medium | mitigate | Every direct dependency is pinned to an exact version verified against `proxy.golang.org` in 01-RESEARCH.md's Package Legitimacy Audit; `go.sum` is committed; no `@latest` resolution.

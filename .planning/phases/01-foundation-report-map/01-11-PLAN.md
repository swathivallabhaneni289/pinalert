<objective>
Load the vendor assets that plan 01-12's vector basemap needs, and update the project's stack
documentation to match. **This plan changes no JavaScript and no CSS. After it lands, both maps still
render exactly the OpenStreetMap raster tiles they render today** — the new globals sit loaded and
unused until 01-12 consumes them. That is deliberate: it means wave 1 cannot ship a broken map, and it
gives the executor a cheap, unambiguous runtime proof (does the bridge's entry point exist in the
console?) that the tags, the load order and the integrity hashes are all correct *before* any map code
depends on them.

**Why this is its own wave.** The bridge's browser build reads Leaflet's global and the MapLibre global
**at script-evaluation time** — both must already exist when it runs. If 01-12's JavaScript shipped
first, or if these three tags were ever reordered, the primary map would die on load with the bridge's
entry point undefined. That ordering constraint is a correctness property, not a formatting preference,
which is why this plan locks it with a Go test rather than a comment.

**Context.** This is a deliberate, user-chosen quality upgrade — **not** UAT gap closure. The user was
shown Google Maps (declined: requires a billing card even for the free tier, against this project's
"no paid map API" budget constraint), MapTiler raster @2x (declined: prefers a genuinely free,
no-signup option), and a full Leaflet-to-MapLibre rewrite (declined: prefers the far smaller bridge
integration). The user chose **OpenFreeMap**, the **liberty** style, and migrating **now**, before the
eight still-pending UAT tests are resumed. All of this is settled — do not re-litigate it in code, in a
comment, or in the SUMMARY.

**Version pin — read this before touching a tag.** Everything below is verified in
`01-11-RESEARCH.md` against the CDN's own responses and the plugin's published source; do not
re-derive it and do not "upgrade" the pins:

  - The MapLibre renderer must be pinned to **5.24.0**. The version-6 line ships **only** ES modules —
    it has no browser-global build at all, and the classic script tag this project uses would 404 on
    it and then fail with the bridge's entry point undefined. Loading version 6 would additionally
    require an import map plus Leaflet's own ES-module build, which destroys the global the app's four
    JavaScript modules all depend on — the exact rewrite the user declined.
  - The bridge's browser build lives at the **package root** (`/leaflet-maplibre-gl.js`), not under
    `/dist/`. The file under `/dist/` with an `.mjs` extension is the ES-module build and will not work
    in a classic tag.
  - **No `defer` and no `async` on any of the three vendor tags.** The app's own four modules are
    already deferred, and classic non-deferred scripts always execute before any deferred script, so
    the bridge's entry point is guaranteed present by the time `map.js` runs. Mixing deferred and
    non-deferred among the three vendor tags would break their relative order.

Purpose: get the vendor layer in place, pinned, integrity-checked and order-locked, so 01-12 is a pure
JavaScript change with no infrastructure risk left in it.

Output: five added lines in one template, one new Go test file, and a documentation update in three
places.

**This plan closes no UAT test.** Tests 1 and 8 already passed; Tests 2, 3, 4, 5, 6, 7, 9 and 10 remain
`[pending]` and are re-entered via `/gsd-verify-work 01` after 01-12 lands.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CDN to visitor's browser | Three third-party scripts and two third-party stylesheets execute with full page privileges. A compromised or substituted CDN response runs arbitrary JavaScript in the same origin that handles the visitor's anonymous session cookie and their reported location |
| author-time hash to runtime enforcement | The integrity attribute is only as trustworthy as where its value came from. A hash read from the CDN's own metadata endpoint is the CDN vouching for itself and enforces nothing meaningful |
| vendor script order to runtime correctness | The bridge reads two other globals at script-evaluation time. Reordering the tags is not a formatting change — it is the difference between a working map and an undefined entry point |

## STRIDE Threat Register

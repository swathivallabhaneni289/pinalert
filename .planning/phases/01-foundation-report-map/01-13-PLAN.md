<objective>
Close the single remaining major gap `/gsd-verify-work 01` recorded in `01-UAT.md` — the one entry
tagged `test: [2, 6]`. This is surgical repair of an already-shipped phase, not new scope. The root
cause is fully confirmed in the UAT record and re-confirmed at code level during planning; no
further debugging is required.

**The gap (major, UAT Tests 2 and 6 — one defect, two symptoms).** All nine category glyphs render
as solid black in dark mode, illegible on the modal's category grid. Every committed icon file
(`web/static/icons/*.svg`) paints its shape with `stroke="currentColor"` — a technique that resolves
against the surrounding element's CSS `color` **only when the SVG lives in the page's own DOM**. All
of this app's icon call sites instead build a replaced-element image node and point its source at
the icon file. A file referenced that way is a sealed sub-document: the parent page's CSS cannot
reach inside it, so `currentColor` resolves to that isolated document's own default (effectively
black) no matter what the page's theme is. Light mode masked the defect (black on a light tile still
reads); dark mode exposed it (black on `#16181C`).

**Three call sites, not two.** The UAT gap's `artifacts` list names `map.js` and `modal.js`. Planning
found a **third** site with the identical defect: `feed.js` builds the same image node for the feed
list row's badge (`web/static/js/feed.js:131` creates it, `:170` assigns its source), sized by its
own rule in `feed.css:58`. Same root cause, same fix, so it is closed here rather than left to
resurface as a separate gap. This is a deliberate, flagged scope note — not silent expansion.

**The real context matrix is 3 x 2, not 4 x 2.** The three shipped colour contexts a glyph must
serve are: (1) inside `.icon-badge` — map pin and feed row — where `main.css:232` sets
`color: var(--color-bg)` over a severity-coloured circle; (2) an unselected `.category-tile`, where
`main.css:354` sets `color: var(--color-text-muted)`; (3) `.category-tile--selected`, where
`main.css:362` sets `color: var(--color-bg)` over a `--color-text` fill. Each has a distinct light
and dark value, so two static per-theme icon variants provably cannot cover the space. A fourth
"selected tile tinted by the chosen severity" state described in `01-UI-SPEC.md:129` **does not
exist in the shipped DOM** — `modal.js`'s `selectCategory` (lines 265-279) toggles only
`category-tile--selected` and never puts a `sev-*` class on a tile. That is a separate UI-SPEC
conformance observation, not this root cause and not what UAT reported; building it here would be
scope expansion and is explicitly out of scope. The fix chosen below is forward-compatible with it:
because glyph colour comes from the ordinary `currentColor` cascade, adding a severity class to a
tile later would recolour its glyph automatically with no further change here.

**The technique, and the two that were ruled out.** Recolour each glyph with a CSS mask: give the
glyph element a `currentColor` background and use the icon file purely as an alpha-channel mask
shape. The rendered colour then comes from a real CSS property on a real in-page element, which
participates normally in the cascade — every one of the six combinations above resolves from
declarations that already exist in `main.css`, with no per-context colour logic added anywhere.
Rejected: (a) fetching each file and injecting it as markup — this codebase's verified FOUND-04
invariant is that no JS file assembles DOM from a markup string, `map.js`'s own header comment
records that as a deliberate convention, and introducing the first exception would produce a false
regression flag on the grep-based check a future verification pass re-runs; (b) shipping a light and
a dark icon variant and swapping the source by theme — two variants cannot cover six combinations,
as the matrix above shows.

Purpose: restore legibility of the product's category vocabulary in dark mode, and remove the whole
class of defect by making glyph colour a normal CSS concern instead of a property sealed inside a
sub-document.
Output: a CSS-driven glyph system, three renderers switched onto it, and two durable Go regression
tests that fail the build if any category loses its glyph or any renderer reverts.
</objective>

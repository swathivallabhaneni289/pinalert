## Phase Goal

A visitor can submit a location-tagged emergency report and see it alongside other nearby reports
on a live map, without creating an account.

> **User-story format not locked.** ROADMAP.md's `**Goal:**` line states an actor and a capability
> but no `so that` outcome, so it does not satisfy the three-slot MVP user-story form. Reproduced
> verbatim above; the planner must not invent the missing clause. Run `/gsd mvp-phase 1` to lock a
> canonical story if the strict form is wanted.

<objective>
Deliver the second half of the landing view: the report feed. Reports already reach the browser
through the shared store plan 01-04 built; this plan renders them as a list, orders them the way a
person scanning for danger needs (D-08 — critical first, then newest), encodes severity and age in
the row itself (D-16, D-17), links the list and the map in both directions (D-06), and makes the
narrow-screen experience work (D-07).

The list is the "alongside other nearby reports" half of the phase goal and the accessible,
low-bandwidth-friendly view of the same data — which is why it must never fetch independently.
It subscribes to the same array the map renders from, so the two panels cannot drift apart
(01-RESEARCH.md Pattern 3).

Requirements landed here: FOUND-03 (the visitor sees the nearby feed), FOUND-04 (the list is bound
to the map pins), FOUND-05 (an expired report is simply absent, and an ageing one visibly says so).
Decisions realised: D-06, D-07, D-08, D-15, D-16, D-17.

This plan owns exactly two files and runs in parallel with plans 01-05 and 01-07. It must not edit
`index.html.tmpl`, `main.css`, `app.js`, `map.js`, or `modal.js` — every hook and class it needs
already exists.

Purpose: make the feed readable under stress, in one glance.
Output: the production report list and the map/list linkage.
</objective>

  <action>
    Age ramp (D-15, D-17): apply the class returned by `Pinalert.ageStage(report)` — `age-fresh`,
    `age-aging`, or `age-stale` — to each row alongside its severity class. Plan 01-02 already
    defined those three classes to desaturate the row's accent and badge toward `--color-age-stale`
    via `color-mix`, so this task adds no colour logic of its own; do not compute a colour in
    JavaScript and do not reduce a row's opacity. Desaturation is the chosen encoding precisely
    because a faded element reads as disabled or unimportant, whereas a desaturated one reads as
    going stale — which is the meaning D-15 wants, and, once Phase 2 ships, the visual cue that a
    report needs re-confirming.

    Because the stage is a function of elapsed time rather than of any server push, re-evaluate the
    stage on a light interval — once a minute is ample — updating only the class on existing rows
    rather than re-rendering the list, so a report visibly ages even in a tab nobody has touched.
    Reuse the same interval to refresh the relative-time text.

    An expired report needs no client handling at all: the server's read-time predicate simply stops
    returning it, so it leaves the list on the next refresh. Do not add a client-side expiry filter —
    a second, drifting definition of "expired" is exactly the kind of divergence FOUND-05 exists to
    prevent.

    States, driven by `state.status`: on the first load show `#feed-skeleton` with its
    `.skeleton-row` placeholders and hide the list. On a *background* refresh leave the current rows
    in place and show no skeleton — flashing placeholders every 30 seconds on a live emergency feed
    is worse than a brief staleness. On success with zero reports, hide the list and reveal
    `#feed-empty` with its existing heading "No reports near you yet" and body "Nothing has been
    reported in your area recently. Tap + to report what you're seeing." — an empty map is a real and
    expected Phase 1 state (the seeded demo that guarantees a populated first view is Phase 5), so
    the copy must not imply data exists. On a fetch failure reveal `#feed-error` with "Couldn't load
    reports" / "Check your connection and try again." and wire `#feed-retry` to
    `Pinalert.fetchReports()`; leave the map's last successfully loaded pins alone rather than
    clearing them, since stale pins are more useful than a blank map to someone who just lost signal.

    Extend `feed.css` with the skeleton, empty-state, and error-state layouts and the state
    transitions, honouring `prefers-reduced-motion` on the skeleton pulse. Continue consuming
    `main.css` tokens exclusively.
  </action>

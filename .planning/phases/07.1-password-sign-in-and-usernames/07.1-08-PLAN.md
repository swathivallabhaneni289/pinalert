The helper rule (advisor note, binding): verifySession first POSTs /api/auth/sign-in with e2eTestPassword; a 200 means the account already has that password and the client is now signed in. A 400 with field credentials means no such account or no password yet: it then POSTs /api/auth/sign-up with the same password, reads the code with recordingMailer.codeFor, and POSTs /api/auth/sign-up/code. Any other status fails the test with the status and body. This covers a second browser for the same address (no second send, no cooldown) and an account seeded without a password (the legacy branch).

Step 4 is not filled by these helpers: the gate lets /api/ through for every account, and only tests with OnboardingGate true need a full profile; plan 10 adds a separate fillProfile helper for those.

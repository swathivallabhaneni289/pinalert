# Phase 7.1 Plan 11: The sign in card, server side Summary

Phase 5's sign in page now holds the password card: one card titled Pinalert, Create account and Sign in as two choices, four POST forms (Create account, Sign in, the code screen, Forgot password), and one row of four outlined buttons under it. LoginGate redirects signed in people, restores the code screen after a reload, and shows the closed done lines and the switch notice once. The browser script is plan 12.

## What was built

- **LoginGate** (internal/api/handlers/auth.go): the `?low=` handling runs first (line 168), then the signed in redirect (line 181) to `/` or `/low` (constants, 303, no-store), then the closed done list (`all-devices` opens Sign in, `deleted` and the new `old-link` open Create account), then a live code row (mode create or reset, the address as page text, seconds left), and only when none of those apply and no done word is set, the switch notice with `Session.ClearCookie` before the body. Referrer-Policy same-origin and Content-Type kept. `AuthConfig.Login` nil is checked. The `sent` parsing and the `Email`, `Sent`, `LinkTTLSeconds` fields are gone; the new fields are `StartPanel`, `CodeMode`, `CodeEmail`, `CodeSecondsLeft`, `CodeDigits`, `CodeTTLSeconds`, `ResendSeconds`, `PasswordMin`, `PasswordMax`.
- **Template**: ids and data attributes of UI-SPEC 1b (`data-start-panel`, `data-code-mode`, `data-code-seconds-left`, `data-code-ttl-seconds`, `data-resend-seconds`, `data-password-min` on `#login-form-panel`). No sentence under the title. The inbox partial include is gone. The globe partial stays after `.login-column`, outside the card.
- **Row under the card**: `login_ways_links.html.tmpl` is now four `a.btn` in the order Try the demo (`#login-try-demo` first), Low data view or Turn off low data view (`#login-low`), Disclaimer, Policy, then the reserved video comment. With LowDataDefault on, one `p.login-ways__status` above the row. The separate panel and "Text only, no map" are gone. Phone: 2 by 2 grid; laptop (min-width 900px): one centred wrapping flex row.
- **CSS**: auth.css card, choice control, Show button, code field (the one `0.25em` literal), rule and status lines, card scoped error rule, lock and shield-check icons, the row; chrome.css `.btn--off`; login-globe.css glass moved onto the card and the four row buttons (own 65 percent mix and 4px blur, the same three solid fallbacks), the solid error backing moved to `.login-gate.has-globe .login-card .inline-error:not([hidden])`, the `--g` box and phone layout untouched.
- **Tests**: login_card_contract_test.go (the ten named tests plus `TestLoginCardLockIcon`), login_gate_e2e_test.go (`TestLoginGateRedirectsSignedIn`, `TestLoginGateComesBackToCode`, `TestLoginGateSwitchNoticeOnce`, `TestLoginGateDoneWords`).

## Decisions recorded for later plans

- **Card error size (sketch 010 finding 2):** 14px on the card per the UI-SPEC, through the card scoped rule; the shared `.inline-error` stays 16px. If the owner wants one size everywhere, it is a one rule change.
- **`.btn--off` for plans 13 and 15 (Continue on step 4, Save username):** add `btn--off` to the button and toggle only `aria-disabled="true"`; the class does nothing otherwise. Never combine it with `btn--destructive`. The real selector is `.btn.btn--off[aria-disabled="true"]:not(.btn--destructive)` (plan text said 0,3,0; the outlined aria-disabled rule counts 0,4,0, so a 0,3,0 selector would lose). `TestBtnOffFullContrast` pins the order after both shared rules.
- **For plan 12 (auth.js):** the markup follows sketch 010. Show buttons carry `data-show-for="<input id>"`; error lines are empty `p.inline-error[hidden]` (no inner spans), and `.login-card .inline-error__text > span` rules exist if a two line error wants a wrapper; `#code-new-wrap` holds the reset only field and Show button; `#code-ready-live` is the visually hidden announcer; `#code-resend` starts as `Resend in 45s` with `aria-disabled="true"`. Create/Sign in/Forgot submit buttons do not carry `btn--off` (they show busy with `aria-busy`); `#code-submit` and `#code-resend` do. The old auth.js still looks for the removed ids and does nothing useful on this page until plan 12 lands.
- **Start state classes:** `login-choice` is `hidden` on the code start panel; `#auth-panel-forgot` is always server hidden.

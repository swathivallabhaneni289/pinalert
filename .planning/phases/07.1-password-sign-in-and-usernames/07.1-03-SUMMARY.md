# Phase 07.1 Plan 03: Auth emails, daily ceiling, fake mailers Summary

The mailer seam now sends the four password sign in emails (code_signup, code_reset, account_exists, no_account) as pure, test pinned text plus HTML with no link anywhere, behind a 90 a day UTC ceiling decorator that reserves 20 sends for Forgot password.

## Commits

- dc3ed0c9 feat(07.1-03): daily send ceiling and auth email fakes

## What was built

- `AuthEmailContent` returns subject, text and HTML from the UI-SPEC words. Code kinds need exactly 6 digits and MinutesValid of 1 or more, else `ErrBadAuthEmail`. The HTML code sits in a bordered span at 24px and weight 600. The minutes come from the caller.
- `Mailer` gained `SendAuthEmail(ctx, to, AuthEmail) error` beside the link method. Resend sends Subject, Html and Text and wraps failures with `resendFailureKind` only (no address, no code). The log mailer prints `kind=` and `code=` only, no address.
- `NewDailyCeiling(next, perDay, reservedForReset, now)`: mutex guarded count per UTC date, all kinds counted, failed sends count, the call to next happens outside the lock. Other kinds stop at perDay minus reserve; code_reset and no_account may use the whole budget.
- Fakes: `recordingMailer`, `gateFakeMailer` (record per address; `codeFor` fails the test when nothing was sent or the newest email has no code), `fakeMailer` (records `auth:<kind>` in calls). No existing assertion was changed.

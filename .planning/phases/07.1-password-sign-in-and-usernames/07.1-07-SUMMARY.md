# Phase 7.1 Plan 07: HTTP surface of the credential service Summary

The CredentialService of plan 05 is now reachable over six public POST routes, with CSRF protection, strict JSON, device and network buckets, the UI-SPEC sentences, the fresh session cookie, the wiring in `cmd/server/main.go`, the e2e harness and the regenerated API reference. The link routes are untouched and still work.

## What was built

- **handlers/credentials.go**: `SignUp`, `ConfirmSignUp`, `ResendCode`, `SignIn`, `RequestReset`, `ConfirmReset`, the request and response types, `decodeAuthBody` (415, 413, 400 for unknown field or trailing data, all with the generic sentence and no-store), `writeCredentialError`, `signedInNext`. Every handler sets `Cache-Control: no-store` first and answers 503 field `auth` when the service is nil. `ConfirmSignUp` and `SignIn` call `mgr.SetCookie` for the service's fresh id before writing the body, and refund their failure token on success. The send token is refunded on a `ValidationError`. `ConfirmReset` also refunds on a `ValidationError` (a bad new password is refused before a try is counted) and on success.
- **handlers/authlimits.go**: `AuthLimits`, `AuthGate`, `NewAuthGate`, `ReserveSignIn`, `ReserveCodeSend`, `ReserveCodeTry`, `ReserveUsernameCheck`, `ReserveUsernameSave`, `ipBucketKey`, `deviceKey`, `arrivedWithoutCookie`. Reservations return a `ratelimit.Decision` whose `Cancel` refunds every token that call took; a later refusal refunds the earlier tokens. All methods are nil safe.
- **auth.go** (additions only): `LoginState`, `AuthConfig.Login`, `AuthConfig.Session`, the `context` import. **session/cookie.go**: `CookieName`.
- **router.go**: `Deps.Credentials`, `Deps.AuthLimits`, `AuthLimits` alias, `AuthLimitsDefault`, `resolveAuthLimits`, a compile time `var _ handlers.LoginState = (*service.CredentialService)(nil)`, the six routes through `r.With(cop.Handler).Post`, `auth.Login` (only when non nil) and `auth.Session`, `WithAccountScreener` (when Reports is set) and `WithThrottleKeyer` (when Credentials is set). The NewRouter doc comment has a dated amendment. None of the six joins `sessionSkipSet`.
- **cmd/server/main.go**: the named auth bucket constants and an `authLimits()` function that builds the Deps field, `authDailyEmailCeiling = 90`, `authResetEmailReserve = 20`, the mailer wrapped once with the daily ceiling right after `LoadMailer`, the credential service with code and throttle keys derived from `SESSION_SECRET` and the production hasher.
- **Tests and docs**: see Verification. `make swag` added only the six paths and nine definitions (no removed lines); a second run was byte identical.

## Notes for later plans

- **ResendRequest is `{}`**: the page (plan 11) must send the empty object, because an empty body fails decoding with 400. Content-Type must be `application/json` on all six routes.
- **Write deadline rule** (plans 08, 09, 10, 10b, 14, 14b): any handler that sends mail inside the request calls `extendWriteDeadline(w)` (in credentials.go) after decode and bucket checks.
- **Error fields**: wrong credentials is field `credentials`, wrong code is field `code`, the rate limited, locked and mail answers use field `email`, nil service and unexpected errors use field `auth` (503 and 500). 429 bodies are `RateLimitResponse` with `Retry-After` (60 for ErrRateLimited, 3600 for ErrTooManyCodes, the lock wait for SignInLockedError).
- **Buckets**: the device key is the session id from the session middleware. A request with no cookie gets a fresh id each time, which is why the shared cookieless send bucket exists. Network buckets are off without `CLIENT_IP_HEADER` (T-07.1-03 accepted; plan 17 records the canary step).
- **Harness**: the e2e router sets `SendCooldown` to 1 ms in `newTestCredentials`; tests of the 45 s cooldown or hourly count need their own service through the tweak hook (see `TestSendingRoutesOutliveTheServerWriteTimeout` for the shape). `recordingMailer.codeFor` gives the code.
- **Plan 11**: `AuthConfig.Login` is nil when the router has no CredentialService; check for nil before use. `AuthConfig.Session` is always set.
- **Plan 10**: `ReserveUsernameCheck(accountID)` and `ReserveUsernameSave(accountID)` exist and return a `ratelimit.Decision`; map `service.ErrUsernameRefused` to 400 on field `username` with `service.UsernameRefusedMessage`.
- The older link routes and tests are unchanged.

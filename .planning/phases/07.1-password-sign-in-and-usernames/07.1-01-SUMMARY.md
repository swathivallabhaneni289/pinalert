# Phase 7.1 Plan 01: Storage for passwords, usernames, typed codes and throttles Summary

One migration (00014) and every query of Phase 7.1: a session bound, keyed hash code table with an atomic try budget, a database throttle, a combined cooldown and hourly send claim, unique lowercase usernames, and the gate's presence fields.

## What was built

- **Migration 00014** adds the four accounts columns with named CHECKs (argon2id prefix only, username shape, plain UNIQUE on the canonical lowercase form, screen state pair), `auth_codes` (no foreign key on session_id, keyed hash only, `delivery` of `code`, `account_exists` or `no_account`), `auth_throttles` (keyed by an HMAC of the address), the `email_cooldowns` window columns, and the Option X data step that revokes every session of a password-less account. Down removes the schema and says in a comment that the revoke cannot be undone.
- **Queries** (all generated once by `make sqlc`): code issue/bump/consume/latest/delete/prune, throttle get/record/clear/prune, `ClaimAuthEmailSend` and `GetAuthEmailSendWindow` (ClaimEmailCooldown left unchanged), sign in read, password and username writes (7 day rename gap in SQL), batched `UsernamesByAccountIDs`, `SessionEndedByPasswordSwitch`, `RevokeSession`. `GetAccountBySessionID` now returns `has_password`, `has_username`, `has_name`, `has_home_area`. `GetAccountProfile` returns the username fields. `ScrubDeletedAccount` clears the password and frees the username. `GetSessionBinding` is kept, with a comment that plan 05 reads it.
- **Truncate** lists `auth_codes` and `auth_throttles`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] CHECK let a username with a NULL screen state through**
- **Found during:** Task 1, the first run of TestMigration00014.
- **Issue:** `username IS NOT NULL AND username_screen IN ('clear','pending')` is NULL (not false) when `username_screen` is NULL, and a CHECK passes on NULL.
- **Fix:** added `AND username_screen IS NOT NULL` to `accounts_username_screen_valid`; the test pins it.
- **Files modified:** internal/store/migrations/00014_add_passwords_and_usernames.sql
- **Commit:** 109e277d

**2. [Rule 3 - Blocking/ergonomics] Argument types of generated params**
- Seconds arguments of `RecordAuthFailure` are `::int` (Go `int32`) rather than float, and `RevokeSession.Now`, `SetAccountPassword.PasswordHash`, `GetAccountIDByUsername.username` are cast so Go callers pass plain `time.Time` and `string`. The existing `RevokeAccountSessions` was deliberately left uncast so its callers still compile.
- **Commit:** b34ce99e

## Notes for later plans

- Migration number is **00014**. Next free after this is 00015.
- `RecordAuthFailureParams`: `Scope`, `KeyHash`, `Now`, `ForgetCutoff` (time.Time), `FreeFailures`, `BaseLockSeconds`, `MaxLockSeconds` (int32). `ClaimAuthEmailSendParams`: `Email`, `Now`, `CooldownCutoff`, `WindowCutoff`, `MaxSends` (int32).
- `SetAccountUsernameParams` takes `Username`, `UsernameScreen` (`clear` or `pending`), `Now`, `WaitCutoff`; zero rows means too soon; a taken name is SQLSTATE 23505 and a bad shape 23514.
- `ScrubDeletedAccount.Now` is still `pgtype.Timestamptz` as before.
- Pre-existing test hygiene issue (not touched, out of scope): the older `TestMigration00008` to `TestMigration00013` use `defer db.Close()` before `t.Cleanup`, so their cleanup deletes silently fail and a second run of `-run TestMigration` on the same database fails with duplicate account emails. They pass on a fresh database and inside the full package run (NewTestDB truncates). The two new tests close the handle inside their own cleanup, so they rerun cleanly.
- Deploy order (from the plan): run the migration, then start the new binary. Never run `make migrate` against any database but one's own; nothing was run against the owner's database.

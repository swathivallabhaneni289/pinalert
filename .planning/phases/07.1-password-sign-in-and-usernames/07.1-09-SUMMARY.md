# Phase 7.1 Plan 09: Security tests of the new sign in Summary

The security properties of the code and password sign in are now pinned end to end on a real database: uniform answers, the lock schedule, device and network buckets, the code budget, login CSRF, session fixation, reset, no address in any URL, and the gate's exempt list. All of it passed against the existing production code, so no fix was needed.

## What was built

- **credentials_security_e2e_test.go** (package handlers_test, 23 tests). Every client is a fresh cookie jar with response compression off, so `Content-Length` is a real header on both sides of a compare (the test fails if the header is missing, so the compare cannot silently check nothing).
  - Enumeration: `TestEnumerationSignUpIdentical` (new address, link account with no password, account with a password: same bytes and headers, mail kinds code_signup, code_signup, account_exists), `TestEnumerationResetIdentical` (known, link account, unknown: code_reset, code_reset, no_account), `TestEnumerationSignInIdentical` (unknown, wrong password, no password), `TestEnumerationLockIdentical` (six wrong then a seventh, known vs unknown, the five minute sentence), `TestEnumerationResendIdentical` (five branches). Each also asserts `bytes.Equal` directly.
  - Codes: `TestLimitsCodeTries`, `TestCodeBoundToSession`, `TestResendReplacesCode`, `TestLimitsHourlyCodeCap` (hour sentence, Retry-After 3600, the refused send mails nothing), `TestLimitsHourlyCapSharedAndIdentical` (3 Create account and 2 Forgot password use up the hour; a sixth and a seventh of either kind are 429 with identical bytes and headers for a known and an unknown address), `TestResetCodeBoundToSession`, `TestSignUpCodeRefusedOnReset` (also shows the refusal did not burn the code).
  - Throttle and buckets: `TestLimitsAccountThrottle`, `TestLimitsResetClearsThrottle`, `TestLimitsLockScheduleReachesCap` (failures 7 to 11 read from `auth_throttles`, locks about 600, 1200, 2400, 3600, 3600), `TestLimitsDeviceBucketCGNAT`.
  - CSRF, fixation, reset, addresses, shared phone: `TestCSRFCrossSiteRefused`, `TestCSRFTextPlainRefused` (also form urlencoded and a charset parameter), `TestFixationFreshSessionID` (both the code and the password path), `TestFixationPlantedCookieStaysUnbound`, `TestResetEndsEverySession`, `TestNoEmailInAddress` (a recording transport sees every redirect hop; checks "@", "%40" and the address in request URLs, Location headers and JSON answers; the HTML of /login is deliberately not scanned because the code screen shows the address as page text), `TestSignInCleansReplacedSessionPush`.
- **ratelimit_spoof_test.go**: `TestAuthSendLimiterIgnoresSpoofedProxyHeaders` replaces the link limiter test, with two subtests: no CLIENT_IP_HEADER (six sign ups on one browser with six forged X-Forwarded-For values: five 200 then a 429), and CLIENT_IP_HEADER X-Real-IP with CodeSendIP burst 3 on cookieless requests (three 200, a 429, another X-Real-IP passes). `forgedIPFor` kept.
- **ip_backstop_test.go**: `TestIPBackstopAuthSends` (good sign in first and refunded, three wrong are 400, the fourth is 429, another header address passes). `TestIPBackstop` untouched.
- **gate_test.go**: six rows (`sign up`, `sign up code`, `code resend`, `sign in`, `reset`, `reset code`) with a dated note naming D-03 and Pitfall 18, plus one added check that those POST routes answer their own 200 or 400.

### Choices

**1. [Note] Test-side setup in TestLimitsHourlyCapSharedAndIdentical.** verifySession's own sign up spends one of the known address's five hourly sends (aging the claim keeps the window count). The test deletes the address's `email_cooldowns` row after creating the account, so the known and the unknown address both start from no row. No production code touched.

**2. [Note] The 45 second collision does not occur on this harness.** `newTestCredentials` sets `SendCooldown` to 1 ms. `ageClaim` is still called before every compared send, as the plan asks, and keeps the tests true to the production rule.

**3. [Note] Narrowed limits copy the generous set.** A zero field of `AuthLimits` resolves to the production default, not to open, so the CGNAT, spoof and backstop tests copy `e2eGenerousAuthLimits` or `gateGenerousAuthLimits` and override one field.

**4. [Note] The link limiter test is gone.** The plan says to replace `TestRequestLinkLimiterIgnoresSpoofedProxyHeaders`; the link route's limiter has no regression test between now and the cleanup plan that deletes the link routes. `TestIPBackstop` still sets `RequestLinkRateLimit` as the plan said (its line is deleted in the cleanup plan).

**5. [Note] Extra coverage beyond the plan list:** exact 200 or 400 check on the six exempt rows; form urlencoded and charset variants in the text/plain test; the other-browser lock case in `TestLimitsAccountThrottle`; the reset resend and unknown reset branches in `TestEnumerationResendIdentical`.

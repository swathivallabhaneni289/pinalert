# Phase 7.1 Plan 06: Username save, live check, required name and home area Summary

The account service now saves and checks a unique Username with the plan 04 rules and Phase 4's ScreenAbuse (D-16 pending choice recorded in code), refuses clearing the Name and the Home area, refuses a numbered street address as a home area, exposes the batched `UsernamesFor` read for Phases 8 and 9, and makes Delete my account remove the new auth rows.

## What was built

- **Username save** (`internal/service/profile.go`, `saveUsername`): shape and reserved rules first (no provider call, no write), then the stored name is read (same name writes nothing), then the 7 day gap (first set and first change with no recorded change are free; days left rounded up), then `ScreenAbuse` on `UsernameScreenText` (never `CheckText`), then `SetAccountUsername`. SQLSTATE 23505 answers `{name} is taken. Try another.`; zero rows answers the wait sentence. The username is written before the name and home area, so a username error leaves those unsaved.
- **D-16** is written in the doc comment of `saveUsername` with its reasons and names Phases 8 and 9 as followers.
- **Live check and batched read** (`internal/service/account_username.go`): `CheckUsername` answers invalid, reserved, yours, wait (with days), taken or available from format, reserved words and uniqueness only; it never calls the screener (tested). `UsernamesFor` is one query keyed by account id, an empty list answers an empty map with no query, and deleted or username-less accounts are left out.
- **Clears refused** (D-15, D-06): an empty name answers `Your name can't be empty.`, a cleared home area answers `Choose a home area.`. The `HomeAreaClear` value and the disable-alert branch stay for data repair, with comments.
- **Never a street** (W14, R2-W1): `geocode.IsNumberedStreetAddress` (digit rule plus the shared `hasStreetWord` helper; `looksLikeStreetAddress` behaviour unchanged). A home area whose first part is a numbered street address answers `Choose a town or area, not a street.`. `TestHomeAreaSearchIsAreasOnly` pins `kind=area` in welcome.js and settings.js.
- **Delete my account** (`accountdelete.go`): `DeleteAuthCodesForEmail` always; `ClearAuthThrottle` (scope `sign_in`) when `WithThrottleKeyer` is set; both inside the same transaction, right after the cooldown delete. The scrub of plan 01 already frees the username and clears the password hash (checked on a real database).

# Phase 7.1 Plan 10: Step 4 required on the server Summary

The gate, the /welcome page and first-run-done now share the one onboarding predicate, step 4 (username, name, home area) is required by the server, the username can be saved on the profile route and checked live with per account limits, and the one time fill in for accounts made with the old link is proven end to end with no loop.

## What was built

- **Profile route** (`handlers/me.go`): `UpdateProfile(svc, gate)` decodes `username` (also on the exported `UpdateProfileRequest` so swag documents it). A request that names a username first reserves `gate.ReserveUsernameSave(account id)`; a refusal is a 429 on field `username` with Retry-After. The service result maps to one fixed status each: `ErrUsernameRefused` is the only 422 (field `username`, `service.UsernameRefusedMessage`, matched with `errors.Is` before the ValidationError branch); taken, wrong characters, reserved and too soon are 400 on field `username`.
- **Live check** (`handlers/username.go`, new): `UsernameCheck(accounts, gate)` on the gated `GET /api/username/check?u=`, per account limited (10 then one a second, 429 field `username`), `Cache-Control: no-store`, answers `{state, message, days}`, reads the name from the query only and logs only the account id. It never calls the screener (tested with a counting screener).
- **Router**: the check route registered flat beside the `/api/me` routes in the gated group; `authGate` passed to `UpdateProfile`. `sessionSkipSet` and every Phase 5 route untouched.
- **Settings**: `settingsViewModel.Username` filled from the profile, for plan 15.
- **Gate and predicate**: `account.Account` gained `HasUsername`, `HasName`, `HasHomeArea`, filled in `requireVerifiedAccount` from the plan 01 row. `onboarded` builds a `service.OnboardingState` and returns `service.OnboardingDone`. `requireOnboarded` still passes every `/api/` path, `/welcome` and every non GET, and its doc comment now says a Phase 8 route that needs a username checks it itself. The `/api/` 401 sentence is "Sign in to continue." (field `auth` unchanged).
- **first-run-done**: `MarkFirstRunDone` returns `ErrProfileIncomplete` after the terms check unless username, name and home area are all present; the handler answers 409 field `profile` with `service.ProfileIncompleteMessage`.
- **/welcome**: `WelcomePage` redirects (303 to `/`) only when `service.OnboardingDone` is true. `welcomeStartStep` picks the first missing step; the view model carries `AfterTermsStep` (4 when FirstRunDone, else 3), `FillingIn` (FirstRunDone) and `Username`. No email in the model. The template does not read the new fields yet (plan 13).
- **Swagger**: `make swag` after each change; the diffs touch only `/username/check`, the `/me/profile` patch block (username, 422, 429) and the `/me/first-run-done` description. A final run left the tree byte identical.

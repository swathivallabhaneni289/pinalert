# Phase 7.1 Plan 12: Sign in card script Summary

auth.js is now the panel state machine of the new sign in card: Create account, Sign in, the typed code screen and Forgot password swap in place, post JSON to the six /api/auth routes, and never write an email into the page address, a link, the address bar or browser storage.

## What was built

- **web/static/js/auth.js** (rewritten, one IIFE with `'use strict'`): `showPanel`, `selectTab`, `onTabKey` (arrows, Home, End, Enter, Space; roving tabindex; focus stays on the pressed choice), `submitCreate`, `submitSignIn`, `submitCode`, `submitForgot`, `resend`, `changeEmail`, `startResendWait`, `startExpiry`, `cleanCode`, `onCodePaste`, `toggleShow`, `postJSON`, `showError`, `clearErrors`, and the constants named in the plan (`RATE_LIMIT_MESSAGE`, `WRONG_CREDENTIALS_MESSAGE`, `OLD_ACCOUNT_LINE`, `OFFLINE_MESSAGE`, `SERVER_MESSAGE`, `CODE_*`, `PASSWORD_SET_MESSAGE`, `MAX_CLIENT_TRIES = 5`, `NEXT_PATHS = ['/', '/low']`). Busy words are Sending, Signing in and Checking with the U+2026 ellipsis, written as `…` escapes. A paste handler cleans "482 913" (also with a hyphen or U+00A0) to six digits before the browser's maxlength cut (sketch 010 finding 1). A page that opens on the code screen (reload) takes the address from the page text and the clocks from the data attributes. Navigation is only `location.assign` with a path from `NEXT_PATHS`.
- **web/auth_flow_test.mjs** (new, 20 tests, self contained sandbox copied in shape from welcome_flow_test.mjs, which is neither imported nor edited): fake elements with throwing markup setters, hand moved timers including setInterval, a hand answered fetch, and `location`, `history`, `localStorage` and `sessionStorage` getters that record any access. `URL`, `URLSearchParams` and `Event` are absent from the sandbox, so any use throws. Every test asserts the touched list is empty.
- **web/auth_contract_test.go**: the three tests that pinned the link timers and the check inbox partial are replaced by `TestAuthJSPanelContract` (every literal id and data attribute in auth.js exists in login_gate.html.tmpl, the six routes appear as literal paths), `TestLoginNoLinkNoEmailInURL` (no query string read or history write in the script; no link, `href` or GET form in the card; the four card forms are POST), `TestAuthJSSentencesOnce`, `TestAuthJSLeavesPushIntent`. `TestAuthJSUsesNoMarkupParsingSink` keeps its logic. A dated note at the top names the removed tests (D-12, Phase 7.1 plan 12).

Its doc comment still says auth.js SECURITY comments use dashes; that is stale (the new file has none) but harmless, and the plan says to amend only if the once check named the old layout.

### Notes for the Safari tab care

The card has no focus trap, so welcome.js's own Tab loop is not copied. Where the script moves focus it calls `focus()` explicitly (the pressed choice, the title on the code and Forgot panels, the field a refusal names, Resend or the title after the fifth refused code).

## Notes for later plans

- Forms rely on the browser's constraint checks before `submit` fires; the script does not repeat them. The code field has `required` and a digit pattern but no minimum length, so a three digit code reaches the server and counts as a refusal.
- `code-new-password` has no `required` in the template; the script adds and removes it by mode.
- The script reads `code-email` page text on a restored code screen; plan 11 renders it escaped.
- After a successful sign in or sign up code the button is un-busied and the page navigates; there is no bfcache special case.

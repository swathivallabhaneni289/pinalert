# Phase 7.1: Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Built from `07.1-RESEARCH.md` "Validation Architecture" and its "Tests that pin the removed or changed pieces" list.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Go `testing` (real Postgres for store, service and e2e tests), `node:test` for `web/*.mjs`, Go contract tests in `web/` that read the embedded templates, CSS and JS, manual iPhone simulator and Mac Safari checks |
| **Config file** | none. CI (`.github/workflows/ci.yml`) runs `go build ./...`, `go vet ./...`, `node --test web/*.mjs`, then `go test -v -p 1 ./...` against Postgres 16. `Makefile` targets: `test`, `test-short`, `vet` |
| **Quick run command** | `env -u DATABASE_URL go test ./internal/auth/ ./internal/service/ ./internal/mailer/ ./web/ -short -count=1 && node --test web/*.mjs` |
| **Full suite command** | `DATABASE_URL=postgres://localhost:5432/p71_<plan>_a?sslmode=disable go test ./... -p 1 -count=1`, then `node --test web/*.mjs`. The database is a disposable one, created for the run (refuse if the name exists) and dropped after |
| **Estimated runtime** | about 30 seconds quick, about 6 minutes full (an estimate at the size of the Phase 5 suite, recheck after Wave 0) |

Never run against `pinalert_test`, `pinalert`, `p31_4_uat` or `p34_uat`. Give every subagent its own database name and tell it so.

---

## Sampling Rate

- **After every task commit:** run the quick run command for the packages the task touched. A task that touches a DB backed package also runs that package's tests with `DATABASE_URL` set to the plan's own `p71_<plan>_a` database.
- **After every plan wave:** run `go vet ./...`, `node --test web/*.mjs`, and the full suite on the plan's own scratch database (owner recipe: per plan databases, own merge gate).
- **Before `/gsd-verify-work`:** the full suite must be green on a fresh scratch database. Then run the Linux CI check recipe, the visual checks of the new card at phone width in the iPhone simulator and Mac Safari (WebKit only Playwright misses real Safari clipping), and the one real phone check.
- **Max feedback latency:** 60 seconds for the quick run.
- **Wave 0 goes first.** The four e2e helpers are replaced in place with identical signatures before any other plan runs, because about 272 call sites reach the account system through them. Only the e2e harness passes `auth.TestParams()`; a unit test pins that `DefaultParams` meets the OWASP floor so test params can never ship.

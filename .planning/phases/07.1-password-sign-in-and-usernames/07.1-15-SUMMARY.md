# Phase 7.1 Plan 15: Settings Username row, and Name and Home area that cannot be emptied Summary

Settings, About you now lists Username, Name and Home area (laptop line "Your username, name and home area."), the Username opens the built edit window with step 4's live check and a Save username that stays off until the name is available, and the Name and Home area can be changed but never emptied or removed.

## What was built

- **Template (settings.html.tmpl):** `settings-username-row` (line 37) comes before `settings-name-row` (line 45); its second line is "Shown on your comments, to everyone" and its value is the stored name without an @, or "Not set". The Username window holds the `.username-field` box with the `@` prefix, the input (`name="handle"`, `autocomplete="off"`, `maxlength="20"`, capitalisation, correction and spellcheck off), the live line `settings-username-status` (role status, aria-live polite), the small line "Shown on your comments, to everyone.", the inline error and Save username (`btn btn--off`, `aria-disabled="true"`, no disabled attribute). `username-check.js` loads with defer before `settings.js`. The Name window label reads Name. The Remove home area button and the sentence "Removing it also turns off alerts ..." are gone and Save home area has no disabled attribute.
- **settings.js:** `usernameWin`, `usernameRow`, `usernameValue`, `usernameClose`, `usernameForm`, `usernameInput`, `usernameSave`, `usernameError` and the open, check, save and close code. The wiring is optional (`hasUsername`), so the early return still depends only on the Name and Home windows. The input is prefilled and selected on each opening; focus goes to it. `updateUsernameSave` is the live check's `onChange` (on only when `isGood()` and no save is out). A press while off sends nothing. The save sends only `{username}`; on 200 the row value and `data-value` update and the window closes; a late answer from an earlier opening refills an untouched field. An empty name now writes "Your name can't be empty." without a request; Save home area with nothing picked writes "Choose a home area." without a request; `removeHomeArea`, its button handler and the export are deleted. Every text still reaches the page through textContent.
- **settings-alerts.js:** removed `MESSAGE_HOME_REMOVED` and its `say` call, `homeNote`, `syncNote` and its six call sites; `homeNote` is out of `alertsReady`, so the section still comes alive on the real page. `redrawAlerts` and `syncHome` stay as the defensive no home state (the Critical, official and Reliable "Add a home area first" rows are untouched in the markup).

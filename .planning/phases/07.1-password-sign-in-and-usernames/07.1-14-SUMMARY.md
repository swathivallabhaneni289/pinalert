# Phase 7.1 Plan 14: Retire the HTTP side of the emailed link Summary

The emailed link can no longer be requested or opened: the route and both handlers are gone, an old link now redirects to the sign in page with the plain old-link line, and the link tests of auth_e2e_test.go are replaced by code tests.

## What changed

- internal/api/router.go: removed POST /api/auth/request-link and the per IP limiter instance built for it. The `RequestLinkRateLimit` type, its default and the Deps field stay, unused, with comments saying plan 14c removes them. `GET /auth/verify` is registered with `handlers.RetiredLink()`. The NewRouter doc comment lists the final exempt set with a dated amendment.
- internal/api/handlers/auth.go: removed RequestLink, RequestLinkRequest, RequestLinkResponse, Verify and the unused `maxAuthBodyBytes`. Added `RetiredLink()` (Cache-Control no-store, `http.Redirect` 303 to the constant `/login?done=old-link`).
- internal/api/gate_test.go: deleted the "request link" and "verify landing" rows of TestAccessGateExemptRoutes (now 23 rows, with a dated note) and added `TestRetiredLinkRedirects`: three queries (none, a token, a token plus an address), each 303, Location exactly `/login?done=old-link`, no `@`, no-store, following it shows "That sign in link no longer works.", and the same browser is still refused GET / afterwards (302 to /login).
- internal/api/handlers/auth_e2e_test.go: deleted `requestLink`, `getVerify` and nine link tests; added five code tests; moved the Profile and Logout tests onto `verifySession`.

| TestVerifyEndToEnd | A successful verification binds the session to an account | TestSignUpCodeSignsInSmoke and TestSignInWithPasswordSmoke (credentials_e2e_test.go), TestCredentialFlowOnDatabase (account bound to the new session id) |

<objective>
Close the gap the security review found in Option X (revision round 1, W1). The migration revokes every session that existed when it ran. A session created afterwards for an account with no password could still be live: for example, the old binary signing someone in with an emailed link during the deploy gap. The gate must treat any such session as signed out, so every legacy account goes through the typed code and the fill in.

Purpose: IDENT-06 (no way in without the password or a typed code) and IDENT-07 (the one time fill in cannot be skipped).
Output: the has_password rule in the two gates, test seed helpers with a test password, and an e2e test.
</objective>

# Phase 4 Plan 17: Retries never store twice, and late reports say when they were written

## Phase Goal

**As a** person reading or reporting during an emergency, often on a weak phone connection, **I want to** keep reading, posting and confirming reports when the signal is bad, knowing abusive posts are screened out and that the site says plainly it is unofficial, **so that** the reporting loop keeps working and I am not misled about what Pinalert is.

**This plan's step (slice S4, "weak network main page", after 04-13):** after this plan, a report whose answer was lost on a bad connection can be sent again with the same `request_id` and is never stored twice, the repeat costs no allowance, and a report that reaches the server more than 30 minutes after it was written shows "Written 4 hours ago" after its meta line on the feed row and under it in the map popup, while its expiry still counts from upload. Before this plan a retried post made a second report and there was no way to tell a late report from a fresh one. The offline queue that sends `request_id` and `written_at` automatically is 04-22; this plan makes the server contract and the reading surfaces ready for it, proven end to end by tests that send both fields.

<objective>
Implement D-19 and R-05 on the server and the P4-A8 Written line on the feed row and popup.

1. Service (`internal/service/report.go`): `SubmitInput.RequestID` and `SubmitInput.WrittenAt`; `ValidateSubmitInput` rejects a malformed non empty request id with `RequestIDInvalidMessage`; `ClampWrittenAt` and `WrittenAtMaxAge`; `FindReplay`, account scoped; `SubmitChecked` passes the request id, the account and the clamped written time into `InsertReportIdempotent` and turns a conflict into an account scoped `ReportByRequest` replay (`Replayed` true).
2. Handler (`internal/api/handlers/reports.go`): the two new request fields, `parseWrittenAt`, step 3 of the pinned `POST /api/reports` order (replay lookup before any bucket), the 200 answers for both replay kinds (the at insert one leaves 04-15's `stored` false so the allowance is refunded), `FeedReportResponse.WrittenAt`, swag annotations and one `make swag` run (this plan is the only wave 5 swag runner).
3. Client: `Pinalert.writtenLine(report)` in `app.js`, mounted under the meta line in `feed.js` rows and in the `map.js` popup card.

Purpose: D-19 (owner: a saved report never expires client side, the server stamps on arrival, and readers see "Written 4 hours ago" to judge freshness) and R-05 (request id plus unique index, display only written time) are the server half of the offline queue. Orchestrator decision 1 says a replay costs nothing.
Output: three edited Go sources and tests, three edited JS modules, three new test files, one stub method in an existing fake, the regenerated swagger docs.
</objective>

## Phase Goal

**As a** person reading or reporting during an emergency, often on a weak phone connection, **I want to** keep reading, posting and confirming reports when the signal is bad, knowing abusive posts are screened out and that the site says plainly it is unofficial, **so that** the reporting loop keeps working and I am not misled about what Pinalert is.

**This plan's step (MVP slice S7 "flag and moderate", fourth and last plan):** after this plan, a moderator works the queues on a phone: three lists with real counts, scores and reasons in words, Find a report by id or pasted link, Keep, a confirmed Remove and Refresh lists, with every string through `Pinalert.setText` (D-08, P4-A17 remove, open item 12). Before this plan the moderator API (04-23) answered JSON and the page rendered only its static frame: there was no way for a person to read a list, look a post up or act on it from the screen.

## Decisions recorded for this plan (Claude's discretion and open item defaults)

- **`trust.js` is loaded on the moderator page (a recorded departure from the outline and UI-SPEC script order `theme.js`, `app.js`, `moderate.js`, `account-menu.js`).** Reason: UI-SPEC row item 1 requires "the shared read only severity label", and Phase 3 plan 03-16 makes `PinalertTrust.createSeverityLabel` and `updateSeverityLabel` the one builder of that label; the outline also forbids a consumer typing another module's classes. Building the label inside `moderate.js` would create a second builder. The final order is `theme.js` (head), `app.js`, `trust.js`, `moderate.js`, `account-menu.js`. `votes.js` and `visibility.js` are NOT added. `trust.js`'s capture phase Escape listener stays inert here (no feed row, no popup, no trust panel), and the inline Remove confirmation owns its Escape through `moderate.js`'s root listener (P4-A5). The outline "Script order" Moderator entry now reads `theme.js` (head), `app.js`, `trust.js`, `moderate.js`, `account-menu.js` and the outline records the departure under "Open questions resolved during planning" (the approved UI-SPEC is not edited), so the departure does not live only in a SUMMARY. The consumer of the note is 04-27's `docs/MODERATION.md` moderator section, which reads the outline "Script order" section and must list `trust.js` in the moderator page's script order; the SUMMARY records the departure as well.
- **Open item 20 default kept:** no link to `/moderate` anywhere; the owner bookmarks it. **Open item 12 default kept:** no flagger identity, no polling, Refresh lists only.

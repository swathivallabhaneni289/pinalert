## Phase Goal

**As a** person reading or reporting during an emergency, often on a weak phone connection, **I want to** keep reading, posting and confirming reports when the signal is bad, knowing abusive posts are screened out and that the site says plainly it is unofficial, **so that** the reporting loop keeps working and I am not misled about what Pinalert is.

**This plan's step (slice S2 "abuse screened, held state"):** after this plan, a held or removed report provably never counts for or against its author's reporter rating. The Phase 3 history read carries `moderation_state`, `ClassifyOutcome` is neutral when `ReportMeta.Withheld()`, and neutral rows still fill the 30 row cap. Before this plan, the rating read no moderation state at all, so a report removed after review, or one held because its text check never finished, would be judged on its votes and could mark its author unreliable (or reliable) for a report nobody was shown. Nothing produces a pending report until 04-11, so this plan proves the rule with row literals and with rows whose state a store test sets directly.

<objective>
Make the reporter rating neutral for every report that moderation withholds (ROBUST-03; R-02, R-01; with D-02 and R-03 defining which reports those are).

After this plan:
- `ReporterHistoryReports` returns `moderation_state` as a sixth column and never filters on it.
- `reporterHistoryMeta` carries it into `ReportMeta.Moderation`.
- `ClassifyOutcome` returns `neutral` first when `ReportMeta.Withheld()`, leaving Phase 3's single neutral `Resolve(` line untouched.
- A pending serious report and every clear or zero value report are judged exactly as before.

Increments, task by task:
- After Task 1: the store proves that a reporter's history rows carry each report's current moderation state and that withheld rows still fill the per account cap. This is shown on a disposable Postgres (`p4_0429`).
- After Task 2: the service proves that those rows are neutral for the rating while still counting toward the cap, and that nothing else about the rating changed.

Purpose: R-02 says the rating never judges a report because of a moderation outcome. 04-01 made `Resolve` aware of moderation, and 04-07 wires it into the read and vote paths. The rating path is Phase 3's: the history query, `reporterHistoryMeta` and `ClassifyOutcome`. It needs its own two edits, and this plan makes them. The outline's "New decisions" records the classifier rule: neutral exactly when `ReportMeta.Withheld()`. It is one line, so the owner can veto it and make every pending report neutral without touching anything else.

Output:
- One query edit and its regenerated file.
- One line of behaviour in each of `reliability.go` and `reporter.go`.
- Two amended store tests and one added store test.
- One new service test file.
</objective>

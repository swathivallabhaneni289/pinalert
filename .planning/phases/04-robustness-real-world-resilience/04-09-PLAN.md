## Phase Goal

**As a** person reading or reporting during an emergency, often on a weak phone connection, **I want to** keep reading, posting and confirming reports when the signal is bad, knowing abusive posts are screened out and that the site says plainly it is unofficial, **so that** the reporting loop keeps working and I am not misled about what Pinalert is.

**This plan's step (slice S3 "limits", after 04-03):** after this plan, votes are throttled per verified account: 20 quickly, then 1 every 15 seconds, and a 30 second cooldown on casting the same kind of vote again on one report, refunded on any refusal. A blocked vote gets a 429 with a `Retry-After` header and a message that says exactly how long to wait. The network address backstop applies only when a deploy setting names the header, and every limit value lives in one named place. Before this plan the vote routes (four when this plan was written, five since Phase 3.1 added the take back) had no throttle at all (STATE.md WR-01), so one verified account could cast unlimited votes against the Core Value's "resistant to trivial gaming" promise.

**Points the outline leaves open, settled here (each recorded in the SUMMARY):**
1. **Where the limit types live.** Package `api` imports `handlers`, so the gate in `handlers` cannot take an `api` type. The struct bodies `BucketLimit` and `RateLimits` are declared once in `internal/api/handlers/ratelimit_gate.go`. `internal/api/router.go` declares `type BucketLimit = handlers.BucketLimit` and `type RateLimits = handlers.RateLimits` (Go type aliases, the same types), plus `var RateLimitsDefault` and `func resolveRateLimits`, so `api.BucketLimit{Every, Burst}`, `api.RateLimits{...}` and `api.RateLimitsDefault` exist in `router.go` exactly as the outline pins. 04-15's step 0 finds them there.
2. **Defaults are resolved once, in `router.go`.** `resolveRateLimits` replaces every zero field with its `RateLimitsDefault` field, and `NewRateGate` receives fully resolved limits. 04-15 and 04-20 then build their buckets inside the constructor body from the same `limits` and `clock` parameters, with no default logic of their own, and `NewPerKey`'s panic catches a half filled field at startup.
3. **Constructor:** `func NewRateGate(limits RateLimits, clock func() time.Time, clientIPHeader string, chrome Chrome) *RateGate`. It is built once in `NewRouter` as `rateGate`, before the gated group, so 04-15 passes the same variable at the `/api/reports` line. This plan builds three buckets (`vote`, `voteChange`, `ipBackstop`). 04-15 adds `reportSerious`, `reportOther` and `submitAttempt`, and 04-20 adds `flag`, without changing the signature.
4. **Order inside `VoteMiddleware`:** the backstop, then the vote bucket, then the cooldown. A vote bucket refusal never creates a cooldown entry. A cooldown refusal still spends its vote token, because the vote bucket is never refunded (the client sends nothing while a known wait runs, UI-SPEC "The 112 link" paragraph).
5. **Cooldown key canonical form.** The middleware parses `chi.URLParam(r, "id")` exactly as `parseReportID` does (`strconv.ParseInt` base 10, 64 bit, greater than 0) and keys on `strconv.FormatInt(id, 10)`, so `/api/reports/007/...` and `/api/reports/7/...` share one key. An unparseable id skips the cooldown, and the handler answers its own 400.
6. **Refund trigger.** The cooldown `Cancel` runs in a deferred function after the handler returns or panics, whenever the wrapped status is outside 200 to 299. A status of 0, meaning nothing was written, counts as a refusal.
7. **Wait wording.** `WaitPhrase` first rounds up to whole seconds, with a minimum of 1 second. It then uses seconds below 60, minutes rounded up below 3600 seconds, and hours rounded up from there. So 59.5 seconds is "1 minute", and 3599 seconds is "60 minutes", the UI-SPEC rule "under 60 minutes, the number of minutes rounded up" read literally. 04-19's `Pinalert.formatWait` follows `WaitPhrase` (its must_haves say "the same rules").
8. **`CLIENT_IP_HEADER` is validated at startup.** It is trimmed, and a non empty value with any character other than ASCII letters, digits and hyphen stops startup with `log.Fatalf` naming the variable (fail fast, like the other settings). Unset or empty logs one WARNING and leaves the backstop off.
9. **Missing account in `VoteMiddleware`** (a routing bug) answers `http.Error(w, "internal server error", http.StatusInternalServerError)`, the Shared Patterns rule.
10. **Harness generous bucket:** `BucketLimit{Every: time.Millisecond, Burst: 1000}` for all seven buckets. The request link limiter setting is untouched, so `TestRequestLinkLimiterIgnoresSpoofedProxyHeaders` still sees exactly five 200s and one 429.

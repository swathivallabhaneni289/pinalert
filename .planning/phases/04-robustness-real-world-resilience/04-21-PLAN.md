## Decisions recorded by this plan (planner choices with reasons; each is separable)

1. **The "is on" note follows the cookie, not only the query.** UI-SPEC section 1 describes the note for `/login?low=1`. The note states a fact about the device ("is on for this device"), so `LoginGate` shows it whenever the request carries `pinalert_low_data=1` (or `low=1` sets it) and `low` is not `0`. Reason: a device with the remembered choice reaching plain `/login` after Log out (a 303 to `/login`) or through the gate would otherwise be offered a link to turn on what is already on, with no visible way to turn it off.
2. **`Cache-Control: no-store` on every `GET /login` response.** The page now varies per device (the cookie) and `low=1` and `low=0` responses set a cookie; a cached copy would show the wrong state. Same convention as the gate's own redirect and the main page.
3. **Disclaimer and Policy stack below 360px.** UI-SPEC section 1 says the two links sit side by side and wrap under each other at 320px. At 320px the panel's inner width (about 240px) holds both short links on one line, so `flex-wrap` alone never wraps them; a `@media (max-width: 359.98px)` rule sets the row to a column. The 360px breakpoint is the one the UI-SPEC already uses for the moderator row actions.
4. **`flex-shrink: 0` on the open menu's children.** `.account-menu__item` declares `min-height: var(--touch-target-min)`, so inside a height capped column flex panel an item would shrink to 44px and overlap its text at 200 percent text instead of scrolling. One rule `#account-menu:not([hidden]) > *` (no `display` declaration, so the hidden guard is untouched) keeps every child at its content height.
5. **One accessible name by `aria-label`.** The UI-SPEC fixes the name "Low data view, Text only, no map"; the two spans alone compute without the comma, so the item carries that exact `aria-label` (it starts with the visible words).
6. **The back link chooses by in attribute conditionals keyed on one bool.** `profile-back-link` stays exactly once in the template, the two literal targets and names stay in the template where the web test can render both, and plan 04-25 reads the rendered `href` (`/low` or `/`) without a new data attribute.

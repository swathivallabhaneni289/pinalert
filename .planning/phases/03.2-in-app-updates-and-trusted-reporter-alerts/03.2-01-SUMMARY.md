# Phase 3.2 Plan 01: Storage for in app updates and trusted reporter alerts Summary

One migration and one query file lay the whole storage of Phase 3.2: stored updates with read state, derived followers, per pair cursors that write each announcement exactly once, mutes, the hourly roll up and the alert switch and distance, all proven on a real Postgres.

## What was built

- **Migration 00009**: tables `updates`, `update_cursors`, `report_mutes`, `account_alert_settings` with closed CHECK lists (`updates_kind_valid`, `updates_more_shape`, `update_cursors_state_valid`, `account_alert_settings_radius_valid`), partial unique indexes `uq_updates_reliable_once` and `uq_updates_more_bucket`, and the columns `sessions.revoked_at` and `accounts.deleted_at`. Down removes all of it in reverse order. `TestMigration00009` runs Up, the constraint refusals, the defaults (off, 5 km), Down and Up again.
- **updates.sql (23 queries)**: `FollowedOpenReports` (posts through any session, revoked included, plus any vote row, unexpired only, capped), cursor reads and silent baselines, `AdvanceCursorAndInsertUpdate` and `MarkFadingAndInsertUpdate` (one statement compare and swap with the hour gap, the ceiling and the roll up), `InsertReliableAlert`, `AlertsFromReporterInWindow`, list, count, capped unread count, scoped mark read, prune, mute and unmute (each one statement), muted list, alert settings upsert with `enabled_at` stamping.
- **Other queries**: `GetAccountHomeCell` in accounts.sql; `viewer_muted` on `ReportExtrasForReports` (NearbyReports untouched).
- **Truncate** names the four new tables.
- **12 new store tests** plus `TestMigration00009`.

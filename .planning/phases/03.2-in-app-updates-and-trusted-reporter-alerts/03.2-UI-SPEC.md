## Surface A: The bell (count, list, rows, states)

The button, the list shell, the X, "No updates yet" and "See all updates" are built (3.4 Surface 9). This phase adds the count, the rows and the states.

**Focal point:** the red count on the bell when anything is unread; once the list is open, the newest unread row's event line (weight 600, with its 4px edge), at the top of the body. Nothing else in the list competes: read rows are quieter by weight and have no edge.

### A1. The count

| Part | Value |
|------|-------|
| Badge | a `span` inside `#bell-trigger`, `aria-hidden="true"`, top 4px, right 4px, `--color-alert-fill` fill, `--color-on-alert-fill` digits, Caption 12px/600, 20px high, 20px minimum wide, padding `0 4px`, radius 4px. **Not drawn at zero.** |
| Digits | 1 to 9 as the number; 10 or more reads "9+" (so the badge never grows past about 24px and never covers the icon). |
| Button name | "Updates" at zero; "Updates, {N} new" otherwise ("Updates, 99 or more new" at 99, the server's cap). Updated quietly: **no `aria-live` on the count.** |
| Where | every page that has a top bar (Nearby, Official alerts, My activity, Settings), phone and laptop. On Nearby the phone bell hides while Search a place is focused, as 3.4 built. |
| Clears | the count goes to nothing the moment the list opens (D-06), and the server marks the shown updates read. If that write fails the count comes back at the next refresh; nothing else is shown. |
| Refresh | every 30 seconds while the page is visible, once when the page is shown again, and once after a vote or a mute on the page (D-04). The request is the bell's own; `app.js` is untouched. |

### A2. The list

Shell as built: `role="dialog"`, `aria-label="Updates"`, 340px wide (max `calc(100% - 24px)`), 1px border, radius 8px, `--shadow-menu`, opens under the bell, right aligned. **Added:**

| Part | Value |
|------|-------|
| Order | head ("Updates" and the X, built), body, footer ("See all updates", built). The head and footer never scroll away. |

At 320 by 568 the body is about 388px (568 less the 60px bar, 24px of air and 96px of head and footer): three rows of about 100 to 120px show whole, a fourth when the lines are short, and the rest scroll. |

## Surface C: Mute and unmute on an opened report

The smallest control that fits: one quiet text button in the report card's actions block, next to Flag. No new row, no icon, no redesign of the popup or the detail sheet.

| Part | Value |
|------|-------|
| Element | a `button` built like `.flag-control` (`chrome.css` line 492): underlined Label 14px, `--color-text`, 44px high, padding `0 4px`, radius 8px, no fill, `margin-top: 4px`. |
| Placement | inside `.popup-card__actions`, after the vote controls and the too far note. Mute and Flag sit on one line with `gap: 4px` and `flex-wrap: wrap`: Mute first, Flag after it. When the line is too narrow (the 296px phone detail pane at 320, or a 340px popup with long labels) Flag wraps under Mute. The vote buttons are untouched. |
| Labels | not muted: **"Mute this report"**; muted: **"Turn updates back on"** (D-11). Accessible name adds the report like Flag does: "Mute this report, Flood, 12 min ago". |
| Who sees it | **a signed in reader who follows the report (posted it or voted on it) or has muted it.** Everyone else sees nothing, because a control that cannot change anything would be noise on the trust card. It shows on the reader's own report (where Flag is hidden). Open question 3 below. |
| Press | immediate, no confirmation (it is undone by the same control). The label flips; the button keeps focus; the page's polite status line (`#notice-live`) says "Updates are off for this report." or "Updates are on again for this report." |
| What mute does | clears that report's unread updates (the bell count drops with them), stops new ones, and the report joins Muted reports in Settings. A later vote does not turn updates back on: mute wins until the person turns them back on. |
| Failure | an `.inline-error` line under the button, `role="alert"`: "Couldn't change this. Try again." Offline: "You're offline, so this wasn't saved. Try again when you have a signal." (the Flag wording). The label does not flip on failure. |
| Reduced motion | the label change is instant; no animation exists. |

## Interaction and Accessibility

- **Focus order, bell:** bell button, then (open) first row, further rows, "See all updates", with the X before the rows as built. Escape closes and returns focus to the bell; Tab stays inside while open (the `account-menu.js` pattern).
- **Row targets:** every link row is at least 44px high and full width; "and N more" and "no longer available" are not focusable.
- **Names:** the bell and badge as P32-C2; a row's name starts "New." when new (P32-C8); the tick is a checkbox menu item named by its words; the switch is named by its row label; the select by "How far from my home area"; Unmute this report is named by its own words and described by its row.
- **Live regions:** no live region on the bell count. The mute and unmute results, the home area removal and the Unmute this report result speak through the page's one polite status line (`#notice-live`). Errors are `role="alert"`.
- **State is never colour alone:** new = weight + edge or dot + "New" in the name; the tick = the check icon; the switch = its native on and off look.
- **Reduced motion:** nothing animates in this phase; the list, the label flips and the row removals are instant.
- **Text size:** all rows wrap and grow; no horizontal page scroll at 320px and 200 percent text; the bell body scrolls instead of the list overflowing the screen.
- **Forced colours:** see Color.
- **Keyboard:** every control reachable; the tick by the Show menu's arrow keys; the muted list by Tab; windows trap Tab and return focus to the row that opened them.
- **Security (carries the boundary rules):** every report word, category, severity and sentence arrives from the server and is written with `textContent` or `setAttribute`, never parsed as markup. The updates response carries no voter, no account, no session and no coordinates.

## Open questions for the owner

All answered by the owner on 2026-10-18: questions 1, 2 and 3 as recommended, and question 4 with the title "Notifications". The questions are kept below as the record.

1. **Should an update row say which report it is about?** *The choice:* today a row says "Now confirmed", "Flood, Critical", and how sure we are, with no report text, so two floods look alike. The approved mockup drew the report's words in each row ("Your report 'Water above knee level...' is now confirmed"). *Recommendation:* yes, add the report's own first line (two lines at most) between the event line and the category line, built at read time so a held or removed report shows "This report is no longer available" instead. Paragraphs 1 and 2 of the window are true either way.

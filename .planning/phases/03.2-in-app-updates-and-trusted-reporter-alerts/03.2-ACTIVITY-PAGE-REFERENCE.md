# Phase 3.2 design reference: the Activity page (owner, 2026-10-09, direction 2026-10-10)

Status: a reference for the Phase 3.2 discuss session. It is not a decision record, CONTEXT.md is. The owner gave two pictures
on 2026-10-09 as the look they want for the Activity page. The project keeps no images, so the pictures are described in words
in `.planning/sketches/004-activity-page/README.md`, which also holds the working copy of the picture (variant B) and the
measured sizes. Open the board at `http://127.0.0.1:8799/.planning/sketches/004-activity-page/index.html` while a no cache
server serves the repo root.

## Owner direction, 2026-10-10: exactly as pasted

After seeing a first preview that adapted the picture to Pinalert's own look (kept the confirmed counts, three tabs, no side
menu), the owner answered: "I wanted to look exactly how I pasted so do that accordingly." The adapted preview (variant A) is
withdrawn. Plan for the picture as drawn: a top bar, a side menu (Map, Reports, Alerts, Activity, Account), the page title with
one line of help, six tabs with counts (All, My posts, My votes, My disputes, Resolved, Not resolved), and cards with a round
icon coloured by the kind of event, a small tag (Your post, Your vote, Your dispute, System update), a title, a line with what
happened, when and how far, a chip (Critical, Medium, Low, Resolved, Not resolved) and an arrow. The phone layout has a back
arrow and the title, a tab strip that clips and scrolls, and shorter sub lines.

## Where it goes

Built with Phase 3.2: the in app updates that phase adds are the "System update" rows and fill the All tab, and the bell can
open this page. The arrow on each row uses the report link Phase 3.1 adds (`/?report=ID`). Do not start before Phase 3 closes:
the Activity row code (`feed.js`, `map.js`, `activity.js`, `trust.js`), the Activity template and its contract tests
(`web/activity_trust_contract_test.go`) are still in motion there.

## What copying the picture changes for the build

- **Trust signals.** The rows have no confirmed counts, no state word and no reporter words. TRUST-07, D-20 and the Activity
  contract tests need a recorded amendment first.
- **Reopen** has no place on the row. The poster's way to undo a resolve needs a new home, most likely the opened report.
- **Distance** needs a reader location. The server stores none and the page is server rendered, so decide the source (a fix
  taken in the browser on this page, or the last known map view) or drop it.
- **The side menu and top bar** mean a new app shell. That is backlog 999.10 (the app wide design pass), or it is pulled into
  Phase 3.2. Phase 5's Alerts tab and Phase 8's report page both sit inside it.
- **The 127.0.0.1 pill** in the top bar is the browser's own address bar, captured from the screenshot the picture was made
  from. It cannot ship as a dead control. Decide at the discuss step: drop it, or turn it into search.
- **House rules.** For this page only, the owner's picture overrides the pill shaped count chips, the event coloured icons and
  the sizes and spacing that are off the app's scale. The departures are listed in the sketch README and each needs a recorded
  amendment to the UI contract. Two come from the picture's own colours and are real accessibility problems to fix in the build
  (not copy): text under 4.5 to 1 contrast on the amber "Medium" chip and on one grey line, and targets under 44px.

## What waits

- "System update" rows: Phase 3.2's updates table. "Comment added": Phase 8.
- Votes by account (My votes and My disputes): a new account scoped read over `votes`. The only votes index is report first, so
  it wants a new index, which is a migration the owner runs.
- The tab counts are real in the app (distinct reports), and sample numbers in the sketch. The picture's counts do not add up
  to its seven rows.

## Open points for the discuss session

1. Past (expired) and Hidden reports: which tab shows them? The picture's "Not resolved" is "still active and need attention".
2. Does All carry a count? The picture's has none.
3. Should the tab live in the address so Back and a bookmark land on the same view?
4. Does the whole card open the report, or only the title and the arrow?
5. Where does the poster reopen a resolved report (see above)?
6. The Phase 3 trust block redesign (sketch 003 variant H) is a separate open decision. The picture does not show a trust block
   on the row, so it matters only for the opened report and the map popup.

## Rules to carry into the UI contract

Site design rules still hold elsewhere: no purple gradients, no emoji icons, no long dashes, no hero text, no fake metrics,
restrained motion. Guard the new tab and chip corners with a test: `TestNoPillShapedControls` covers only `.view-toggle`,
`#toast` and the severity slider. The picture's typeface is not one the app ships (no web fonts), so the build uses the system
font stack and the letters differ a little.

# Phase 03.2 Plan 03: UpdatesService Summary

UpdatesService refreshes lazily through DecideUpdate over the same resolver pipeline the feed uses, lists with every word built at read time from the live trust object, and marks rows read, with every store call keyed by the account id passed in.

## What was built

- **Refresh**: prunes the account's updates and cursors older than the 7 day edge first, then reads the followed open reports (cap 200), the votes, the reporters and the cursors once each, resolves every report with `BuildVoteTally`, `Resolve` (moderation state set in the same function body) and `ViewOf`, and acts on `DecideUpdate`: silent baseline, silent adoption, one state event, one fading event. `pgx.ErrNoRows` from the two inserts is the normal "another request won or the hour blocked it". No ticker, timer or goroutine. Other errors are wrapped as `service: Refresh: ... report N: %w` and never carry an email. The function ends with a comment naming plan 13's Reliable alert step (NOTIF-05).
- **List**: one `UpdatesForAccount`, `UnreadUpdateCount` (cap 99) and `CountUpdatesForAccount`, then one batched `ReportsForUpdates`, `CurrentVotesForReports` and `ReporterAccountsForReports` only when an event row exists. Per row, in List's own body: Resolve with moderation, `ViewOf`, `BuildTrust` (nil reporter), `ConfirmedByPeople`, `EventLine`, `UpdateTrustLine` (so a Reliable row reads Not confirmed yet. at posting and the confirmed sentence once people confirm it), `ReportFirstLine` with the Q1 comment. A held, removed or missing report is the unavailable item (no report id, category, severity, trust or text). A rolled up row reads And N more changes.
- **MarkRead**: `up_to` below 1 is a `ValidationError` on field `up_to` with `UpToMessage`; otherwise `MarkUpdatesRead(account, upTo, now)`.
- **UpdateItem** has no field for a description beyond `ReportLine`, a coordinate, a session id, a voter cell or an account id (T-03.2-01).

### Warnings for the owner (built as planned, but worth a decision)

**Resolved 2026-10-19 (after this report was written):** W1 closed by gap fix 03.2-18, W3 closed by gap fix 03.2-19, W2 kept by design (D-14). See each warning's `resolution` in the frontmatter. The findings below are kept as found.

**W1. A sign in again brings back old cookie copies after Log out of all devices.** `VerifyTokenAndBind` rotates the session id only when the account is deleted or a different account signs in (`internal/service/auth.go:324`). When the same person signs in again on a device whose session was revoked, `BindSessionAccount` sets `revoked_at = NULL` on the same id (`internal/store/queries/sessions.sql:22`), and `TestRevokedBrowserSignsInAgainAsSameEmail` (`internal/api/handlers/session_revocation_e2e_test.go:287`) fails if the id changes. So a cookie copied from that device before Log out of all devices works again once the owner signs back in there. That is the case the button exists for. No test checks that a copy made before the logout stays refused after the owner signs in again. Suggested fix: always rotate when the bound session is revoked. One test changes on purpose.

**W2. Two rules for a fading note on a Provisional report.** `DecideUpdate` writes "Fades in about an hour" whenever the view is active (`internal/service/updates.go:204`), and `ViewOf` returns active for Provisional (`internal/service/history.go:82-89`). So a person who posted or voted on a report nobody has confirmed gets the fading note. `MayNotifyAboutReport` says fading needs Live, `updates_test.go:362` pins that, and its comment calls it the gate "for anything Phase 3.3 adds". The bell and a later phone channel could disagree. Nothing leaks, because the person already posted or voted on the report and Provisional reports show in the feed. But it is a second rule where the contract asks for one.

**W3. A second row about one report inside the hour.** A Reliable reporter note is written without a cursor (`updatesalerts.go:159`). If the reader then votes on that report, it becomes followed and gets a silent baseline with no `last_update_at` (`updatesservice.go:219`). If others then make it Live within the hour, a "Now confirmed" row follows the note. That is a second row inside the hour, so D-12's one per report per hour does not hold across the two kinds. No test covers note, then vote, then confirmed by others.

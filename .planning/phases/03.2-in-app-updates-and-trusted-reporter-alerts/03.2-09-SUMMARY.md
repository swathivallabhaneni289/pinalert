# Phase 3.2 Plan 09: Delete my account (Option A, anonymise) Summary

POST /api/me/delete scrubs the account in place, deletes the person's own rows and revokes every session in one transaction, and the end to end test shows that another reader's feed bytes and the reporter rating do not move.

## What was built

- **accounts.sql**: eight queries, each commented with the rule. `AccountEmailForDelete` reads the real address and the deleted stamp first. `DeleteMagicLinkTokensForEmail` and `DeleteEmailCooldownForEmail` remove the address's links and resend cooldown. `DeleteAccountUpdates`, `DeleteAccountCursors`, `DeleteAccountMutes`, `DeleteAccountAlertSettings` remove the person's own rows. `ScrubDeletedAccount` (`:execrows`, guarded by `deleted_at IS NULL`) sets the `.invalid` email, clears name, home area pair, consent pair and first run mark, and stamps `deleted_at`. `make sqlc` changed only `accounts.sql.go`. Nothing touches votes, reports or `sessions.account_id`.
- **accountdelete.go**: `AccountDeleteQuerier` (nine methods, asserted against `sqlcgen.Queries`), `AccountTxFunc`, `PgxAccountTx` (reuses `TxBeginner`), `AccountDeletionService` with `WithAccountDeleteClock`, `DeleteAccount` in the order read email, tokens, cooldown, updates, cursors, mutes, alert settings, revoke sessions, scrub last. The doc comment states the rule and its effect, including that the report text and the precision 7 voter cell remain. `DeletedEmailFor(42)` is `deleted-42@deleted.invalid`.
- **me.go / router.go / main.go**: `DeleteAccountRequest`, handler `DeleteAccount(deletions, mgr)` (strict body, 400 on a malformed body or a missing/false/non true confirm with `DeleteConfirmMessage`, 404 if already deleted, bare 500 logged with the account id only, success clears the cookie, sets no-store, answers 204), the route inside the gated group, `Deps.AccountTx`, and `AccountTx: service.PgxAccountTx(pool)` in main.
- **Docs**: `make swag` regenerated; `TestSwaggerSpecCoversRoutes` now requires `/me/delete post` and its 401.

## Deviations from Plan

### Test shape decisions (no rule triggered)

**1. The "deleted browser" test uses a browser that still holds the cookie.** The delete response clears the cookie of the browser that sent it, so that browser signs in with no session at all and the rotation rule is not exercised. `TestDeletedBrowserSignsInGetsFreshSession` therefore deletes from one browser and signs in from a copy of its cookie (a second device), which is the case plan 06's rotation exists for. It asserts a new session id, the old row still naming the deleted account and revoked, the new row bound to the new account, and no inherited report.

**2. Extra assertions beyond the plan.** `TestDeleteAccountNeedsConfirm` also covers `{}`, a non boolean confirm and non JSON bodies, an anonymous caller (401) and a second delete from the deleted account (401 at the gate). `TestDeleteAccountRemovesPersonalRows` checks another account's updates, cursors, mutes and settings survive. The proof test counts votes, reports and bound sessions before and after, and confirms the transaction seam ran exactly once.

**3. The AccountTx seam is wired lazily in the harness.** `newE2EServerWith` does not expose its pool to the tweak, so the test seam resolves the pool after the server is built. It runs the real `PgxAccountTx`.

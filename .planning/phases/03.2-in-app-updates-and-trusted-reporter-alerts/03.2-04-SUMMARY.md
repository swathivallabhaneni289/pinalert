# Phase 3.2 Plan 04: MuteService Summary

**MuteService mutes, unmutes and lists the caller's own muted reports, never reveals a held report, and always lets a mute be cleared.**

## What was built

- `internal/service/mutes.go`: `MuteQuerier` (five methods, asserted against `*sqlcgen.Queries`), `MuteService`, `NewMuteService(q, opts...)`, `WithMuteClock`, `Mute`, `Unmute`, `MutedReports`, `MutedCount`, `MutedReport`.
- `internal/service/mutes_test.go`: fake querier and tests `TestMuteMissingAndWithheldReadAsNotFound`, `TestMuteStoreErrorIsWrapped`, `TestMutePendingSeriousAllowed`, `TestMuteCallsOneStatement`, `TestUnmuteAlwaysAllowed`, `TestMuteKeyedByAccountOnly`, `TestMutedReportsAvailability`, `TestMutedReportsTextRule`, `TestMutedCount`.

## Behaviour

- Mute reads the report once through `ReportForMute`. No row gives `ErrReportNotFound`; a `ReportMeta.Withheld()` report gives the same error. Otherwise one `MuteReport` call. Errors wrap as `service: Mute: ...: %w` with the report id.
- Unmute is one `UnmuteReport` call and never reads the report.
- MutedReports asks for `MutedListCap` rows and keeps their order. A row is Available when the report is not withheld and its expiry is after now minus `HistoryWindow`. An unavailable row carries only `ReportID` and `MutedAt`. Text is `ReportFirstLine(report, finished)` with finished true when the report expired or is a Rescue report. `MutedReport` has no coordinate, session, voter cell or account.

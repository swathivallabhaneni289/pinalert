# Phase 3.2: Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Built from `03.2-RESEARCH.md`, "Validation Architecture" (refreshed 2026-10-17 against main after Phase 3.4).

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Go `testing` (contract tests in `web/` read embedded files; DB tests through `internal/testutil.NewTestDB`), plus browser script tests in `web/*.mjs` run with `node --test` |
| **Config file** | none (`Makefile` targets `test`, `test-short`, `check`; CI `.github/workflows/ci.yml` runs build, vet, `node --test web/*.mjs`, then `go test -v -p 1 ./...` against postgres:16) |
| **Quick run command** | `env -u DATABASE_URL go test ./web/ ./internal/service/ ./internal/api/... ./internal/store/ -short -count=1 && node --test web/*.mjs` |
| **Full suite command** | `DATABASE_URL=<a disposable database of the plan's own> go test ./... -p 1 -count=1` |
| **Estimated runtime** | about 6 seconds for the quick Go half (measured 2026-10-17); the full suite with a database takes minutes |

Database rule for every task and every subagent: DB backed tests run only against a disposable database created for the plan and dropped afterwards. Never `pinalert`, `pinalert_test` or `p34_uat`. Never ports 8080 or 8090; leave port 8776 alone. No Python.

---

## Sampling Rate

- **After every task commit:** run the quick command.
- **After every plan wave:** run the full suite against the plan's own disposable database.
- **Before `/gsd-verify-work`:** full suite green, `make sqlc` and `make swag` output current, dash and image greps clean, and the browser harness (`~/code/pinalert-browser-checks`) updated for the bell count, the Updates part, the Reliable tick and the new Settings rows.
- **Max feedback latency:** 60 seconds for the quick command.

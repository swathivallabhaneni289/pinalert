# Phase 3.2 Plan 10: Only Reliable reporters, server side Summary

The server now says, per report, whether the opt in Only Reliable reporters tick keeps it (`kept_by_reliable_filter`), from one predicate: the reporter's tag is Reliable reporter or the report is serious.

## What was built

- `KeptByReliableFilter(tag, meta)` in `internal/service/reliablefilter.go`: `tag == ReporterReliable || meta.Serious()`. The doc comment records the dense read limit (reporters past `MaxReporterAccountsPerRead` read none, research Pitfall 8) and that Resolve never reads it.
- `ReportView.KeptByReliableFilter` set in `Nearby` (report.go) and `baseView` (historyread.go, used by Focus and History). Both now build `Trust` into a local first and read `trust.Reporter.Tag` from it, so the tick and the reporter line cannot disagree. Plan 05's `ViewerFollows` and `ViewerMuted` lines are untouched.
- Wire field `kept_by_reliable_filter` after `confirmed_by_people` in `FeedReportResponse`, mapped in `reportViewToResponse`.
- `testutil.SeedReliableReporter`: account bound to the session, two voter accounts, six reports expiring at now minus one hour, five confirmed from two distinct precision 7 cells (5.25 of 6, score 78, the numbers of `TestReporterSignalFromSeededHistory`).
- TRUST-MODEL.md section `## Show menu: Only Reliable reporters` (what the field is, opt in only, no default view changes, the 200 reporter limit, the price of the tag, the test names). `TestTrustModelDocMatchesCode` passes.

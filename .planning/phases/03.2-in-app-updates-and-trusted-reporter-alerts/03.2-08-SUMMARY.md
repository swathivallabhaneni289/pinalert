# Phase 3.2 Plan 08: Bell count, list and Updates rows Summary

The bell now shows a red count that clears the moment its list opens, the list shows the latest 10 updates with loading, error and stale states, and My activity's Updates part draws the same rows server side, all from the routes of plan 07, with no markup sink and no change to app.js or app-bar.js.

## What was built

- **updates.css** (new): the one stylesheet of the phase. Bell count badge (20px, `--color-alert-fill`), bell list body (scrolls, head and footer 48px), bell rows and their states, the Updates `urow` grid (phone arrangement as base, one `min-width: 900px` block for the laptop), the hub `N new` tag, the mute control (the Flag control look), and the Settings switch, select, danger label and muted rows for plans 11, 12 and 15. Forced colours block for the unread edge, dot and badge.
- **app_bar.html.tmpl**: `data-poll-interval-ms="30000"` and the hidden `#bell-count` span on the bell button; the list body holds `#bell-loading` (three skeleton rows), `#bell-error`, `#bell-stale`, `#bell-rows` and the built empty line, between the head and the footer. The four bell pages (Nearby, Official alerts, My activity, Settings) load the stylesheet before phone.css and the script after app-bar.js.
- **updates.js** (new): polls `GET /api/updates` on load, every 30000 ms while the page is visible, when the page is shown again from the cache, on `visibilitychange` to visible and on `pinalert:updates-refresh` (one queued extra poll at most). Opening clears the count, draws the frozen list with new marks, sends `POST /api/updates/read` with the largest shown id and moves focus to the first link; closing drops the marks. A link row is an `a` to `/?report=ID` only for an available row whose id passes the digits pattern; the "and N more" and "no longer available" shapes are plain blocks. The severity class comes from a closed table. On My activity it marks the Updates rows read once when they are on view (laptop stack on load, phone Updates screen), then polls. One `fetch(` in the file.
- **profile.html.tmpl**: the Updates branch (`ul#updates-rows.urow-list`, `li.urow[data-update-id]`, link or plain `urow__link`), `#updates-error`, the `Showing the newest 50.` line, and the hub `span.activity-hub__new` in place of the count while anything is unread. The shared empty state is unchanged (two `<h3>{{.EmptyTitle}}</h3>`).
- **Tests**: `TestBellCountMarkup`, `TestUpdatesCSSTokensOnly`, `TestUpdatesControlsMeetTouchTarget`, `TestUpdatesLoadedOnTheFourBellPages`, `TestUpdatesScriptContract`, `TestUpdatesPartMarkup` (web), 23 node tests in `updates_test.mjs`, and `TestActivityUpdatesPartRenders` (e2e on a disposable database).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Dots drawn with clip-path, not a round border-radius**
- **Found during:** Task 1 (first `go test ./web/`)
- **Issue:** `TestReadOnlyLabelsRoundedControlsNot` fails any rule with `border-radius: 50%`, which the 8px severity and unread dots needed.
- **Fix:** `.bell-row__sev`, `.urow__sev` and `.urow__dot` use `clip-path: circle(50%)` and a comment says why. The shape contract stays unchanged.
- **Files modified:** web/static/css/updates.css
- **Commit:** 31af88a

**2. [Rule 3 - Blocking] Updates error block text kept out of the Ended nearby exact string count**
- **Found during:** Task 3
- **Issue:** `TestEndedNearbyStatesCopy` (not in this plan's file list) counts `<p>Check your connection and try again.</p>` across the whole template and wants 1. The plan's own `activity_page_contract_test.go` change scoped the other two counts to the Ended shell, but this third test would still fail with the Updates error block's identical paragraph.
- **Fix:** the Updates error paragraph carries `class="activity-empty__text"`, so its words are unchanged and the Ended nearby test needs no edit. `activity_page_contract_test.go` is scoped as the plan said, with a dated note.
- **Files modified:** web/templates/profile.html.tmpl
- **Commit:** 677148e

**3. [Rule 2 - Missing critical] Modifier classes `bell-row--more` and `urow--more`, and `data-unread`**
- **Found during:** Tasks 2 and 3
- **Issue:** the "and N more" row must read muted (UI-SPEC A3) while an unavailable row stays regular text, and CSS had no hook to tell them apart. The new dot and weight belong only to link rows, yet a plain unread row (the rolled up one) still has to be marked read with the part, or the hub tag would never clear.
- **Fix:** two modifier classes (in updates.css and the markup) and a `data-unread="true"` attribute on every unread `li`, read by the part's mark. The plan's class list said later plans add none; these are used by this plan only.
- **Files modified:** web/static/css/updates.css, web/static/js/updates.js, web/templates/profile.html.tmpl
- **Commit:** 31af88a, ef94bd4, 677148e

**4. [Rule 2 - Missing critical] Phone Updates box, error retry link and a 401 stop**
- **Found during:** Tasks 2 and 3
- **Issue:** the phone has no `.activity-box` border (UI-SPEC B2 wants one rounded box of rows), the error block's Try again is an `a` that needs the button look, and the bell would show an error to a signed out visitor.
- **Fix:** `.urow-list` carries the phone border and drops it in the laptop block; `main.profile-page a.activity-retry` gets flex centring; a 401 stops polling quietly.
- **Commit:** 677148e, ef94bd4

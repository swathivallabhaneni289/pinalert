# Phase 03.2 Plan 02: Update decision core and update words Summary

Pure, table tested Go for when an in app update is written (DecideUpdate), the one eligibility predicate for announcing a report (MayNotifyAboutReport with a kind argument), and every server written word of an update row.

## What was built

- **updates.go**: `UpdateKind` (reached_live, hidden, resolved, fading, reliable_nearby, plus the rolled up marker more which is never an event), `KindForState`, `UpdateCursor`, `DecideInput`, `Decision`, `DecideAction`, `DecideUpdate` (an early return ladder: muted, withheld, baseline, self caused adopt, state change with the one per hour gap, fading), `MayNotifyAboutReport`, `HourBucket` and the phase constants.
- **MayNotifyAboutReport** answers from `ViewOf`: false unless the report is active (so never Hidden, Withheld, Retracted or expired). The Reliable reporter note is true for Live and Provisional (the note comes at posting, owner amendment 2026-10-18); every other kind needs Live. Its declaration does not name FeedView, so it is a free function the source guards do not reach; TestWithheldInNoView has an explicit row for it.
- **updatescopy.go**: event lines (Now confirmed, Now disputed, Marked resolved, Fades in about an hour, Reported nearby by a Reliable reporter.), `UpdateTrustLine` chosen at read time from the current trust object and view (never empty for an event kind; "Not confirmed yet." for an active, unconfirmed Reliable note, the confirmed sentence once confirmed), `MoreLine`, `UnavailableLine`, `UnconfirmedLine`, and `ReportFirstLine`, which reads report text only through `CoarsenFinishedRescue` and cuts to 160 runes.

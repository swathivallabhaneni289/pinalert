# Phase 3.2 Plan 16: Log out of all devices Summary

POST /api/me/logout-all revokes every session of the gate's own account through plan 06's SessionService and clears this browser's cookie, and the sign in page now says what happened after Log out of all devices or Delete my account.

## What was built

- `LogOutAllDevices` handler (new file logout_all.go): account from the gate (bare 500 when absent), strict empty body through `decodeEmptyBody`, `sessions.LogOutAllDevices(ctx, acc.ID)`, `ClearCookie`, `Cache-Control: no-store`, 204 with no body. A failure logs the account id only.
- Route `POST /api/me/logout-all` in the gated group, with `sessionsSvc := service.NewSessionService(deps.Sessions)` built in NewRouter. No Deps literal changes.
- Swagger docs regenerated with `make swag` (docs.go, swagger.json, swagger.yaml, 138 added lines, nothing else drifted); TestSwaggerSpecCoversRoutes now asserts `/me/logout-all` post and its 401.
- LoginGate reads `done` and compares it exactly with `all-devices` and `deleted`, setting `You are logged out of all devices.` or `Your account has been deleted.`; template line `<p class="login-done" role="status">` above the h1; token-only CSS.

## Tests (disposable database p32_16, zero skips)

- TestLogoutAllRevokesEverySession: a copied cookie and the original both work; a malformed body and an unknown field are 400 and end nothing; the real call is 204 with no-store and a cleared cookie; both browsers then get 401 on /api and 302 to /login on pages; a third account is unaffected.
- TestLogoutAllEndsASecondSignIn: a second sign in of the same address is ended too, and an empty body is accepted.
- TestLogoutAllKeepsAuthorship: another reader's JSON for A's confirmed report is byte equal before and after; every session row of A still names A and is revoked.
- TestLogoutAllNeedsAnAccount: 401 JSON for an anonymous caller, nobody revoked.
- TestLoginDoneLineIsClosedList: the two words show their line inside role=status; empty, markup, wrong case, trailing space and a repeated key show no line and the value is never echoed.

`go test ./web/ ./internal/api/... -p 1 -count=1 -v` against p32_16 passed with no SKIP and no FAIL. `go vet ./...` is clean and the short run of web, service, api and store passes. p32_16 was dropped at the end.

## Deviations from Plan

None in behaviour. One small choice: the CSS selector is `.login-card .login-done` instead of a bare `.login-done` so the 14px label size is not overridden by `.login-card p`. The sandbox refused `env -i` and `env -u`, so tests ran with the `DATABASE_URL=...` prefix only (DATABASE_URL was confirmed empty in the shell first).

None.

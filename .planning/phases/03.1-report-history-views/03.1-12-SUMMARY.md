# Phase 3.1 Plan 12: Past cards, recent counts and report links Summary

The Past tab now draws Resolved then Expired groups of white read only cards from the frozen wire shape, the empty Active tab says what really happened in the last 24 hours with a button to Past, and a report link selects the tab of the report's own state without touching the address.

## What was built

- **feed.js**: `createPastCard(id)` (an `li.past-card`, tabindex 0, role listitem, `data-report-id`, title, meta, facts, visually hidden Open report last; click, Enter and Space call `activateRow`), `updatePastCard`, `buildPastMeta`, `renderPastGroups`, `placePastGroup`, `removeDepartedPastCards`, `clearPastCards`, `cutLineText`, `placeInList`. `renderPastTab` calls `renderPastGroups` after the groups container is shown. The groups keep the server's order (no sort, no client cap) and a group with no card is hidden with its header. `refreshAgeAndTime`, `applySelectionHighlight`, `revealRowInListPane`, `focusAfterRemoval` and `moveFocusIntoView` find a Past card by id.
- **Words**: Resolved meta is `{Category} · {closed_text}, {relativeTime(at)}`; Expired meta is `{Category} · Faded {relativeTime(at)}, {lifetime_text}`; an approximate card is titled `Rescue needed`, its meta begins `Approximate location`, and its description is never read. The Expired facts line begins with the server's `outcome_label` in a 600 weight span; a corroborated outcome leaves its confirm count to the label.
- **Empty Active tab**: `recentSentence(recent)` builds C39's counts sentence from `state.recent`; `render` picks the `history` kind only for an unfiltered Active tab with a non empty sentence and writes `{sentence} Tap + to report what you're seeing.` into `#feed-empty-history-body`. `#see-past-reports` already switches to Past through `switchTab`.
- **Report links**: `handleFocus(state)` runs after each ok list draw (live list, empty list, Past tab), once per focus object. `too_old` and `unavailable` show the two plain toasts; `ok` with a report whose view differs from the tab calls `selectTabOnScreen(tab)` (store, strip, refetch, no address write). `resolved` and `past` both map to the Past tab.
- **feed.css**: `.past-group__label` (14px 600 uppercase, 0.04em, muted), `.past-group__list`, `.past-group__cut`, `.past-card` (white, 1px border, 8px corner, padding calc(var(--space-md) - 1px), no bar, tint or severity colour), `.past-card__title` (16px 600, two line clamp), `.past-card__meta`, `.past-card__facts`, `.past-card__outcome`, focus and selected rings with `outline-offset: -2px`. Tokens only, no media rule.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - blocking pin] feed.js may not name `confirmed_text` or `disputed_text`**
- **Found during:** Task 1, first full `go test ./web` run.
- **Issue:** `TestTrustBlockMountedOnBothSurfaces` (trust_contract_test.go, a file plan 13 owns this wave) forbids both field names in feed.js, so the plan's `{confirmed_text} confirmed` could not be written literally.
- **Fix:** the facts line is the row's trust line from `PinalertTrust.createTrustLine()` and `updateTrustLine()`. Its numerals and words are the server's, written by trust.js. The card shows its own outcome label span first, hides the first counter for a corroborated outcome, and sets `card.trust.word.hidden = true` because the currency word belongs to a live report. If the trust object is unusable the line hides itself (never an invented zero) and the label alone stays. The two counters get the card's own classes `past-card__count` and `past-card__count--second`, because `TestCompactRowLiftScopedToList` forbids `.report-row` heads without the `#report-list` prefix in feed.css. I did not edit trust_contract_test.go.
- **Files modified:** web/static/js/feed.js, web/static/css/feed.css, web/past_tab_contract_test.go.
- **Commits:** 2883cb9, 0b3078d.

**2. [Rule 2 - layout] `#past-groups { flex: none; }`**
- The phone list pane is a scrolling flex column. A plain block child keeps its content height there already, so this is a guard like plan 05's, with no geometry change, set at the top level (no phone only rule, no phone.css edit). No extra bottom padding was added: phone.css's pane padding already reserves room under the fixed toggle button (`.pane--list #report-list` is zeroed there for the same reason).

**3. [Doc] Stale message in view_strip_contract_test.go**
- `TestViewStripPaneScript` still counts zero literal `setEmptyState('history')` calls, which stays true because render selects the kind through its `kind` variable. Only the failure message was reworded (commit 0b3078d). No pinned literal changed.

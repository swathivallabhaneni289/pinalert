# Phase 3.1: UI Design Contract

> Visual and interaction contract for Phase 3.1 (the Active | Disputed | Past tab strip, the Past tab, compact report rows, place search on the map, category chips, the take back of a mistaken Mark resolved, finished Rescue reports). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.

---

## Source of Truth and Scope

**Token source of truth:** `web/static/css/main.css`. Every colour, spacing, type size and weight below is an existing token. This phase declares no new colour and no new type size. It adds three composed values (see Spacing, "Composed values").

**Baselines this contract amends:** `03-UI-SPEC.md` (A-numbers are quoted by id and not copied), `04-UI-SPEC.md` (P4-A4, P4-A7, P4-A16, P4-A25), sketch 005 (the phone layout as built) and sketch 006 (winner A). Where this file is silent, those stay in force.

**Decisions treated as the contract:** D-01 to D-26 of `03.1-CONTEXT.md`. Where this file adds a choice the context left open, the choice is marked **Decision** with one line of reasoning. Nothing was put to the owner.

**Draw order (owner rule D-26):** every surface is specified at 320, 360 and 390 px wide first (phone rules live only in `phone.css`, one `max-width: 899.98px` block), then at 900 px and up. Light and dark both use the same tokens.

**Sample data rule:** every number, name and sentence in an example is sample data. Real values come from the server and the page config. The browser computes no trust figure, no outcome, no count of history.

**Not designed here:** the reader's own history (the Activity page, built by quick task 261013-wm5), in app updates (3.2), official alerts (5), the report page (8), any page wide redesign (backlog 999.10), a severity filter on the phone, a "Search this area" button, counts on the tabs.

**Stack:** Go `html/template`, vanilla JS, hand written CSS, Leaflet 1.9.4 with the MapLibre basemap. No framework, no build step, no new library. Tool: none.

## Surface 1: The Tab Strip (D-01, D-02, D-06)

**Markup:** `<nav class="view-tabs" aria-label="Report views">` holding three `<a class="view-tab">` links, the same pattern as the Activity strip (`activity-tabs.js`): links so each tab is a real address, middle click and "open in new tab" work, and a script only makes the switch instant. The current tab carries `aria-current="page"`; the others carry none. No `role="tablist"`, no roving tabindex.

| Tab | Visible text | `href` | Written to the address |
|-----|--------------|--------|-----------------------|
| Active | Active | `/` | nothing (the `view` parameter is removed) |
| Disputed | Disputed | `/?view=disputed` | `view=disputed` |
| Past | Past | `/?view=past` | `view=past` |

**Address rules:**
1. `?view=active` is never written, by the script or in any link. A main page address with a query string is never sent to the Low data view, so writing it would break the remembered choice.
2. The page uses `replaceState`, never `pushState`. A tab press adds no Back step.
3. Other parameters (`report`, `full`, `resend`) are kept as they are.
4. Read only aliases: `view=resolved` opens the Past tab. `show_disputed=true` opens Disputed and is rewritten once to `view=disputed` on first load. Any unknown `view` value opens Active and the parameter is dropped (fails closed).
5. **Decision:** the Past tab always writes `past`, never `resolved`. Reasoning: the word in the address matches the word on the tab, and a reload must not move the list. `view=resolved` and `view=past` both land at the top of the Past tab. The "scrolled to the matching group" wording of D-04 is not built: a report named by `&report=ID` is revealed by the existing row highlight (and on phones the list pane's own scroll, never the page), which is the only scroll that matters.
6. The place and the chip are not written to the address (D-18: a fresh open starts clear). A reload returns to the reader's own location and All.
7. `pageshow` with `persisted` re-reads the address and refetches, as today.
8. A link `/?report=ID` with no `view` that lands on a finished report selects the Past tab on screen, but the address is not rewritten, so Phase 4's moderator links and Phase 3.2's deep links stay as they were sent. The address changes only when the reader presses a tab.

**Geometry (same look at every width, Activity phone strip):**

| Part | Value |
|------|-------|
| Track | `--color-surface` fill, 8px corner, `padding: var(--space-xs)`, `gap: var(--space-xs)`, `display: flex; flex-wrap: wrap` (wraps to two rows only at large text sizes, each tab stays 44px tall) |
| Tab | `flex: 1 1 0; min-width: 0`, `min-height: var(--touch-target-min)`, `padding: 0 var(--space-sm)`, centred text, 8px corner, 1px transparent border, 16px, weight 400, `--color-text`, no underline, `overflow-wrap: anywhere` |
| Width 320 | strip 288px, each tab about 91px ("Disputed" at 16px is about 66px) |
| Width 360 and 390 | strip 328px and 358px, each tab about 104px and 114px |
| Laptop | `max-width: 360px`, left aligned, `margin: var(--space-md) 0 var(--space-sm)`. Reason: the fixed account button sits at the top right of the page, over the right end of the list pane (x from 60px to 16px from the viewport edge), so a strip of 360px clears it even at 900px wide (pane 434px). |
| Phone | `margin: 0 0 var(--space-sm)` (the list pane already has 16px padding) |

**States:**

| State | Look |
|-------|------|
| Rest | transparent fill, `--color-text` 400 |
| Hover | fill `color-mix(in srgb, var(--color-border) 50%, transparent)`, no underline (the A77 value). The current tab does not change its fill on hover. |
| Pressed | fill `--color-border` |
| Current (`aria-current="page"`) | `--color-bg` fill, 1px `--color-border` border, weight 600. The weight and the border are the non colour cues. |
| Keyboard focus | the global `:focus-visible` ring, with `outline-offset: -2px` so the ring is not clipped by the track |
| Forced colours | current tab gets `border: 1px solid CanvasText`; hover and press change the border colour, never an underline |
| Reduced motion | there is no transition to turn off; hover is instant |

**Behaviour:**
- Press on a tab (a plain left click): `preventDefault`, set `aria-current`, `replaceState`, refetch through the one list `fetch(` in `app.js`, render. Rows fetched under the other tab never stay under the new one (a failed fetch clears them). Amended after the code review (finding WR-03, 2026-10-16): while the list loads a different set (another tab, chip or place), the list pane carries `data-loading`, the old rows are hidden behind the skeleton and the map hides its report pins and its label, so nothing from the old set is readable under the new tab; both come back the moment the answer or the error lands. The store keeps its rows meanwhile.
- Focus stays on the pressed tab. The result is announced once through `#feed-status` (see Copywriting, S1 to S3).
- The chip and the searched place stay when the tab changes (D-15). The map follows (D-13).
- Keyboard: Tab moves through the three links, Enter follows. Space is not bound (links).
- Screen reader: the landmark is "Report views, navigation", each link is announced with "current page" when selected.
- The phone bottom bar keeps exactly two tabs, Feed (current) and Activity. It is not changed and never shows Past.

### Distance segment (element 4)

| Situation | Text | Shown when |
|-----------|------|-----------|

**Too far to vote on a row (D-14):** the row adds a second plain fact "Too far to vote" right after the distance (14px 400, same line) only when the reader's last cached fix (the one `applyDistanceHint` reads, no new location request) puts the reader farther than `data-vote-radius-km` from the report. With no cached fix the row says nothing and the opened report explains, with the existing sentence "Too far to vote. You need to be within 1 km of this report." (1 comes from `data-vote-radius-km`). The row never asks for a location by itself.

### Colour rules on a row (carried from the phone card; the good tone is phone only)

- Meta and distance take `--color-text` on a tinted row (a severity tint, or the `--color-surface` tint of a laptop provisional row) and `--color-text-muted` only on a `--color-bg` card (provisional and hidden cards on a phone, a hidden row on a laptop), because muted fails 4.5 to 1 on every tint and on `--color-surface` in the light theme (A42).

On a laptop the trust line takes `--color-text` on a tinted row and `--color-text-muted` on a `--color-bg` card, never the good tone.
- Severity is never colour alone: the row says the word.

### The short Undo on the message after "Yes, mark resolved"

## Accessibility

- Every target is 44px or more. The map label is not interactive and is exempt.
- Visible focus on every control: the global ring, inset (`outline-offset: -2px`) on tabs, chips and cards, `--color-bg` ring on the toast button.
- Keyboard: Tab order on a laptop is search, Search button, chips, map pins, add button, tab strip, place line button, filter line button, rows. Enter and Space open a row or card. Escape order: results, then the expanded phone search, then (existing) confirmation, trust panel, popup.
- Names: the strip is a navigation named "Report views"; the chip group is named "Filter by category" with `aria-pressed`; the search input and both search buttons carry "Search for a place"; the Undo has "Undo my resolved mark"; the toast action "Undo marking this report resolved".
- State is never colour alone: the current tab has weight and a border, a pressed chip has weight and inverted fill, a finished pin has a ring and a dashed or solid cue, a row says its severity word, a Past card says its outcome and who closed it in words.
- A timer is never the only route: the toast Undo expires, the persistent take back does not (until the report fades).
- Live region: `#feed-status` announces tab, place and chip changes once; `#map-search-status` announces search progress and results; `.vote-error` keeps `role="alert"`.
- Forced colours: current tab, pressed chip and toast action get explicit borders; the finished pin ring uses `CanvasText`.
- Reduced motion: no animation is added. The toast keeps its existing rule.
- Text size: tabs wrap, chips scroll, rows and cards wrap between whole facts, nothing is cut to a fixed height. No horizontal page scroll at 320 and 200 percent text.

# Phase 3.1 Plan 09: Compact list rows Summary

The feed list row is the size A phone card at every width with no control inside it: severity dot and word, state word, category and time, distance, an optional "Too far to vote" fact, a title clamped at two lines, one plain text trust line with both counters and the currency word, and the reporter words.

## What was built

- **trust.js**: `createTrustLine()` returns `{ el, counts: { confirmed, disputed }, word, reporter }`; `el` is a `p.report-row__trustline` of plain text (two counters, the currency word when the server sent one), hidden until filled. `updateTrustLine(line, trust)` validates the trust object first (an invalid object hides the line and the reporter words, never a made up zero), writes `confirmed_text`, `disputed_text`, the server's currency and reporter labels through `setText`, and sets `data-currency-tone` from `currencyTone(trust.facts)`. Both exported. `createTrustBlock`, the card and the Activity path are unchanged.
- **votes.js**: `farFromCachedFix(report)` mirrors every guard of `applyDistanceHint` (own report, unknown radius, no cached fix, a fix older than the hint bound, an unreadable distance all answer false) and compares with a strict `>` against the radius. It reads the cached fix only. Exported. Nothing else in votes.js changed.
- **feed.js**: `createRow` builds the badge (kept for pins, hidden by CSS) and a body of severity label, state line (visibility tag and reporter words), meta, distance (`p.report-row__away`), far fact (`span.report-row__far`), title, trust line and a visually hidden "Open report" cue. No vote block, no trust block. `updateRow` fills them with `Pinalert.distanceText`, `PinalertVotes.farFromCachedFix` and `PinalertTrust.updateTrustLine`. Selection highlight, `activateRow` and `renderRows` are unchanged.
- **feed.css**: the lifted rules under `#report-list .report-row`: block layout, badge hidden, flex wrap body, state line `display: contents`, dot and word severity label, critical dot, visibility tag, meta, distance, far fact, title clamp at two lines with `overflow-wrap: anywhere`, trust line (flex wrap, wraps between whole facts), numerals, reporter order, the open cue, the dot separators, and the laptop only muted trust line on a hidden row.
- **phone.css**: keeps the card's `border: 0` and 8px corner, the white provisional and hidden cards, their muted pairs (now naming the far fact and the trust line), and the good tone rule re keyed to `.report-row__trustline[data-currency-tone="good"]`. `.report-row__away` left the base hide group. Plan 05's `flex: none` rule for the strip and the note moved here from feed.css.

## Phone widths (320, 360 and 390 px)

No browser was run (owner rule). The static rules that stand in for each width, all asserted by `TestCompactRowFitsPhoneWidths`:

- **320 px (card 288 px):** the body is `display: flex; flex-wrap: wrap`, so line one wraps to two lines as intended. The title is `flex: 0 0 100%`, `min-width: 0`, `overflow-wrap: anywhere` and clamps at two lines, so a pasted URL wraps and the card cannot grow past 288. The meta, distance and far fact carry `min-width: 0` and `overflow-wrap: anywhere`; the trust line is `display: flex; flex-wrap: wrap` and wraps only between whole facts, with no `white-space: nowrap` anywhere on the row.
- **360 px (card 328 px) and 390 px (card 358 px):** the same rules, with more room, so line one fits on one line more often. No lifted rule sets a fixed `width` (the 8px severity dot is a `::before` and exempt), and no `min-width` other than 0, 100% or the 44px tap floor. The row keeps 16px padding on all sides, so it is at least 44px tall.
- Font sizes in lifted rules are only the 14, 16 and 18 tokens.
- The real width check (at least three rows at 390 by 844 averaging 160px or less, no horizontal page scroll at 320 px and at 200 percent text, laptop 1280 by 800 averaging 125px or less with at least five rows visible) is the orchestrator's browser pass, plan 16 list item 3.

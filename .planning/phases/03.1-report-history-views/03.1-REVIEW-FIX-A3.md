## Item 1: a distant linked report vanishes after Mark resolved and the toast Undo cannot bring it back

**Commit:** 605efdf
**Files:** web/static/js/votes.js, web/static/js/map.js, web/takeback_contract_test.go, web/review_fix_a_contract_test.go, web/review_fix_a3_contract_test.go
**Status:** fixed: requires human verification (state machine logic)

What changed:

- votes.js `resolveToastAction` runs before the refetch that follows the
  mark, so the link is still held there. When `Pinalert.state.focusId` is this
  report, it keeps a key of the tab, chip and centre (`linkSetKey`) and hands
  it to the Undo as a third argument.
- `takeBackFromToast(reportId, wasClosed, link)` calls the new
  `relinkAfterToastUndo` on success, before its own refetch. It puts the id
  back through the existing `Pinalert.setFocusId` only when the toast belonged
  to the link, the mark had closed the report, the take back reopened it (not
  `retracted`), no link is held now, and the reader is still on the same tab,
  chip and centre. A refused Undo never relinks. A reader who moved to another
  tab, chip or place keeps the link ended, so no `report=` rides a poll with
  nothing on screen.
- map.js `endLinkOnClose` now clears `openedFocusId`, so the popup of the
  reopened report opens again from the server's answer. The only path that
  links the same id again is this Undo; closing that popup afterwards ends the
  link again as before.

Pinned literal edited (takeback_contract_test.go TestToastAction, twice, and
review_fix_a_contract_test.go TestReviewFixARefusedTakeBackRefetches):

- old: `takeBackFromToast(reportId, wasClosed)`
- new: `takeBackFromToast(reportId, wasClosed, link)`

Driven: a distant link opens its pin; the mark's refetch removes it and ends
the link; the Undo's refetch carries `report=42`; the answer brings the pin

ends the link and the next poll has no `report=`. Kept ended: a reader who

## Item 3: refusal feedback waits for a list round trip

**Commit:** c43dfbd
**Files:** web/static/js/votes.js, web/review_fix_a_contract_test.go
**Status:** fixed

- `onTakeBackClick`'s refusal branch restores the label, releases the block,
  writes the refusal line and focuses the button (when it can take focus)
  first, then reads the list for an answered refusal. After the render,
  `focusAfterTakeBack(origin)` runs only when the button can no longer take

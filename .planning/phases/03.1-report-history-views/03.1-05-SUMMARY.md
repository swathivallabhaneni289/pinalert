One strip (Active, Disputed, Past) replaces the disputed checkbox at every width, the store holds one view, one category, one place and one link id, and the whole list pane markup of the phase exists once with its UI-SPEC words.

## What was built

- **app.js**: `state.view` replaces `state.showDisputed`. `fetchReports` captures view, category, centre and link id at call time, adds `&view=` only for disputed and past, `&category=` only when set, `&report=` only on the first call after `setFocusId`. `isStale` also drops a response whose tab, chip or centre no longer matches the store. The failure path drops rows fetched for another tab, chip or centre (`rowsFor`, `rowsMatchStore()`). The poll skips while the view is past. `recent`, `cut` and `focus` are stored without being rendered. Still exactly two `fetch(` calls. `distanceText` formats the C20 and C21 sentences; the server owns the numbers (D-23).
- **feed.js**: `readViewFromURL`, `syncViewURL`, `switchTab`, `updateTabStrip`, `showTab`, `updateFeedHeading`, `updateFeedStatus`, `renderPastTab`, the strip click handler (plain left click only), the one time rewrite of an old bookmark, the page restore re-read. `setEmptyState` shows at most one of five blocks.
- **index.html.tmpl**: `nav.view-tabs`, `p#feed-status`, heading with `#feed-heading-title`, `p#feed-note`, `p#place-line`, `p#filter-line`, `div#past-groups` with Resolved and Expired sections, `#feed-empty-history` (C39), `#past-empty` (C40), `#filter-empty` (C38). Every new block ships hidden.
- **feed.css**: strip, tab, note, inline text button, hidden guards for the new blocks, laptop heading rule for Disputed and Past. **trust.css**: the `.filter-toggle` rule and its comment removed.

## Deviations from Plan

1. **[Rule 3 - boundary] A phone only rule in feed.css.** The plan says a phone only override means stop and report. I added `.pane--list > .view-tabs, .pane--list > .feed-note { flex: none; }` in feed.css's existing max-width 899.98px block (not phone.css). Reason: the phone list pane is a scrolling flex column and a flex item can shrink under a long list. It changes no geometry, and plan 09 may move it into phone.css or drop it if its pane rules make it redundant.
2. **`data-feed-view` attribute on each strip link.** Not in the plan's list; the script reads the tab word from it instead of parsing the href. The three links keep the pinned hrefs.
3. **Empty block button spacing scoped by id** (`#feed-empty-history .btn, #filter-empty .btn`) so the shared `.empty-state` on other pages is untouched.
4. **Template sections of the Past groups ship hidden**, not only the container, so a Past response with results shows no empty Resolved or Expired header before plan 12 fills and unhides them.
5. **A literal ellipsis and middle dot in app.js and feed.js comments and strings** were normalised back to `…` and `·` escapes in code, matching the file's existing style.

Do not run a browser or UAT check of the strip until they are merged.
- **Changes by design (not edited, outside this plan's files):** `internal/api/handlers/reports.go`, `swagger_test.go`, `trust_e2e_test.go`, `feed_visibility_e2e_test.go`, `internal/service/feed_test.go` and `docs/swagger.*` still use `show_disputed` as the server's deprecated alias; the server plans own them. Any browser harness or UAT script that clicks `#show-disputed-toggle` now has to press the Disputed tab link (`a.view-tab[data-feed-view="disputed"]`); no such script is in the repo.
- **Gap for a later plan:** `votes.js` `focusAfterRetract` only knows `feed-empty` and `disputed-empty` as empty fallbacks, not `feed-empty-history`, `past-empty` or `filter-empty`.
- **Template checkbox ban:** TestFeedExplainsAnEmptyDisputedResult bans `type="checkbox"` in the whole template; a later checkbox in the report modal would trip it and should narrow that check to the list pane.

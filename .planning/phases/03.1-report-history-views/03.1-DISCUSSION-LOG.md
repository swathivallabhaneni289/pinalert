## Undoing a resolve

Question: someone taps Mark resolved by mistake, or strangers close a report while the water is still rising. Where do people undo it? Today only the person who posted it can reopen, and the button is only on the Activity page.

| Option | Description | Selected |
|--------|-------------|----------|
| Only the poster, in the opened report (recommended) | The existing Reopen control and endpoint, no new power; nobody else sees a control | |
| No controls at all | The literal roadmap text, no way back | |
| Nearby people can also reopen | A new capability, deferred | |
| The person who marked it can take it back, once or twice (the owner's own words) | Not one of the three options as asked | ✓ |

**User's choice:** Answered in the same message as the row size: "I think they should be able to change it because um, yeah I think they, they should uh, the user uh, the other user who marked it uh, by mistake should be able to do it once or twice that's it". Claude's reading: the person who marked a report resolved by mistake can take that mark back, at most twice on one report.
**Follow up (same day, a few minutes later):** the owner asked "Have any suggestions regarding the what we should do when someone taps mark resolved by mistake? Do you have any ideas". The reply listed what already protects against a mistake (the Yes or Cancel step, the two people rule, the report fading after 8 or 24 hours) and proposed: the take back in the opened report for whoever marked it (also from the Past tab), at most twice per person per report, the same limit on the poster's Reopen, and an optional short Undo on the message after "Yes". The owner answered "all 3" (2026-10-14), so all three parts are decided and D-22 is OWNER DECIDED.
**Notes:** The Phase 3.2 Activity reference already says a row has no Reopen and its new home is most likely the opened report. Nearby people reopening a closed report stays deferred. The planner constraints (a neutral resolution value instead of `reopen`, counting from the vote log, the viewer's own vote on the wire) are in CONTEXT.md under "Conflicts and risks".

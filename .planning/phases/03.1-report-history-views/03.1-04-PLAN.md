<objective>
Write the three history reads the service needs (plan 06 composes them): expired reports in the 7 day window inside the reader's area, unexpired reports in the area (the ones that may be closed), and one report by id for links. Every bound is a parameter.

Purpose: NearbyReports filters on the database clock and on unexpired rows, so it cannot serve Past and must not change (scope note 2). The candidate split stops a disaster's many live reports from crowding expired ones out of the Past tab.
Output: history.sql, its generated Go file and store tests on a disposable database.

Generated code in this wave: plans 02 and 04 both run make sqlc. Each adds its own new query file, so each produces its own new generated file (history.sql.go here, undos.sql.go there); sqlc's shared db.go and models.go do not change because no migration is added; and each plan stops if any other generated file changes. The two outputs are disjoint files, which is why sharing the generator in one wave is safe.
</objective>

ExpiredReportsInWindow :many: the NearbyReports inner and outer shape with the same twelve output columns; the inner WHERE keeps the bounding box and replaces the expiry predicate with expires_at at or before the now parameter and strictly after the window_start parameter (both cast to timestamptz, the same edges ReporterHistoryReports uses); the outer query keeps distance_km at or under radius_km, orders by expires_at descending then id descending, and limits to the row_cap parameter. OpenReportsInArea :many: the same shape with expires_at strictly after the now parameter, ordered by distance_km ascending then id ascending, limited by row_cap. It feeds only the Resolved group (a closed report that has not yet expired).

ReportForFocus :one: the same twelve columns for one report id (sqlc.arg(report_id)), with distance_km computed from the lat and lon parameters, with no expiry, area or radius predicate, because a link must open a report outside the reader's radius and outside the window (D-11); the service decides too old.

Lettered comment blocks, in the reliability.sql style: (a) what each read feeds; (b) why two candidate sets with separate caps (one set ordered by expiry would let live reports fill the cap and empty Past during a disaster); (c) every bound is a parameter and the statements hold no database clock call, so an injected clock reaches them (backlog 999.5; write this in words, do not quote a clock function name); (d) no vote, visibility or votes table predicate (Resolve decides in Go, T-02-04), and the prefilter is a safe superset because CastVote refuses every vote on an expired report, so a closure always happens before expiry; (e) no session id, cell or account in the output (T-01-02); (f) the indexes the predicates can use (idx_reports_expires_at, idx_reports_lat_lon) and that no new index is added (RESEARCH A8).

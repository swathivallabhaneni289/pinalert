## WR-02 and W8: cut flag when a candidate read hits its cap

**Commit:** ec73e73
**Files:** `internal/service/historyread.go`, `internal/service/review_fix_b_test.go`
`historyCandidates` now returns a `candidateSet` that says which read returned
exactly its row cap. `History` sets `ResolvedCut` when either read was capped
(a resolved entry can come from the open set or from the expired set) and
`ExpiredCut` when the expired read was capped (a past entry comes only from
there). This is in addition to the "more than 25 kept" rule. The doc comments of
`History` and `RecentHistoryCounts` say the counts can under report when a read
hit its cap; the counts and the wire shape are unchanged.
**Checked by:** `TestHistoryCutWhenCandidateReadHitsItsCap` (open read at 1000,
one short of 1000, expired read at 500) and `TestRecentHistoryCountsKeepsItsShapeWhenCapped`.

## IN-01 and W1: Nearby clock gap

**Commit:** 89bd79e
**Files:** `internal/service/report.go`, `internal/service/review_fix_b_test.go`, `internal/service/trust_paths_test.go`
After `ViewOf` in `Nearby`, any report whose view is not active or disputed is
skipped, so a report that expired between the database clock and the service
clock is simply absent (the next read lists it in Past, blurred). The SQL is not
touched. `TestTrustAttachedOnEveryReadPath/each path reads its injected clock`
relied on a fake returning an expired report through Nearby; it now expects zero
views from Nearby, and still checks the Activity and CastVote paths.
**Checked by:** `TestNearbySkipsAReportThatExpiredInTheClockGap` (a Flood report
expired by 1 ms and a Rescue report expiring exactly now, both reads).

## W3: drift test

**Commit:** 7d73fb1
**File:** `internal/service/review_fix_b_test.go`
`TestListableInFeedAgreesWithViewOf` loops every visibility plus two unknown
values over three expiry sides (unexpired, expired, exactly now). For an
unexpired report `ListableInFeed(false)` matches active and
`ListableInFeed(true)` matches disputed; the two are never both true; an expired
report is in no live tab; retracted is never listable and is resolved at any
expiry; an unknown visibility is in no tab.

## IN-02: undos_left on a faded report

**Commit:** e243efa
**Files:** `internal/service/historyread.go`, `internal/service/feed.go` (doc comment), `internal/service/review_fix_b_test.go`
`attachUndos` sets `UndosLeft` to 0 for a view that is Past or whose expiry has
passed (this includes a resolved report past its expiry). It already skipped the
undo count read for those, so no new reads. `attachUndos` is the one place that
fills the field for Nearby, History and Focus.
**Checked by:** `TestUndosLeftIsZeroOnAFadedReport` (a Past entry and an expired
resolved entry on History, a Past report on Focus, no `ResolutionUndoCounts` call).

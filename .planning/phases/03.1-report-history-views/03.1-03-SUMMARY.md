# Phase 3.1 Plan 03: Reader place search lane Summary

Reader place search now has its own geocoder lane (a no wait token path on the shared limiter, a 256 entry 6 hour cache keyed by text and a 0.1 degree centre bucket, a non bounded viewbox bias) and a gated `GeocodePlace` handler with a per account budget and plain 429 and 503 messages. No route is registered here; plan 08 mounts it.

## What was built

### Task 1: Client.SearchReader (commit d0d85d6)
- `Search` and `SearchReader` share one unexported `fetch`; `buildRequest` takes an extra parameter set that `Search` passes as nil, so the reporter request is unchanged.
- `SearchReader` normalises the text, serves a fresh cache hit with no token, otherwise calls `c.limiter.Allow()` and returns `ErrReaderBusy` when no token is free.
- With a centre it sends `viewbox` (left, top, right, bottom, plus and minus 0.5 degrees) and `bounded=0`; without one, neither.
- Constants `readerCacheEntries` (256), `readerCacheTTL` (6h), `readerBiasDegrees` (0.5), `readerBucketDegrees` (0.1), each commented as RESEARCH A4 and easy to retune.

### Task 2: GeocodePlace (commit 08d7cd8)
- Order: account from context (500 if absent), budget keyed `place:<account id>` (429), `parseGeocodeQuery`, optional lat and lon both or neither and finite and in range (400 naming the field), nil searcher (503), `SearchReader` (any error 503), field by field mapping to `GeocodeResult`, `Cache-Control: private, max-age=300`.
- Swagger annotation added with `@Router /geocode/place [get]`. `make swag` was not run (plan 10 owns it).

# Phase 3.1 Plan 11: Place search, category chips and the map tools Summary

A place search and five category chips now sit over the map, the list pane says why it is not the default area or the full set, and the map can move to a place and back to the reader without a map move ever reading the list.

## What was built

- **map.js**: `locateReader` (one geolocation step), `moveTo` (project, shift by half the measured reserve, unproject, so the target sits below the tools), `recenterOnReader` (store the centre with its own flag, move, read the list once, resolve `{ own }`), `getCenter` (wrapped longitude, null before the map exists). `refreshPanPadding` takes `Math.max(top, toolsReserve())`; `toolsReserve` is its own helper (measured bottom of `.map-tools` minus the container top plus `--space-sm`, 0 when absent or hidden), so the token name list the narrow max-height test compares is not widened. The popup meta distance is `Pinalert.distanceText(report)`. No `zoomend` or `dragend` handler exists and the one `moveend` handler never reads the list.
- **map-tools.js**: one `fetch(` to `/api/geocode/place` with an `AbortController`. No input listener: the box is read on submit only, 3 letters or more (counted in code points), a second submit during a request is ignored, an answer for an older or dismissed search is dropped by a sequence guard, an abort is not an error line. Results are at most five buttons, name cut at 32 characters, full name as a second line, every string through `Pinalert.setText`. A pick runs `setCenter(lat, lon, false)`, `setPlace`, `PinalertMap.moveTo(..., 13)`, one `fetchReports`, closes the results and returns focus (search button on a phone, box on a laptop). Escape closes the results, then the expanded phone row. Chips render from `Pinalert.state` on every notification and right after a tap; a second tap on the pressed chip goes back to All. The place line shows `Showing reports near {Place}.` and Back to my location, or `Your location isn't available. Showing the default area.` after a Back that found no fix. The filter line shows `Filtered by {Word}.` and Clear (name `Clear filter`). Nothing is stored and nothing is written to the address.
- **index.html.tmpl**: `div.map-tools` before `#map` in `.pane--map` holding `form.map-search[role=search]` (collapsed button, box with `maxlength=200`, Search submit, Close, `#map-search-status` role status, `#map-search-results`) and `div.map-chips[role=group][aria-label="Filter by category"]` with five `button[aria-pressed]`; hidden `p.map-label#map-label`; the deferred script tag after map.js and feed.js.
- **CSS**: laptop two rows (box capped at 320px plus a 44px Search button, chips at top 60px), phone one row (a 44px search button then sideways scrolling chips, the open box fills the row, results fixed under the row down to the bottom bar), sheet hide through the one existing rule extended with `.map-tools`, `.map-label`, `#map-search-results` and the theme toggle while the search is open, forced colours border on a pressed chip, popup `max-height` subtracting `--map-tools-height` from 900px (placed before the short screen rule so that one still wins).

## Deviations from Plan

1. **[Rule 1 - correctness] `.map-tools` has no `z-index`.** The plan's TestMapToolsCSS line says the layer has z index 1000. A z indexed layer is one stacking context, and the add button (z 1000, later in the page) would then paint over the results list that UI-SPEC puts at 1005 inside it, which defeats the stated purpose of 1005. The controls (`.map-search__field`, `.map-search__open`, `.map-chips`) carry 1000 and the results and status carry 1005. TestMapToolsCSS pins exactly that and fails if `.map-tools` gains a z index.
2. **[Test ordering] TestPlaceSearchScript is split.** In Task 1 map-tools.js did not exist, so the test checked the map.js side only; in Task 2 the script side was added as a helper the same test calls (`p31mSearchScript`). The plan's Task 1 acceptance command still names it and passes at that commit.
3. **[Allow list] No dimension literal allow list exists in this package** (as plan 05 also found), so `320px` and `1005` were not added anywhere; TestMapToolsCSS pins them where they are used.
4. **Both mask images of `.map-search__icon` and `.map-search__close-icon` are on one line each**, so `grep -c 'url("/static/icons/search.svg")' feed.css` prints 1 as the acceptance asks. Declaration semantics are unchanged.
5. **Phone expanded widths differ from the UI-SPEC table by 12px.** The table lists 236, 276 and 306 px while expanded; the stated insets (left 56, right 16) give 248, 288 and 318. The CSS follows the stated insets. The usable widths are browser check measurements, not declared values.
6. **The phone Search submit button is `display: none`** in the open row (UI-SPEC draws only the box and Close; the keyboard search key submits). It exists in the markup and is the form's single submit button.
7. **[Rule 1 - Bug] A press outside the search did not cancel the request in flight.** Found in the final review: the outside press closed the results but left `inFlight` and the sequence number, so a late answer reopened the list. It now calls `abortSearch()` first, like Escape and Close, and TestPlaceSearchScript pins all three dismissals. Fix commit: d42a275.
8. **Ellipsis written as an escape.** The write tool turned `…` into the literal character; it was rewritten to the escape (app.js style) by sed. No dash character is on any added line.

# Phase 3.1 Plan 14: The take back and the short Undo Summary

A mistaken Mark resolved can be taken back from the opened report (laptop popup, phone sheet, report opened from the Past tab) or from a short Undo in the message that follows Yes, mark resolved, at most twice, with the poster's Reopen counted in the same two and a faded report offering nothing.

## Deviations from Plan

1. **[Rule 3] `app.js` `serverNow` export landed in Task 1's commit**, not Task 2's: `isReportFaded` in votes.js needs the server clock and Task 1 had to be green on its own. app.js is in the plan's files_modified.
2. **The poster's Reopen mounts only `createReopenControl(reportId).button`**, not its wrapper and error line. Mounting the wrapper would nest a second `.vote-controls` grid in the first and confuse `findLiveControls`; the block's own listener and error line serve it. `onControlsClick` routes `'reopen'` to `onTakeBackClick`.
3. **A rotate-ccw icon rule in main.css for the phone sheet.** phone.css hides every vote button icon at rest, but UI-SPEC draws the take back icon at every width. phone.css is plan 13's file, so a head with three more classes than that rule lives in main.css instead (`.leaflet-container .leaflet-detail-pane .vote-controls .vote-btn--takeback .vote-btn__icon:not([hidden])`). Plan 13 can fold it into phone.css.
4. **Statement for a waiting mark with no undo left** reads C47 plus C52, not C46 plus C52, so the reader still learns it is waiting for agreement. A finished report with none left reads C46 plus C52 as written.
5. **The take back button is never marked too far** (the hint list is unchanged), as the UI-SPEC decision says.
6. **Extra tests** beyond the plan's list: `TestTakeBackNoDashesInNewWords`. Test name `TestToastAction` is the plan's artifact name.
7. **The Write tool turned a unicode escape for the two long dashes in a test string into literal characters** in Task 1's commit; Task 2's commit replaced it with rune values, so the final diff against the base has no long dash on an added line.

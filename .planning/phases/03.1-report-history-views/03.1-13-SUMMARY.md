## What was built

- **visibility.js**: `displayState` answers Resolved for a retracted visibility or `history.state === 'resolved'`, then Expired for the Activity flag or `history.state === 'expired'`, else the resolver's own state. No date is read (T-31-61). `visibilityState` and the four state allowlist are unchanged.
- **map.js**
  - `updateMapLabel(state)` writes `#map-label` through `Pinalert.setText` and hides it on Active; `render` calls it first on every notification.
  - `finishedPinClass(report)` adds `icon-badge--resolved` or `icon-badge--expired` to the pin badge from `displayState`; `popupStateClasses` now reads `displayState` too.
  - `closedLineText(report)` joins the server's `closed_text` or `lifetime_text` to `Pinalert.relativeTime(history.at)`; `updatePopupCard` shows it in the fade slot (class `popup-card__fade--closed`) and calls `Pinalert.formatFade` only when there is no closed line.
  - Approximate: the title is the fixed Rescue needed words, the shelter line slot holds Approximate location, `p.popup-card__privacy` holds the privacy line (built once, hidden by default). `zoomFor(id)` returns `MAX_APPROX_ZOOM` or 16; `flyTo` and `centerPinInStrip` use it. `pinName` ends with `approximate location`. No circle layer exists in the file (pinned).
  - `render` merges `focusPinReport(state)` into the marker set and ends with `openFocusOnce(state)`; `belongsToTab` maps the report's own `view` word to the tab (Past holds `resolved` and `past`).
  - `returnFocusToOpener` queries `.report-row, .past-card`; `markerForElement` also resolves a marker from a row or Past card ancestor by its report id as a key.
- **trust.css**: laptop ring rules (2px `--color-text-muted`, `--color-bg` fill, muted glyph, dashed for Expired) scoped to `#map`, forced colours `CanvasText`, the closed line colour, the privacy line paragraph, and a `.leaflet-popup.vis-expired` tint rule.
- **phone.css**: the same ring on the 20px dot with a 3px border, inside the one narrow block.

## Deviations from Plan

1. **[Rule 3 - blocking] Ring heads name icon-badge--resolved and icon-badge--expired, not the vis- classes.** The plan asked for `#map` scoped `vis-retracted` solid and `vis-expired` dashed. TestRetractedRowTreatmentMatchesHidden (votes_contract_test.go) wants exactly one trust.css rule that names the retracted class and declares a background, TestExpiredRowTreatmentMatchesRetracted (labels_contract_test.go) wants exactly one for expired and bans mixed state heads, and TestMapPopupTintTracksFeedRowAcrossStatesAndThemes reads the popup override by its exact two part head. Those files belong to plans 12 and 14, so the code was changed instead: map.js adds a ring modifier beside the vis- class and the ring heads name the modifiers. The look and the geometry are exactly as specified.
2. **[Rule 1 - bug prevented] displayState also maps `history.state === 'resolved'` to Resolved.** The plan asked only for expired. A finished report whose visibility is not retracted would otherwise draw as live; the word is the server's own.
3. **[Rule 1 - bug] A `.leaflet-popup.vis-expired` tint rule.** The shared `.vis-expired` rule sets the tint transparent, and the phone sheet background is `var(--severity-tint, var(--color-bg))`, so an expired report would have shown the map behind its text. The new rule is separate from the hidden and retracted one because a pinned test reads that rule by its exact head. `popupStateClasses` now reads `displayState` so the popup container, the pin and the header show the same word.
4. **[Rule 1 - bug] An approximate pin is set to zoom 14 exactly in `centerPinInStrip`, not capped by `Math.min`.** Found in the final review: on a phone the strip centring stops the fly from a list row before its zoom has left its start, so `Math.min(map.getZoom(), ...)` left the pin at the start zoom. Fix commit ebe4e84.
5. **`phone_layout_contract_test.go` edit landed in Task 2's commit**, although the file is in Task 1's list: the test pins `centerPinInStrip`, which Task 2 changes.
6. **`Pinalert.select(id, 'map')` before the link open.** Not in the plan's list; it lets the list highlight the row when the linked report is in it, as a pin tap does. feed.js ignores an id with no row.
7. **Title written when it changes.** The title is also written by `updatePopupCard` (a report that becomes approximate loses its description on the wire), guarded by a text comparison so a poll does not replace the text node under a selection. `buildPopupCard` still writes `report.description` first, as the pinned order requires.

## Limits worth knowing

- The linked report's data is the one from the first answer (`state.focus` is never refreshed by the store's poll). If it sits outside the list, its pin and popup are as old as the page until a reload; once it is in the list the list's fresher copy is used. The browser decides no state from a date, so it cannot drop a linked pin that faded since.
- `openFocusOnce` opens only after a marker exists under the current tab, so a link to a finished report opens once the Past tab has been selected (plan 12's feed.js owns that switch). If that switch does not happen, the link does not open.

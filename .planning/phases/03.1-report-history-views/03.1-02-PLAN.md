## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client to vote service | the account comes from the verified account gate; report id and vote value come from the route |
| vote log to visibility | every stored row feeds Resolve, so a new value must never be miscounted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-31-05 | Tampering | CastVote take back | high | mitigate | separate neutral value; TestTakeBackNeverEntersReopenCells proves it never reaches ReopenCells, so it cannot lift a report other people closed |
| T-31-06 | Tampering | withdraw spam | medium | mitigate | two per report per account counted from the append only log, only after a standing resolve (step 5c), refused before any write |
| T-31-07 | Elevation of privilege | poster reopen | high | mitigate | the reporter identity comes from ReportVoteContext against the gate's account (T-03-01); isReporterResolutionVote is unchanged and the take back has its own predicate |

| T-31-10 | Information disclosure | ResolutionUndoCounts | low | mitigate | keyed to the caller's account only; returns counts, no cell and no other account |
</threat_model>

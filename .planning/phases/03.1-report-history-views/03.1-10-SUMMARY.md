# Phase 3.1 Plan 10: History views on the wire and the frozen swagger Summary

One list endpoint now serves Active, Disputed and Past, the 24 hour counts for an empty Active tab and a report link, with strict parameters and one wire mapper; finished Rescue reports are proven blurred at the wire from two centres, and the swagger documents were regenerated once for the whole phase and guarded.

## What was built

- `internal/api/handlers/reports.go`
  - `parseFeedView`, `parseCategory` and `parseReportParam` are pure functions over `url.Values` returning a value and a `*paramProblem` (field and message). The handler writes the 400 before any service call, and `Cache-Control: no-store` is still set first.
  - `NearbyReports` calls `svc.Nearby` for active and disputed (with Category), `svc.History` for past (and sets `cut`), `svc.RecentHistoryCounts` only for an unfiltered, empty active view, and `svc.Focus` when `report` was sent. The echoed `view` is always present and `resolved` is echoed as `past`.
  - `FeedReportResponse` gains `view`, `history` (null or `HistoryResponse`), `approximate`, `your_resolution` (null or word) and `undos_left`. `reportViewToResponse` is the only function building one; it maps the new fields field by field and blanks and logs a description when `Approximate` is true.
  - The swagger block now documents the three views, the alias, the category filter, the focus object, the recent counts and the finished Rescue coarsening, and says a retracted report is listed only in the past view (D-25).
- `internal/api/handlers/reports_wire_test.go`: TestFeedViewParameterParsing, TestFeedReportResponseBuiltInOneMapper (go/ast source guard over reports.go and four other handler files), TestApproximateGuardBlanksDescription, TestFeedReportWireShapeKeys, TestNearbyRejectsBadFeedParametersBeforeTheService.
- `internal/api/handlers/history_e2e_test.go`: TestFeedViewStrictAndAlias, TestPastViewListsRetractedAndExpired, TestPastViewNeverLeaksIntoActive, TestCategoryFilterEndToEnd, TestRecentCountsOnlyWhenActiveEmpty, TestFocusOutsideRadiusAndWindow, TestFocusUnavailableAndTooOld.
- `internal/api/handlers/rescue_privacy_e2e_test.go`: TestFinishedRescueNeverLeaksOnPastOrLink (raw bytes and struct, two centres, two viewers, resolved and expired, past view and link, past view with a link) and TestLiveRescueAndFinishedFloodStayExact (flood, shelter_open, power_outage finished; rescue live).
- `docs/*`: one `make swag` after every annotation of the phase. The diff held only the new `/reports/{id}/unresolve` and `/geocode/place` paths, the new GET /reports parameters, the new definitions and properties, and the rewritten description lines of GET /reports and the vote routes (plan 08's text). Nothing else moved. A second `make swag` after the commit leaves `git status --porcelain docs` empty.
- `internal/api/handlers/swagger_test.go`: the unresolve path with 401, 403 and 409; GET /reports declares lat, lon, radius_km, view, show_disputed, category and report as query parameters; `/geocode/place` with q and 200, 400, 401, 429, 503; exact property key sets, types, enums and `$ref` links of HistoryResponse, RecentResponse, CutResponse, FocusResponse and ReportListResponse; `undos_left` on FeedReportResponse and CastVoteResponse; `handlers.ReportListResponse` added to the guard roots.

## Deviations from Plan

- Plan 06's note said this plan "splits" the History reports by View. `History` already returns the Resolved group then the Expired group in order and the wire contract is one `reports` array, so the handler maps them as is and each entry carries `view` (resolved or past). TestPastViewListsRetractedAndExpired proves the order.
- The plan's verify lines use `env -u DATABASE_URL` and `env -i`; the owner rules forbid those wrappers, so fast checks ran with `DATABASE_URL=` set empty inline and the database gate with the variable set inline.
- The plan says the leak test computes the haversine from each centre; the service's `haversineKm` is unexported, so the test carries its own small haversine with the same 6371 km radius.
- The plan says tests are run red first. The tests were written before the code, but the red run was not observed separately (the parsing helpers did not exist, so the first state was a compile failure). Per the one commit per task rule the test and the code of Task 1 are in one commit.
- Plan rule 3 says "stay on main"; the executor stayed on its worktree branch as the spawn rules require.
- `swag` on this machine is v1.16.4. Its output only changed the planned places, so no stop and report was needed.

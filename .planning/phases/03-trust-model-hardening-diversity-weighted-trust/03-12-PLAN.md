## Phase Goal

**As a** person reading the feed during an emergency, **I want to** see how many different nearby people confirmed or disputed each report, and whether it is still current and its reporter reliable, **so that** a few accounts cannot make a weak report look well corroborated.

<objective>
Load the reporter history on every read path, once per request, so the feed, the vote response and the Activity page carry the real reporter signal (TRUST-07, second half; slice S4 "source reliable" in the outline's MVP framing). After this plan:
- `Nearby`, `CastVote` and `ActivityForAccount` each read the reporters' bounded history with one `ReporterHistoryReports` call keyed by verified account (D-10), with the 90 day window and the 30 report cap passed from Go constants and the injected clock (D-13, R-05), and fold the history report ids into their one existing `CurrentVotesForReports` call.
- Each path composes the signals with one `ReporterSignals` call (03-10) and sets `TrustInput.Reporter`, so the three paths return the same trust object for the same data (D-21). Accountless reports carry none.
- A feed read rates at most 200 reporter accounts, nearest reports first, and reports past that cap carry none (Q7, T-03-05).
- The rating never changes what is listed, in what order, or how anything else on the trust object reads (D-14).

Increments, task by task (each ends at something a real test observes):
- After Task 1: a service caller of any of the three read paths gets the real reporter signal on every trust object, keyed by account, built from one history read and one vote read, and deeply equal across the paths for the same data.
- After Task 2: a test proves a feed read with 201 reporters asks for exactly 200 and gives the farthest new account none while still listing its report, proves that swapping a reporter between New reporter, Reliable reporter, Mixed record and Unreliable reporter changes nothing else, and the whole suite is green on a fresh `p3_0312`.

Purpose: 03-10 composed the signal but no read path loads history yet, so every trust object carries none. This plan is the wiring that makes the signal real; 03-14 then puts `Trust.Reporter` on the wire.

Output: edited `report.go`, `trust.go` and `auth.go` in `internal/service`; three fakes and five pinned tests plus two added tests in `feed_test.go`, `trust_test.go` and `auth_test.go`; the expected values of two 03-05 tests in `trustview_test.go` and `trust_paths_test.go`.
</objective>

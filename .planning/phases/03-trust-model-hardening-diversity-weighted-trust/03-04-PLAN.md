## Phase Goal

**As a** person reading the feed during an emergency, **I want to** see how many different nearby people confirmed or disputed each report, and whether it is still current and its reporter reliable, **so that** a few accounts cannot make a weak report look well corroborated.

<objective>
Make the 1 km rule visible to a real person, and keep it from wrongly refusing someone who walked to the incident. After this plan, a vote cast from more than 1 km from the report gets HTTP 403 with error field `location` and the fixed sentence "Too far to vote. You need to be within 1 km of this report." (D-01). The browser keeps a timestamped location fix and refreshes it silently when location permission is already granted. On a too far refusal it retries once with a fresh fix before showing that sentence, and it never prompts per vote (D-02).

Purpose: this closes slice S1 "nearby is real" from the outline's MVP framing, and it is the phase's first user visible increment. Plan 03-01 made `CastVote` return `ErrVoterTooFar`, which today falls through to the handler's generic 500 branch. This plan maps it to 403 and adds the client half.

Increments, task by task (vertical, each ends at something a real user or a real test observes):
- After Task 1: a real HTTP client voting from 2 km away gets the 403 `location` sentence on all four routes with nothing written, while the reporter's own resolve from Chennai still succeeds. The API docs say so.
- After Task 2: a real browser whose cached fix is stale is re-located silently and its vote goes through. A truly far voter sees the server's too far sentence after one silent retry, and no location prompt ever appears for a vote after the first one in a session.

Output: edited `votes.go`, `votes_e2e_test.go`, `votes.js` and `votes_contract_test.go`; regenerated `docs/docs.go`, `docs/swagger.json` and `docs/swagger.yaml`.
</objective>

# Phase 03: Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

**Scope of this result.** `threats_open: 0` is a statement about the threat register that the 21 built plans authored (03-01 to 03-20 and gap plan 03-25): 15 unique ids, T-03-01 to T-03-12 from the outline and T-03-25-01 to T-03-25-03 from plan 03-25. It is not a claim that the vote mechanic resists a spoofed location (accepted, AR-03-01), and it does not cover the items under "Outside The Register", which were found while verifying and are neither counted nor accepted. The folder `held-redesign-drafts/` (draft plans 03-21 to 03-24, not built) is not part of this audit.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| browser to vote API | Untrusted input reaches the four vote routes. The voter's latitude and longitude arrive in the body and are unverifiable client claims. The account id comes from the verified account gate's request context, never from the body. | Latitude and longitude (4 KiB body cap, unknown keys rejected) |
| database to VotingService | `ReportVoteContext` returns the report's coordinates, expiry and reporter account id. They are the only inputs to the reporter exemption and the 1 km check. | Report coordinates, expiry, reporter account id (service internal) |
| vote log to reliability decision | Tallies come from the server's own vote rows, with cells computed server side. The reporter controls only their own resolve and reopen votes, which `ClassifyOutcome` clears before it classifies. | Distinct cell counts, outcome |
| service to handler to wire | `service.Trust` holds integers and server authored strings. The handler copies it field by field. The object is the same for every viewer and carries no identifier. | Counts, scores, enum words, sentences |
| published OpenAPI spec to the public | `/swagger/*` is reachable without verification (the Phase 1.1 accepted risk AR-32), so the documented response shapes are public surface. | Property names of the trust definitions |
| client to `GET /api/reports` | A client chosen point and a radius reach a read that is polled every 30 seconds. The number of reporter accounts on a page, and with it the history and vote read size, follows from that input. | Point, radius |
| database to service (history) | History rows carry account id, report id, severity, category and expiry only. No session id, voter cell, email, description or coordinates return through this read. | Account id and report metadata (service internal) |
| server JSON and HTML attributes to browser DOM | The trust object, severity, category, shelter fields and the stranger supplied description cross into feed rows, Leaflet popups, pin attributes and the Activity page's `data-trust` attribute. | Server authored strings, report authored text |
| static assets to browser | The SVG files under `web/static/icons/` are used only as CSS mask images and are also reachable by direct URL. | Static SVG |
| browser hint to server decision | The too far hint, the cached fix and the focus steps change only what the browser shows. Whether a vote counts is decided by the server alone. | Cached fix in `sessionStorage` (client controlled), `aria-disabled` |
| public docs to reader | `docs/TRUST-MODEL.md` and `README.md` state the trust rules publicly and must not overstate what the model resists. | Documentation |
| public rating to the person rated | The reporter rating is shown to everyone by decision D-10 and links one person's reports. | Tag, score, two counts |

## Phase Goal

**As a** person reading the feed during an emergency, **I want to** see how many different nearby people confirmed or disputed each report, and whether it is still current and its reporter reliable, **so that** a few accounts cannot make a weak report look well corroborated.

<objective>
Build the one server side trust object that every surface will show (D-21). After this plan, a single pure function `BuildTrust` turns a report's batched vote rows into `Trust`. It carries:
- the distinct confirming place count N (D-04) and the distinct disputing place count M (R-04);
- the capped numerals for the two counters, always present, zeros included (D-16, A27);
- the panel sentences: the lead line (the Unconfirmed sentence of D-17 per A6, or the expiry line), the confirmed sentence (A7) and the disputed sentence (A56). Every sentence is authored on the server (D-19, delivered through the one panel per A5).

N and M come from the same row filter `BuildVoteTally` uses, so the resolver's gate and the number a reader sees cannot drift. `Nearby`, `CastVote` and `ActivityForAccount` each attach the object with one `BuildTrust` call, and each reads an injectable clock so later end to end tests can pin time.

Purpose: this is the first step of slice S2 "counters" in the outline's MVP framing. Plan 03-07 puts `Trust` on the wire for the feed and the vote response, 03-13 renders the block, and 03-15 shows it on the Activity page. Plans 03-08 and 03-10 extend `BuildTrust`'s body and the `Trust` struct with the still current and reporter signals, so the struct and its input stay exactly as the outline pins them.

Increments, task by task (each ends at something a real test observes):
- After Task 1: a test can hand any set of vote rows to `BuildTrust` and get N, M, the `99+` capped numerals and the exact panel sentences. A seeded property test proves N and M always equal the resolver's own counts.
- After Task 2: a service caller casting a vote gets the trust object back in `CastVoteResult`, built from the post vote rows, and an injected clock decides expiry.
- After Task 3: a service caller of any of the three read paths gets N, M and the panel sentences, and one test proves the three paths return deeply equal trust objects for the same data, for every viewer, under each path's own injected clock.

Output: new `trustview.go`, `trustcopy.go`, `trustview_test.go`, `trustcopy_test.go` and `trust_paths_test.go` in `internal/service`; edited `trust.go`, `feed.go`, `report.go` and `auth.go`.
</objective>

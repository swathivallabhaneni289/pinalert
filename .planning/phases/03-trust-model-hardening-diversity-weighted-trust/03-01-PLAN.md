## Phase Goal

**As a** person reading the feed during an emergency, **I want to** see how many different nearby people confirmed or disputed each report, and whether it is still current and its reporter reliable, **so that** a few accounts cannot make a weak report look well corroborated.

<objective>
Make the word "nearby" true on the server. After this plan, `VotingService.CastVote` refuses a vote cast from more than 1 km from the report before anything is written, for all four vote values (D-01). The reporter's own resolve and reopen stay exempt, NaN and Inf fail closed, and the report's coordinates and creation time come from the same `ReportVoteContext` query that already loads the reporter. The `voterGeohashPrecision` comment records precision 7 as the deliberate D-03 choice. The existing HTTP e2e voters move inside the radius so the suite stays green.

Purpose: this is slice S1 "nearby is real" in the outline's MVP framing, and the first step of TRUST-05's "distinct nearby places" rule. Plan 03-04 maps the sentinel to HTTP 403 and adds the client retry. Plan 03-02 documents the rule and the grandfathering of older votes.

Increments, task by task (vertical, each ends at something a real test observes):
- After Task 1: a real Postgres test reads a report's latitude, longitude and created_at through the vote context query, and every HTTP e2e voter stands within 1 km of the report it votes on.
- After Task 2: a service test casts each of the four vote values from 1.0008 km and gets `ErrVoterTooFar` with zero inserts, while the reporter's own resolve from 290 km away still succeeds. The HTTP e2e suite stays green with the rule live.
- After Task 3: the geometry is proven at five Indian latitudes, NaN and Inf fail closed, the refusal sentence is pinned, and the whole suite passes on a fresh disposable database.

Output: new `internal/service/geo.go` and `geo_test.go`; edited `trust.go`, `trust_test.go`, `votes.sql`, regenerated `votes.sql.go`, `votes_test.go` and two e2e test files.
</objective>

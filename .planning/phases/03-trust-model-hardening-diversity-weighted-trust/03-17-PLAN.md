## Phase Goal

**As a** person reading the feed during an emergency, **I want to** see how many different nearby people confirmed or disputed each report, and whether it is still current and its reporter reliable, **so that** a few accounts cannot make a weak report look well corroborated.

<objective>
Opening a pin shows one neutral popup card, built once and updated in place on every poll, with the close button first, the severity and state labels above the title, a category and time meta line with the shelter line, the trust block with scores and the vote controls. This delivers D-09 and D-20 on the popup surface, with A2, A9, A10, A11, A19, A20, A21, A24 (popup meta), A25, A30, A31, A32, A39 (x.svg), A54, A62, A65 (CSS) and RR-4, RR-5, RR-6, RR-7 (popup rules).

Purpose: this is the first step of the outline's "Popup card" slice. Until now the popup is rebuilt every 30 seconds, so an open trust panel or Mark resolved confirmation collapses on each poll (03-13 SUMMARY note). After this plan a reader opens a pin and gets the d4 card that keeps its state across polls. Plan 03-19 then adds keyboard, focus and autopan behaviour on top of the named hooks this plan creates.

Increments, task by task:
- After Task 1: a pin opens a card in the A21 order whose trust panel, confirmation and focus survive every poll (TestPopupCardBuiltOnceUpdatedInPlace).
- After Task 2: the card is the neutral 340px d4 card with the severity bar, the 20px header glyph and a max height that scrolls inside itself (TestPopupHeaderGlyphIs20px, TestPopupCardSurfaceAndGeometry).
- After Task 3: the close button is first in the popup DOM and is a 44px X button with visible hover, focus and press states (TestPopupCloseButtonComesFirst).

Output: new `web/popup_contract_test.go` and `web/static/icons/x.svg`; edits to `map.js`, `votes.js`, `trust.css`, `main.css`, `js_contract_test.go`, `votes_contract_test.go`, `css_contract_test.go`.
</objective>

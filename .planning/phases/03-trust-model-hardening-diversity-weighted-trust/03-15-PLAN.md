## Phase Goal

**As a** person reading the feed during an emergency, **I want to** see how many different nearby people confirmed or disputed each report, and whether it is still current and its reporter reliable, **so that** a few accounts cannot make a weak report look well corroborated.

<objective>
Show the one trust block on each report a reporter posted, on the Activity page, so a reporter sees their own reports exactly as readers see them (D-20). After this plan the server writes the same trust object the feed and vote response carry into each Activity row (through the one mapper `trustToResponse`), plus a server authored `data-expired` flag and a visible severity word. `activity.js` mounts the shared block from that JSON and refreshes it from the vote response after Reopen (R-08, A29, A64). `visibility.js` gains the one display rule that turns an expired, unresolved report into an Expired label and row class without the browser comparing dates (A44, A57). Every row names its severity in words before the title (A26, A58).

Purpose: this is the last step of slice S2 "counters" in the outline's MVP framing (03-05, 03-07, 03-13, 03-15). Plan 03-07 put the counters on the wire and 03-13 rendered them on the feed row and popup; this plan brings them to the third surface. Because the Activity JSON comes from the same mapper, it gains the still current and reporter signals the moment plan 03-14 lands, with no change here.

Increments, task by task (each ends at something a real end to end test observes):
- After Task 1: an end to end test reads each Activity row's `data-trust` and finds it deep equal to the vote response trust, before and after a Reopen; expired rows carry `data-expired="true"` and the right row class; every row starts with its severity word.
- After Task 2: the reporter sees the two counters and the panel on each own report, and the block refreshes from the Reopen response with focus on the toggle when Reopen goes away.
- After Task 3: an expired, unresolved report reads Expired (never Unconfirmed or Disputed), and the label and row class survive page load because `displayState` decides them once.

Output: edited `internal/api/handlers/auth.go`, `web/templates/profile.html.tmpl`, `web/static/js/activity.js`, `web/static/js/visibility.js`, `internal/api/handlers/activity_e2e_test.go`; new `web/activity_trust_contract_test.go`.
</objective>

# Phase 3: UI Design Contract

> Visual and interaction contract for Phase 3 (the trust block, the map popup card, the too far state and the Activity page block). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Source of Truth and Scope

**Token source of truth:** `web/static/css/main.css` (every colour, spacing, type size and weight token already exists) and `.planning/phases/01-foundation-report-map/01-UI-SPEC.md`. This contract redeclares none of them. The only new token is `--shadow-popup` (declared in `main.css` `:root`, never in `trust.css`).

**Format baseline:** `.planning/phases/02-trust-mechanic-core-confirm-dispute-visibility/02-UI-SPEC.md`. It stays in force wherever this document does not amend it. Every amendment is listed in the table named "Amendments to locked decisions".

**Inputs used:** `03-CONTEXT.md` (D-01 to D-23, R-01 to R-08), `03-VALIDATION.md` (V-01 to V-42), `03-DESIGN-BRIEF.md`, the d4 sketch in `.claude/skills/sketch-findings-pinalert/` (popup structure, trust block, `variants/d4.css`, `REVIEWS.md`), and the existing CSS, JS, templates and contract tests under `web/`.

**What this phase designs:**

1. One shared trust block (two counters, two signals, one panel) that is identical on the feed row, the map popup and the Activity page.
2. The map popup card (neutral card, severity bar, label, title, meta, trust block, vote controls).
3. One vote button style on all three surfaces, plus the too far state.
4. The Activity page block and Reopen.

**Not designed here (out of scope):** comments and the report page (Phase 8, the popup layout must not depend on them), triage ordering (Phase 6), vote rate limiting (Phase 4), demo mode (Phase 5), any distance figure in the meta line (see Open items). Deferred ideas in `03-CONTEXT.md` are ignored.

**Sample data rule:** every number, name and sentence quoted in an example in this document is sample data. Real values always come from the server's trust object (D-21) and the page config. The browser holds no threshold and no trust formula.

**Stack:** Go `html/template`, vanilla JS, hand written CSS, Leaflet 1.9.4 with MapLibre basemap. No framework, no build step, no new library. Tool: none.

## Owner decisions (2026-10-03)

Status: **locked**. The project owner answered four questions on 2026-10-03 and a fifth on 2026-10-04 (Q5, a sub-block below). These answers beat every other source (`03-CONTEXT.md`, `03-VALIDATION.md`, the d4 sketch, `02-UI-SPEC.md`) wherever they differ. Each question and answer is recorded verbatim.

**Q1.** "How should the trust block explain itself on the feed row, the map popup and the Activity page?"
**Answer:** "One panel button everywhere (Recommended)".
Meaning: as in d4, the block is one button that opens a short panel of sentences, on all three surfaces. It replaces the per word hover reasons (amends D-19 and V-39), keeps the block identical everywhere (D-20), and cuts a row from three focus stops to one.

**Q2.** "Your reference image has a fully rounded severity label, which your no-pill rule and test V-40 forbid. Which shape do you want for read only labels?"
**Answer:** "Rounded labels, square buttons (Recommended)".
Meaning: fully rounded Critical, Medium, Low and Unconfirmed labels as in the reference, and the same shape for the other read only state labels (Disputed, Resolved) so labels stay consistent. Buttons keep modest corners. V-40 (`TestNoPillShapedControls` and the 999px ban) is narrowed to controls. This is the owner's explicit exception for read only labels. No button, input or toggle may be fully rounded.

Scope note on Q2: no text labelled or rectangular control (the vote buttons, `.btn`, `.view-toggle`, inputs, switches) may use a radius of half its height or more. The circular icon only controls (`.fab`, `.theme-toggle`, the account trigger, `.profile-back-link`, `.icon-badge`) are 50 percent circles that other contract tests pin: that is the pre existing exemption, and the severity slider track and thumb (`.severity-slider::-webkit-slider-thumb` and `.severity-slider::-moz-range-thumb`, 44px circles at 50 percent) keep their existing exemption. All of those are unchanged by this phase. The test mechanic is stated once, in A38.

**Q3.** "What should the signal row (for example Up to date and Reliable reporter) look like?"
**Answer:** "Icons, normal text colour (Recommended)".
Meaning: keep the small clock and user icons beside the two signals, and set the signal words in the normal text colour on every surface (grey fails 4.5:1 contrast on tinted feed rows). Amends D-18's no icons rule, keeps D-20 identical everywhere. Numbers (popup only, D-09) stay semibold, words regular.

**Q4.** "Popup surface and vote buttons: follow d4, or keep what Phase 2 and the severity tint quick task shipped?"
**Answer:** "d4 everywhere (Recommended)".
Meaning: neutral popup card, outlined icon vote buttons with 16px labels, pressed Confirm or Dispute as an inverted fill (not a hue), Mark resolved outlined with the inline confirmation. Applied to the popup, the feed row and the Activity page Reopen button, so only one vote button style exists. Amends the Phase 2 UI-SPEC and quick task 260923-mb0 (the severity tinted popup).

### Q5 (asked 2026-10-04)

Status: **locked**.

**Q5.** "The contract says state is never shown by colour alone, but on the feed row and the map pin severity is only colour (bar, tint, badge fill), plus a hidden word for screen readers. How should we handle that?"
**Answer:** "Row word, pin exception (Recommended)".
Meaning: show the same rounded severity word (Critical, Medium, Low) visibly on every feed row and Activity row, as the popup does. Map pins stay colour only, recorded as a dated accessibility exception, because the popup names the severity when opened. The visible row label has the popup label's shape and treatments, sits in `.report-row__body` ahead of the title, and fits inside the 236px row body at 320px width and the 188px Activity row body. D-20 covers only the trust block, so adding a label to the row conflicts with no locked item.

Factual note (2026-10-04): the shipped rows carry no hidden severity word. Today severity on a row is colour only (bar, tint, badge fill), so screen reader users currently get no severity on rows. The visible label fixes that for everyone. It is real text inside `.report-row__body`, read before the title, so no extra visually hidden severity text is added and there is nothing to delete.

### Q6 (owner choice 2026-10-09, sketch 003 variant H, A75)

Status: **locked**.

**Q6.** No question was put in words. After the owner's remarks of 2026-10-08, sketch 003 drew variants E, F, G and H and the owner picked one.
**Owner's words (2026-10-08, as recorded in sketch 003):** (1) "All of these are underlined, including confirmed, disputed and new reporter. I don't understand why we are underlining it. I don't like that part." (2) "The new reporter thing should be on the top part of the box where Unconfirmed is located, because it doesn't look really nice under the confirmed and disputed one." (3) "Redesign it better, but don't use that tag things, underline things, it looks really odd."
**Answer (2026-10-09):** variant H, "Beside the label".
Meaning: nothing in the block is underlined and hover is a fill (A77); the reporter words sit as plain regular text on the state line beside the state label (A75); the user icon is removed (A76); a 20px chevron at the end of the toggle says it opens (A78); the heading gets more air above the title, 16px in the popup and 8px on rows (A81). Shorter wording is a separate decision (A84). This answer supersedes Q3's clause "keep the small clock and user icons beside the two signals" for the user icon and for where the reporter words sit, while Q3's clock icon and normal text colour stand.

## Trust Block (shared by all three surfaces)

One block, one builder, identical on the feed row, the map popup and the Activity page (D-20). It is a single button that looks like plain text and opens a short panel of sentences underneath it (owner Q1). It lives in a new `web/static/js/trust.js` (create once, update per poll, the same pattern as `visibility.js`) and is styled in `trust.css`. Consumers call only `PinalertTrust.*` and never type a `trust-*` class. Function names below are suggestions for the planner. (Amended by A75: D-20 still holds; the instance also holds the reporter words, `updateTrustBlock` refreshes them, and each consumer places them through `PinalertTrust.createStateLine`.)

### What the block shows

Row 1, the counters (always both, zeros included): `{N} confirmed` and `{M} disputed`. The number is 16px semibold, the word 16px regular, both `--color-text`. N is the distinct confirming place count (D-04), M the distinct disputing place count (R-04). Raw vote totals never appear. A count above 99 shows as `99+` on the surface (the panel sentence carries the real number). The two counters sit on one line with a 24px gap and a 1px separator in the middle of the gap. If the pair cannot fit (for example `99+ confirmed` and `99+ disputed` in the 236px row, where the toggle's inner width is about 228px), the second counter wraps under the first and its separator is clipped away (amendment A22). (Amended by A79: the chevron takes 24px beside the face, so a pair of counts near the limit wraps sooner.)

Row 2, the signals: a 16px clock icon and the still current word, then a 16px user icon and the reporter tag, 14px, words regular, all `--color-text`. The popup adds a 14px semibold number directly after each word when that signal's score is not null (D-09, R-07): `Up to date 82`, `Reliable reporter 78` (sample data). Each number carries a visually hidden prefix, so the accessible name reads "Up to date, score 82" and "Reliable reporter, score 78" (decided: a prefix, the names are not left bare; the prefix is the fixed literal `, score` in `trust.js`, inside the V-32 closed character set). The panel explains what the number means (a score sentence per signal, see The panel). The feed row and the Activity page never show numbers. No "/100", no bar, no extra icon. A signal with a null score shows no number, no prefix and no score sentence. When the two signals do not fit on one line the reporter signal drops under the first and its separator is clipped. (Amended by A75, A76, A82: the reporter words moved to the state line, with no user icon; the popup number follows them in regular weight.)

### Which signals show

| Condition | Still current signal | Reporter signal |
|-----------|----------------------|-----------------|
| Live row with 2 or more confirming places | Up to date, Getting old or Needs re-confirming (server band) | tag |
| Critical or rescue needed row with fewer than 2 confirming places (no Unconfirmed label) | Too early to tell | tag |
| Provisional row (Unconfirmed label showing) | none | tag |
| Hidden row (Show disputed view, Disputed label showing, R-03) | none | tag |
| Retracted (Resolved) or expired (Expired) report (Activity page only, R-08) | none | tag |
| Accountless, official or over the cap report (the research `none` value, D-10 "no rating") | as above | none (no icon, no text) |
| Neither signal applies | the whole signals row is not rendered, only the counters | (Amended by A75, A83: the reporter words are hidden for `none`, and a state line with no visible child takes no space.) |

The `none` row is a deliberate departure from "the tag on every report" (amendment A47): a report with no accountable reporter has nothing to rate, so no tag, no icon and no text is drawn for it.

The server decides which words show. The browser renders the server's label strings and holds no rule, no threshold and no formula. Words: Up to date, Getting old, Needs re-confirming, Too early to tell. Tags: Reliable reporter, Mixed record, Unreliable reporter, New reporter. New reporter must never look like a good tag: it is the same plain text as the others, with no check, star or colour.

If the `trust` object is missing or fails validation, the block is not rendered at all (the block element carries `hidden`). The browser never invents `0 confirmed` for data it did not receive. The rest of the surface (label, vote controls) still renders.

### The panel

Opened and closed by the toggle (click, tap, Enter, Space). Plain text directly under the toggle, in normal flow, expanding the row or the card height. Not a floating tooltip, no shadow, no animation. Up to five sentences on the feed row and the Activity page and up to seven in the popup, one per line, 14px regular `--color-text`, line gap 4px, in this order:

1. The Unconfirmed sentence, only while the Unconfirmed label is showing (RR-2, D-17). On the Activity page an expired report gets its expiry line here instead (Surface: Activity Page).
2. The confirmed sentence.
3. The disputed sentence.
4. The still current sentence, only while a still current word is showing.
5. Popup only: the still current score sentence "Score {SCORE} out of 100, based on how recently different places confirmed this.", omitted when that score is null.
6. The reporter sentence, only while a reporter tag is showing.
7. Popup only: the reporter score sentence "Score {SCORE} out of 100, based on how often their reports with a clear result were confirmed.", omitted when that score is null.

The score sentences are authored by the server and the browser never computes or holds them. The words "out of 100" live in the sentence only, so R-07's ban on "/100" beside the number holds. **Traceability:** the panel sentence is the replacement for D-09's "no extra sentence" and for R-07's hover reason that explained the popup numbers, so no reader sees a contradiction (amendment A50).

Sentence templates, placeholders and every variant are in the Copywriting Contract. Each sentence carries the real numbers from the server's trust object and is plain text set through `Pinalert.setText`. If the viewer votes while the panel is open, or the 30 second poll arrives, the sentences update in place: the panel stays open, no node that holds focus is replaced.

### Behaviour

* **One focus stop.** The toggle is the only focusable element in the block. Panel text is not focusable. `aria-expanded` is `false` or `true`. There is no `aria-live` anywhere in the block, because the 30 second poll would re-announce it.
* **No row activation.** The block's root stops propagation of click, and of keydown for Enter and Space, so a tap or key press never calls `activateRow` or reaches Leaflet's popup handlers. This is the same technique `createVoteBlock` uses.
* **Escape.** The app owns popup Escape. Leaflet 1.9.4's own Escape handler is a document keydown listener installed only while the map container itself has focus, and this contract moves focus onto `.popup-card`, so Leaflet's Escape never fires. One document level keydown listener in `trust.js` is installed once, registered in the capture phase as d4 does. Each press resolves one level, in this order, and the listener calls `stopPropagation` and `preventDefault` only when it acted: (a) if the report modal or the account menu is open, do nothing (the A23 guards); (b) if a Mark resolved confirmation is open in the focused popup or row and focus is inside it or its block, take the Cancel path: close it, send nothing, focus that block's Mark resolved button; (c) else find the surface that owns `document.activeElement` (amendment A70): the `.leaflet-popup` container (including `.popup-card`, the close button, the vote buttons and the trust toggle) or the nearest visible `.report-row` (a row is an owner only when its list pane is displayed). Focus on the marker that owns the open popup, or on the page body, counts as owning the open popup's panel (so a panel open in the popup closes before the popup does, which also covers Safari and Firefox on macOS leaving focus on the card or the body after a button click). If that surface's own trust panel is open, close it and focus its toggle; (d) fires only when the owning popup's panel is closed: if a popup is open and focus is inside the popup container, on `.popup-card`, or on the marker that owns the open popup, close the popup the way the close button does (click the popup's close anchor, or `map.closePopup()`; focus then returns to the opener through the `popupclose` focus return specified in Surface: Map Popup, new in this phase). With focus on the page body, no panel open and nothing else open, do nothing. It acts only on the panel of the surface that owns focus, never closes a row panel from inside an open popup, and never tries to focus a toggle inside a hidden list pane (amendment A23).
* **Open state.** Kept on the block instance and never reset by an update. The same report's row block and popup block are independent. When a popup closes, its panel collapses.
* **Sink.** Every string reaches the DOM through `Pinalert.setText`, never a markup parsing sink. No report description ever enters a trust string.
* **Fade.** `PinalertTrust.fadeStage(report)` returns the worse of the server's fade stage and the time based stage, and both `feed.js` and `map.js` use it everywhere they used `Pinalert.ageStage(` (V-37, including the 60 second `refreshAgeAndTime` timer). The block's text is never dimmed by a fade stage: fades desaturate the severity colour tokens only.

### Build once, update in place

`map.js` builds the whole card once when the marker is created, in one builder `buildPopupCard(report)` (it replaces `buildPopupContent(report)`), and binds that element with `bindPopup(card.el, options)` (options below). The builder holds the label builder call `PinalertVisibility.createVisibilityTag(`, the title fill and the vote block builder call `PinalertVotes.createVoteBlock(` in DOM order (amendment A21); none of them appears in the update function, and `buildPopupCard` declares no nested `function` before them. On every 30 second poll it calls an update function that writes text, classes and attributes on the existing nodes. It never calls `setPopupContent(`, never calls `unbindPopup(`, never rebuilds a node, and calls `setLatLng` only when the coordinates changed. Guarantees the build must test or UAT:

1. A refresh never closes an open popup.
2. A refresh never closes an open Mark resolved confirmation, and the update functions never write `hidden` on the three primary buttons or on the confirmation.
3. A refresh never moves focus.
4. A refresh never collapses an open panel.
5. A refresh never re-enables a busy button (`setBlockBusy` stays the sole owner of `disabled`).

`className: popupStateClasses(report)` stays inline in `bindPopup(`, and `syncPopupState` keeps swapping the `sev-`, `age-` and `vis-` classes on the live popup element (the card reads `--severity-current` and `--severity-tint` by inheritance). The call is written with the options object literal inline, because `TestMapPopupCarriesReportStateClasses` reads the `className` option inside the `bindPopup(` call:

```js
marker.bindPopup(card.el, { className: popupStateClasses(report), minWidth: 340, maxWidth: 340, autoPan: !reducedMotion, autoPanPaddingTopLeft: [16, top], autoPanPaddingBottomRight: [16, bottom], keepInView: true });
```

`reducedMotion` is the `prefers-reduced-motion: reduce` match (A60). `top` and `bottom` are the values in Component Geometry, Popup autopan padding (76 and 84 below 900px, 16 and 16 at 900px and above, A60). They are first guesses at `bindPopup`, recomputed on `popupopen` and in the A59 `resize` handler and written to `popup.options.autoPanPaddingTopLeft` and `autoPanPaddingBottomRight` (A68). They replace the symmetric `autoPanPadding: [16, 16]` named in the REVIEWS build checklist (`map.js` does not set that option today, so Leaflet's default `[5, 5]` applies) because the fixed account trigger (44px circle at top 16px, right 16px, z-index 1050) sits above the popup pane and would cover the close button, and the fixed FAB, theme toggle and view toggle (z-index 1000) would cover the card bottom. Do not use the `maxHeight` option (Leaflet applies it only inside `_updateLayout`, which runs on open and on `update()`). Scrolling is done in CSS, see Component Geometry. The pin icon gets `popupAnchor: [0, -22]`. Do not set `closeOnClick: false`. The card root is observed with a `ResizeObserver` because the Mark resolved confirmation and an open panel both change the height. On resize it calls `popup.setLatLng(popup.getLatLng())` (throttled to one animation frame), which in Leaflet 1.9.4 only repositions the popup and, when `autoPan` is true, re-runs autopan through `keepInView`. With `autoPan: false` (reduced motion) `_adjustPan` returns at once, so `setLatLng` only repositions and `keepInView` is a no op; the pan is then the explicit `panPopupIntoView(popup)` of A68. The ResizeObserver must NEVER call `popup.update()`: in 1.9.4 that removes and re-appends the content node, which drops keyboard focus and would undo the guarantees above (verified in `leaflet-src.js`, `DivOverlay.update` calls `_updateContent`).

**Re-measure rule (A59).** Building once with no `setPopupContent` leaves a popup that was opened while the map pane is `display: none` mispositioned and mis autopanned, because Leaflet measures the container width only in `update()` and `onAdd` (at zero width the left offset becomes 0, and the ResizeObserver's `setLatLng` reuses the stale width). `popup.update()` is therefore allowed at exactly two points and never while focus is inside the card: (1) `map.js` registers `map.on('resize', handler)`; Leaflet's `invalidateSize` fires `resize` and the existing window resize dispatch reaches it, which also covers a breakpoint change such as rotating a phone with no `switchView` call. In the handler, if a popup is open, call `popup.update()` once, only when `!container.contains(document.activeElement)` (the same node keeps its panel and confirmation state). (2) `focusOpenPopup()` calls it before it focuses `.popup-card` when the popup was opened while the pane was hidden (a flag set in the `popupopen` handler when `card.offsetParent === null`).

**Reduced motion (A60, A68).** Popup autopan calls `panBy`, which animates. Under `prefers-reduced-motion: reduce` the `autoPan: !reducedMotion` key above is `false` and Leaflet's `_adjustPan` returns at once, so `map.js` runs one helper, `panPopupIntoView(popup)`. It takes the popup container rect relative to the map container (`getBoundingClientRect`), compares it with the padded view rectangle (from `[padLeft, padTop]` to `[mapWidth - padRight, mapHeight - padBottom]`, the same four padding values), derives `[dx, dy]` per axis (dx is `left - padLeft` if that is negative, else `right - (W - padRight)` if positive, else 0, and the same for dy), and calls `map.panBy([dx, dy], { animate: false })` only when the offset is non zero. It skips while the user is dragging the map and cannot loop (a card inside the rectangle yields a zero offset). Under reduced motion it runs at three points only: after `popupopen`, after every `ResizeObserver` height change (in the same animation frame callback that calls `setLatLng`), and on `moveend` while the popup is open (the stand in for `keepInView`).

### Keyboard and screen reader

* The dialog role and name sit on the Leaflet popup container, `popup.getElement()` (the `.leaflet-popup` element, which also holds the close button): `role="dialog"`, `aria-modal="false"`, `aria-labelledby` pointing at the title id (a module counter id). The inner `.popup-card` carries `tabindex="-1"` as the focus target.
* On `popupopen`: focus moves to `.popup-card`, but only when the map pane is visible. While the pane is hidden (a phone in list view, `PinalertMap.flyTo` opens the popup anyway) the move is a silent no op and `PinalertMap.focusOpenPopup()` does it later. Leaflet removes the container before `popupclose` fires, so "focus was inside" cannot be read then: record it with `focusin` and `focusout` listeners on the container (or the close click) and on `popupclose`, only when that flag is set, return focus to the opener (A74): the list row (looked up by report id at close time, used only if it exists, `isConnected` and its list pane is displayed) when the popup was opened from a list row, otherwise the marker element. The opener is a report id plus kind: `activateRow` sets a module level "list opened" marker for that id just before `PinalertMap.flyTo(id, { opener: 'list' })`, pin click, Enter or Space sets none, and `popupopen` consumes and clears it, so a later pin opened popup never inherits a stale row. The row return applies to Escape and the close button alike, and when a mouse click on a row opened the popup. `map.js` has no `popupclose` handler today, so this handler is new in this phase and is listed in what must change in `map.js` (with the `popupopen` handler, the `map.on('resize', ...)` handler of A59, the `focusOpenPopup` export of A51, the pin `keydown` handler of A49, and the shelter formatter call). The `popupopen` handler also sets the hidden pane flag of A59 (`card.offsetParent === null`).
* On a phone, a list row click calls `activateRow`, which opens the popup and then `switchView('map')`, whose `moveFocusIntoView('map')` currently focuses the report button. The popup wins, through a new `map.js` export (`PinalertMap.focusOpenPopup()`, amendment A51): it returns true and focuses the open popup's `.popup-card` when a popup is open and the map pane is visible (an explicit check such as `card.offsetParent !== null`), and otherwise returns false and focuses nothing. `moveFocusIntoView('map')` calls it first and focuses `#fab-report` only when it returns false. `switchView` calls it after `data-view` is set to `map` and after the resize dispatch, so the pane is already displayed. `feed.js` cannot see a popup on its own, because `map.js` keeps the Leaflet map private and exports only `flyTo` and `highlight` today.
* The close button is moved to be the first element of `.leaflet-popup` (Leaflet appends it last), so Tab order is: close, trust toggle, Confirm, Dispute, Mark resolved. It stays an anchor with `role="button"` and the accessible name "Close popup". Space activates it (a keydown handler calls `preventDefault` and closes the popup) as well as Enter. Each pin element gets the same Space handling in the other direction: Leaflet 1.9.4 opens a marker popup only on the Enter keypress, so a pin `keydown` handler opens the popup on Space with `preventDefault` (amendment A49).
* Escape resolves one level per press: confirmation, then panel, then popup (Trust Block, Behaviour). With focus on `.popup-card` and no panel or confirmation open (the panel is closed), one Escape closes the popup and focus returns to the opener (A74): the marker when the popup was opened from the pin, the list row when it was opened from a row on a layout where that row is displayed.

## Interaction Contract

1. **Open the explanation.** Click, tap, Enter or Space on the trust toggle opens its panel. The same action or Escape closes it. Nothing else on the row or card reacts to that input.
2. **Vote (D-04, unchanged).** Tap Confirm, Dispute or the confirmed Yes: `votes.js` resolves the viewer's location (silently refreshing it when permission is already granted and retrying once, D-02, never prompting per vote), all buttons disable, the POST fires, and on success the feed refetch drives every surface (counts, labels, pressed state). 3. **Poll (every 30 seconds).** Updates are in place on all three surfaces: text, classes and attributes only. No open popup, confirmation, panel, focus position or busy button is disturbed, including by other rows being removed or reordered around a focused one (A71).
4. **Fade timer (every 60 seconds).** Re-applies the combined fade class and the meta text on rows. It never touches the block.
5. **Mark resolved.** As specified in Vote Controls and Too Far.
6. **Too far.** As specified in Vote Controls and Too Far.
7. **Keyboard.** Row: row, toggle, vote buttons. Popup: close, toggle, vote buttons. Enter and Space on any control inside a row never activate the row. Pins open the popup on Enter and Space. Escape order: confirmation, then panel, then popup.
8. **Touch.** Every target is at least 44px. There is no hover only information anywhere: the panel and the too far sentence are click and tap based or always visible.

| Still current | Getting old or Needs re-confirming when a standing dispute raised the bar | Someone nearby disputed this, so it needs {K} places to confirm it in the last {WINDOW}. |
| Still current | Too early to tell | Fewer than {T} places have confirmed this so far. |
| Reporter | Reliable, Mixed or Unreliable | {C} of {J} earlier reports were confirmed by people nearby. |
| Reporter | New reporter, J of 2 or more | Only {J} of their reports have had a clear result so far. A rating needs {MIN} reports with a clear result. |
| Reporter | New reporter, J is 1 | Only 1 of their reports has had a clear result so far. A rating needs {MIN} reports with a clear result. |
| Reporter | New reporter, J is 0 | None of their reports has had a clear result yet. A rating needs {MIN} reports with a clear result. |
| Score (popup only) | Still current score not null | Score {SCORE} out of 100, based on how recently different places confirmed this. |
| Score (popup only) | Reporter score not null | Score {SCORE} out of 100, based on how often their reports with a clear result were confirmed. |
| Expired (Activity page only) | Report expired and not resolved | This report has expired. It can no longer be confirmed. |

Rules: both counter sentences, confirmed and disputed, always keep the tail "Counts separate places, not votes." because N and M are place counts and so lower bounds on people (D-04, R-04, D-19). The disputed sentence is fixed by this contract (A56) and must not be reworded to drop the tail or to state an exact head count. Never use "fades unless re-confirmed" (known stale wording, expiry is flat by severity). Never say "first report" for a New reporter (it is false for one to four judged reports). The New reporter sentences say what J counts (reports with a clear result) and give MIN its noun. Only the still current wording (the four still current cases and the standing dispute variant) stays the planner's to finalise in `trustcopy.go`, within these placeholders and this plain style.

## Accessibility

* **Text contrast 4.5:1** on every surface and theme. All trust text, the row meta line and the `.vote-error` text are `--color-text`. * **Keyboard.** Every control is reachable and operable. Row tab order and popup tab order are in the surface sections. Escape order is confirmation, then panel, then popup. Pins open on Enter and Space.

## Summary

This phase is mostly a front end rebuild, but five facts found in the repo change what the planner must plan. First, **the next free migration number is 00008, not 00007**: `internal/store/migrations/00007_add_moderation_and_idempotency.sql` already exists from Phase 4 `[VERIFIED: ls of the migrations folder]`. The brief and 03.2-RESEARCH (which proposes `00007_add_updates.sql`) are stale on this. Second, **"Confirmed" in the Show menu has no safe definition on today's wire fields**: `Resolve` checks the critical bypass rung before the confirm gate, so a Critical report (or an old rescue_needed report posted before D-24a) confirmed at five places still comes back `live` with reason `critical_bypasses_gates`, never `confirmed`. Third, **All needs one new feed view word** (a server read of Live, Provisional and Hidden together), which changes the feed filter (`ListableInFeed`) but not `Resolve`, `ViewOf` or any count. Fourth, **several contract tests stop with `Fatalf` rather than just failing** when the old structure disappears (`TestNoPillShapedControls`, which requires `.view-toggle` rules and a `999px` severity slider rule), and one rule that bites the new sheet code (`scrollIntoView` is banned in feed code). Fifth, **the browser harness is outside the repo** (`~/code/pinalert-browser-checks`, Playwright, Chromium and WebKit) and its checks 13 to 16 pin the old layout, so someone must own rewriting its selectors.

The front end work divides into: a shared page frame and navigation (bottom bar, top bars, laptop strip, person menu), Nearby (Show menu, grouping, sheet, selection), My activity (hub plus five parts, with Ended nearby fetched client side because the page has no reader position), Official alerts (an honest empty place), Settings, Post a report (tiles, severity boxes, Call 112 box, picks), the first-time flow and the one reader. The backend work is one migration, one gate extension, three small endpoints and one wire change. There are no new packages.

**Primary recommendation:** Build in this order: (1) migration 00008 plus account gate plus onboarding endpoints plus the `all` view word and Confirmed membership word, each with its own Go tests, (2) shared frame and navigation as one plan that owns `index.html.tmpl`, `main.css`, `phone.css`, `chrome.css` and `theme.js`, (3) the surfaces one at a time (Nearby with the sheet first, because it is the riskiest), each plan amending the contract tests it breaks in the same commit, (4) a last plan for the harness rewrite, dated notes in ROADMAP and REQUIREMENTS, and the final gate. Do not run surface plans that touch `phone.css`, `index.html.tmpl`, `app.js`, `feed.js` or `router.go` in parallel.

**Dependency on the pinalert-c8 quick task (CONTEXT D-24a, orchestrator message of 2026-10-16).** Plan against `main` after that quick task merges: it adds the `traffic` category on the server (validation, API enum, labels, seed, tests, a plain icon), refuses new `rescue_needed` posts with a 400, swaps the category list in `app.js`, and leaves old rescue reports on their built rules until they fade. ### Pattern 1: One markup, two arrangements (D-01)
**What:** Render each nav item once from a Go slice and range it into both the phone bottom bar and the laptop top bar; a contract test compares label and href lists of both. Nearby is already one DOM (the sheet, the list pane and the map are the same elements), only CSS differs.

### Pattern 2: Contract-test amendment in the same plan as the code that breaks it
Each surface plan edits the tests its own change breaks, with a dated comment naming the owner decision, so `main` is never red between waves. The repo's own precedent is the "Departure R6 of plan 03.1-09" comment on `phoneBaseHideHeads` in `web/phone_layout_contract_test.go`.

### Anti-Patterns to Avoid
- **Deriving "confirmed" in JavaScript** from `trust.confirmed_places` or from `visibility === 'live'`. `web/static/js/visibility.js` states the module computes nothing, and a client that guesses trusted overstates corroboration.
- **Two reads for All** (active plus disputed) concatenated in the browser. Rows could move between reads and appear in both or neither.
- **A new `fetch(` in `map.js`** (pinned at 0) or in `activity.js` / `activity-tabs.js` (banned by `activity_page_contract_test.go`). Put Ended nearby's fetch in a new module and change the test deliberately.
- **`scrollIntoView`** in feed code (banned by `popup_contract_test.go:704` and `phone_layout_contract_test.go:260`). The mockup's pin to card code uses it; use `listEl.scrollTo({ top: card.offsetTop - headHeight })` on the list container instead (element `scrollTo` is not in the ban regex for the feed script, but is banned in the activity scripts, `activity_page_contract_test.go:161`).
- **Opacity on text or rows** for disputed or ended items (D-07).

## The phone sheet (question 5)

**Structure.** On phone the list pane becomes a positioned sheet that is a **sibling above** the map container (never a child: Leaflet owns `touch-action` and pointer handling inside the map). The page does not scroll as a document (UI-SPEC page frame). The sheet's height is fixed at its "full" height and it moves with `transform: translateY(...)`; only the inner `.sheet__scroll` scrolls. Compositor only transforms are smoother on iOS than animating `top` or `height`.

**State machine in a pure module.** Write `sheet.js` as a small pure function set (snap positions from container height, nearest snap with a flick threshold, the handoff decision) plus thin DOM glue, so `node --test` can test it in the existing vm sandbox style (`account_menu_scroll_test.mjs` is the model). Snap positions come from the container height measured with a `ResizeObserver` on the Nearby container (not `window.resize`): the iOS URL bar collapsing and the on screen keyboard change the visible height without a classic resize.

**Gesture ownership (the hard part).** Rule: the sheet owns the gesture until it is at full; at full with `scrollTop > 0` the list owns it; at full with `scrollTop === 0` a downward drag returns to the sheet.
- Handle and list head use Pointer Events with `touch-action: none`. Without it the browser claims the gesture and sends `pointercancel`, so a drag stops mid way `[CITED: developer.mozilla.org/en-US/docs/Web/CSS/touch-action]`. Changing `touch-action` after a gesture starts has no effect on that gesture (same page), so decide it in CSS before the touch, with a state attribute: `[data-snap="full"] .sheet__scroll { touch-action: pan-y }` else `none`.
- For the list body handoff at full and top (pull down shrinks), the mockup uses non passive `touchmove` with `preventDefault` decided on the first movement; this works on iOS Safari only with `{ passive: false }` and only if decided before the browser starts scrolling. Pointer Events alone cannot take back a gesture the browser already owns (`pointercancel`). Keep the mockup's approach for the body (`touchstart` records Y, first `touchmove` decides) and Pointer Events for the handle.
- Suppress the click that follows a drag (the mockup sets a 60ms flag); use a movement threshold of about 6px so a tap still selects a card. Add `touch-action: manipulation` on cards to drop double tap zoom delay.
- Wheel on laptop trackpads is not needed: the sheet only exists below 900px. Keep the mockup's wheel handler out unless the phone layout is used with a mouse (a narrow desktop window), where the handle button and keyboard still work.

**Map resize.** D-16 says the map above the sheet resizes. Resizing the Leaflet container each pointer move forces a redraw of the MapLibre GL canvas and tiles. Recommend: while dragging only the sheet moves; at settle (after the snap transition ends or immediately when reduced motion) set the map container height to the visible region and call `map.invalidateSize({ animate: false, pan: false })` once. An equivalent that avoids resize is to keep the map full height and offset the centre with `paddingBottomRight` on `flyTo`/`fitBounds`; either way the check is "no pin under the sheet". `map.js` `onMapResize` only closes the popup when the 900px breakpoint is crossed (`crossed`), so snap resizes do not close an open report `[VERIFIED: map_follow/phone_layout tests describe it; map.js:onMapResize]`. Whether maplibre-gl-leaflet resizes its GL canvas on Leaflet's `resize` event is `[ASSUMED]`; verify in the browser harness.

**Accessibility.** The handle is a real `<button>` with `aria-expanded` (true at full) and `aria-controls`; Enter and Space cycle half and full; an accessible name that changes with state ("Show more of the list" / "Show the map again"). The list is always in the DOM and reachable in tab order whatever the position; when focus lands on a row that is clipped by a short sheet, grow to half first (a focus ring hidden under the screen edge fails WCAG 2.4.11 style visibility, D-03). Do not use `inert`, `aria-hidden` or `display:none` for the clipped part. The sheet never traps page scroll because the page does not scroll as a document there; the inner scroller uses `overscroll-behavior: contain`.

**Reduced motion.** Read `matchMedia('(prefers-reduced-motion: reduce)')` once and on change; with reduce, snap instantly (no transform or height transition). `feed.js:1313` already reads this query.

**iOS Safari pitfalls.**
- `100vh` is the large viewport and hides the bottom of the page behind the toolbar; use `100dvh` with the legacy unit first (the repo's existing pairing in `main.css` and `phone.css`).
- Rubber banding: `overscroll-behavior: none` stops chaining and the bounce; `contain` stops chaining but the bounce can still occur `[CITED: developer.mozilla.org/en-US/docs/Web/CSS/overscroll-behavior]`. Use `none` on the page container and `contain` on the sheet scroller. Safari version support for `overscroll-behavior` is `[ASSUMED: Safari 16 or later]`; the repo's existing comment (`account-menu.js`, F-P4-10) already records that "WebKit chains it to the page despite overscroll-behavior: contain", so keep the touchmove guard pattern from `account_menu_scroll_test.mjs`.
- `env(safe-area-inset-bottom)` returns 0 unless the viewport meta has `viewport-fit=cover`; the bottom bar needs it to clear the home indicator. Adding it changes layout at the notch, so test on a real phone.
- The on screen keyboard (Search a place in the top bar) shrinks the visual viewport; recompute snaps on `visualViewport` resize and close the sheet to short while the search field is focused so results are not covered.
- Leaflet 1.9.4 uses pointer events on Safari 13+; the map's own `touch-action: none` is why the sheet must not be its child.

**Tap a report shows its pin; tap a pin shows its report (D-17).** The store already has `Pinalert.select(id, source)` and `onSelect`. Today a row tap runs `activateRow` (`feed.js`): select, highlight, `PinalertMap.flyTo` which also opens the popup (the opened report with Confirm, Dispute, Mark resolved), and a pin click selects and the list highlights. Keep that pipeline and change only presentation: pin grows (scale) and loses the 3px `--color-text` outline in `phone.css` and the `data-popup-open` / `map-pin--highlight` rules; chosen card gets the soft grey fill (`.card-focus` in the mockup); on the phone the sheet goes to short on a card tap. Scroll the list to the card with `list.scrollTo`, not `scrollIntoView`. **Not drawn in the mockup and a real conflict:** on the phone the opened report is the "detail sheet" (`.leaflet-detail-pane` in `phone.css`, a full screen sheet under a 192px map strip, pinned by `TestPhoneDetailSheetStylesheet` and `TestPhoneDetailMapScript`, z-index 1080 in UI-SPEC). Two bottom sheets collide. Recommend keeping the detail pane exactly as built (the sketch findings skill says the popup and trust block stay as built), setting the list sheet to short underneath, and restoring the previous snap when the detail closes. ## Common Pitfalls

### Pitfall 1: Confirmed that is not confirmed
**What goes wrong:** Show Confirmed lists Critical reports nobody confirmed. **Why:** the critical bypass rung makes them `live`. **Avoid:** server authored membership with a truth table test. **Warning sign:** a Critical report with "Not confirmed yet" in the Confirmed list.

### Pitfall 2: Red `main` between waves
**What goes wrong:** a frame plan lands and 30 contract tests fail until a later test sweep. **Avoid:** each plan amends its own pins in the same commit; run `go test ./web` after every plan (it needs no database) and the handler e2e on a disposable database.

### Pitfall 3: Onboarding gate breaks every e2e harness and the offline queue
**Avoid:** additive `Deps` flag off by default; redirect HTML GETs only; exempt `/api/*`.

### Pitfall 4: `Fatalf` tests
`TestNoPillShapedControls` stops the whole test if its premises vanish. Rewrite it in the same plan that removes `.view-toggle` and the slider.

### Pitfall 5: `hidden` versus `display`
The repo's standing trap (`TestPhase4HiddenGuard`): any new `display` rule on an element that can carry `hidden` needs `:not([hidden])` in its head.

### Pitfall 6: Sheet covers or traps
A clipped row taking focus offscreen, a `touchmove` guard that blocks all scroll, a map resize every pointer move, `100vh` on iOS, and two bottom sheets at once (list sheet and detail pane). See the sheet section.

### Pitfall 7: Fake reassurance
Official alerts saying none in force; the Disagree line promising a Demo that does not exist yet; the picks rendering without storage. Each is a trust problem for an emergency app.

### Pitfall 8: Phone rules scattered
`TestPhoneRulesLiveInTheNarrowBlock` requires them inside the one media block. Parallel plans that all append to `phone.css` will conflict; give each a named section and merge sequentially.

## Code Examples

### Pure snap helper (testable under node --test)
```js
// Source: this research (pattern); modelled on the mockup's snapTops/onUp (sketch 007 lines 1285 to 1325)
function snapTops(containerH, searchRowH) {
  var full = searchRowH, peek = Math.max(full, containerH - 210);
  var half = Math.round(full + (containerH - full) * 0.45);
  return { full: full, half: half, short: peek };
}
function nearestSnap(tops, currentTop, startTop, startState) {
  var best = 'half', bd = Infinity;
  Object.keys(tops).forEach(function (k) { var d = Math.abs(tops[k] - currentTop); if (d < bd) { bd = d; best = k; } });
  if (best === startState && Math.abs(currentTop - startTop) > 30) { // a short flick still moves one step
    var order = ['full', 'half', 'short'], i = order.indexOf(startState);
    best = order[Math.max(0, Math.min(2, i + (currentTop > startTop ? 1 : -1)))];
  }
  return best;
}
```

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Open redirect via the onboarding gate or X link | Tampering | Constant redirect targets only; the X uses same site history or `/` |
| Stored XSS via name or home area shown in Settings | Tampering | `html/template` auto escape; client uses `setText` |
| Cross site POST to consent or profile | Spoofing | SameSite=Lax withholds the cookie from cross site POST (DEC-L), as for the vote routes |
| Gate loop or lockout on `/api/*` | Denial of service | Exempt list and tests (offline queue flush must not get a new 4xx) |
| Client derived trust word | Spoofing / information | Server authored membership field; contract test that the client holds no threshold |
| Location leak through the stored position | Information disclosure | Position stays in the browser's localStorage only; request logger already drops query strings |
| False reassurance on Official alerts | Information disclosure (integrity of advice) | "Not connected yet" copy, never "none in force" |

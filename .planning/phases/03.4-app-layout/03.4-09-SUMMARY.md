# Phase 3.4 Plan 09: Post a report Summary

**Post a report is now a full screen sheet on the phone and a 1180 by 780 two pane window on the laptop (map and Near line on the left, form on the right, one Post report button in the footer), closed with the X only, with eight tiles from one WINDOW_TILES constant, three soft coloured severity boxes and Describe it; the Low data view keeps the form it was built with.**

PLAN_BASE: `32fe4c8e8714e4942d786f6fc7136e76f12295c9`. `git diff 32fe4c8 -- web/static/js/app.js web/static/js/queue.js` is empty, so `Pinalert.CATEGORIES` (which still holds earthquake) and the offline queue are untouched; an untouched queued item sends as stored.

## What was built

- **Task 1** (`e09539f`): the `#report-modal` shell in `index.html.tmpl` (header with `h2#modal-title` "Post a report", the line "Say what is happening and where." and the X `button#close-report`; the map pane with the "Search an address or a landmark" combobox, `#modal-map`, `p#near-line`; the form pane; a footer holding `#form-error`, `#send-after-wait` and `#submit-report`). `report_form.html.tmpl` became two modes: the Low data branch (byte for byte the old fields, including Cancel report) and the window branch. `modal.js` writes the bold Near / Pin at part. `report-form.js` wires the X (optional Cancel), passes the result's short name to `choose`, and registers the backdrop click close only on a page without the X. `modal.css` holds the window (phone base, one 900px block: `min(1180px, 94%)` by `min(780px, 92%)`, radius 12px, `--shadow-window`, backdrop `top: var(--disclaimer-bar-height)`).
- **Task 2** (`fd5aa3f`): `WINDOW_TILES` (eight `{category, word}` lines), the window grid (4 columns, ArrowUp and ArrowDown move by 4), the severity boxes (`div#severity-group[role=radiogroup]`, three `button.severity-box[role=radio][data-severity]`, roving tabindex, Left and Right move and choose), Describe it (280 letters, placeholder, the one line under it), `currentSeverity` and `setSeverity` over the slider and the boxes, `tileOffered` so `applyPrefill` selects a tile only when the mode has one. CSS: chosen tile `--color-surface` with weight 600 and the 1px `--color-border` kept; boxes with a 4px own colour edge and `-bg` chosen fills; forced colours add a Highlight border.

**2. [Rule 3 - Blocking] Three more contract tests outside the list needed their anchors moved**
- `web/view_strip_contract_test.go` searched for `<div class="modal-backdrop"` to find the end of the list pane; the backdrop now has the class `post-window` too, so the anchor names the whole attribute.
- `web/queue_contract_test.go` pinned the note slot directly after `</h2>` on both pages (now after `</header>` on Nearby) and `applyPrefill` containing `SEVERITY_BY_VALUE` and `updateSeverityReadout()` (now `tileOffered(` and `setSeverity(`, with `setSeverity` holding the old two).
- `web/report_form_contract_test.go` (in the list) was rewritten around the two branches: `p410Branches` splits the partial, the pinned id order is the window's, the modal-map and modal rule tests ignore the rules named `.post-window`.
- Each carries the dated note.

**3. [Rule 1 - Bug avoided] The footer is in `index.html.tmpl`, not a second block of the partial**
- The plan words the footer items as moving into "the footer area in the window mode" of the partial. A `{{define}}` block in the partial would have broken the template expander of `phone_markup_contract_test.go` and the id counting tests; the three footer elements are plain markup of the window shell instead, and the partial keeps a single include.

**4. [Rule 2 - Missing critical] No backdrop click close in the window**
- The shipped script closed the form on a tap on the backdrop. D-02 and the Post a report text say the X only, and a tap beside the laptop window would ask or close with typed text. The listener is now registered only when `#close-report` is absent (the Low data view). Escape still runs the X path.

**5. [Plan wording not reachable] "Posting it again unchanged shows the server's 400 message"**
- With no tile chosen the form's own check stops the post first ("Choose a category to continue."), so the server's message cannot appear from an unchanged post. The queue already delivers the server's message with Edit and resend as the note (`Not sent. ...`) shown at the top of the window, so the node test `queued rescue_needed reopens with no tile` asserts: no tile chosen, severity, text and shelter state restored, the server's message in `#form-note`, nothing thrown, the form asks for a tile on Post, and after choosing a tile the post goes out under the saved request id. A second test (`a server 400 for the category shows its message ...`) pins that a 400 with `field: category` shows its message in `#form-error`. A hidden `selectedCategory = rescue_needed` was rejected on purpose: it would post a retired category with nothing visible chosen.

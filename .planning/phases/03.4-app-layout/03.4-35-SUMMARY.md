# Phase 3.4 Plan 35: The typed home area survives a slow Photon Summary

**The Use "Gayathri Nagar, Vijayawada" row now comes back through Nominatim when Photon fails or times out, within the cap of four requests, and the page never says Not found for a search that did not finish.**

## What changed

### Go (`internal/geocode`, `internal/api/handlers`)
- `typed.go`: every typed lookup (`lookup`) tries, in order, the Photon cache, Photon (only when the latest Photon request of this search did not fail), then Nominatim (`nominatim`): the reader cache, the cap check, the reader rule token (try index 1, a wait of at most 1.5 s that never queues ahead of a report search), one `fetch` (areas lookups keep `featureType=settlement`, any place lookups send none). The cap of four is checked before every Photon and Nominatim request. An empty Nominatim answer is not cached after a Photon failure (the same guard `search` has).
- `typedLookup.incomplete` is set by any lookup nothing answered (both failed, the cap was full, a limiter was busy).
- `position()`: with one request left the town is looked up first.
- `areas.go`, `client.go`: Nominatim rows now carry the two private flags Photon rows had: `cityLevel` (place or boundary, addresstype city or town) and `region` (for a postcode row, the town read from the label: "520008, Vijayawada Urban Mandal, NTR District, ..." gives Vijayawada; a trailing (Urban), Urban, Mandal, District, Taluka, Tehsil is dropped).
- `photon.go`: `askPhoton` records the latest Photon outcome in the search's counter (`notePhoton`).
- `SearchReaderAreas`: `Answer.NoCloseMatch` is now `notFound && !incomplete`, and the new `Answer.Unfinished` is `notFound && incomplete`, where incomplete is a lookup that was unanswered or a latest Photon request that failed. `noCloseMatch` is true for an empty answer even for a street address.
- `place.go`: `PlaceResponse.unfinished` (omitempty, kind=area only). `docs/` regenerated into the scratchpad with `swag init` and copied in (diff: the new field and the description), as in plans 28, 32 and 34.

### Pages (`welcome.js`, `settings.js`)
- A pick now also hides the status line (step 4 and Settings), as well as the list.
- Rendering rules: rows with `no_match === true` and no typed row show Not found (unchanged); `unfinished === true` with rows shows Search unavailable on Enter and nothing on a typed search; an empty list with `no_match` true shows Not found, with neither flag shows Search unavailable on Enter and nothing on a typed search. Both flags are read only when exactly `true`.
- The phone and the laptop run the same code.

## Worst case upstream requests for one typed search
**4**, the unchanged per search cap. The Photon take function, the Nominatim fallback and the main search all check or count against the same counter. The longest path through the fallback: Photon try (1), Photon retry after a time out (2), Nominatim search (3), Nominatim town lookup (4); then nothing more is sent, and a typed row is placed only when the town is known without another request (from the answer in hand or the town lookup). A repeat of the same text sends 0 for lookups that were answered (Photon or Nominatim cache). `TestOwnersTextWithPhotonDownUsesTheRecordedNominatimAnswers` pins exactly 4; the other new tests assert at most 4.

## Deviations from Plan

**1. [Rule 2 - correctness] A new `unfinished` flag.** Truth 2 says an Enter search shows Search unavailable when a needed request failed. With only `no_match` the page cannot tell an unfinished search that has rows from a finished one, so `Answer.Unfinished` and `PlaceResponse.unfinished` were added (`place.go` is in the plan's file list; `docs/` regenerated).

**2. [Interpretation of "answers busy"]** Busy is read as an error status or a time out from Photon. A busy local Photon limiter (a report search is waiting) does not move a reader onto Nominatim (D-16); the lookup counts as unanswered. Say if that case should fall back too.

**3. [Behaviour change] An empty complete answer is now always `no_match` true,** street addresses included (before, `noCloseMatch` was false for a street address and the page showed Not found for any empty list by itself). Two existing node tests per page now send `no_match: true` with their empty answer; an empty answer without it now shows Search unavailable on Enter.

**4. [Heuristics]** The Nominatim city level rule (place or boundary with addresstype city or town) was confirmed live for Vijayawada only. The postcode town rule (the label part after the code, minus Urban, Mandal, District and similar words) was confirmed for 520008 only; for other codes the town may read as a district name.

**5. [Process] `docs/` regenerated.** **6. [Process]** The Go suite ran twice (the first run was before the last code change and was discarded for the counts).

## Known limits
- The browser side search time limit is 10 s in both pages (`SEARCH_TIMEOUT_MS = 10000`). The owner's 5.8 s search plus a Nominatim wait of up to 1.5 s and one fetch can approach it on a slow day; a typed search that times out stays quiet, and Enter shows Search unavailable.
- With Photon down the typed lookups cost real Nominatim requests (one a second, process wide). They take their token by the reader rule and give up when a report search is waiting.

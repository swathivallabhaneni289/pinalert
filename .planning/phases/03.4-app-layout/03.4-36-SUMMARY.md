# Phase 3.4 Plan 36: Ask for location once Summary

**The browser's location question is asked on its own once per account in a browser, then Nearby and the Low data view start from the kept fix (else the home area centre, else the fallback) and Back to my location is how the person refreshes.**

## What changed

- position.js: `askedBefore`, `markAsked`, `permissionState` and `startMode(callback)` added to `window.PinalertPosition`. `startMode` answers `silent` (Permissions API says granted), `reuse` (asked before and not granted) or `ask` (first time; it sets the marker before answering).
- map.js: `centerOnVisitor` asks `askMode`. `silent` and `ask` run the old `locateReader` step. `reuse` boots at the kept fix (zoom 13, own true, not saved again), else at the configured centre (the home area centre from plan 33, else the city fallback, own false) and never calls `getCurrentPosition`. `recenterOnReader` is unchanged apart from setting the marker; it still asks on the tap and a good fix renews the kept fix. `locateReader` is untouched, so map.js still has exactly one `getCurrentPosition` call.
- low.js: the load calls `requestPositionOnLoad`, the same rule. With the marker and a kept fix the list stays on it with the line "Near your last known position. Use Retry position to find where you are now." and the Retry position button visible. With no kept fix it goes to the default area as when location is off. Retry position always asks.
- welcome.js: `allowLocation` sets the marker when it asks. Not now sets nothing.
- Voting (votes.js) is unchanged.

## Tests
- web/map_ask_once_test.mjs (new, 12 tests): first load asks and sets the marker; second load with prompt, denied or no Permissions API does not ask and starts at the kept fix; granted reads silently; home area then fallback; another account's kept fix and marker; Back to my location asks and renews; throwing storage keeps today's behaviour; no location API. It cuts `centerOnVisitor` and `recenterOnReader` out of the real map.js text and runs them with the real position.js, because map.js builds a full Leaflet map on load.
- position_test.mjs (+7), low_page_test.mjs (+7), welcome_flow_test.mjs (+2).
- trust_facts_contract_test.go: `centerOnVisitor` now boots the fallback centre twice (the location failure and the asked once, no kept fix start); the pin was changed from 1 to 2 and also pins `askMode(`, `keptReaderFix()` and `mode !== 'reuse'`.

## Deviations from Plan

**1. [Process] Tests were written after the code in one commit, not as a separate failing first commit.**
- The plan marks the task tdd. To work fast I wrote the implementation and then the tests in a single commit (a8f711b). The tests do exercise each behaviour the plan lists and all pass; there is no standalone RED commit.

**2. [Rule 3 - Blocking] The Low data view copies the marker code instead of using position.js.**
- low.html.tmpl does not load position.js and the template is not in the plan's file list, so low.js keeps its own small copy under the same key.

**3. [Design choice inside the plan] A new Low data line and the Retry position button for the reuse state.**
- Without it the page would say "Finding your position." forever. The text and the button are the minimum needed so the person can still refresh; no other Low data wording changed.

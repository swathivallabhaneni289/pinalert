### Task 2: areas only search (commit 35eb28c)
- `GET /api/geocode/place?kind=area` runs `Client.SearchReaderAreas`. An unknown kind is a 400 on field `kind`; an empty or missing kind is the normal search. The per account budget key is still `place:<id>`.
- The mode travels in the context (`withAreasOnly`) so it reaches the first Photon try, its timeout retry, the shorter Photon tries, the Nominatim whole text try and the Nominatim plan, without changing the search order signatures. Both caches (the lane cache and the shared Photon cache) key on the mode (`cacheKeyFor`); the normal key is unchanged.
- Server side filter after the fetch: Photon rows must be of type locality, district or city and drawn as `place` or `boundary`, or `landuse=residential` (OpenStreetMap draws Kothrud, Pune that way); industrial and commercial land use (a port, a depot) and single dwellings are dropped. Nominatim rows must be `category` place or boundary with an area `addresstype`.
- Swagger docs regenerated (`swag init`); the only diff is the new `kind` parameter. `docs/` is not in the plan's file list; it is the generated output of the annotation change.

### Task 3: suggestions while typing (commit 86da45a)
- `welcome.js` (step 4) and `settings.js` (Settings home area) search as the person types: 400 ms after the last keystroke, only with 3 or more characters, never the same text twice in a row, a request still out is cancelled by a newer one, at most 5 results in the existing listbox, and Enter still searches at once (and clears the pending pause).
- A typed search is quiet like the map search: no Searching line, no too short line, no failure line. A 429 or 503 from a typed search is retried quietly up to 3 times, 1 s apart, and only the last failure shows its line (Too many searches, or Search unavailable). A network error from typing stays quiet. Enter shows every line as before.
- Typed searches go out at least 1000 ms apart. A pause that comes due inside the gap waits for it.
- Step 3's own search (any place) does not search while typing and keeps `/api/geocode?q=`. The report form search is untouched.
- URLs: step 4 and Settings now call `/api/geocode/place?kind=area&q=`; their contract tests were moved to that.

### Task 4: step 3 prefills the area (commit 04af9ff)
- Every geocode result carries an additive `area` field (omitted when unknown): the place's own name when it is an area, otherwise Photon's locality, then district, then city.
- `welcome.js` prefills step 4 with `step3Pick.area` only. A street or building pick shows its area; an area pick prefills as before; no known area leaves the field empty (or the stored home area of a returning account) and the Filled in line hidden. The coordinates stay the picked point; a code comment says why (the server keeps a cell about 5 km wide).

## Live parameters that worked (checked once, 2026-10-17, User-Agent "Pinalert development (plan 03.4-28 live check)")
- Photon: `https://photon.komoot.io/api/?q=<text>&limit=10&lang=en&bbox=68.0,6.4,97.5,37.1&layer=locality&layer=district&layer=city` (the layer parameter repeated). Indiranagar returned the Bengaluru district and suburb plus villages of that name; Banjara returned Banjara Hills and the Banjara villages; the text "Hyderab" returned the city. "MG Road Bengaluru" returned no street, only localities, so streets are excluded. Without the layers, the same query returned bus stops, a mall and a clinic.
- The locality layer let through land use rows: Chennai Port, MG Motor India, a bus depot (industrial and commercial) and also Kothrud itself (`landuse=residential`). That is why the server filter keeps residential land use and drops the rest.
- County layer: Hyderabad gave "Hyderabad" and "Hyderabad District" (administrative duplicates of the city), so it was left out.
- Nominatim: `https://nominatim.openstreetmap.org/search?q=<text>&format=jsonv2&limit=5&countrycodes=in&featureType=settlement`. Indiranagar returned the Bengaluru suburb and village rows (place_rank 19); "MG Road, Bengaluru" returned nothing.
- Live requests made: 9 to Photon and 2 to Nominatim.

## Search budget numbers
- Per account budget on `place:<id>` (unchanged; Burst 8, Every 1 s, confirmed in `cmd/server/main.go` as placeRateLimitBurst = 8 and placeRateLimitEvery = one second, which equal PlaceRateLimitDefault): 8 searches at once, then 1 a second. The areas mode counts on the same key.
- Process wide Photon limiter (unchanged): 2 requests a second, burst 2; Nominatim 1 a second, burst 1.
- Typing a 12 character area name in one go (a keystroke every 100 ms): 1 request.
- Typing it slowly (a pause of 450 ms after every keystroke, the worst case for requests): 4 requests, at 1300, 2650, 4000 and 5350 ms. The gap rule guarantees at most 1 typed request a second, which equals the refill rate, so typing alone never drains the burst of 8. The only extra requests are the quiet retries, at most 3 per typed text and only after a 429 or 503.
- Each search can send up to 4 upstream requests (the existing cap); that is unchanged.

# Phase 3.4 Plan 32: Let a person keep a neighbourhood the map data lacks Summary

**When OpenStreetMap has no area by the typed name in the typed town, the home area list starts with Use "Gayathri Nagar, Vijayawada" placed in Vijayawada, never for a street address, within the existing cap of four upstream requests.**

## What changed

### Task 1: the typed row on the server (RED 6101869, GREEN 7daa803)
- `SearchReaderAreas` (areas mode only; the report search and the normal place search are untouched) now cleans the text, runs the areas search with the cleaned text, and then may add one typed row.
- Cleaning: a trailing country (India), PIN code (six digits, alone, after a space or dash, or sharing a part with the state) and state name are dropped. A state is kept when dropping it would leave one part (it is then the town). Delhi, Chandigarh and Puducherry are not in the state list because they are also the city people mean.
- The saved name is the first two comma separated parts, at most 120 characters (the stored limit).
- No typed row when: there is no second part; the first part contains a digit (house or plot number); the town contains a digit; either part is under 3 letters; the first part contains a street word.
- A close named area in the typed town means the area is already offered, so no row.
- Position, in order: an any place Photon search for the cleaned two part text, taking a row whose name is a close spelling of the first part or starts with one (Gayatri Nagar Main for Gayathri Nagar) and that is in the same town; else the town itself from the areas answer in hand or an areas search for the second part; else no row. A code comment says why a street or landmark point in the right town is fine (the home cell is about 5 km).
- Result gets `Typed` and `Town`; the typed row has Name = cleaned text, DisplayName = town. The handler passes `typed` and `town` through (omitted on other rows). Swagger regenerated into the scratchpad and copied in (diff is the new fields and the description only).
- The list stays at five rows (the typed row replaces the last area when there are five).

### Task 2: show it in step 4 and Settings (RED 0888b17, GREEN 6c129db)
- `welcome.js` and `settings.js` draw a row with `typed: true` as `Use "<name>"` with the town on the second line. A pick fills the field with the cleaned name and saves it with the row's position. Step 3 and the report form never receive typed rows (the server only adds one for kind=area). All text goes through textContent.

## Worst case upstream requests for one typed search
**4**, the unchanged per search cap. The cap is now counted over the whole search (a counter in the context, noted at every Photon and Nominatim request, retries included), and each extra lookup is refused when 4 are used. Examples: the areas search alone can use all 4 (then no extra lookup is sent and no row appears); owner's example live is 3; a repeat of the same text sends 0 because the areas answer and every lookup are cached. Tests pin: exactly 4 when the search uses 4, at most 4 in the other paths including a Photon timeout and retry. The per account budget (8 then 1 a second), the process limiters and the browser side gap (one typed request per second) are unchanged.

## Deviations from Plan

**1. [Rule 2 - owner rule] Street words also block the row.** The plan blocks a first part with a digit; the orchestrator's rule is never to offer a street address as a home area, so a first part with road, street, lane, marg, gali, avenue, highway, flat, apartment, building, plot, house or floor also gets no row (for example "MG Road, Bengaluru").

**2. [Interpretation of truth 1] The close area must be in the typed town.** See key decisions. Costs at most one extra request (the town point), inside the cap.

**3. [Small extension] A trailing "India" is stripped too**, because pasted addresses end with it.

**4. [Scope note] The Nominatim fallback is not used for the typed lookups**; only Photon. If Photon is down the typed row is simply not offered and the plain answer is returned.

**5. [Process] `docs/` regenerated** (generated output of the handler annotations), as in plan 28.

**6. [Process] One mistaken background command** ran the full Go suite with its output discarded; I killed it and ran the suite again properly. It used only p34_w32.

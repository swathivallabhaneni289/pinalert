# Phase 3.4 Plan 39: The phone report view and the report address Summary

**On the phone an opened report now fills Nearby. The top row reads Back, Report, the bell and the gear. Under it a 160px map strip keeps every pin with this one centred, and the report runs down to the bottom bar and scrolls to its last control. On both sizes an open report has the address ?report=ID, so Back, Escape and the browser's back close it. The laptop is unchanged, at the owner's request.**

## Seams for Phase 3.2 (named on purpose)

- **Public open:** `Pinalert.openReport(id)` in app.js.
  - A report that has a pin opens at once, through `PinalertMap.openReport(id)` (map.js).
  - Any other id is kept as a report link (`setFocusId`) and the list is read once.
  - Before the first list answer it only keeps the id, as an address on load always did.
  - It returns false for an id that is not a report id.
- **Address on load:** the feed.js boot line is now `Pinalert.openReport(new URLSearchParams(window.location.search).get(REPORT_PARAM));`.
- **Card builder:** unchanged and not renamed. It is `buildPopupCard(report)` with refresh `updatePopupCard(card, report)` in map.js.
  - The laptop popup and the phone view share it, because both are the same popup.
  - The actions block is `.popup-card__actions`, built in `buildPopupCard`. Flag (`PinalertFlag.createFlagControl`) is still its last child, so a Mute control goes just before it.
- **Linked report filter:** `focusPinReport(state)` in map.js is unchanged. It is still the one place that decides whether a linked report gets a pin.
- **History helpers** live in one section of map.js, marked `// ---- The report view and its address (plan 39) ----`: `noteReportOpened`, `noteReportClosed`, `onReportPopState`, `noteFocusAnswer`.
- **Note for 3.2:** feed.js `handledFocus` still acts once per page. A second unavailable link opened through `openReport` on the same page shows the phone "no longer available" view again, but not the toast a second time. Bell rows are plain links that load the page, so they are not affected.

## Deviations from Plan

1. **[Owner change] Laptop variant B dropped.** See the section above. Also dropped: "All reports" and the laptop "no longer available" line. The laptop keeps its toast.
2. **[Design inside the rule "only placement changes"] The phone view keeps the card's look.** That look is the severity tint page of sketch 005 as shipped. It is not restyled to sketch 008's plain page. Only the placement changed: the top row, the strip, and the bottom bar shown.
3. **[Rule 1 - Bug] The pin was not in the strip after a row tap.** The bug was there in the base build too. feed.js `activateRow` flies the map a second time after the open, which left the pin at the strip's bottom edge, under the report. The strip centring now runs one turn later, so its setView stops that fly. The pin is now measured at the strip middle.
4. **[Rule 1 - Bug] Putting the map back by its centre was off by 93px.** The map's height follows the sheet, which changes after the restore. It is now restored by its top left corner: the same pin is at 162,202 before and after.
5. **[Rule 3] Escape on the not available view** is handled by map.js. trust.js only knows the popup, and that file is not in this plan.
6. **D-05 wording:** the report parameter is still never removed on load (feed.js). map.js now removes it when the reader closes the report, as this plan asks.
7. **A resize across 900px** still closes an open report, as before. It now also ends its address.
8. **Not done:** the plan's "an id that is not in the current list". A linked report the server can show, but that the current chip or Show choice hides, gets no pin and no line, as before. `focusPinReport` is the one place to change that.
9. **Browser harness** at ~/code/pinalert-browser-checks:
   - It may need selector updates: the phone back control is no longer the round disc at 16,16, and the phone detail now starts at 220 instead of 192.
   - It is outside the worktree and was not touched.

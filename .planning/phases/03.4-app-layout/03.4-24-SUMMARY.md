# Phase 3.4 Plan 24: Strict name check, one statement for the profile save, honest comment Summary

**cleanText now refuses Cf format characters as well as Cc, display names need a letter or digit with an error that says so, UpdateAccountProfile saves name and home area in one statement, and the profile.go header says the stored place name is only as coarse as the person picked.**

## Findings

### WR-02 (name check refuses only Cc): confirmed, fixed

Confirmed first: the new test cases failed on the old code (10 name cases and the home area case all returned no error: a lone U+200B, U+200D U+200C, a U+202E in the middle, a leading U+FEFF, U+2066 between spaces, "...", " - . , ", and an emoji only name). `unicode.IsControl` is category Cc only, and `strings.TrimSpace` does not strip Cf, so these were stored.

Fix: `cleanText` also refuses `unicode.Is(unicode.Cf, r)`. A new `hasLetterOrDigit` check applies to the display name (a name left empty after trimming still means clear, as before). The message is now `DisplayNameRuleMessage`: "Use at least one letter or number in your name, and no hidden characters." The home area name gets the format character refusal through the shared `cleanText` and no letter rule.

Test: `TestDisplayNameFormatCharacters` in internal/service/profile_test.go (refused and accepted tables, the message wording, home area refusals and the unchanged home area rules). Names are built from code points in the Go source, never raw invisible characters. Accepted: "Ravi Kumar", the Devanagari "Ravi", "Ravi 2", "42", "A.", "Anne-Marie O'Neil".

### WR-03 (two statements, no transaction): confirmed, fixed

Confirmed first: `TestUpdateProfileIsAllOrNothing` failed on the old code (name "After" stored while the home area stayed "Old place"). The test installs a trigger on the disposable test database that raises for one marker place name, then restores nothing else; the trigger and function are dropped in `t.Cleanup`.

Fix: one `UpdateAccountProfile` query in accounts.sql with a `CASE WHEN set_name / set_home_area` per column, run once from `UpdateProfile`. `sqlc generate` was run and `sqlc diff` is clean. The two old queries were removed (no other caller). The same test also checks the working save stores both parts.

### CR-01 (home area stores whatever name is sent): comment fixed, main point left to the owner

As the plan says, only the false comment changed. The old header claimed nothing in the database can say where an account lives more precisely than about 5 km. It now says the cell is about 5 km, the name is the place name the person picked kept as sent after the checks, the helper line asks for a town or area, and nothing here checks the granularity, so a building or street name would be stored next to the cell. The search and any server side level check are an open owner question and were not touched.

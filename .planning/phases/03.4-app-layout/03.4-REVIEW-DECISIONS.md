## Skeptic review of the fixes (2026-10-17)

One read only reviewer went over the fix diff alone (`git diff 869f912 abdc5e2`, plans 24 to 26). It found three new problems, all fixed in gap plan 27:

| # | Severity | Problem | Follow up |
| --- | --- | --- | --- |
| S-1 | Warning | Plan 24's refusal of every format character also refuses the zero width joiner and non joiner (U+200D, U+200C), which are a normal part of some Malayalam, Marathi, Bengali, Sinhala, Urdu and Persian text. Such a display name is refused, and a picked home area whose name holds a joiner can never be saved | Plan 27: the contextual rule of RFC 5892 (joiner after a virama; non joiner after a virama or between two Arabic script letters), every other format character still refused |
| S-2 | Warning | Plan 25's position owner rule is only half closed: the first time flow and the Low data view still write a position with no owner, and the next account to read it takes it over; the Low data view also reads another account's position with no check | Plan 27: no page writes an ownerless value (the welcome page gets the account id, low.js writes and checks the owner) |
| S-3 | Info | In Settings, a window reopened while an earlier save is out keeps the old value after that save lands, and pressing Save then writes the old value back | Plan 27: refill an untouched field when the earlier answer lands |

So part 1 WR-02 and part 2 WR-01 count as fixed only with plan 27.

The reviewer checked and found clean: the one statement profile save (a false flag keeps the stored value, a NULL clears it, the home name and cell stay paired); the `&from=link` back arrow, which cannot be turned into a redirect; the header turned div, which no selector names by element; the hidden h1, on Nearby only; the Show menu capture listener; the reader Tab trap; the forced colours glyph rules; the finished report link read; and the shared `account_header_menu` define.

## Residuals the fixes left

- A position saved before plan 27 (or seeded by the browser harness) has no owner and is taken over by the first account that reads it. After plan 27 no page writes such a value, so this covers only values that already exist.
- On the profile page the fallback centre comes from app.js's defaults (12.9716, 77.5946), which equal the server's fallback today. Putting the server's value on the page needs a handler change and was left out.
- Forced colours were checked in Chromium's emulation only. A person on Windows High Contrast should look at the chosen row and the icon buttons once.
- No clear on log out was added for the kept position: the owner rule makes it unnecessary.

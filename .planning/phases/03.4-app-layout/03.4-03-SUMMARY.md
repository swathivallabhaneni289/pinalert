## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The bars are two named blocks of one file, not one partial included once**
- **Found during:** Task 2
- **Issue:** the plan wants the phone bottom bar to be an in-flow child under the content. `.top-chrome` is a sticky wrapper with its own stacking context, so a bottom bar included inside it could not sit under the shell and would be stacked at 1050 instead of 1010.
- **Fix:** `app_bar.html.tmpl` defines `app_topbar` (included inside `.top-chrome` right after the notice bar) and `app_bottombar` (the last child of `body`). The file still ranges `.Nav.Items` exactly twice and holds `data-open-report` exactly twice, so the plan's grep acceptance checks hold. `phoneExpandTemplate` in `phone_markup_contract_test.go` and `TestDisclaimerBarOnEveryFullPage` learned the two block names.
- **Commit:** `c40be85`

**2. [Rule 3 - Blocking] Phone shell height pins kept; the frame is a flex column**
- **Found during:** Task 2
- **Issue:** `TestPhoneShellSubtractsTheBar` pins the exact `body > .app-shell` height rule and forbids a bare `height: 100vh` line, so subtracting the new bar tokens from the shell would have meant editing a test outside this plan's list.
- **Fix:** on the phone `body.has-app-bar` is a screen-high flex column (`block-size`, legacy unit first), the shell takes `flex: 1 1 0; min-height: 0`, and the bottom bar is a normal flex child, so the pinned shell height rule is untouched and `phone_bar_contract_test.go` and `bar_height_contract_test.go` were not edited. The phone search results panel (`top` and `max-height`) now also gives up the title bar and bottom bar heights; `map_tools_contract_test.go` carries the dated note.
- **Commit:** `c40be85`

**3. [Rule 3 - Blocking] A scroll region wrapper on the Activity page**
- **Found during:** Task 2
- **Issue:** with a fixed height phone body, the Activity page's document would no longer scroll.
- **Fix:** `profile.html.tmpl` wraps `<main class="profile-page">` in `<div class="app-content">`, which scrolls inside the phone frame and is a plain block on a laptop. Page content is unchanged (plan 07 rebuilds it).
- **Commit:** `c40be85`

**4. [Rule 1 - Bug] Task 2 kept the old floating button until Task 3**
- **Found during:** Task 2
- **Issue:** `modal.js` returns early without `#fab-report`, so removing the button in Task 2 would have left the report window dead between commits.
- **Fix:** the button stayed in the Task 2 commit and was removed together with its `modal.js` lookup in Task 3. Every commit builds and passes its tests.

**5. [Rule 2 - Missing critical] Pins amended that the plan listed but did not need changing, and one extra guard**
- `web/ways_in_contract_test.go` needed no edit (the account header partial is unchanged until plan 04), so it is untouched.
- `TestThemeToggleFloatsClearOfTheReportButton` was replaced rather than only deleted: `TestFloatingReportButtonIsGone` (no `.fab` rule in main, phone or auth css) and `TestThemeToggleKeepsItsOwnLayout` (the toggle's own fixed position and its display, align and cursor declarations survive, because that property still exists).
- `phoneTabDotHead` in `labels_contract_test.go` is kept as a harmless stale constant with a dated note.

### Notes that are not deviations

- The account header (`header.app-header`) sits inside `header.app-topbar`, as the plan words it. A header inside a header is a content model nit in HTML; browsers render it, and plan 04 rebuilds the person menu.
- The theme toggle stays floating at the bottom right on a laptop; moving it into the top bar is not in this plan's text.
- Pin radius allowance: `phone_layout_contract_test.go` now accepts a 4px corner (UI-SPEC radius scale) for the short bar above the current bottom bar item.

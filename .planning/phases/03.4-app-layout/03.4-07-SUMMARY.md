# Phase 3.4 Plan 07: My activity Summary

**My activity is five parts (Updates, Posted by you, You confirmed, You disputed, Ended nearby) on one server rendered page: a phone list of five rows with a screen per part, and a laptop stack whose rows line up in the columns Report, Status, What happened, When and Distance, with every feature of the six tab Activity page kept.**

- **Tasks:** 3 of 3, plus one small fix commit after review
- **Files:** 19 modified, 1 deleted, 0 created
- **Verification:** `go test ./web`, `node --test web/*.mjs` (154 pass), `go vet ./...`, `gofmt -l` clean, and on the disposable database p34_07 `go test ./internal/api/... ./internal/service -p 1 -count=1` all ok. `make sqlc && make swag` left the tree clean (no change to `internal/store/sqlc` or `docs`).

## Accomplishments

- **Go (task 1).** `activityPartSpecs` lists the five parts with the UI-SPEC lines, hub icons and empty words. `parseActivityPart(rawPart, rawTab)` matches exactly; `posts`, `votes`, `disputes` alias to `posted`, `confirmed`, `disputed`; `all`, `resolved`, `not-resolved`, empty, unknown, upper case and padded values give the list. `buildActivityPage` puts each card in one part, keeps newest event first with ties by report id, keeps the record card from the account's own posts only, and writes the hub lines ("{A} still happening, {B} resolved", "Latest: {text}" preferring a card whose text is shown, "Nothing posted yet", and so on). Cards gain `StatusWord` (same precedence as the row class), `WhenText`, `Lat`, `Lon` (the row's own point, already the coarse centre for a finished Rescue report) and `Approximate`. On a part screen the Profile handler names the phone top bar with the part and sets the back arrow to `/profile`. No trust computation was touched.
- **Page (task 2).** `profile.html.tmpl` holds the heading, the single `#queue-strip`, the hub (`nav.activity-hub`) and a range of five `section.activity-part#part-<key>`. Each row keeps the data attributes the script reads (`data-report-id`, `data-visibility`, `data-visibility-reason`, `data-expired`, `data-trust`, `data-moderation`, `data-can-reopen`, `data-undos-used`) and has six cells. The Ended nearby shell has the four row skeleton visible and the groups, empty, location and error states hidden. The email line, back link, Log out form, tab strip and subtitle are gone.
- **CSS.** `activity.css`: the laptop stack (260px by 1fr sections, gap 40px, hairline top; head row and rows on `40px minmax(0, 2.2fr) 112px minmax(0, 1.5fr) 152px 72px`), chip and disc colours from the state class, the record card in one definition, Ended nearby states. `phone.css` section `/* 03.4 my activity */`: the rounded hub box (72px rows), one part per screen, and the report card grid (disc and chip, text, when, hairline, what happened and distance). No opacity below 1 anywhere on the page (`TestActivityNoOpacity`), no muted text off `--color-bg`.
- **Script.** `activity.js` works on the rows of all five parts with one click listener on the page, mounts the state line, trust block, Reopen and the used both undos sentence into the What happened cell, and keeps the chip word in step after a Reopen. `activity-tabs.js` is removed.
- **Tests (task 3).** `TestActivityPartsRenderFromTheAddress`, `TestActivityTabAliases`, `TestActivityPartMembership`, `TestActivityHubSummaries`, `TestParseActivityPart`, `TestActivityPartsInOrder`, `TestActivityNoOpacity` and the rewritten template, stylesheet, contrast and phone pins. Every other Activity e2e test (reopen, take back limit, shelter words, Rescue blur, held and removed rows, Written line, queue strip, record card) passes on the new structure.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `data-resend-page` replaces the back link as the source the strip reads**
- **Found during:** Task 2
- **Issue:** `resendHref` in activity.js decided between `/` and `/low` by reading `.profile-back-link`, which the plan removes.
- **Fix:** the page writes `data-resend-page="/low"` or `"/"` from `LowDataDefault`; `resendHref` compares `queuePage.dataset.resendPage`. `LowDataDefault` therefore stays in the view model (the plan said to drop it if nothing else reads it; something does). `TestQueueEditAndResendLink` and the new `TestActivityResendPageFollowsDeviceDefault` pin it.
- **Commits:** 3137b16, 8b3354d

**2. [Rule 1 - Spec] The disc shows the category glyph on every card**
- UI-SPEC 3a draws the disc as the category glyph; the old vote and dispute cards used a tick and a speech bubble. `IconGlyph` is now the category glyph for all kinds and the two mask rules were removed. `TestActivityCardWordsPerKind` was amended.

**3. [Rule 1 - Spec] The Written line is folded into the detail line**
- UI-SPEC 3a: "{Category} · {Written line}" in one muted line under the report text, instead of a paragraph of its own. `TestActivityWrittenLine` was amended.

**4. [Rule 2 - Accessibility] A visually hidden severity word in the Status cell**
- The severity word left the chip (the chip says Ongoing, Resolved and so on), so the tint alone would carry severity. The cell keeps "Critical severity. " as visually hidden text before the chip. Pinned in the template and e2e tests.

**5. [Rule 3 - Blocking] Chip words for a reopened report come from `data-word-ongoing` and `data-word-disputed`**
- A contract test (`TestActivityModuleReusesTheSharedLabelMapAndTransport`) bans label literals such as 'Disputed' in activity.js, so the template writes the two words on the chip and the script reads them.

**6. [Rule 3 - Blocking] The 12px corner joins the phone radius allow-list**
- UI-SPEC Surface 3 gives the hub box and cards a 12px radius; `TestPhoneRulesLiveInTheNarrowBlock` allowed 8px. Amended with the dated note (the trust panel already uses 12px).

**7. [Rule 3 - Blocking] Current part is marked with `data-current`**
- The markup walker of `TestPhoneRuleHeadsMatchTheMarkup` cannot see a class written by `activity-part--{{.Key}}`, so the phone rule is `main.profile-page > .activity-part[data-current]` (one rule, not five).

**8. [Rule 1 - Bug] `TestActivityBackLinkFollowsDeviceDefault` replaced**
- Retired because the back link is gone; `TestActivityResendPageFollowsDeviceDefault` keeps the cookie-drives-it coverage and the "no Low data link in the person menu" check.

**9. [Rule 3 - Blocking] Two files outside the plan's `files_modified` were edited**
- `internal/api/handlers/chrome_render_test.go`: the profile render case built `profileViewModel{Email: ...}`; the `Email` field is removed (T-34-32), so the case now builds `profileViewModel{Chrome: chrome}`. Dated note added.
- `internal/api/handlers/auth_e2e_test.go` (`TestProfileRendersSharedHeader`): it asserted that the signed in address appears on `/profile`; the page no longer prints it, so the assertion became a check that it does not. Dated note added.

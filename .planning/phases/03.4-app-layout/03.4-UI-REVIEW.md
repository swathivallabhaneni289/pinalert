# Phase 3.4: UI Review (visual audit of the running test copy)

**Audited:** 2026-10-17
**Baseline:** 03.4-UI-SPEC.md (locked design) plus WCAG 2.2 AA (1.4.3, 1.4.4, 1.4.11, 2.5.8 at the 44px app rule)
**Screenshots:** captured with Playwright (WebKit, plus Chromium at 1440), stored only in the session scratchpad `audit/` folder, not in the repo
**Sizes:** 320x568, 390x844, 1280x800, 1440x900. **Themes:** light and dark.
**Method:** for every screen a script read computed colours and computed WCAG ratios, font sizes, control boxes, gaps between neighbouring controls, clipped text and page overflow. 200 percent text was simulated by doubling the five font size tokens (the tokens are px, so browser text zoom is the only real route; see finding 14).

Not covered: the first-time flow at phone size (after finishing it, `/welcome` redirects away, so only the laptop run of all four steps was measured), and nothing was posted, voted, flagged or saved.

## Ranked findings (most visible first)

Each finding: screen and size, element (selector, file), what was measured, smallest fix. Tag: **[phone]**, **[laptop]** or **[both]**.

### 1. BLOCKER. Report popup runs under the chip row and off the map [laptop]
- Screen: Nearby, a report opened from the list, 1280x800 (fits only just at 1440x900).
- Element: `.leaflet-popup-content-wrapper` / `.popup-card` (`web/static/css/trust.css`, `web/static/js/map.js` autopan), chips `.map-chips` (`feed.css`).
- Measured: popup is 640px tall; the map area is 692px (800 minus 48 strip minus 61 top bar). Popup top measured at y = -220 after autopan, so the severity chip, title and trust rows sit under the top bar and under the chips (chips box 476,117 to 1264,161, popup x 679 to 1020). "Flag this report" is cut at the popup bottom edge and the pin under the tail is cut by the viewport at 1440x900.
- Fix: give the popup content a ceiling and its own scroll, `.leaflet-popup-content { max-height: calc(100% of map height minus 44px chips minus 2 x var(--space-md)); overflow-y: auto; }` (set it from JS as `maxHeight` in the Leaflet popup options using `map.getSize().y - 92`), and set `autoPanPaddingTopLeft: [16, 161 - map top + 8]` so autopan stops below the chip row.

### 2. BLOCKER. Phone detail back button sits on top of the search field [phone]
- Screen: Nearby, report opened, 390x844 and 320x568, both themes.
- Element: the round back button of the phone detail sheet (`phone.css`) over `#map-search-input` (`.app-topbar`).
- Measured: back disc at about 16,16, 44x44; search field box 12,8, 230x44. The field text reads "ch a place" because the disc covers the first 40px. Both are visible at once, so it looks like two layers colliding.
- Fix: while the detail sheet is open, either hide the top bar search (`body.detail-open .app-topbar .map-search { visibility: hidden; }`) or place the back disc below the top bar (`top: calc(60px + var(--space-sm))`). The first keeps the layout as drawn.

### 3. WARNING. Post a report opens with a dark ring on Flood that reads as "chosen" [both]
- Screen: Post a report, all sizes and themes.
- Element: `button.category-tile[data-category=flood]` (`modal.css`, focus set by `web/static/js/report-form.js` or `modal.js`).
- Measured: on open, `document.activeElement` is the Flood tile, `:focus-visible` matches, 2px near black outline; no radio is checked (`aria-checked=false` on all eight). A user sees a black box on Flood and believes Flood is already picked, which is exactly the "dark outline on a chosen item" the owner rejected.
- Fix: move initial focus to the window title (`tabindex="-1"`, no outline, see 4) or the X, not the first tile. Keep the keyboard ring for real Tab presses.

### 4. WARNING. The reader title shows a black focus box on open [both]
- Screen: Disclaimer and Policy reader opened from Settings, 390 and 1280.
- Element: `h2.app-window__title` with `tabindex="-1"` (`window.css`, focus from `web/static/js/reader.js`).
- Measured: `outline: 2px solid rgb(26,29,33)`, `:focus-visible` true in WebKit. A rectangle is drawn around the word "Policy" (screenshot 390 light reader).
- Fix: `.app-window__title:focus { outline: none; }` (programmatic focus targets with `tabindex="-1"` do not need a ring; real controls keep theirs).

### 5. WARNING. Meta lines wrap with a lone dot at the start of the line [both]
- Screen: Nearby list, phone sheet and laptop column, every width; worst at 320.
- Element: `#report-list .report-row .report-row__meta::before`, `.report-row__away::before`, `.visibility-tag::before` (`web/static/css/feed.css` lines 901 to 911).
- Measured: at 390 the second row reads "Medium · Unconfirmed" then a new line "· Road blocked · 59 min ago"; at 1280 "· 1.1 km away" starts line two; at 320 "· 0.3 km away" and "· Report up to date" start lines. The separator is a `::before` on the next item, so it travels with the wrap. Also the laptop critical row shows a double space before the dot ("Critical  · Fire").
- Fix: drop the dot `::before` content and separate the flex items with `column-gap: var(--space-sm)` on the row meta container; or keep the dot but move it to `::after` of the preceding item with `white-space: nowrap` on each item, so a wrap breaks after the dot, never before.

### 6. WARNING. Missing separator, "0 disputed New reporter" [both]
- Screen: Nearby rows, unconfirmed reports, all sizes.
- Element: `.report-row__trustline-word` next to the reporter line (`feed.css` 910 to 911, `feed.js` 245 to 250).
- Measured: the confirmed rows read "0 disputed · Report up to date" then "New reporter" on its own line; unconfirmed rows put "New reporter" on the same line as "0 disputed" with no separator, so it reads as one phrase.
- Fix: give the reporter line the same `flex: 0 0 100%` own line it gets on confirmed rows (or the same gap rule as finding 5).

### 7. WARNING. Muted text on the grey surface, 4.34:1 [both]
- Screens and elements:
  - Sign in page `div.login-card > p` lead (`auth.css`), 320, 390, 1280.
  - Magic link verify page `div.login-card > p` ("Taking you to Pinalert", "Magic links only work once") (`auth.css`).
  - Post a report `p#coord-readout` on the map column (`modal.css`); it is visually hidden but still the measured pair, and the visible "Pin at..." line sits on the same surface.
- Measured: #6B7280 on #F1F3F4 = 4.34:1 (needs 4.5). UI-SPEC Color says muted text is only used on `--color-bg`.
- Fix: `color: var(--color-text)` on these three, or put the sign in card on `--color-bg` with a `--color-border` edge.

### 8. WARNING. Mark resolved and Flag this report 4px apart [both]
- Screen: report popup (laptop) and phone detail, both themes.
- Element: `div.vote-controls > button.vote-btn--resolve` and `div.popup-card__actions > button.flag-control` (`trust.css`).
- Measured: resolve box 699,351 to 395; flag box 399 to 443 at 1280. Gap 4px between two 44px targets, one of them a destructive style action. At 390 the gap is also 4px and Flag ends 4px from the bottom of the viewport (796 to 840 of 844).
- Fix: `.popup-card__actions { margin-top: var(--space-md); }` (16px) and `padding-bottom: var(--space-md)` on the phone detail sheet body.

### 9. WARNING. "Not set" wraps onto two lines [phone]
- Screen: Settings, About you, 390 and 320.
- Element: `.place-row__value` (`web/static/css/places.css` line 99).
- Measured: 51x48 box, two lines "Not / set"; the row sub line also wraps ("Shown only if you let others follow / you"). Breaks rule R3 (labels never break onto two lines at 320 to 390).
- Fix: `.place-row__value { white-space: nowrap; flex-shrink: 0; }` and keep `overflow-wrap: anywhere` only for a stored place name (`.place-row__value--place`).

### 10. WARNING. Pill shaped tags on the Low data view [both]
- Screen: Low data view, 390 and 1280.
- Element: `.severity-label` and `.visibility-tag--provisional` (`web/static/css/low.css` or `trust.css`).
- Measured: border radius 12px on a 24px tall box (66x24 "Critical", 88x24 "Medium", 106x24 "Unconfirmed"), so fully rounded ends. House rule: no pill shapes; UI-SPEC radius scale puts tags at 4px.
- Fix: `border-radius: 4px` on both in the Low data view.

### 11. WARNING. Field and card edges below 3:1 [both]
- Screens: Post a report (address search, Describe it textarea), first-time step 4 inputs, Nearby phone cards, Settings boxes, My activity hub.
- Element: borders using `--color-border` #E1E4E8 (light) and #2A2D31 (dark) (`main.css` lines 123, 159, 194).
- Measured: #E1E4E8 on #FFFFFF = 1.27:1; #2A2D31 on the dark bg is about 1.3:1. For cards this is decoration, but for text inputs WCAG 1.4.11 needs 3:1 on the boundary that shows where to type.
- Fix: give inputs only a stronger edge, for example `input, textarea { border-color: var(--color-text-muted); }` (#6B7280 on white 4.8:1), leave card hairlines as they are.

### 12. WARNING. Placeholder text 2.4:1 [both]
- Screens: sign in email field, Post a report address search and description, first-time step 4.
- Element: `::placeholder` (no rule found, so WebKit default).
- Measured: rgb(169,169,169) on white = 2.35:1. The sample text ("For example: Ravi Kumar") carries meaning.
- Fix: `::placeholder { color: var(--color-text-muted); opacity: 1; }` (4.8:1 light). Spec already does this for the phone search field.

### 13. WARNING. Row padding below the declared 12px and uneven between tinted and white rows [phone]
- Screen: Nearby sheet, 390 and 320.
- Element: `#report-list .report-row` (`phone.css`).
- Measured: tinted rows `padding: 8px 16px`, border 0; white rows `padding: 7px 15px` plus a 1px border. UI-SPEC Spacing: card padding is 12. Text sits 8px from the top edge, which is what makes the list look packed. Laptop rows already use `12px 16px`.
- Fix: `padding: var(--space-12) var(--space-md)` on phone rows and `calc(var(--space-12) - 1px) calc(var(--space-md) - 1px)` on bordered rows, or give tinted rows a 1px transparent border so both share one padding.

### 14. WARNING. Row titles cut at 200 percent text; text tokens are px [both]
- Screen: Nearby list, 390 with tokens doubled.
- Element: `#report-list .report-row .report-row__title` with `-webkit-line-clamp: 2` (`feed.css` 855 to 866); tokens `--font-size-*` in px (`main.css` 82 to 88).
- Measured: every title cut, for example 326x140 content in a 326x94 box; "Water up to the knee..." needs 187px. Hub summaries also ellipsis (allowed by spec). No horizontal page scroll at 390 (scrollWidth 390), so layout holds. Separately, px tokens mean browser "larger text" settings do not scale the app at all.
- Fix: raise the clamp to 3 lines, or remove the clamp below 360px and at large text; move the five size tokens to rem (12px = 0.75rem and so on) so user text size applies.

### 15. WARNING. Sign in page: decoration peeks out between the two cards, uneven gaps [both]
- Screen: sign in, 390 and 320 (fresh context).
- Element: `.login-card` stack and the background art (`auth.css`).
- Measured: an arc of the background drawing shows in the 8px gap between the cards and reads as a rendering fault; input to button gap is about 54px while label to input is 4px and the lead to label gap about 24px.
- Fix: increase the gap between the cards to `var(--space-md)` and give the stack an opaque `--color-bg` behind it at phone width, or hide the art below 900px until Phase 5 builds the globe; set the form gaps to one rhythm (`gap: var(--space-md)` in the form, button `margin-top: var(--space-lg)`).

### 16. WARNING. Low data view buttons 4px apart [laptop]
- Screen: Low data view, 1280.
- Element: `a#low-full` and `button#low-report` (`low.css`).
- Measured: side by side with a 4px gap (both 44px). On the phone they stack with an 8px gap.
- Fix: `gap: var(--space-sm)` (8px) or `var(--space-12)` on their container.

### 17. WARNING. Chip row clipped short of the screen edge and tight against the zoom control [phone]
- Screen: Nearby, 390 and 320.
- Element: `.map-chips` (`feed.css` / `phone.css`) next to `.leaflet-control-zoom`.
- Measured: chips box x 56 to 322 at 390 (scrollWidth 402), so the fourth chip is cut at 322 with 68px of empty map to its right; at 320 the third chip ("Tra") is cut. Zoom control 10 to 44, chips start at 56 (12px gap, fine). The cut at a fixed edge looks like a bug rather than a scroll hint.
- Fix: let the row run to the screen edge, `right: 0; padding-right: var(--space-md);` on `.map-chips`, so a chip is cut by the screen, which reads as "scroll for more".

### 18. WARNING. Disclaimer page: heading touches the top of its grey box, title shown twice [laptop]
- Screen: `/disclaimer`, 1280.
- Element: `.legal-box.legal-text` (`legal.css`).
- Measured: `padding: 4px 20px 20px`, box top 16, inner H2 "Disclaimer" text at y 20, so 4px from the edge against 20px on the sides; the page H1 "Disclaimer" sits beside it at y 32. Body text runs about 88 characters per line (703px at 16px).
- Fix: `padding: var(--space-lg)` on `.legal-box` (24 all round) and `max-width: 68ch` on its paragraphs. Hiding the inner H2 when the page H1 already names it is a markup change only if the owner agrees.

### 19. WARNING. Map attribution takes two lines at phone width [phone]
- Screen: Nearby 320 and Post a report map at 390 and 320.
- Element: `.leaflet-control-attribution` (`main.css` or `modal-map.css`).
- Measured: wraps to two lines (about 32px) at 320 on Nearby and at 390 inside Post a report, covering the bottom of a 286 to 356px map. Its links are 16px tall targets.
- Fix: `font-size: 12px; white-space: nowrap; overflow-x: auto;` on the attribution in the phone block only (the text must stay, the size is not covered by the content size rule because it is a credit, not content), or use Leaflet's compact attribution toggle.

### 20. Minor. Leaflet zoom buttons 30x30 [both]
- Element: `.leaflet-control-zoom a` (Leaflet default, not overridden).
- Measured: 30x30 on Nearby and in Post a report. Spec: everything pressed is 44px.
- Fix: `.leaflet-control-zoom a { width: 44px; height: 44px; line-height: 44px; }`.

### 21. Minor. Disclaimer and Policy part links 43px wide [both]
- Element: `a#reader-part-policy`, `p.login-ways__links > a` "Policy" (`legal.css`, `auth.css`).
- Measured: 43x44.
- Fix: `min-width: var(--touch-target-min)` or `padding-inline: var(--space-sm)`.

### 22. Minor. Bottom bar labels at 12px [phone]
- Element: `.app-bar__label` (`app-bar.css`).
- Measured: 12px. This is the declared caption exception in the spec and is not a defect against the contract; listed only because the owner asked for "visually accessible to everyone". Leave it unless "Official alerts" can fit at 14px, which it cannot at 320.

### 23. Minor. Visiting the Low data view makes it this device's default [both]
- Measured: opening `/low` once (from Settings) then opening `/welcome` or `/` in the same context redirected to `/low`; the page says "This device opens the Low data view by default." A person who only wanted to look gets stuck there until they find "Open full version".
- Fix: no layout change; flagged for the owner as behaviour, not a visual item.

### 1. Copywriting (3/4)
Findings 5 and 6. Copy itself follows the house rules (no dashes, plain words). The trouble is that separators are generated by CSS and land wrong.

Findings 1, 2, 15, 17, 18. Two screens show layers colliding (popup under chips, back disc on search field).

### 3. Color (2/4)
Findings 7, 11, 12. The banned muted on surface pair still ships in three places; inputs have no visible edge in either theme.

### 4. Typography (3/4)
Findings 14, 19, 22. Sizes and weights match the declared five and two.

### 5. Spacing (2/4)
Findings 8, 9, 13, 16, 18. The tight spots are exactly where the owner sees "clumped": the action stack under the trust block, the phone rows, and the Settings value column.

### 6. Experience Design (2/4)
Findings 3, 4, 10, 20, 21, 23.

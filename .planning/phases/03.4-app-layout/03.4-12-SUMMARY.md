# Phase 3.4 Plan 12: Call 112 box and What is happening? picks Summary

**Critical reports in the Post a report window now show a Call 112 tel link built from the configured number and seven optional "What is happening?" picks, sent as `happening` only with Critical.**

## What was built

- **Markup** (`report_form.html.tmpl`, window branch only): `a#call-112-box.call-box[hidden]` between the shelter fieldset and Describe it. The whole box is the link, `href="{{.Chrome.Numbers.TelHref}}"` (a typed `template.URL`, so html/template does not rewrite it). It holds the 36px disc (phone glyph through `app-icon--phone`, aria-hidden), "Someone in danger right now?", "Call {Primary} first, then post here." and a `span.call-box__button` "Call {Primary}". Then `fieldset#happening-fields[hidden]` with the legend "What is happening?" and an empty `div#happening-group[role=radiogroup]`. No hint line anywhere (D-05). The Low data branch has neither.
- **Script** (`report-form.js`): `HAPPENING_PICKS` (seven `{value, word}` entries, the only list), `selectedHappening`, `buildHappeningPicks` (window mode only, words through `Pinalert.setText`), roving tabindex, Left and Right move and choose with wrapping, tapping the chosen pick clears it. `renderCriticalPart` runs from `setSeverity`, so a tap, an arrow key, `resetForm` and `applyPrefill` all show or hide the box and the picks, and leaving Critical clears the pick. `buildPayload` adds `happening` only when `windowMode`, severity is critical and a pick is chosen. `applyPrefill` restores a pick only for Critical and only for one of the seven. `focusField('happening')` lets a server 400 on that field land on a pick. Revealing the box scrolls the form's own scroll container only when the box is partly off screen, never the page, and never moves focus.
- **Styles** (`modal.css`, size independent, no phone.css): `.call-box:not([hidden])` (critical tint, 1px critical border, radius 12px, padding `8px 8px 8px var(--space-12)`, gap 12px), `.call-box__disc` (36px, `--color-alert-fill`), `.call-box__button` (44px, alert fill, on alert fill, 600, radius 8px, padding `0 16px`), `.app-icon--phone` mask, `.happening-pick` (44px, radius 8px, Label 14px, 1px border; chosen is `--color-surface` and weight 600 with the border unchanged), and a forced colors rule.
- **Tests**: `TestPostWindowCallBoxCriticalOnly`, `TestPostWindowHappeningPicks` (also cross checks the seven values and order against `service.Happenings`), `TestPostWindowPicksSoftFill`; 15 new node cases in `report_form_session_test.mjs` and 2 in `queue_logic_test.mjs`; `TestPostWindowCallBoxRendersConfiguredNumber` renders the real page with the default and a configured number; `phone.svg` appended to `phase34IconsInUse` in the same commit as its mask.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Partial's static markup pin refused the number actions**
- **Found during:** Task 1, before writing the template
- **Issue:** `TestReportFormPartialKeepsMainFormOrder` banned any `{{.` action in the partial and required exactly 4 `{{`. The plan's `{{.Chrome.Numbers.TelHref}}` and `{{.Chrome.Numbers.Primary}}` could not exist.
- **Fix:** Replaced the blanket ban with an allowlist: exactly three actions (`TelHref` once, `Primary` twice), every other action still refused, the Low data branch still fully static, the other four actions still counted. Dated note names D-24a. (`web/report_form_contract_test.go`, in the plan's file list.)
- **Commit:** 9800166

**2. [Rule 3 - Blocking] Round disc refused by the fully rounded controls check**
- **Found during:** Task 1 verification
- **Issue:** `TestReadOnlyLabelsRoundedControlsNot` rejects `border-radius: 50%`. The 36px disc is round in the spec and the owner's picture.
- **Fix:** Exempted exactly `static/css/modal.css` `.post-window .call-box__disc` in `web/labels_contract_test.go`, with a dated note, on the welcome progress precedent (an aria-hidden drawing, not a control). File not on the plan's list.
- **Commit:** 9800166

**3. [Rule 3 - Blocking] Low data byte budget exceeded**
- **Found during:** Task 1 verification
- **Issue:** `report-form.js` (+6995 bytes) and `modal.css` (+2916 bytes) are linked by the Low data view too. The total went from about 581000 to 590992, over the 585728 budget (the earlier Phase 3.4 plans had already used most of the headroom).
- **Fix:** Followed the documented process: re-measured, set `lowDataMeasuredBytes = 590992` and `lowDataByteBudget = 679936` together (the test forces the budget to be the measured total plus 15 percent, rounded up to 1024), and updated `docs/MODERATION.md`. Files `web/low_budget_contract_test.go` and `docs/MODERATION.md` are not on the plan's list.
- **Commit:** 9800166

**4. [Rule 2 - Missing critical] Render level proof of the tel target**
- **Issue:** `go test ./web` only reads template text, so a wrong field path or a rewritten URL would show only at render time. T-34-53 asks for the link to come from the configured number.
- **Fix:** Added `internal/api/handlers/call_box_render_test.go`, which renders the real page with the default and a configured number and checks the link, the line, the button, no `ZgotmplZ`.
- **Commit:** 9800166

**5. [Plan wording] Accessible name through aria-labelledby**
- The plan describes the link name as "Call 112. Someone in danger right now? Call 112 first, then post here." An `aria-label` repeating that copy would add two template actions and break the acceptance greps that expect each phrase once. The link instead uses `aria-labelledby="call-112-action call-112-title call-112-line"`, which yields the same words in the same order with no duplicated text.

**6. [Plan wording] One commit**
- The plan has one task, so there is one feature commit (this summary is a second commit). The RED run for the node cases was observed before the implementation; it was not committed separately.

# Phase 3.4 Plan 20: The laptop Nearby list pane Summary

**The laptop now shows the list on the left at 420px with only the cards scrolling and the map filling the rest of the width, and a tapped pin brings its row into view on both sizes. Presentation only: no trust computation, count or resolver was touched; phone.css and sheet.js are untouched.**

## What was built

- **main.css (laptop block only).** `.app-shell` is `420px minmax(0, 1fr)` with one `minmax(0, 1fr)` row, no gap, and a height of the viewport less the bar and the top bar (100vh first, 100dvh second). `body.has-app-bar:has(> .app-shell)` takes `overflow: hidden` so the document does not scroll. `.app-shell > .pane--list` is a flex column in grid column 1 with the 1px `--color-border` right border; every child except `#report-list` is `flex: none`, and the pane itself only scrolls in the odd case where the fixed parts alone are taller than the screen. `.app-shell > .pane--map` sits in column 2 and keeps the one row `--map-tools-height`. No `1fr 1fr` is left in the file.
- **feed.css (laptop block).** `#report-list` is `flex: 0 1 auto`, `min-height: 0`, `overflow-y: auto`, `overscroll-behavior: contain`; rows are `flex: none`. The phone sheet is not affected (the rule sits in a 900px block).
- **feed.js.** `revealRowInListPane` scrolls `#report-sheet` on the narrow query and the cards list otherwise, with `scrollTo`. The head is only counted when it is inside the scroll box, so the laptop arithmetic needs no head height and no gap.
- **map.js.** `watchMapBox(container)` puts one `ResizeObserver` on the map element; it waits 150ms for the size to hold, then calls `invalidateSize({ animate: false, pan: false })` once. It does nothing at a phone width, where the sheet's own settle path (`resizeToSheet`) runs, so the sheet's height ease cannot fire it every frame.

## Deviations from Plan

**1. [Rule 1 - Bug] The laptop message (toast) would have landed on the map.**
- **Found during:** Task 1, reading main.css before the change.
- **Issue:** The 900px `.app-shell > #toast` rule centred the message at 75% with a max width of half the shell, which was the list half when the map was on the left. With the list at 0 to 420px, 75% is the middle of the map, exactly the F-P4-9 case (a message covering an opened report's Undo).
- **Fix:** `left: calc(420px / 2)` and `max-width: calc(420px - var(--space-md) * 2)`, so the message is centred over the list pane with 16px at each side.

# Phase 3.4 Validation Strategy

> Per-phase validation contract for feedback sampling during execution. Built from the Validation Architecture section of `03.4-RESEARCH.md`. The planner fills the per task map from the plans.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Go `testing` (static contract tests in `web/`, service unit tests, handler end to end tests on a real Postgres), Node `node --test` over `web/*.mjs` (vm sandbox, no browser), and the Playwright harness in `~/code/pinalert-browser-checks` (Chromium and WebKit, outside the repo) |
| **Config file** | `.github/workflows/ci.yml` (build, vet, `node --test web/*.mjs`, `go test -v -p 1 ./...`); no Go config file |
| **Quick run command** | `go test ./web -short` and `node --test web/*.mjs` (no database needed) |
| **Full suite command** | `DATABASE_URL=<disposable db> go test ./... -p 1 -count=1` on a fresh database created for the run (never `pinalert_test` or `pinalert`), then count `--- SKIP` (must be 0) |
| **Browser pass** | `PINALERT_REPO=$PWD PINALERT_DB=p34_auto PINALERT_PORT=<free port, never 8080, 8090 or 8792> BUILD_FROM=worktree bash ~/code/pinalert-browser-checks/run.sh --browsers chromium,webkit` (database name must end `_auto`) |
| **Estimated runtime** | quick about 20 seconds; full suite several minutes; browser pass longer |

---

## Sampling Rate

- **After every task commit:** `go test ./web -short` and `node --test web/*.mjs`
- **After every plan wave:** the changed Go packages on a disposable database, `go build ./...`, `go vet ./...`, then the full suite gate on a fresh database
- **Before `/gsd-verify-work`:** full suite green on a fresh database with 0 skips, `sqlc generate` and `swag init` leave no diff, dash grep over templates and new JS copy, no image files added, then the browser harness in Chromium and WebKit at 320, 360, 390 and 1280 px, light and dark
- **Max feedback latency:** about 30 seconds for the quick run

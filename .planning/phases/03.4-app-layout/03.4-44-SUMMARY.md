# Phase 3.4 Plan 44: Low data view in clear blocks, with a Back and Reload top row

The Low data view now reads as separate blocks and has a slim top row with Back (to the full version) at the left and one Reload at the right, replacing four separate buttons.

## Owner words

- 2026-10-21 (the arrangement): "should be like arranged and divided neatly so we know they're like all separate things".
- 2026-10-21 (the amendment): "instead of having so many buttons for the low data view, maybe we could have like a reload option instead of having a whole text ... somewhere on the top, not making it a big issue. Maybe we could add like a back button to get out of the low data view."
- 2026-10-21 (confirmation): "arrow button instead of having like try another position or something, reload button makes more sense."

## What was built

- Top row (`.low-topbar`): `Back` link (id `low-full`, href `/?full=1`, aria-label "Back to the full version", left arrow plus the word Back) and a `Reload` button (id `low-reload`, aria-label "Reload", clockwise arrow). Both are 44px targets, and have the global focus ring. The right padding clears the account trigger below 900px.
- Reload logic (`low.js`): when the list shows the default area or a kept position it asks for the position again (what Retry position did, including the asked marker and the disabled-while-asking guard); otherwise it asks the store for a fresh list (what Retry now and Retry did).
- Blocks: the intro (title, line, note, Report an emergency), the position line, the stale line and the queue strip each sit in their own outlined 8px block with 16px between; the Active reports heading has a hairline above it; each report is a card with a hairline, the 4px severity bar kept on its left, and 8px between cards. The position block hides itself while its text is empty.
- Kept: the short note "This device opens the Low data view by default." (it introduces no button, so it was not removed), the position line text, the stale line text, the error heading. The error body now reads "Check your connection, then use Reload at the top."

## Removed buttons

1. "Open full version" button under the intro (now Back).
2. "Retry position" button under the position line (now Reload).
3. "Retry now" button in the stale line (now Reload).
4. "Retry" button in the "Couldn't load reports" block (now Reload).

The page now has two buttons outside the report dialog: Reload and Report an emergency (pinned by a test).

## Deviations from Plan

1. [Owner amendment, 2026-10-21] The plan text said to keep every button; the coordinator relayed the owner's amendment to replace four of them with Back and Reload. Recorded above.
2. [Judgment] The report dialog (modal) keeps its own "Open full version" and "Retry position" buttons. They belong to the post form's location step, not the page, and the page Reload cannot serve them while the dialog covers the page. If the owner meant these too, that is a small follow-up (the location-retry id and its tests).
3. [Judgment] Arrows are text characters, not inline SVG, because the existing asset policy test forbids `<svg` in the template and weakening it was not allowed.
4. [Judgment] The "footer links" named in the plan are not part of the Low data page template (the account header supplies them), so they were not restyled.
5. Simulator check owed, see Verification.

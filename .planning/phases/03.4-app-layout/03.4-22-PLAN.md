<objective>
Fix the last bug plan 17 found and plan 21 could not fix under its rules: at 320px and 200 percent text the still current label on a My activity row breaks inside a word ("confirm" / "ing") and the trust toggle grows to 400 to 520px tall. Plan 21 proved it is a Phase 3.4 regression (at 022ce30 the same label broke at a space) and found the cause: the phone card grid in phone.css (plan 07), `grid-template-columns: minmax(0, 1fr) auto` with the last row "what distance". At 200 percent text the distance column takes about 131px, the What cell gets 123px and the label's text box 95px, while "confirming" needs about 150px; `overflow-wrap: normal` alone keeps the word whole but overflows and is clipped. Plan 21's suggestion: let the What cell take the full row on the phone card.

The normal size look must not change, so the reflow happens only when the text is enlarged. One mechanism to consider first: make the card list a size container and use a container query in em units (which scale with the container's computed font size) to switch the last row to "what what" over "distance distance", with the threshold chosen so that 100 percent text at 320px keeps today's layout. Any other mechanism that meets the truths is fine; pick the simplest that works in Chromium and WebKit.
</objective>

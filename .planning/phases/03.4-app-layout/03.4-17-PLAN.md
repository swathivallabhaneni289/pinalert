## Repo rules for this plan

1. No Python. The harness is node and bash; use the Edit tool for its files.
2. No em dash or en dash in any file or message.
3. The harness is not a git repo: make no commit for its files. Make no change to any file inside the Pinalert repo in this plan; the SUMMARY (written in the repo's phase folder) is the only repo file this plan writes, committed path limited by the orchestrator.
4. Back up first: `cp -R ~/code/pinalert-browser-checks ~/code/pinalert-browser-checks.bak-$(date +%Y%m%d)`; if that folder exists, add the time to the name (`.bak-$(date +%Y%m%d-%H%M)`). Record the harness path and the backup path in the SUMMARY.
5. Database: the harness creates and drops its own; use `PINALERT_DB=p34_17_auto` (the name must end in `_auto`). Never `pinalert`, `pinalert_test`, `p3_view`, `p_view_act`.
6. Port: `PINALERT_PORT=8717` on 127.0.0.1 (never 8080, 8090, 8123, 8792, 8793, 8794, 8797 or 8799; if 8717 is busy pick another 87NN that is free and record it).
7. Pictures, recordings and results go to the work folder given by PINALERT_CHECKS_WORK in the session scratch directory, never into the repo or the harness folder (owner rule: no images in the project).
8. Keep the lid open and the Mac on power for the run; say so in the SUMMARY if the run was interrupted.

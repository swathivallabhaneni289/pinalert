# Phase 01.1 Plan 07: Profile page and explicit logout Summary

**GET /profile lists a verified account's reports across every device it has ever verified on (ReportsByAccount joining through sessions.account_id) inside one merged Activity section under 01.1-06's shared header, and POST /auth/logout clears the session cookie while leaving that history intact for the next re-verification.**

## Performance

- **Started:** 2026-09-12T10:20:00+05:30 (approx.)
- **Completed:** 2026-09-12T10:32:26+05:30
- **Tasks:** 3 (all `type="auto"`)
- **Files modified:** 13 (1 created, 12 modified)

## Accomplishments

- `internal/store/queries/reports.sql`: `ReportsByAccount` — the query this whole plan exists to prove correct. Joins `reports` to `sessions` on `session_id`, filters on `sessions.account_id`, selects no session identifier (continuing Phase 1's T-01-02 control), applies no expiry predicate (a person's own history survives leaving the public feed), ordered newest first.
- `internal/service/auth.go`: `AuthQuerier` widened with `ReportsByAccount`; `(*AuthService).ReportsForAccount(ctx, accountID)` wraps it as the profile handler's read seam, matching how `ReportService` owns the nearby query.
- `internal/api/handlers/auth.go`: `Profile(svc, tmpl, cfg)` reads the gate-resolved account from `internal/account.FromContext`, maps each row into a `profileReport` view struct (category label, `icon-glyph--{category}`, `sev-{severity}`, a server-computed relative-time meta line mirroring `app.js`'s own formatting), and executes `profile.html.tmpl` with `Cache-Control: no-store` (DEC-T). `Logout(mgr)` clears the cookie, sets `no-store`, and redirects to `/login` with 303.
- `web/templates/profile.html.tmpl`: includes `account_header.html.tmpl` by reference (no copied markup), renders exactly one `<section>` headed `<h2>Activity</h2>` containing the reports list (or the "No reports yet" empty state) followed by the always-empty voting-history notice (D-13) — verified by a full set of grep-based structural gates plus four new e2e tests.
- `internal/session/cookie.go`: `(*Manager).ClearCookie(w)` mirrors every attribute (`Name`, `Path`, `HttpOnly`, `Secure`, `SameSite`) of the cookie `Middleware` issues, with a negative `MaxAge` — verified against the *real* issued cookie, not hard-coded literals, so the two can never silently drift apart.
- `internal/api/router.go`: `GET /profile` registered against the same parsed `deps.Template` value `/` uses (load-bearing — the shared header partial only resolves within that template set); `POST /auth/logout` registered POST-only inside the gated group, closing the loop on the control `01.1-06` already shipped in the header menu.
- `README.md`: a new "Account access and logout" section stating plainly that there is no account-recovery path in v1 (D-11) and that logout, unlike a lost inbox, is fully reversible.

**1. [Rule 3 - Blocking] `internal/store/queries/reports.sql`'s doc comment reworded to avoid a false-positive substring match**
- **Found during:** Task 1
- **Issue:** The plan's own acceptance criterion requires `grep -c 's.account_id' internal/store/queries/reports.sql` to return exactly 1. My first draft's comment prose used the literal words "sessions.account_id" and "WHERE s.account_id = ..." twice more, and `"sessions.account_id"` itself contains the substring `"s.account_id"` (the trailing `s` of "sessions" + the literal dot), pushing the count to 3.
- **Fix:** Reworded the comment to say "the session's bound account" / "the WHERE clause below" instead of repeating the literal column reference, leaving exactly one real occurrence — the actual `WHERE s.account_id = sqlc.arg(account_id)` line.
- **Files modified:** internal/store/queries/reports.sql

**2. [Rule 3 - Blocking] `internal/store/identity_test.go`'s multi-session seed query needed an explicit `::timestamptz` cast**
- **Found during:** Task 1
- **Issue:** `TestReportsByAccountSpansMultipleSessions`'s seed `INSERT` reused one placeholder (`$3`) both as a plain value and inside `$3 + interval '1 hour'`; Postgres refused with "inconsistent types deduced for parameter $3" (SQLSTATE 42P08) since the two uses type-check differently without an explicit cast.
- **Fix:** Cast both occurrences explicitly: `$3::timestamptz` and `$3::timestamptz + interval '1 hour'`.
- **Files modified:** internal/store/identity_test.go
- **Verification:** `TestReportsByAccountSpansMultipleSessions` passes against real Postgres.
- **Committed in:** `8dbf9dd` (Task 1 commit)

# Phase 01.1 Plan 05: Verification-email rate limiting and the live resend countdown Summary

**DB-backed per-email resend cooldown checked before token insert/send, a reusable in-memory per-IP token-bucket limiter (`internal/ratelimit`) scoped to only `POST /api/auth/request-link`, and a check-inbox panel with a live per-second resend countdown plus an independent link-expiry notice.**

## Performance

- **Duration:** ~20 min
- **Started:** 2026-09-11T19:15:00+05:30 (approx.)
- **Completed:** 2026-09-11T19:32:25+05:30
- **Tasks:** 3 (all `type="auto"`, Tasks 1-2 `tdd="true"`)
- **Files modified:** 15 (3 created, 12 modified)

## Accomplishments

- `internal/ratelimit.PerIP`: a token-bucket limiter per client IP, backed by `golang.org/x/time/rate` (never hand-rolled), with independent budgets per key, a background sweep evicting idle entries, and an `http` `Middleware()` returning the exact generic 429 envelope (`{error:{field:"email",message:"Too many requests — try again in a minute."}}`) — deliberately identical to the per-email refusal so a caller can't tell which limiter tripped or whether an address has an account. The package has zero dependency on `internal/service` or `internal/api`, so Phase 4's ROBUST-04 can reuse it unchanged.
- `LatestTokenForEmail` (SQL + sqlc), a new `service.ErrRateLimited` sentinel, and a cooldown check inside `RequestLink` placed strictly between email normalisation and token generation — before any insert or send. A refusal therefore never writes a row (can't extend its own cooldown, DEC-J); a mailer failure after a successful insert still leaves the cooldown consumed (Pitfall 3), proven by driving `RequestLink` twice against one fake querier.
- `handlers.RequestLink` now branches on `errors.Is(err, service.ErrRateLimited)` ahead of the `ValidationError` branch, returning 429. `router.go` constructs the per-IP limiter (DEC-I: burst 5, one token/60s) and scopes its middleware with `r.With(...)` to the single `POST /api/auth/request-link` registration — never a top-level `r.Use` — so static assets and the login page itself stay unthrottled during exactly the burst a real emergency produces. `cmd/server/main.go` names the DEC-I values in one place (`api.RequestLinkRateLimit`) instead of leaving them as router literals.
- `loginGateViewModel` gained `LinkTTLSeconds` (from `auth.TokenTTL`) alongside the existing `ResendCooldownSeconds`; both render as `data-cooldown-seconds`/`data-link-ttl-seconds` on `#check-inbox`. `auth.js` starts two independent `setInterval` timers on a successful send: a per-second "Resend in {n}s" countdown disabling/re-enabling `#resend-link`, and a separate timer that reveals "This link has expired. Request a new one above." after the link TTL elapses. A 429 response starts or resets neither timer (UI-SPEC item 6).
- `web/auth_contract_test.go` (new, package `web`, modelled on `js_contract_test.go`) asserts the template/JS attribute contract, the two-independent-timer shape, and the absence of markup-parsing DOM sinks in `auth.js` — a gap Phase 1's threat register (T-01-03) left unguarded for this specific file until now.

## Decisions Made

- **`NewPerIP(every, burst)` kept at exactly two arguments** (see key-decisions above) — an unexported `newPerIPWithIdleWindow` gives this package's own tests a short idle window without widening the exported contract Phase 4 will reuse.
- **Link-expiry notice text lives in `auth.js`, not the template** — set via `setText` at reveal time so the acceptance grep against `auth.js` passes and the DOM-write stays textContent-only (T-01-03), consistent with the countdown label's own approach.
- **`docs/` regenerated via `make swag`** after adding the `@Failure 429` annotation — a direct, minimal consequence of documenting the new response code accurately (Pitfall 7), not scope creep: the diff is exactly the one new response object.

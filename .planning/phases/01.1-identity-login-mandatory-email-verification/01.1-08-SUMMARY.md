# Phase 01.1 Plan 08: Rate-limit and cooldown gap closure Summary

**Un-forgeable per-IP limiter key (chi's ClientIPFromRemoteAddr/GetClientIP replacing the deprecated header-trusting RealIP) plus an atomic email_cooldowns claim (INSERT ... ON CONFLICT ... DO UPDATE ... WHERE) replacing the TOCTOU read-then-insert resend cooldown, closing SC4/IDENT-04.**

## Performance

- **Duration:** ~20 min
- **Tasks:** 3
- **Files modified:** 15 (5 created, 10 modified)

## Accomplishments

- Replaced chi's deprecated `middleware.RealIP` (mutates `r.RemoteAddr` from a caller-supplied header) with `middleware.ClientIPFromRemoteAddr`, read via `middleware.GetClientIP` in `ratelimit.PerIP.Middleware`, with a TCP-peer fallback preserving standalone package use.
- Added `email_cooldowns(email PRIMARY KEY, last_requested_at)` and the single-statement `ClaimEmailCooldown` (`INSERT ... ON CONFLICT (email) DO UPDATE ... WHERE ... RETURNING`), replacing the unserialised read-then-insert cooldown. The primary key does the serialising; the guard on `DO UPDATE` means a refused claim writes nothing.
- Rewired `AuthService.RequestLink` to claim the cooldown atomically before minting a token, removing the now-dead `LatestTokenForEmail` query and its generated method in the same task boundary.
- Wrote three adversarial regression tests that fail against the pre-fix tree: `TestRequestLinkLimiterIgnoresSpoofedProxyHeaders` (six forged-header requests from one peer → five 200s, one 429), `TestClaimEmailCooldownConcurrent` (four concurrent claims for one address → exactly one winner), and `TestRequestLinkConcurrentSameAddressSendsExactlyOneEmail` (eight concurrent requests for one address, limiter opened up → exactly one email/token row).

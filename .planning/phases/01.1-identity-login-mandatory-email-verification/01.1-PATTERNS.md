## Pattern Assignments

### Core Token & Crypto Pattern

#### `internal/auth/token.go` (utility, crypto operations)

**Analog:** `internal/session/cookie.go` (lines 1–50)

**Imports & crypto pattern** (lines 1–20):
```go
package session

import (
	"crypto/hmac"
	"crypto/rand"
	"crypto/sha256"
	"encoding/base64"
	"errors"
	"log"
	"net/http"
	"strings"
	"time"
)

// idBytes is the number of raw random bytes drawn from crypto/rand per
// session id, before base64url encoding.
const idBytes = 16

// NewID draws idBytes from crypto/rand — the cryptographically secure
// generator, never math/rand, whose output would be predictable from
// observed values and let an attacker guess future ids — and returns a
// base64url-encoded session id.
func (m *Manager) NewID() string {
	raw := make([]byte, idBytes)
	if _, err := rand.Read(raw); err != nil {
		panic("session: crypto/rand unavailable: " + err.Error())
	}
	return base64.RawURLEncoding.EncodeToString(raw)
}
```

**Copy pattern:** Use `crypto/rand.Read()` for token generation (never `math/rand`), base64url-encode the raw bytes, and sha256-hash the result for storage. Scale `idBytes` up from session's 16 to 32 (256-bit token, per RESEARCH.md Code Examples).

### Handler Pattern (3 sub-patterns)

#### `internal/api/handlers/auth.go` — POST /api/auth/request-link (handler, request-response)

**Analog:** `internal/api/handlers/reports.go` SubmitReport (lines 145–193)

**JSON decode + validation + error mapping** (reports.go lines 145–193):
```go
// SubmitReport handles POST /api/reports: decode, validate (via svc), and
// persist under the caller's session id. A ValidationError maps to 400 with
// the offending field named; any other error maps to a generic 500 with the
// detail logged server-side only.
func SubmitReport(svc *service.ReportService) http.HandlerFunc {
	return func(w http.ResponseWriter, r *http.Request) {
		sessionID, ok := session.FromContext(r.Context())
		if !ok {
			http.Error(w, "internal server error", http.StatusInternalServerError)
			return
		}

		r.Body = http.MaxBytesReader(w, r.Body, maxSubmitBodyBytes)
		dec := json.NewDecoder(r.Body)
		dec.DisallowUnknownFields()

		var req SubmitReportRequest
		if err := dec.Decode(&req); err != nil {
			writeFieldError(w, http.StatusBadRequest, "body", "Request body is missing or malformed.")
			return
		}

		// ... field conversion and validation ...

		report, err := svc.Submit(r.Context(), sessionID, in)
		if err != nil {
			var ve service.ValidationError
			if errors.As(err, &ve) {
				writeFieldError(w, http.StatusBadRequest, ve.Field, ve.Message)
				return
			}
			log.Printf("handlers: SubmitReport: %v", err)
			http.Error(w, "internal server error", http.StatusInternalServerError)
			return
		}

		writeJSON(w, http.StatusCreated, SubmitReportResponse{Report: reportToResponse(report)})
	}
}
```

**Input validation & MaxBytesReader** (reports.go lines 22–31, 153–161):
```go
// maxSubmitBodyBytes caps the POST body so an unbounded request can't be
// used as a cheap denial-of-service vector.
const maxSubmitBodyBytes = 64 * 1024

// SubmitReportRequest is the raw JSON shape a client posts to POST /api/reports.
// Every field that the server itself computes is deliberately absent here.
// Decode with DisallowUnknownFields so an attempt to set one is a loud 400.
type SubmitReportRequest struct {
	Category string `json:"category" enums:"..."`
	// ... exported field-by-field declarations with swag annotations ...
}

// In handler:
r.Body = http.MaxBytesReader(w, r.Body, maxSubmitBodyBytes)
dec := json.NewDecoder(r.Body)
dec.DisallowUnknownFields()
```

**Copy pattern:** Use `MaxBytesReader` to cap the POST body, `DisallowUnknownFields()` to reject unknown fields at decode time, `errors.As(err, &ve)` to distinguish ValidationError from other errors. Return 400 for validation, 500 for DB/other errors with server-side logging.

**Verification-email rate-limit response** — intentionally generic (never reveal whether email exists or cooldown reason), mirroring reports.go's error pattern but with a 429 status for rate-limit rejections.

```go
// loadSessionSecret reads SESSION_SECRET, failing fast unless env is

func loadSessionSecret(env string) string {
	secret := os.Getenv("SESSION_SECRET")
	if secret != "" {
		return secret
	}
	if env != "development" {
		log.Fatal("SESSION_SECRET must be set outside ENV=development")
	}
	log.Println("WARNING: SESSION_SECRET unset; using insecure development fallback secret")
	return devInsecureSecret
}
```

**Copy pattern:** Wrap the Mailer construction in a similar fail-fast function. #### `internal/store/queries/accounts.sql` (SQL, CRUD)

**Analog:** `internal/store/queries/sessions.sql` (lines 1–4)

**Upsert pattern for lazy account creation** (RESEARCH.md Code Examples and Pattern 1):

```sql
-- name: UpsertSession :exec
INSERT INTO sessions (session_id)
VALUES (sqlc.arg(session_id))
ON CONFLICT (session_id) DO NOTHING;
```

**Copy pattern:** Define two queries: one to create-if-absent, one to read-if-exists:
```sql
-- name: ResolveAccount :one
INSERT INTO accounts (email) VALUES (sqlc.arg(email))
```

### JSON Response & Error Writers

**Source:** `internal/api/handlers/reports.go` (lines 284–294)

**Reusable utilities** (unexported, same package):
```go
// ErrorDetail names the single input field that failed validation (or
// "body" for a malformed request) and a user-safe message.
type ErrorDetail struct {
	Field   string `json:"field" example:"category"`
	Message string `json:"message" example:"Choose a category to continue."`
}

// ErrorResponse is the JSON shape of every 400 and 500 response.
type ErrorResponse struct {
	Error ErrorDetail `json:"error"`
}

func writeFieldError(w http.ResponseWriter, status int, field, message string) {
	writeJSON(w, status, ErrorResponse{Error: ErrorDetail{Field: field, Message: message}})
}

func writeJSON(w http.ResponseWriter, status int, body any) {
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(status)
	if err := json.NewEncoder(w).Encode(body); err != nil {
		log.Printf("handlers: writing JSON response: %v", err)
	}
}
```

**Apply to:** `handlers/auth.go`'s POST and GET handlers use the same `writeFieldError()` and `writeJSON()` functions for consistency. No new response-writing patterns.

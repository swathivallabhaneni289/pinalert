### Gaps Summary

One roadmap success criterion (SC4 / IDENT-04, per-email + per-IP rate limiting so the verification-email endpoint "can't be trivially abused") does not hold as shipped. Both of its two independent layers are defeatable by evidence read directly from the pinned dependency source and the service code, not by trusting any summary or review narrative: chi's `middleware.RealIP` is deprecated specifically for IP-spoofing and is used here with no trusted-proxy allowlist, and the per-email cooldown is an unserialized check-then-insert (a TOCTOU race) unlike the atomic `ConsumeToken` a few lines below it in the same file. The phase's own `01.1-REVIEW.md` (already committed, dated the same day) documents this in more depth as CR-01/WR-01 — this verification independently re-derived and confirmed both findings from primary sources before including them here, per the adversarial-verification mandate, rather than accepting the review's narrative at face value.

This is not deferred to a later phase: Phase 4's `ROBUST-04` covers report-submission rate limiting being session-first/IP-secondary — a different endpoint and a different mechanism, only a tangential match, so per Step 9b's conservative-matching rule this stays a live gap rather than being filed as deferred.

Separately, SC2/IDENT-02 (real email delivery) is present and correctly wired in every code path this verifier can exercise, but — by the phase's own explicit test-design decision to never touch the live Resend API from any test — has no behavioral proof of an actual successful send. This is not a code defect; it needs one human-run check with real credentials before the phase can be called fully proven end-to-end.

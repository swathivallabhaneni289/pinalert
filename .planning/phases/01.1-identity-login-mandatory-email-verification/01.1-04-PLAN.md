## Phase Goal

**As a** visitor, **I want to** verify my email with a magic link before I can report or vote, **so that** every report and vote is tied to an accountable, verified identity.

Plans `01.1-01` through `01.1-03` built a working way in. This plan closes the door behind it: from here on, an unverified visitor sees the login gate and nothing else. This is deliberately sequenced last of the three core slices so the application is never left in a state where it is locked with no key.

<objective>
Apply D-05's "login required to view anything" as a chi middleware over the existing session pipeline, and bring the published API reference back in line with reality.

Purpose: IDENT-01 is only satisfied when the gate actually blocks; IDENT-05 requires the gate to read the account through the Phase 1 session cookie rather than introduce a second identity mechanism.
Output: `requireVerifiedAccount`, the regrouped router, updated Phase 1 tests, and a regenerated OpenAPI spec.
</objective>

<decisions_resolved>
- **DEC-G — gate scope (RESEARCH.md assumption A1, which the researcher explicitly asked not to be treated as locked):** the following stay reachable without verification — `/static/*` (the gate page cannot style itself otherwise), `/swagger/*`, `GET /login`, `POST /api/auth/request-link`, and `GET /auth/verify`. Everything else is gated, including `GET /` and both `/api/reports` methods.

  **The `/swagger/*` exemption is in tension with D-05** ("login is required to view anything") and is being called out rather than slipped through. It is retained because OPS-01 requires a stable, browsable API reference at a public URL, and the spec describes endpoint *shapes* — it discloses no report content, no coordinates, and no session or account data (`TestSwaggerSpecCoversRoutes` already forbids a session identifier from ever appearing in it). D-05's intent, stated in `01.1-CONTEXT.md`, is that a person cannot browse *reports* anonymously; a schema document is not report content. If the developer disagrees, moving `/swagger/*` inside the gated group is a one-line change and this plan's test file is where that decision would be re-locked.

  A consequence worth recording: Phase 1's accepted risk **AR-06** (Swagger "Try it out" issues live writes against `POST /api/reports`) is **superseded** by this plan — those calls now require a verified session and are refused with 401 from the docs page.
</decisions_resolved>

## Trust Boundaries

| Boundary | Description |

| session cookie → account identity | Resolved per request from the database, never from a client-supplied value |

## STRIDE Threat Register

Numbering continues the project register; `01.1-03` ended at `T-01-69`, accepted risks at `AR-31`.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-70 | Elevation of Privilege | A route added later that silently sits outside the gate | high | mitigate | All protected routes live inside one `r.Group` applying `requireVerifiedAccount`; a route registered outside it is visibly outside the group. `TestAccessGateBlocksUnverified` and `TestAccessGateExemptRoutes` pin both sides of the boundary |
| T-01-71 | Spoofing | Client claiming verified status | high | mitigate | Verification is read per request from `sessions.account_id` via the signed session cookie; no header, body field, or cookie flag can assert it. This continues Phase 1's server-computed-fields pattern (T-01-07) |
| T-01-72 | Denial of Service | Database fault opening the gate (fail-open) | medium | mitigate | Any lookup error other than no-rows is logged and treated as unverified — the gate fails closed. | T-01-73 | Information Disclosure | App-shell markup or report data reaching an unverified visitor | high | mitigate | The unverified HTML path is a 302 to `/login` issued before any handler runs, so no shell bytes are produced; the API path returns 401 with the standard error envelope and no data. Asserted on the response body, not just the status code |

The spec carries endpoint schemas only — no report content, coordinates, account or session data, the last of which `TestSwaggerSpecCoversRoutes` actively forbids. Retained because OPS-01 requires a stable browsable URL. Accepted risk **AR-32** |
| T-01-75 | Information Disclosure | An intermediary caching the unverified redirect for a since-verified browser | low | mitigate | `Cache-Control: no-store` on the gate's redirect response |

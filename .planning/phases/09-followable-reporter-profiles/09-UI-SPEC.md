# Phase 9: UI Design Contract

> Visual and interaction contract for Phase 9 (Followable reporter profiles): My profile and other people's profiles, Follow and the Notify me bell, the Followers and Following lists, the star rating control and the skippable star box after "Yes, mark resolved", "See this reporter" in the trust block, mute and block, the People and reports rows in Settings, and the wording of the follow note in the bell and on the lock screen. It designs only what Phase 9 adds. Tokens, components and patterns are owned by `03.4-UI-SPEC.md` (built) and `03.3-UI-SPEC.md` (built). Generated by gsd-ui-researcher, to be verified by gsd-ui-checker.

## Source of Truth and Scope

**Reused, never redefined.** This file adds no colour token, no type size, no spacing value and no new component family. Tokens are in `web/static/css/main.css`. Reused components and classes: the page frame, top bars, bottom bar and the Settings page grid (`.place-section`, `.place-box`, `.place-row`, `03.4` Surface 6); the window (`.app-window`, `.app-window--edit`, `.app-window__panel`, `.app-window__head`, `.app-window__close`); the system style confirm box (`.logout-confirm` with `__body`, `__title`, `__text`, `__actions`, exactly as `#settings-delete-confirm` in `settings.html.tmpl`); `.btn`, `.btn--primary`, `.btn--destructive`; `.inline-error`; `.empty-state`, `.error-state`, `.skeleton-row`; the status chips and the My activity row and card looks (`03.4` Surface 3); the person menu and Show menu pattern; the trust block explanation panel (`.claude/skills/sketch-findings-pinalert`, variant H as shipped); the page's one polite status line `#notice-live`.

**Upstream decisions treated as the contract:** `09-CONTEXT.md` D-01 to D-14 (D-13 is the header order, with the addition below), `09-RESEARCH.md` (names, routes and data rules only; its recommendations are inputs, not decisions), the orchestrator decisions of 2026-10-25 for Phase 9 (the home area shows on an opted in profile, Q1), ROADMAP Phase 9 owner decisions of 2026-10-16 and 2026-10-17, `07.1-CONTEXT.md` (Username, Name and Home area are required and exist for every account that reached the app), `08-CONTEXT.md` (usernames, the report page), `03.3-UI-SPEC.md` Surface 3 (lock screen text rules and the fixed order of kinds) and `03.4-UI-SPEC.md`.

**Sample data rule:** every username, number and sentence below is sample data. Real values come from the server. **The browser computes no star, no tag, no count and no eligibility.** It draws strings and booleans the server sends, always through `textContent`.

**Stack:** Go `html/template`, vanilla JS, hand written CSS. No framework, no build step, no component library. Tool: none. The shadcn gate does not apply (no `components.json`, no `package.json`).

**Not designed here (and why):**
- **Where a tapped report opens.** Every report row that opens a report "opens the report the way Phase 8 opens it". Phase 8's laptop host is an open owner question, so no host is drawn here.
- **The moderator screen for tapped ratings** (list a reporter's ratings, remove one, remove all by one rater). It reuses the built moderator screen rows and its Keep and Remove look with no new style; the plan for it names the strings.
- **The Policy text** that Phase 9 edits (opt in profiles, ratings, public Followers and Following lists). The words belong to the plan that edits the Policy and to the owner.
- **A picture upload.** The round picture is a letter disc (see Surface 1). No image of any kind is stored.
- **Making commenters' usernames (Phase 8) into links.** Only the trust block row and the lists open a profile.
- **Phase 3.2's bell list, Phase 3.3's device switch.** Only the follow note's words are new.

### Owner design rules (binding, quoted)

- Not "vibe coded": no purple or heavy gradients, no pill shaped buttons (modest radius rounded rectangles are fine), no fake numbers, reviews or testimonials (this is a trust product), no hero text or tagline block, no emoji used as icons (real SVG icons or plain text), no em dashes or en dashes anywhere a user can read, no scroll triggered animation (short restrained hover, press, focus and state transitions only).
- Actions are real buttons with 44px touch targets and are never underlined text links. A link that only navigates (a row that opens a page) is drawn as a row or button, with no underline at rest.
- Confirm boxes behave like a normal system alert: reuse `.logout-confirm`, no button outlined on open, only its buttons close it, the page stays still.
- No explanatory hint text under simple options. A state message that answers "why is this like that" is not a hint and is allowed where listed.
- Same features and words on phone and laptop; only the arrangement differs. Phone first: judge at 320, 360 and 390 px, then laptop.
- One way to close each window: the X at the top. One place for each thing.
- A chosen item looks chosen (soft grey fill), never a black outline or a dark box.
- **No buzzes anywhere.** Every phone notification is built to make no sound and no vibration. **No user visible string may use** the closed list in `BANNED_NOISE_WORDS` (buzz, vibrate, vibration, sound, ring, silent, silently, quiet, quietly, hear and their forms). Silence is spoken of in this file's prose and in `docs/` only. Every string in the Copywriting Contract below was written against that list.
- Nothing a user needs sits off the edge or under something floating. Muted text only on `--color-bg`.

## Surface 1: The profile page

**Focal point:** the username (the page's h1, Display 24/600) with the round letter disc beside it; everything else in the header stacks under it in the D-13 order.

One page for My profile and for anyone else's. Address `/u/{username}`; `/me` answers a 303 to `/u/{my username}` (the person menu and the phone Settings row both link `/me`, so no page needs the username). It is a place like Settings: **no bottom bar item and no nav link is current**. The header and the Recent reports rows are server rendered; the lists and the actions use script, as the Settings windows do.

### 1a. Frame

| Size | Frame |
|------|-------|
| Phone | the app top bar (60px) with the back arrow button (name "Back"), the title **"My profile"** on your own page and **"Profile"** on anyone else's (Heading 18/600), a spacer, the Updates bell and the Settings gear; then one scrolling column with 16px padding; the four item bottom bar stays, with no item current. Back is `history.back()` when the previous entry is an app page, else `/` (the Settings rule). |
| Laptop | the app top bar with no nav link current (like Settings). Below it the page is **full width, never a centred column (03.4 R6)**: a two column grid, **320px | 1fr**, gap 32px (`--space-xl`), padding 24px. Left: the header block (1b to 1g). Right: the Recent reports section (Surface 5). Both columns scroll with the page. The laptop strip is not drawn here. |

**Same features and same words on both sizes.** The only difference is that the laptop puts the header and the reports side by side and the phone stacks them, and that the laptop reports are rows in columns while the phone reports are cards (the My activity rule).

### 1b. The header block, in order (D-13 plus the home area)

Top to bottom, gap 8px inside a group and 16px (laptop 24px) between groups. The same order on both sizes. A line is not drawn when the server sends nothing for it.

| # | Part | Look |
|---|------|------|
| 1 | **Round picture and username** | a row. The 64px disc: `--color-surface` fill, 1px `--color-border`, radius 50%, the first letter of the username in uppercase (Display 24/600, `--color-text`), `aria-hidden="true"`. It is not a button. Beside it, gap 12px: the **username** as the page's h1 (Display 24/600) and under it the **Name** (Body 16px, `--color-text-muted`). |
| 2 | **Stars** | see 1c. Not drawn for a New reporter. |
| 3 | **The reporter tag** | a chip (Label 14/600, `--color-text` on `--color-surface`, 1px `--color-border`, radius 4px, padding `4px 8px`, `white-space: nowrap`) holding the server's tag word: "Reliable reporter", "Mixed record", "Unreliable" or "New reporter". The same neutral chip for all four. Under it the server's counts sentence (Label 14px, `--color-text`): "7 of their last 9 reports were confirmed." (the shipped sentence, see Defaults 1), or for a New reporter the shipped "Not rated yet. It needs 5 reports with a clear result." |
| 4 | **Member since** | Label 14px muted: "Member since October 2026". |
| 5 | **Home area** | `map-pin.svg` 16px and the home area name (Label 14px muted): "Vijayawada". A town or area name only, never a cell or a street. Shown on an opted in profile (orchestrator decision Q1) and on your own page. |
| 6 | **Followers and Following** | two buttons side by side, gap 8px, each 44px high, padding `0 12px`, 1px `--color-border`, radius 8px, `--color-bg`, Body 16px: the number in 600, the word in 400: "12 Followers" ("1 Follower"), "30 Following". Each opens the list window (Surface 4). The counts are the totals including people shown only as a number. |
| 7 | **Actions** | see 1d to 1f. |
| 8 | **State message** | only where listed in 1g. |

On your own page the Name line, the stars, the tag and every other line show exactly as others would see them, so you see what your profile says.

### 1c. Stars

The stars line is one glyph and the server's numbers. **It is never a row of five stars**, because a row of stars reads as something to tap; the tapping control is separate (Surface 3).

| Case | What is drawn |
|------|---------------|
| New reporter (no score) | nothing. The tag chip and its sentence carry the message. |
| Fewer than 5 people have rated | the total only: `star-filled.svg` 20px, then "3.6 stars" (the number Heading 18/600, "stars" Body 400). No "0 ratings", no rating count. |
| 5 or more have rated | the same total, then on the same wrapping row, gap 12px, the **two parts** (Label 14px muted): "3.6 from reports" and "4.0 from ratings by 12 people". They wrap under the total on a narrow phone; no separator dot is drawn. |

The group's accessible name is one sentence: "Stars: 3.6 out of 5. 3.6 from reports. 4.0 from ratings by 12 people." (parts only when shown). The numbers are the server's, floored to one decimal (a score of 69 reads 3.4 and can never read 3.5 beside "Mixed record"); the browser never rounds.

### 1d. The action row (another person's profile)

One row, wrapping, gap 8px, every control 44px high. Which controls are drawn is decided by the server.

| Control | When drawn | Look and behaviour |
|---------|-----------|--------------------|
| **Follow** | the person is opted in, holds the Reliable reporter tag now, is not you, and you do not follow them | `btn btn--primary`, label "Follow". Busy: disabled with `aria-busy="true"`, no spinner, the label does not change. |
| **Following** | you follow them | an outlined `btn`, label "Following", `aria-pressed="true"`. Tapping it unfollows at once (no confirmation: Follow undoes it; the bell turns off and is forgotten). |
| **Notify me bell** | you follow them and have not muted them | a 44 by 44 button, 1px `--color-border`, radius 8px, `bell-off.svg` 24px when off, `bell.svg` when on. **Off by default** and one on/off only. `aria-pressed`, name "Notify me when {username} posts". On: fill `--color-surface` (the chosen look) and `border: 1px solid Highlight` under forced colours; the icon differs too, so state is not colour alone. It appears the moment Follow succeeds, after the Following button. |
| **More** | always on someone else's page | an outlined `btn` with the word "More" and `chevron-down.svg` 16px, `aria-haspopup="menu"`, `aria-expanded`. Opens the options menu (1e). |

Order left to right: Follow or Following, the bell, More. A person who does not hold the Reliable reporter tag shows **no Follow and no bell**, with no line explaining it (the tag chip already says why); More stays.

### 1e. The options menu

`role="menu"`, `--shadow-menu`, minimum width 220px, 44px rows, Body 16px, the Show menu pattern: Arrow keys move, Enter or Space chooses and closes, Escape closes and returns focus to More, an outside click closes. Items, in order:

| Item | Drawn when | Result |
|------|-----------|--------|
| **Mute** or **Unmute** | always | Mute stops every note from this person (the bell, the phone, and Reliable reporter alerts). **Their reports still show everywhere.** No confirmation (Unmute is the same menu item, and Settings lists everyone you muted). Muting turns the Notify me bell off and hides it; Unmute brings it back, off. Status: "{username} is muted. Their reports still show." and "{username} is unmuted." |
| **Remove follower** | they follow you | opens the confirm box (1h). |
| **Block** | always | opens the confirm box (1h). |

### 1f. Your own page

The action row holds one outlined button, **"Edit in Settings"**, a link styled as a button to `/settings` (44px). There is no Follow, no bell, no More, no rating control. The Followers and Following buttons work as above. Where listed in 1g a state message sits under the buttons.

### 1g. State messages and the faces of a profile

A state message is a `p` in Body 16px `--color-text`, `role="status"` only where it can change in place. These answer "why is my page like this" and are the only explanatory lines on the page.

| Situation | Who sees it | What the page looks like |
|-----------|-------------|--------------------------|
| **Opted in, holds the Reliable reporter tag** | everyone | the full page above. Others see Follow. You see "Edit in Settings" and the line "People can follow you while you hold the Reliable reporter tag." |
| **Opted in, does not hold the tag** (never had it, or lost it) | everyone | the same page, with the tag chip reading "Mixed record", "Unreliable" or "New reporter" and **no Follow and no bell**. Everyone who followed is gone (the follows ended when the tag was lost). The Followers button reads "0 Followers". Others see no line. You see "People can follow you once you hold the Reliable reporter tag." |
| **Switched off** (Let others follow me off) | only you | your own page still opens, with the same header, and the line **"Only you can see this page. Turn on Let others follow me in Settings."** Everyone else gets the not found page below, the same page as for a username that does not exist. Followers are gone. |
| **Not found** | a viewer of an unknown, private, deleted or blocking profile | HTTP 404 in the standard frame. A state box (Surface 6) with the heading "Profile not found" and one line. The same page in all four cases, so it never tells who opted in. |
| **Blocked by you** | you, on that person's page | no profile data, only a state box: heading "You blocked {username}", line "They can't see your profile or follow you. Their reports still show in the feed.", and one outlined button "Unblock". Unblock undoes the block with no confirmation and redraws the page as a normal profile (or the not found page if they have since gone private). |
| **Action refused because the page is out of date** | the viewer | the refusal redraws only what changed: a 404 on an action redraws the whole page as Not found; a "can't follow right now" shows the inline error below the buttons and removes Follow and the bell. |

### 1h. Confirm boxes (Block, Remove follower)

One native `dialog.logout-confirm` per page, filled by script with `textContent`, structured exactly like `#settings-delete-confirm`: title (`logout-confirm__title`, `tabindex="-1"`, focus lands on it), text paragraphs, an error line (`inline-error`, `role="alert"`, hidden), then **Cancel** (`btn`) and the confirm button (`btn btn--destructive`). No X; only its buttons close it; no button is outlined on open.

| Box | Title | Text | Confirm |
|-----|-------|------|---------|
| Block | "Block {username}?" | "They can no longer see your profile or follow you, and you stop following each other." and "Their reports still show in the feed. You will not see their comments." | "Block" |
| Remove follower | "Remove {username} as a follower?" | "They stop following you. They can follow you again." | "Remove" |

After a confirmed Block the page redraws as "Blocked by you" (1g) and focus lands on its heading. After Remove follower the status line says "{username} no longer follows you." and the menu item is gone.

## Surface 2: Follow, the bell and what a follower is told

### 2a. In the app (the Phase 3.2 updates list, the one the bell opens)

This is the D-09 note: one row per post, in the same updates list as every other update, and nowhere else. It is a notification about one report, not a feed of followed reporters' reports. D-06 keeps those on profile pages only; nothing in this phase adds them to Nearby, to a Show menu choice, or to My activity's own report lists.

A new update row, same layout as every other update row (03.2). Words are built on the server at read time from the report's current trust object, so the row updates in place when people nearby confirm the report.

| Part | Words |
|------|-------|
| Line 1 | "{username} posted a report." |
| Line 2 | "{Category}, {Severity}." |
| Trust line while not confirmed | "Not confirmed yet." |
| Trust line once confirmed | "Confirmed by people nearby." |
| Row gone | "This report is no longer available" (the built line, also used when the follow has ended or the person has gone private) |

A bell row already written stays after a follow ends (it is history); it reads "This report is no longer available" if the report can no longer be shown.

### 2b. On the phone (lock screen)

One notification per report, built by the one Go builder of 03.3 Surface 3 (no field for the report's words, a name, an address or a coordinate). **No username on the lock screen.** Same rules as the other kinds: the tag is `report-{id}`, the same notification is replaced in place when people nearby confirm (it does not alert again), no action buttons, built to make no sound and no vibration, taps open `/?report={id}`.

| Case | Title | Body |
|------|-------|------|
| First note | `{What is happening pick, else Category} near {Area}` | `From someone you follow. {Distance} from your home area. Not confirmed yet.` |
| No area name | `{Pick or Category}` | as above |
| No home area | as the first note | `From someone you follow. Not confirmed yet.` (the distance part is left out; **a follow note is not held back by distance or by a missing home area**) |
| Replaced once confirmed | unchanged | `Confirmed by people nearby. {Distance} from your home area.` (distance left out with no home area) |

Samples: **Water rising near Central Market** / From someone you follow. 2 km from your home area. Not confirmed yet. Then the same notification reads: Confirmed by people nearby. 2 km from your home area. The pick is used for Critical reports only; other reports use the Category word. The title stays within the 64 character budget with the area cut at 28 characters.

**Place in the fixed order of kinds** (03.3: when several kinds match one report for one person, only the first is sent): **Critical, then Follow, then Changes, then Reliable.** A person who follows a Reliable reporter with the bell on gets the Follow note, never two. The planner checks this against the dispatcher; it is the default, not a new rule.

The device switch "On this device" (Settings, Notifications) still governs every phone note. The bell has no phone only meaning: with the device switch off, the bell still fills the in app list. No line under the bell says so.

## Surface 3: Star ratings

### 3a. The rating control on a profile

Drawn **only when the server says this viewer may rate** (a verified account that has voted on one of this reporter's reports, who is not the reporter, on a profile that is opted in). When it is not drawn, **nothing explains why** and nothing is left blank. It is never drawn on your own page.

Placement: a box under the action row (above the state message area) on both sizes. `fieldset` with a `legend` "Your rating" (Body 600); inside, a row of five buttons, gap 4px, each 44 by 44 with its star glyph 24px, then, only when a rating exists, an outlined `btn` "Remove my rating".

| Part | Value |
|------|-------|
| Group | `role="group"` named by the legend; five `button`s each named "1 star", "2 stars" to "5 stars", `aria-pressed="true"` on the one equal to your rating. Tab walks the five; Enter or Space chooses. **No arrow key selection**, because choosing saves to the server and an arrow walk would send five saves. |
| Look | unchosen: `star.svg` outline in `--color-text`. Your rating of n: stars 1 to n show `star-filled.svg`, the rest outline; the nth carries `aria-pressed`. No dark border, no ring, no colour. Hover is a `--color-surface` fill. |
| Saving | a tap saves at once (the server upserts); the five are disabled with `aria-busy="true"` while the call is out. Status: "You rated {username} 4 stars." ("1 star") or "Your rating was removed." |
| Limit | one rating per reporter, changeable, at most once a day per reporter: a second change inside the day shows "You can change this rating again tomorrow." as an `inline-error` under the box. |
| Aggregate | the control never shows anyone else's rating. Others' taps appear only as the header's "from ratings" part, with 5 or more raters. |

### 3b. The skippable star box after "Yes, mark resolved"

Shown only when the server's resolve response carries a rate prompt (an eligible rater, a reporter who is opted in, not your own report). It appears **under the "Marked resolved" message and its Undo**, wherever the report is open (the popup, the phone detail sheet, the Phase 8 page: the host is Phase 8's). It is one block, `div.rate-box`: 1px `--color-border`, radius 12px, padding 16px, `--color-bg`, gap 8px.

| Part | Value |
|------|-------|
| Title | "Rate {username}" (Body 600) |
| Control | the same five buttons as 3a (same names, same saving), starting unrated |
| Skip | an outlined `btn` "Skip" (44px). It dismisses the box and is the box's only way out. |
| After a tap | the box collapses in place to one line (Body, `role="status"`): "You rated {username} 4 stars." It stays until the report view closes. |
| Undo | taking back the resolve with Undo removes the box. |

The box never blocks the report, never repeats for the same report after Skip, and sets no rating by itself. Skip is not a rating of zero and nothing is sent.

## Surface 4: Followers, Following, Muted people and Blocked people

**One list component** serves all four, opened from the two buttons on a profile and from the rows in Settings. It is a window: `app-window app-window--edit` (phone full screen, laptop 480px wide, radius 12px, `--shadow-window`, `role="dialog"`, `aria-modal="true"`, the page behind inert), **closed only by its X** (name "Close"), Escape does the same, focus returns to the control that opened it. The title (Display) is the list name; focus starts on it (`tabindex="-1"`). On another person's profile a Label line under the title names whose list it is: "{username}". On your own, no line.

### 4a. Followers and Following rows

A list with hairlines between rows. Named people first (newest first), 50 per page.

## Interaction and Accessibility

- **Names:** the stars group, the bell ("Notify me when {username} posts", `aria-pressed`), each star ("4 stars"), the counts (their visible words), More (`aria-haspopup`, `aria-expanded`), the lists by their titles, the row link in the trust block ("See this reporter {username}"). A report row's name starts with its state ("Disputed, may not be true." or "Not confirmed yet.") as on Nearby; a finished row's name starts "Ended."
- **State is never colour alone:** the tag is a word; the bell changes icon and `aria-pressed`; a chosen star changes glyph; a finished row has no chevron, no hover and the word "Ended"; Disputed has its word and its red line.
- **Focus:** no script moves focus on load. After a follow, unfollow, rating or bell change focus stays on the control used. Unfollow removes the bell, focus stays on the Follow button that replaces Following. After Block or a 404 redraw, focus lands on the state box heading (`tabindex="-1"`). Windows and confirm boxes put focus on their title and return it to the opener. Escape order: menu, then a window or confirm box.
- **Live regions:** `#notice-live` (polite) for the status lines; `inline-error` has `role="alert"`; the own page state line that can change is `role="status"`.
- **Touch targets:** every control 44px or more, including each star and each list row.
- **Motion:** none added. Hover and press are instant fills; star fill and bell fill change with no animation; nothing animates on scroll; nothing loads on scroll.
- **Text size:** everything wraps; usernames break anywhere; no horizontal scroll at 320 px and 200 percent text.
- **Security:** every username, Name, area and sentence enters the page by `html/template` escaping or `textContent`, never a markup sink. No email, account id or home area cell is on the page or in any JSON the page reads. The page and its JSON are `no-store` and the page is `noindex`.
- **Keys:** Tab reaches the header buttons in order (Followers, Following, Follow or Following, bell, More); the star buttons by Tab (no arrow selection).

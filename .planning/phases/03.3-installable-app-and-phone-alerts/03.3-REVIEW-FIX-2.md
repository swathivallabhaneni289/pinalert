# Phase 3.3: fixes for the skeptic pass

All four items were reproduced and fixed, one commit each, on top of 462a2f7.

## WR-01: docs overstated the Live rule

Fixed in dae2e27 (docs only). `docs/TRUST-MODEL.md` (the gate paragraph) and `docs/PUSH.md` (the fades in about an hour bullet) now say what `eventStillHolds` does:
- Critical and Reliable notes are decided twice, at queue time and at send time.
- Change notes are queued by the dispatcher with no check and decided only at send time.
- A fading note reaches the phone only while the report is Live. "Is now confirmed" needs `ConfirmedByPeople`. "Is now disputed" is sent only while the report is Hidden. "Was marked resolved" is sent only while it is Retracted.
- The false sentence "every note except the Reliable one needs a Live report" is gone from both files.

Test: no new test, docs only. `TestTrustModelDocMatchesCode` still passes.

## WR-02: a rotated key left the switch reading On

Fixed in d6719e5. In `web/static/js/notify.js`, `inspect` now returns `{state: 'ready', sub, known: true}` when the server says the endpoint is registered but the browser subscription was made with another key. The Settings switch shows off, and one tap runs `enable`, which already drops the old key subscription. `reconcile` leaves such a device alone (it posts nothing). I kept the status call so the existing reconcile test about the other key still holds.

`docs/PUSH.md` key rotation sentence now describes this for every case, including the server row that survives until the last good send is more than 7 days old.

Tests, all in `web/pwa_client_test.mjs`:
- `deviceState: a subscription made with another key reads off even when the server still has the row (WR-02)`. It fails before the fix.
- `reconcile: a registered row with another key reads ready and posts nothing, then one enable replaces it (WR-02)`. It fails before the fix.
- `deviceState: a subscription made with the page key and registered on the server stays on (WR-02)`. It covers the same key and the no-key subscription, and passes before and after.

## WR-03: a shutdown signal aborted a send in transit

Fixed in 7f0842c. `fanOut` in `internal/service/pushworker.go` now builds its context as `context.WithTimeout(context.WithoutCancel(ctx), PushSendTimeout)`. A signal no longer aborts a request already sent. The worker loop still stops claiming on `ctx.Done()`, and the 25 s grace covers the 10 s send plus the marks.

Test: subtest `a shutdown signal mid send does not abort the request, and the row is marked sent once (WR-03)` in `TestWorkerSweep` (`internal/service/pushworker_test.go`). The fake sender answers after 50 ms and gives up if its context is canceled, and its hook cancels the run context mid send. Before the fix the row was marked rescheduled. After it, exactly one send and one `sent` mark.

## IN-01: a second Ctrl-C was swallowed during the grace period

Fixed in 4b7e4bb. `cmd/server/main.go` now calls `context.AfterFunc(runCtx, stopSignals)` right after the signal context is created, so the first signal releases the hook and a second one gets the default behaviour. The `defer stopSignals()` stays, and `stopSignals` is idempotent.

Test: the existing `serveUntilDone` tests pass unchanged. A real signal cannot be sent safely inside the test binary, and `main` cannot be run in a test. So the wiring is pinned the same way `TestMainStopsOnSignals` already pins the rest of it, by reading `main.go` for `context.AfterFunc(runCtx, stopSignals)`. This is a source pin, not a behavioural test.

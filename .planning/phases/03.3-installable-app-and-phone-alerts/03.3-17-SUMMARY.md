# Phase 03.3 Plan 17: the device registers again by itself after signing back in

**notify.js runs its guarded reconcile once at page load, so signing back in to the same account brings the device back on the first page without Settings; Nearby and Low data now carry data-push-key, and PinalertNotify.isMacDockApp exists for plans 19 and 20.**

## What was built

- `web/static/js/notify.js`: `reconnectAtLoad()` runs after `register()`. Guards, cheapest first: a non empty `data-push-key`, `intentIsSet()` (the intent flag holds this page's account id), `baseState() === 'maybe'`, `Notification.permission === 'granted'`. Only then `runReconcile(key)` (the old reconcile body, unchanged: server lost the endpoint, kept subscription made with this key). It never calls `requestPermission` (the count in the file is 3 before and after), adds no listener, writes nothing to the page, and swallows any failure. The exported `reconcile(key)` returns the pending load time promise when the key matches, else `runReconcile(key)`. The header comment names the gap (03.3-UAT test 7, owner 2026-10-28). `isMacDockApp` is exported next to `isInstalled`.
- `PushPublicKey` added to `pageViewModel` and `lowViewModel`, filled from `cfg.PushPublicKey`; `data-push-key="{{.PushPublicKey}}"` on the shell element after `data-account-id` in `index.html.tmpl` and `low.html.tmpl`. `PageConfig.PushPublicKey`'s comment updated.
- Tests: 16 new node cases (11 `reconnect: `, 5 `isMacDockApp: `) in `web/pwa_client_test.mjs`, with the sandbox builder extended by a `pushKey` option; `TestPagesCarryPushKey` in `internal/api/handlers/page_test.go`.

## Deviations from Plan

**1. [Environment] `env -i HOME="$HOME" PATH="$PATH"` could not be used.**
The sandbox refused every command containing `env -i` ("too complex to verify"), including when split from pipes. Instead I checked that this shell holds no database variable (`env | grep -ciE '^(PG|DATABASE|TEST_DATABASE|PINALERT)'` printed 0, `DATABASE_URL` empty), so plain `go test` runs with the same (empty) database environment, and counted `SKIP` lines separately (0 in both runs). The no database claim of the plan therefore still holds as proven. No disposable database was created; pinalert_test was never touched.

**2. [Environment] gofmt reports `internal/api/handlers/place_test.go`.** Pre-existing, not touched by this plan, out of scope.

Otherwise the plan ran as written. No auth gates, no stubs, no new network surface (the VAPID public key is public by design and was already on welcome and settings; T-03.3-17-04 accepted).

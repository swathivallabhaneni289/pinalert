<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser to server | The endpoint and keys come from the browser and may be forged |
| server to push service | The server makes outbound HTTPS requests to an address the client chose |
| operator to process | The VAPID private key enters through the environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.3-01 | Tampering / Information disclosure (SSRF) | EndpointPolicy, NewGuardedClient | high | mitigate | https only, dot bounded host allowlist, port 443 only, no userinfo or IP literals; dialer refuses internal addresses after resolution; no redirects; 10 s timeout; policy re-checked before every send; TestEndpointPolicy, TestGuardedClientRefusesPrivateAddresses, TestSenderRechecksEndpoint |
| T-03.3-02 | Information disclosure | WebPushSender.Send | high | mitigate | Errors and logs carry the host only; TestSenderNeverLogsEndpoint captures log output |
| T-03.3-03 | Elevation | VAPID private key | high | mitigate | Environment only; LoadConfig errors never echo keys; vapidkeys writes no file; no generation at boot |
| T-03.3-SC | Tampering | go get of webpush-go and bumps | high | mitigate | Module named in the stack notes, tagged v1.4.0, source read in research; acceptance check that go.mod gains no other module; any further module is stopped and reported for a human check |
| T-03.3-12 | Denial of service | hung sends | medium | mitigate | Client timeout, Retry-After capped at 10 minutes, body drained with a 4 KB limit |
</threat_model>

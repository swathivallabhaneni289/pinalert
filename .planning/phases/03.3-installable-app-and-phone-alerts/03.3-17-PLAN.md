Decisions made at planning (record them in the SUMMARY):
- P-1 The load time check runs in notify.js itself, because notify.js is in the shared head of every page (app_head.html.tmpl) and already holds every guard. It reads the key from the first `[data-push-key]` element and the account from `[data-account-id]` (currentAccount, as today).
- P-2 Cheap guards first, so a person who never turned the device on causes no request: a non empty key on the page, intentIsSet() for this account, baseState() is maybe, and Notification.permission is granted. Only then does it call reconcile(key), which keeps its own checks (the server lost the endpoint, the kept subscription was made with this key) and never prompts.
- P-3 One check per page load: the load time promise is kept while it runs, and a reconcile(key) call with the same key during that time (Settings calls it at load) gets the same promise. After it settles, reconcile works as before.
- P-4 isMacDockApp() is isInstalled() and not isAppleMobile() and a user agent that says Macintosh. It includes a Chrome or Edge app installed on a Mac: such an app shares the browser's subscription, so not asking there loses nothing, and one simple rule is easier to keep. It is used by plans 19 and 20, not by this plan's load time check (a Dock app keeps its own storage, so its intent flag is only ever its own).
- P-5 The view model field is named exactly PushPublicKey in both view models, because Phase 7.1 plan 13c fills that field "unless the field already exists".

# Phase 3.3 Plan 07: Reverse area lookup Summary

**`ReverseArea` on the one geocode client: coarse Photon layers first, Nominatim suburb to city as fallback, tokens taken only if free right now, 2 second cap, no coordinate in any error.**

## What was built

- `internal/geocode/reverse.go`: constants `photonReverseURL`, `nominatimReverseURL`, `ReverseTimeout` (2 s), `ReverseAreaMaxRunes` (120); `ErrNoArea`; `ReverseArea`; `coarseNominatimName`; helpers. Photon is asked `/reverse` with `lat`, `lon`, `lang=en`, `limit=1` and `layer=locality&layer=district&layer=city`. Nominatim is asked `format=jsonv2`, `zoom=14`, `addressdetails=1` (plus `email` when configured) and only suburb, neighbourhood, quarter, village, town, city are read.
- `internal/geocode/client.go`: fields `photonReverse` and `nominatimReverse` set in `newClientWithProviders` (Photon one empty when `photonURL` is empty), and the unexported test seam `withReverseURLs`. Nothing else changed.

All use httptest upstreams; no real service is reached. They pass with `-race -count=3`.

## For plan 09 (the dispatcher)

- Call `ReverseArea` once per saved report, ideally with a context bounded by about 3 s. Treat any error (`ErrReaderBusy`, `ErrNoArea`, a status error, a deadline) as "no name" and send distance only.
- `ErrReaderBusy` means no limiter token was free right now; a retry later is allowed but not needed.

## BLOCKER: TestPhoneRuleHeadsMatchTheMarkup

With the Task 2 diff applied, `go test ./web/` has exactly one failure:

```
phone_markup_contract_test.go:105: failed to read embedded templates/changes_ask: open templates/changes_ask: file does not exist
--- FAIL: TestPhoneRuleHeadsMatchTheMarkup
```

Cause: `phoneExpandTemplate` in web/phone_markup_contract_test.go expands every `{{template "x"}}` include by reading a file named x, with special cases only for the defined blocks `account_header_menu`, `app_topbar` and `app_bottombar`. `changes_ask` is a defined block inside changes_ask.html.tmpl, so it falls through to reading a file called `changes_ask`. That file is outside files_modified, and the plan says to stop and report instead of editing it. The include must stay exactly `{{template "changes_ask"}}` (it is a must_have and the contract tests pin it), so no change inside the plan's own files avoids this.

Which pages it affects: `phoneMarkupPages` is expanded by this one test, and both index.html.tmpl and low.html.tmpl are phone pages, so Task 3 will hit the same failure. One fix covers both pages. This was not checked against `phoneMarkupPages` line by line beyond that; Task 3 should confirm.

Proposed fix, needs a yes before it is made (it touches a file outside files_modified): add one case to the switch in `phoneExpandTemplate`:

```go
// Added by Phase 3.3 plan 21: changes_ask is a defined block in
// changes_ask.html.tmpl, like account_header_menu, so a call to it expands to
// the block body and not to a file of its own name.
case "changes_ask":
    whole := p13ReadTemplate(t, "changes_ask.html.tmpl")
    _, rest, ok := strings.Cut(whole, `{{define "changes_ask"}}`)
    if !ok {
        t.Fatalf("changes_ask.html.tmpl defines no changes_ask")
    }
    body, _, _ := strings.Cut(rest, "{{end}}")
    return body
```

With that case, the dialog markup joins the expanded pages, which is what a phone rule check should see.

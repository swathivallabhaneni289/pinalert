# Phase 3.3 Plan 12: Critical and Changes switches on the alert settings Summary

**The two phone kind switches (Critical reports near the home area, on by default; Changes to reports I posted or voted on, off by default) now ride 3.2's alert settings service and PATCH /api/me/alerts, with one default shared by SQL and Go and the Settings page model carrying both switches and the public push key.**

## Accomplishments

- `AccountService.AlertSettings` reads `GetPushKindSettings`; an account with no row reads Critical on and Changes off from `DefaultCriticalPushOn` and `DefaultChangesPushOn`.
- `UpdateAlertSettings` merges the four optional fields over the stored state, validates all of them before writing, then writes 3.2's row (only when `reliable_alerts` or `alert_radius_km` is set) and the push row via `UpsertPushKindSettings` (only when `critical_push` or `changes_push` is set). The answer is the stored state of all values.
- `me.go`: `critical_push` and `changes_push` on the request and the answer, swag description extended, strict decoding unchanged.
- `settings.go`: `CriticalPushOn`, `ChangesPushOn`, `PushPublicKey` on the view model; booleans and the public key only. No value exists for Severe official alerts or Someone I follow posts.
- Docs regenerated with `make swag` (swag was installed). The swagger drift test asserts both alert schemas list the new keys.

# Phase 3.3 Plan 18: now disputed note only after a confirmation Summary

The now disputed phone note goes out only for a report people nearby had confirmed before, decided at send time by replaying the report's own vote log through `Resolve` and `ConfirmedByPeople`; the bell row is written either way.

## What changed

- `VoteLogForReport` (push.sql): the report's votes ordered by created_at, id, raw facts only. Regenerated with sqlc 1.31.1; `git diff --name-only` under `internal/store/sqlc/` lists `push.sql.go` only. No migration.
- `reportWasConfirmed` (pushworker.go): pure, no I/O, no clock read, no log line. It keeps the latest row per (account, kind) while walking the log, tallies with `BuildVoteTally`, asks `Resolve`, and returns true the first time `ConfirmedByPeople(vis, FeedViewActive, tally)` is true. Rows of another report are ignored before they enter the map.
- `sendRow`: for a changed row whose `UpdateKind` is hidden, reads `VoteLogForReport`, converts the rows to `CurrentVotesForReportsRow`, and sets `run.wasConfirmed` before `stillHolds`. A read error returns `w.rowErr`. No other kind reads the log.
- `eventStillHolds`: the `UpdateHidden` case is now `f.Vis == VisibilityHidden && wasConfirmed`. The doc comment says why (owner wants phone notifications few, 2026-10-28).
- `fanOut` and `settle` are byte for byte unchanged (checked by extracting both functions from the base commit and from HEAD and comparing).
- `docs/TRUST-MODEL.md` "Phone alerts", the paragraph that begins "The gate.": one added sentence group naming `reportWasConfirmed`, `TestReportWasConfirmed` and `TestWorkerHiddenNeedsEarlierConfirmation`.

# Phase 03.3 Plan 19: the sign up alerts pop-up names the home area, asks for it, and offers Reliable alerts

**The sign up pop-up now reads Get alerts for critical reports near {home area}?, shows the step 4 place search when no home area is known (Allow waits for a pick), and offers an unticked A Reliable reporter posts near me tick box that Allow saves after the home area, with sign up finishing whatever happens.**

## What was built

- `web/templates/welcome.html.tmpl`: the dialog (id `welcome-alerts-ask`, still the only one) gains `data-home-area="{{.HomeAreaName}}"`. Title: the words, the stored name or `your home area`, a question mark. A search block (`welcome-alerts-home`, `welcome-ask__home`, `hidden` when an area is stored) holds the step 4 markup (form, label Home area, search input, status line, results list). The tick box is `<label class="welcome-ask__check"><input type="checkbox" id="welcome-alerts-reliable"><span>A Reliable reporter posts near me</span></label>`, no `checked`. No help text, no autofocus. "near you?" is gone from the file.
- `web/static/js/welcome.js`:
  - Constants `ALERTS_URL` (the only place the alerts address is written), `ASK_TITLE_START`, `ASK_TITLE_NO_HOME`, `ASK_TITLE_END`.
  - `homeName` (from `data-home-area`, trimmed; set from the saved place when step 4's profile PATCH answers ok) and `askPick`.
  - A second `makeSearch` instance over the pop-up nodes (typing true, `STEP4_SEARCH_URL`, never the device fix); pick and clear call `refreshAsk`.
  - `needsHome()`, `refreshAsk()` (title by `setText`, search block hidden once an area is stored, Allow disabled while busy or while no area is known), `setAskDisabled` now also freezes the search field and the tick box and follows the home area rule when freed. `openAsk` calls `refreshAsk` before `showModal`.
  - `canAsk()` answers false when `PinalertNotify.isMacDockApp()` is true (a second subscription on one Mac would notify twice).
  - `onAskAllow`: busy check, home check, then `window.PinalertNotify.enable(pushKey)` as the first real statement, then flags, then `Promise.resolve(pending)` settled either way, `saveAskHome(place)` (PATCH the profile with `home_area`), `saveReliable()` (only when ticked and `homeName` is not empty), and `postDone()`. Each save swallows its own failure. Not now and Escape are unchanged: nothing saved, enable never called.
  - `saveReliable()` is the one place the Reliable request is built: PATCH the alerts address, JSON `{"reliable_alerts": true}`, `SAVE_TIMEOUT_MS`.
- `web/static/css/welcome.css`: rules scoped by id for the title margin, the search block, a results list that scrolls inside itself at 12rem, and the tick box row (44px minimum, label clickable). No colour, no motion; `auth.css` untouched, and the string logout-confirm does not appear in `welcome.css`.
- Tests: 23 new node cases (all titled `named pop-up: `), `TestWelcomeAlertsAsk` rewritten (counts the dialog by id), `TestWelcomeAlertsScript` extended, `TestWelcomeAlertsAskRendersForNewAccount` rewritten as three subtests (new account, stored Benz Circle, markup in the stored name escaped in the title and in `data-home-area`).

# Phase 03.3: Installable app and phone alerts - Research

**Researched:** 2026-10-18
**Domain:** Installable web app (manifest, service worker, runtime icons) and silent Web Push (VAPID, webpush-go) on a Go, Postgres, vanilla JS stack with a login gate
**Confidence:** MEDIUM overall. HIGH on the repo seams, webpush-go behaviour (source read) and Apple's push rules. MEDIUM on Android and desktop behaviour. LOW on everything iPhone-specific (sign-in cookie jar, sound, tag replacement), which is why those are open questions and owner device steps.

## Summary

Phase 3.3 adds three things to a finished in-app pipeline. (1) An installable shell: a public web app manifest, runtime-rendered PNG icons (no stored image file is forced anywhere), and one root-scope service worker with a push handler, a notification click handler and deliberately no fetch handler. (2) A subscription lifecycle: per-device Web Push subscriptions tied to an account and to the session that registered them, removed on Log out, Log out of all devices and account deletion, with the endpoint treated as a secret capability URL and checked against a host allowlist before the server ever sends to it. (3) A push pipeline: a Postgres outbox worked by a lease-and-claim worker (the `ModerationWorker` pattern) that picks recipients with an inverse home-cell lookup, decides every alert through `Resolve`, `MayNotifyAboutReport` and `ConfirmedByPeople`, builds server-authored silent notifications that never carry the reporter's words, and sends them with `webpush-go` v1.4.0 through a hardened HTTP client.

Three findings change the shape of the plan. First, a Critical report's resolve reason stays `critical_bypasses_gates` for its whole life, so D-17 ("the reason triggers Not confirmed yet") can never flip to confirmed; the in-place "now confirmed" update must key off `ConfirmedByPeople(...)` (already on main in `internal/service/confirmed.go`), not the reason. Second, webpush-go v1.4.0 has two traps found by reading its source: the `VapidExpiration` option is ignored (the JWT `exp` is hard-coded to now plus 12 hours) and `Subscriber` is prefixed with `mailto:` unless it starts with `https:` (so pass a bare address, never `mailto:x`); it also always sends `TTL: <int>` (0 when unset, which Apple rejects with BadTtl), and its default HTTP client has no timeout and follows redirects. Third, iPhone is the weak platform: `silent` and `tag` are not honoured on iOS (the site can neither enforce silence nor replace a delivered notification), a Home Screen web app very likely has its own cookie jar so the current magic-link sign-in may leave the installed app signed out, and the push needs real HTTPS plus the owner's device.

**Primary recommendation:** Build Android Chrome and desktop first-class and prove them on localhost and a real https host; ship iPhone as "best effort, honestly documented" (no confirmed-update push to Apple endpoints, no promise of silence), and make the hands-on iPhone check an explicit owner step that depends on the hosting choice and on a typed-code sign-in (Phase 8's) being available.

### Pattern 1: Public root-scope assets and the gate exemption list
**What:** Serve `/manifest.webmanifest` (`application/manifest+json`), `/sw.js` (`text/javascript; charset=utf-8`, `Cache-Control: no-cache`), `/app-icon-192.png`, `/app-icon-512.png`, `/app-icon-maskable-512.png`, `/app-badge-96.png`, `/apple-touch-icon.png` (and `/apple-touch-icon-precomposed.png`, which iOS requests by itself) as GET routes registered in the exempt block of `NewRouter`, next to `/disclaimer`.
**Why outside the gate:** `<link rel="manifest">` is fetched without credentials unless `crossorigin="use-credentials"` is set, so a gated manifest answers 302 to `/login` and install fails; the same holds for icons; a service worker script must not be served through a redirect (an update check on a logged-out browser would fail noisily). None of these bytes holds account data (the VAPID public key is public and is rendered into the pages, not into `sw.js`) [CITED: standard behaviour of the manifest fetch; the credentials rule is long established, tag [ASSUMED] for exact current Chrome wording].
**Test pin:** `TestAccessGateExemptRoutes` (`internal/api/gate_test.go:307`, seven cases, doc comment says "seven routes") must grow rows for these routes with a dated note that this amends DEC-G and Phase 1.1 D-05 (nothing sensitive, needed before sign in). Also update the `NewRouter` doc comment that lists the exempt set. A route added in the exempt block is visibly unprotected by construction, which is the existing convention.
**sw.js specifics:**
- Source lives at `web/static/js/sw.js` so `web/js_sinks_contract_test.go` (scans the embedded `static/js` tree) covers it. A root handler reads it from `web.StaticFS` and serves it at `/sw.js`. Keep `/static/js/sw.js` reachable (harmless) but register `/sw.js`, which gives scope `/` with no `Service-Worker-Allowed` header.
- Never put `AssetVersion` in the registration URL: it is the process start time, so every cold start would look like a new worker. The browser already byte-compares `sw.js` on each update check, so a deploy that changes the file updates the worker; the page registers with `{ scope: '/', updateViaCache: 'none' }`.
- **No `fetch` handler.** The current web.dev install criteria list no service worker requirement [CITED: web.dev/articles/install-criteria]. A fetch handler would sit in front of the login redirects, `AssetVersion` busting and the IndexedDB offline queue for no benefit. `skipWaiting()` plus `clients.claim()` are fine because the worker holds no cache.
- The compress middleware list (`compressibleContentTypes`) includes `text/javascript`; add `application/manifest+json` if desired (tiny).
**Every full page** links the manifest and the Apple icon through one shared partial (`pwa_head.html.tmpl`) because each template (`index`, `login_gate`, `welcome`, `settings`, `profile`, `alerts`, `low`, `legal`, `check_inbox`, `verify_outcome`, `moderate`) hand-writes its own `<head>`. Precedent for an every-page test: `TestThemeScriptLoadsBeforeFirstPaintOnEveryFullPage` in `web/theme_contract_test.go`. The login page must carry it too.

### Pattern 2: Runtime PNG icons (nothing stored)
**What:** At process start render, once, into `[]byte` with an ETag: `192` and `512` "any" icons (dark `#1A1D21` square, white map pin built from the same geometry as `web/static/icons/map-pin.svg`: a circle head and a tapering tail), a `512` maskable (full-bleed background, mark inside the central 80 percent safe zone), `180` apple-touch-icon (opaque, no transparency because iOS fills transparent areas black), and a `96` monochrome badge (white pin on transparent, Android masks it). Use `image.NewNRGBA`, 4x4 supersampling per pixel and `image/png`. Serve with `Cache-Control: public, max-age=86400` and the ETag.
**Nothing forces a stored file.** SVG alone is not enough: Chrome's installability wants 192 and 512 px icons and an old Chromium source snapshot filters on PNG [CITED: web.dev/articles/install-criteria; chromium installable_manager.cc snapshot via search]; iOS ignores SVG for `apple-touch-icon` [CITED: apple-touch-icon guidance]. You may additionally list the existing-style SVG with `sizes: "any"`, but only as an extra entry. The `badge` must have transparency, so render it separately from the opaque ones.
**Design guard:** the owner's house rules apply (no purple gradients, no emoji, no vibe-coded look): flat dark tile, white pin, no gradient. The exact mark is a visual choice the owner sees at UAT.
**Tests:** decode each PNG (`png.Decode`), assert bounds, the corner and centre colours, the maskable icon's corners equal the background colour, the badge's corner alpha is 0, deterministic bytes between two renders.

### Pattern 3: The service worker (`sw.js`)
**What:** Three listeners and nothing else: `push`, `notificationclick`, `pushsubscriptionchange`. Pure helpers (`normalise`, `safeTarget`, `notificationOptions`) are top-level functions so a node `vm` test can call them.
**Rules:**
- Every `push` event shows exactly one notification. Chrome shows a generic "updated in the background" notice otherwise and Safari revokes the permission: "Present each notification to the user immediately after the service worker receives it, or Safari revokes the site's push permission" [CITED: Apple developer docs, Sending web push notifications]. All filtering therefore stays on the server. A bad or empty payload still shows a generic "Open Pinalert for a new alert near your home area" notice.
- Options object: `{ body, tag, renotify: false, silent: true, icon: '/app-icon-192.png', badge: '/app-badge-96.png', data: { url }, lang: 'en' }`. **Never include `vibrate`** (`silent: true` with `vibrate` throws a TypeError [CITED: MDN showNotification]). Pin it with a contract test that the file has no `vibrate` token outside comments, and a node test over every kind.
- `notificationclick`: `event.notification.close()`, validate `data.url` against `^/\?report=\d{1,18}$` (else `/`), then in `event.waitUntil`: `clients.matchAll({ type: 'window', includeUncontrolled: true })`, `focus()` then `navigate(url)` on a same-origin window, else `clients.openWindow(url)`. The page's existing `?report=ID` handling (`app.js`, `feed.js` `handleFocus`, `handlers/page.go` line 137) puts the report in the view it now belongs to.
- `pushsubscriptionchange`: re-subscribe with `event.oldSubscription.options.applicationServerKey` and POST the new subscription (same-origin `fetch` carries the cookie). Spotty across browsers, so the page also reconciles on Settings load (Pattern 5).
- `payload.closeFirst` (server sets it only where tag replacement is unreliable): `getNotifications({ tag })`, close each, then show. See Pattern 8 for why the default is to not send updates to Apple at all.

### Pattern 4: The client module (`pwa.js`, `window.PinalertPush`)
**What:** One script, loaded on full pages, that registers the worker at page load (Safari needs it registered early) and exposes `support()`, `status()`, `enable()`, `disable()`, and the install prompt state. `welcome.js` step 5 and `settings.js` call it; neither re-implements it.
**Rules:**
- **Feature detection, in order:** secure context and `serviceWorker`; `PushManager` and `Notification` present. On iOS, `PushManager` is absent in a Safari tab until the site is a Home Screen app, so "iPhone and not standalone" (UA matches iPhone/iPad, or `MacIntel` with `maxTouchPoints > 1` for iPadOS 13+, and `!navigator.standalone && !matchMedia('(display-mode: standalone)').matches`) shows the "Add to Home Screen first" guide (D-11) before anything else [CITED: webkit.org/blog/13878; MDN beforeinstallprompt page for the standalone checks].
- **`Notification.requestPermission()` must be the first thing the click handler does, synchronously, with no `await` before it** (Safari requires a direct user interaction) [CITED: webkit.org/blog/13878]. Then `await reg.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })` with the key decoded from base64url. A node test asserts call order with a fake.
- **"Not now" never calls `requestPermission()`**, so it does not burn the browser permission (D-10). Remember "asked on this device" in `localStorage` (D-13); a denied permission cannot be re-asked in code, so Settings shows a plain line that the browser blocks notifications for this site.
- **Install prompt:** capture `beforeinstallprompt` (Chromium only; Safari and Firefox never fire it), `preventDefault()`, keep the event, call `prompt()` from a tap; hide on `appinstalled`. iPhone gets the guide instead (the Share sheet, Add to Home Screen). Where the install control lives is Open Question 3.
- All text reaches the DOM through `textContent`; the repo's sink scan forbids markup parsing.
- The VAPID public key reaches the page as a `data-` attribute rendered by the template (it is public), not through a route.

### Pattern 5: Subscription lifecycle and routes
**Table `push_subscriptions` (00010):** `id`, `account_id` FK, `session_id TEXT` (the session cookie id that registered it, same value as `sessions.session_id`), `endpoint TEXT NOT NULL UNIQUE`, `p256dh TEXT`, `auth TEXT`, `created_at`, `last_ok_at`, `failures INT`. Index `(account_id)`.
**Routes (gated, flat literal paths like the other `/api/me` routes; JSON bodies, never the endpoint in a URL, because it is a capability URL):**
- `POST /api/me/push/subscription` body is `PushSubscription.toJSON()`: validate (below), upsert on `endpoint` and **move ownership to the caller** (a shared phone must not keep delivering the previous account's home-area alerts), set `session_id` from `session.FromContext`.
- `POST /api/me/push/status` body `{endpoint}` answers `{registered}` for the caller, so the Settings switch can reflect "this device" truthfully.
- `POST /api/me/push/unsubscribe` body `{endpoint}` deletes the caller's row.
- `PATCH /api/me/alerts` (3.2's route) gains `critical_push` and `changes_push`.
**Validation (V5):** `https` scheme, host on the allowlist matched exactly or on a dot boundary (`fcm.googleapis.com`, `updates.push.services.mozilla.com`, `*.push.apple.com` [CITED: Apple docs say allow `*.push.apple.com`], `*.notify.windows.com`; the Google, Mozilla and Windows hosts are [ASSUMED] from widespread knowledge and must be confirmed from `endpoint_host` observed in UAT), no userinfo, no port other than 443, length at most 2048, `p256dh` decodes to 65 bytes starting `0x04`, `auth` decodes to 16 bytes (webpush-go accepts std and URL base64). An unknown host answers a plain message "This browser's notification service is not supported." Log only the host and status, never the endpoint or keys.
**Limits:** per-account bucket (burst 5, one per minute, `ratelimit.PerIP` keyed by account id string, like the geocode budgets), at most 8 subscriptions per account (drop the oldest). SameSite=Lax withholds the cookie from cross-site POSTs (DEC-L), the existing CSRF stance for `/api/me` routes; keep strict JSON decoding (`DisallowUnknownFields`) and a `Content-Type: application/json` check.
**Deletion paths (all server-side, none depends on JS):**
- Plain Log out today only clears the cookie (`handlers.Logout`); change it to delete `push_subscriptions WHERE session_id = <this session>`, plus a best-effort client `unsubscribe()` before the logout form submits.
- Log out of all devices (3.2 `SessionService.LogOutAllDevices` / `RevokeAccountSessions`) and Delete my account (3.2 `AccountDeletionService.DeleteAccount`, one transaction) each delete all of the account's rows; add the delete inside the same transaction, and add the table to `AccountDeleteQuerier`. 3.2 plan 09's order list is the place to insert it before `ScrubDeletedAccount`.
- The worker deletes a row on 404 or 410. The dispatcher also ignores rows whose session is revoked (`JOIN sessions ... revoked_at IS NULL`) and accounts with `deleted_at` set.
- Removing the home area (3.2 `UpdateProfile` clear path) stops kinds 1 and 4; it need not delete the device subscription.
- A Home Screen web app may lose its cookies after 7 days (WebKit bug 237350 [CITED]); the subscription then keeps delivering while the app shows signed out. Acceptable; document it.
**Reconcile on Settings load:** if permission is granted and `getSubscription()` exists, call `status`; if not registered and the person's "On this device" intent exists, re-POST silently. Browsers rotate subscriptions rarely.

### Pattern 6: Recipient selection is an inverse lookup 3.2 does not have
3.2's alert step goes from an account to nearby reports on that account's own bell poll. Phone alerts need the reverse: which accounts have a home cell near this report, with the app closed.
1. In Go build candidate precision-5 cells: take `BoundingBox(lat, lon, maxRadius + cell half diagonal)` (max radius 10 km, cell about 4.9 km across, half diagonal about 3.5 km), step a lattice at half the cell size and collect distinct `geohash.EncodeWithPrecision(lat, lon, 5)`; about 40 to 100 cells.
2. SQL: `accounts.home_area_cell = ANY($1)` joined to settings, subscriptions and sessions. Add `CREATE INDEX idx_accounts_home_area_cell ON accounts (home_area_cell)` in 00010 (3.2's `Nearby` anchor read does not need it; this does).
3. Back in Go: `geohash.DecodeCenter(cell)` and the existing Haversine against the report point; keep an account only if distance is at most its own `alert_radius_km` (default 5 when no settings row).
4. **Defaults when no settings row exists:** kind 1 (critical) counts as ON, kind 3 OFF, kind 4 OFF. Use `COALESCE(s.critical_push_on, true)` in SQL and the same constants in Go, tested together. `account_alert_settings` (3.2, keyed by `account_id`) gets two columns in 00010: `critical_push_on BOOLEAN NOT NULL DEFAULT true`, `changes_push_on BOOLEAN NOT NULL DEFAULT false` (Phase 5 will add `official_push_on`; reserve the name in a comment, add no column and no row).
5. Exclude: the report's author, accounts that muted the report (`report_mutes`), accounts with `deleted_at`, revoked sessions, accounts with no subscription, and (kind 4) reports older than `enabled_at` per 3.2 `EnabledAt` and non-Reliable reporters (`Trust.Reporter.Tag`).
6. Cap the fan-out per report (for example 2000 recipients) so one post cannot become unbounded work; order by distance.
Distance on the lock screen is the same exact distance rounded up to whole kilometres ("about 3 km", "under 1 km"), never finer (D-20).

### Pattern 7: The dispatcher and the outbox
**Why an outbox:** the host sleeps and cold starts, a post wakes it, and the process can be killed right after the commit. A Postgres table with claim and lease is the existing pattern (`internal/service/modworker.go`: sweep at boot, a 30 second ticker, `ClaimDue...` with a lease, jittered exponential backoff, no attempt cap beyond expiry).
**Triggers (write time, never from the handler's decision):** after `SubmitChecked` or `CastVote` succeed, a non-blocking `PushTrigger.ReportChanged(reportID)` (buffered channel, coalescing). The poke carries no decision: the worker loads the report fresh, builds the tally, calls `Resolve` with `Moderation` set, then `ViewOf`, then `MayNotifyAboutReport`. This keeps D-07 ("never notify from Submit directly") true. Recover from a lost poke by a periodic sweep over recent active reports (needs a small `push_report_progress` or a `push_checked_at` marker so the sweep is not a full re-evaluation; the planner chooses).
**Outbox `push_outbox`:** `id`, `account_id`, `report_id`, `kind` (`critical`, `reliable`, `changed`, `confirmed_update`, `more`), `update_id BIGINT NULL` (references 3.2 `updates.id` for kind `changed`, so 3.2's `updates` rows stay channel-free), `state` (`queued`, `sending`, `sent`, `skipped`, `failed`), `attempts`, `next_attempt_at`, `lease_until`, `created_at`, `expires_at`, `sent_at`. Unique keys do the dedupe: `(account_id, report_id) WHERE kind IN ('critical','reliable')` (one initial alert per account and report whatever the kind; priority critical over reliable), `(account_id, report_id) WHERE kind='confirmed_update'`, `(account_id, update_id)` for `changed`, `(account_id, bucket_start) WHERE kind='more'`. Payload words are built at send time from current facts, never stored.
**Kind 3 (changes) without a race:** the push channel reads the same `updates` rows the bell reads. If a bell poll on a laptop creates the row first, a trigger that only looks at "who called Refresh" would skip the phone. So the dispatcher also sweeps `updates` rows with event kinds (`reached_live`, `hidden`, `resolved`, `fading`) for accounts with `changes_push_on` and a subscription that have no outbox row yet (unique key makes it idempotent). To make sure updates exist even when nobody polls, after a vote call 3.2's per-account `Refresh(accountID)` for each follower of the report except the voter (followers derive from the report author and `votes`); `Refresh` is already keyed by account and bounded (200 reports). If 3.2's `Refresh` loop is awkward to call per report, factor a per-report function out of it (a small, tested refactor in `updatesservice.go`).
**Honest limit:** a fading ("about an hour left") push is evaluated only when the process is awake (boot sweep, ticker, any request). While the host sleeps nothing can fire. Say so in the docs; the bell still catches up on the next open.
**Stale work:** on wake, mark outbox rows whose report is no longer active, or whose `expires_at` has passed, `skipped` instead of flushing a backlog.
**Send loop:** claim up to 50 due rows with `FOR UPDATE SKIP LOCKED` and a 60 second lease, fan each row out to the account's subscriptions with bounded concurrency (for example 8 workers), 10 second per-send timeout, then:
| Response | Action |
|---|---|
| 201 | mark sent, `last_ok_at` |
| 404, 410 | delete the subscription |
| 429 | back off, honour `Retry-After` (capped) |
| 5xx, network error | backoff 15 s, 1 min, 5 min with jitter, stop at TTL expiry or 4 attempts |
| 400, 403 | no retry, log status and host only (bad VAPID, subject, TTL, topic; Apple's JSON `reason` such as `BadJwtToken`, `BadTtl`, `BadWebPushTopic`, `VapidPkHashMismatch`) |
| 413 | bug: payload over budget; the build step already refuses over 1 KB |
Log lines: numeric ids, status number, host. Never the endpoint, keys, payload or report text.

### Pattern 8: Payload, copy, silence and the in-place update
**Payload v1 (JSON, well under 1 KB; webpush-go always pads to a full 4096 byte record, so the plaintext limit is 3993 bytes [VERIFIED: source, `MaxRecordSize 4096`, 86 byte header, 16 byte tag, 1 delimiter]):** `{ "v":1, "kind":"critical|reliable|changed|confirmed|more", "tag":"report-123", "title":"...", "body":"...", "url":"/?report=123", "closeFirst":false }`. The worker adds the fixed options; the server owns every word.
**Words (`pushcopy.go`, tests: no U+2013 or U+2014, no reporter text, closed set of strings):**
- Critical: title is the What is happening pick (Water rising, People trapped, Fire, Building collapsed, Landslide, Medical emergency, Other) with the area, for example "Water rising near Indiranagar"; body "About 3 km from your home area. Not confirmed yet." With the area empty: "Water rising" and "About 3 km from your home area. Not confirmed yet.". With no pick (older reports, D-18): category and severity words.
- Reliable reporter: "Reported nearby by a Reliable reporter" plus distance and the same trust line.

- Confirmed update: same tag, body replaces "Not confirmed yet." with the confirmed sentence.

### Pattern 9: Reverse lookup for the area name
`(*geocode.Client).ReverseArea(ctx, lat, lon) (string, error)`: add to the one process-wide client (never a second client or limiter, T-07-01), constant base URLs only. The push waits at most about 3 seconds for the name, then goes with distance only (D-19). The column is read only by push code, never by the feed, never in a bell row; finished Rescue reports keep following `CoarsenFinishedRescue` for anything shown. Add `area_name` to no JSON response.

### Anti-Patterns to Avoid
- **Notifying from `Submit` or `CastVote` directly.** They only poke the trigger.
- **A second critical rule or a visibility check in SQL.** Go decides; SQL only selects candidates.
- **Deriving "Not confirmed yet" from the resolve reason** (R3).
- **A `fetch` handler or any caching in `sw.js`.**
- **Passing `nil` options or an unset TTL/HTTPClient to webpush-go** (nil panics; TTL 0; no timeout; follows redirects).
- **Putting the endpoint in a URL, a log line or an error message.**
- **Generating VAPID keys at boot.** A changed key orphans every subscription (Apple answers `VapidPkHashMismatch`).
- **Filtering inside the service worker** (skip showing). Every push must show something.
- **A markup-parsing sink in any new JS** (`innerHTML`, `insertAdjacentHTML`); `js_sinks_contract_test` fails the build.

## Common Pitfalls

### Pitfall 1: webpush-go ignores `VapidExpiration`
**What goes wrong:** `getVAPIDAuthorizationHeader` receives `expiration` but builds the claim with `time.Now().Add(12 * time.Hour)`; the option is dead [VERIFIED: vapid.go source]. A new JWT is signed on every send, while Apple asks not to refresh it more than once per hour [CITED: Apple docs]. **Avoid:** do not rely on the option; Apple's limit is a request, and 12 hours is under its one day maximum. If Apple answers 403/429 under load, cache by wrapping the `HTTPClient` and rewriting `Authorization` per origin for up to an hour (only if needed). **Warning sign:** `BadJwtToken` or 429 from `*.push.apple.com`.

### Pitfall 2: `Subscriber` gets `mailto:` prepended
**What goes wrong:** anything not starting with `https:` becomes `"mailto:" + subscriber` [VERIFIED: vapid.go], so passing `mailto:ops@x` yields `mailto:mailto:ops@x`, which Apple rejects (subject must be a URL or `mailto:`). **Avoid:** pass a bare address (from `CONTACT_EMAIL`) or an `https://` URL (from `BASE_URL`); validate at boot; test the produced `Authorization` header with a fake `HTTPClient` by decoding the JWT claims.

### Pitfall 3: TTL 0
**What goes wrong:** `Options.TTL` is an int always written to the `TTL` header [VERIFIED: webpush.go]; unset sends `TTL: 0`, which Apple answers with `BadTtl`, and other services drop the message if the device is not reachable right now. **Avoid:** one `Sender` method that computes TTL from the report's remaining life and refuses to send when it would be 0.

### Pitfall 4: default HTTP client
**What goes wrong:** webpush-go uses `&http.Client{}` when `HTTPClient` is nil: no timeout, follows redirects, dials any address [VERIFIED: webpush.go]. A hostile or compromised endpoint becomes SSRF or a hung worker. **Avoid:** always pass `Options.HTTPClient` with a 10 second timeout, `CheckRedirect` returning `http.ErrUseLastResponse`, and a `net.Dialer.Control` (or `DialContext`) that refuses loopback, private, link-local and unspecified addresses after DNS resolution (blocks rebinding). Pair with the host allowlist at subscribe time and again before every send (the stored row could predate a tightened list).

### Pitfall 5: `options` nil and the 4 KB record
`SendNotificationWithContext` dereferences `options` (nil panics). Every message is padded to a full 4096 byte record; plaintext over 3993 bytes returns `ErrMaxPadExceeded`. Keep payloads small and test the bound.

### Pitfall 6: a push that shows nothing
Safari revokes the permission and Chrome shows a generic notice. The worker must show on every push, including a malformed payload.

### Pitfall 7: `requestPermission` after an `await`
Safari then refuses. First statement in the click handler. Register the worker at page load, not inside the click.

### Pitfall 8: manifest, icons and `sw.js` behind the gate
302 to `/login` breaks install and worker updates. They are public routes plus a pinned test update (Pattern 1).

### Pitfall 9: `AssetVersion` in the worker URL
It changes on every cold start (a Unix timestamp at boot), so the worker would re-install constantly. Register `/sw.js` with no query string.

### Pitfall 10: tag replacement is not universal
Do not promise "same notification updates in place" on iPhone or reliably on Safari macOS. See R2 and Pattern 8.

### Pitfall 11: a shared device keeps the old account's alerts
Upsert must move `endpoint` ownership; Log out must delete by `session_id`.

### Pitfall 12: log and error leakage
The request logger already writes path only; keep the endpoint in the POST body. Do not log endpoints, keys, payloads, area names or report text. Tests grep the worker's log output.

### Pitfall 13: first-run timing
`first-run-done` fires at step 4 today. Moving it to step 5 changes `welcome.js` and its tests; a half-done flow must still resume at step 5 (`StartStep`, `?step=N` clamps).

### Pitfall 14: SameSite and cross-site hijack
Fine today (Lax, JSON POST). If SameSite is ever relaxed, subscribe routes need a token.

### Pitfall 15: VAPID key rotation
Rotating the key breaks every subscription. Document: change only with a plan to re-prompt everyone. Store the key outside git (`VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` env vars). Outside development: both keys unset logs a WARNING and turns push off (the app stays usable, Settings shows the unavailable sentence); only one of the two set, or a bad subject, stops startup. The key pair comes from `go run ./cmd/vapidkeys`.

### Pitfall 16: docs guard tests
`TestTrustModelDocMatchesCode` checks heading order, named identifiers, named tests and the dash rule in `docs/TRUST-MODEL.md`; add the TRUSTX-03 phone-alert section in the right place and name only tests and identifiers that exist. 3.2 plan 17 writes a similar section first: re-read it and extend, do not duplicate.

### Pitfall 17: sessions, testutil and truncation
`testutil.NewTestDB` truncates `accounts ... CASCADE`, so new tables with FKs to `accounts` or `reports` are cleaned by cascade; still add them to any explicit inventory 3.2 plan 01 maintains.

```go
// Source: webpush-go v1.4.0 source (webpush.go, vapid.go); behaviour verified by reading it.
type guardedClient struct{ c *http.Client }
func (g guardedClient) Do(r *http.Request) (*http.Response, error) { return g.c.Do(r) }

func newPushHTTPClient() *http.Client {
	d := &net.Dialer{Timeout: 5 * time.Second, Control: func(_, address string, _ syscall.RawConn) error {
		host, _, _ := net.SplitHostPort(address)
		ip := net.ParseIP(host)
		if ip == nil || ip.IsLoopback() || ip.IsPrivate() || ip.IsLinkLocalUnicast() || ip.IsUnspecified() {
			return errors.New("push: refusing non public address")
		}
		return nil
	}}
	return &http.Client{
		Timeout:       10 * time.Second,
		Transport:     &http.Transport{DialContext: d.DialContext, ForceAttemptHTTP2: true},
		CheckRedirect: func(*http.Request, []*http.Request) error { return http.ErrUseLastResponse },
	}
}

func (s *WebPushSender) Send(ctx context.Context, sub Subscription, p Payload, ttl int, urgency webpush.Urgency, topic string) (int, error) {
	if ttl <= 0 { return 0, ErrNoTTL }                  // Apple: BadTtl
	if err := s.policy.Check(sub.Endpoint); err != nil { return 0, err }
	body, _ := json.Marshal(p)                           // size checked: < 1 KB
	resp, err := webpush.SendNotificationWithContext(ctx, body,
		&webpush.Subscription{Endpoint: sub.Endpoint, Keys: webpush.Keys{P256dh: sub.P256dh, Auth: sub.Auth}},
		&webpush.Options{
			HTTPClient: s.client, Subscriber: s.subscriber, // bare address or https URL, never "mailto:..."
			VAPIDPublicKey: s.pub, VAPIDPrivateKey: s.priv,
			TTL: ttl, Urgency: urgency, Topic: topic,       // topic <= 32 chars, base64url alphabet
		})
	if err != nil { return 0, err }
	defer resp.Body.Close()
	io.Copy(io.Discard, io.LimitReader(resp.Body, 4096))
	return resp.StatusCode, nil
}
```

```go
// Source: mmcloughlin/geohash; used by internal/service/coarsen.go and 3.2 HomeAreaAnchor.
func candidateCells(lat, lon, radiusKm float64) []string {
	latMin, latMax, lonMin, lonMax := BoundingBox(lat, lon, radiusKm+3.6) // + cell half diagonal
	step := 0.02                                                           // about 2.2 km, under half a precision 5 cell
	seen := map[string]struct{}{}
	for la := latMin; la <= latMax+step; la += step {
		for lo := lonMin; lo <= lonMax+step; lo += step {
			seen[geohash.EncodeWithPrecision(clampLat(la), clampLon(lo), 5)] = struct{}{}
		}
	}
	out := make([]string, 0, len(seen))
	for c := range seen { out = append(out, c) }
	return out
}
```

## Security Domain

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes | Existing verified-account gate; subscription routes inside the gate; typed-code sign-in dependency for iPhone |
| V3 Session Management | yes | Subscription bound to `session_id`; deleted on Log out, Log out of all devices, account deletion; revoked sessions ignored |
| V4 Access Control | yes | Account id only from the gate's context; ownership move on upsert; status/unsubscribe act on the caller's rows only |
| V5 Input Validation | yes | Endpoint https plus allowlist plus length; key length checks; closed enums for kinds and happening; strict JSON |
| V6 Cryptography | yes | webpush-go for ECDH/HKDF/AES-GCM/ES256; VAPID private key only in env; no hand-rolled crypto |
| V8 Data Protection | yes | Endpoint, `p256dh`, `auth` are secrets; never logged; coarse area name only; no coordinates stored |
| V13 API | yes | JSON only, rate limits, body size cap (`maxMeBodyBytes` style) |

### Known Threat Patterns
| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| SSRF via client-supplied endpoint | Tampering / Info disclosure | https + host allowlist (dot-bounded) at subscribe and send; guarded dialer refusing private ranges; no redirects; timeouts |
| Push spam: one verified account fans an unconfirmed alert to a 10 km area; Reliable-tag farming | Tampering / DoS | Per-reporter fan-out cap, per-recipient hourly cap with roll-up, one push per account and report, kind 4 per-reporter cap, "Not confirmed yet" wording, gap recorded in TRUST-MODEL (TRUSTX-03 not built) |
| Subscription hijack / shared device receives old account's alerts | Spoofing / Info disclosure | Endpoint is an unguessable secret; upsert moves ownership; delete by session on Log out |
| Lock screen disclosure (area name plus distance narrows the home area) | Info disclosure | Coarse name only, rounded distance, no reporter words, no street, bell/feed never show the name; sound/visibility on iPhone is the person's setting |
| Notification click URL injection | Tampering | `safeTarget` regex in the worker; server authors `url`; payload is not HTML |
| VAPID private key leak | Elevation | Env only, never in repo or logs; rotation documented; DB leak alone cannot send (push services require the VAPID signature that matches the subscription's key) |
| Fan-out amplification / DoS of the worker | DoS | Recipient cap, bounded concurrency, claim batches, TTL-based skipping of stale rows |
| Cross-site POST to subscribe/unsubscribe | CSRF | SameSite=Lax cookie (DEC-L), JSON body, strict decoding |
| Endpoint/keys in logs or errors | Info disclosure | Log host and status only; tests assert it |
| False Critical post used to alarm people | Tampering | Existing serious-report rate limit (5 per 5 minutes), moderation screening, per-reporter push cap; remains a documented limit |

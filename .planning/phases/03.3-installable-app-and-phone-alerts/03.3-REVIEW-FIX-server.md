## S-05 (low): no signal handling, workers never stopped

- **Status:** fixed
- **Commit:** ff9396a
- **Change:** cmd/server/main.go builds `runCtx` with `signal.NotifyContext(context.Background(), os.Interrupt, syscall.SIGTERM)` and runs through a new helper, `serveUntilDone`. The helper:
  - starts the push dispatcher and worker on that context;
  - calls `srv.Shutdown` when the context ends;
  - waits for both loops, all within `shutdownGrace` (`service.PushSendTimeout` plus 15 seconds);
  - reports a loop that is still busy after that time as an error.

  With VAPID unset there are no push loops, and the server starts and stops as before. The moderation worker still runs on its own background context, as before (out of scope).
- **Tests:** `TestServeUntilDoneWaitsForTheWorkerMark`, `TestServeUntilDoneWithoutPushRunners`, `TestServeUntilDoneBoundsTheWait`, `TestServeUntilDoneReturnsAServeError` and `TestMainStopsOnSignals`. The last one reads the source to check the wiring, the same way `TestOnboardingGateIsSwitchedOn` does. Before the fix the package failed to build, because `serveUntilDone` did not exist.
- **Residual, by design:** the worker's fan out uses the run context. A send still waiting for its answer at shutdown is therefore cancelled, judged retry, and rescheduled on the `WithoutCancel` write context, while a device that already answered is marked accepted. Delivery stays at least once, as docs/PUSH.md already says.

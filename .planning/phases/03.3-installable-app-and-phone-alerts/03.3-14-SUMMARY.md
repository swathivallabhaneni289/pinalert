## Deviations from Plan

**1. [Rule 3 - Blocking] internal/api/handlers/places_e2e_test.go amended (not in files_modified)**
- **Found during:** Task 1. `TestSettingsRows` pins the page's `button.place-row` ids and the string "Hear about Reliable reporters near your home area.", both of which the new markup changes.
- **Fix:** the expected button list now includes `settings-device-install` and `settings-critical-nohome` (rendered hidden, but present in the markup), and the section line is the N1 line, each with a dated note. **Commit:** 36e1edb.

**2. [Plan wording] reconcile instead of deviceState plus reconcile on load.** The plan lists both; notify.js's `reconcile` already runs the server check and returns the state, so the script calls `reconcile(key)` once. This avoids a duplicate status request.

**3. [Plan wording] Device error line.** A second line `#settings-device-error` was added beside 3.2's `#settings-alerts-error` (the plan's artifact list names it). Showing either hides the other, so only one error line shows at a time.

**4. Dismissed prompt.** notify.js returns state `ready` for a dismissed prompt and `blocked` only for a refused one. The switch stays for a dismissal (the browser asks again); both say "Alerts are off for this device."

**5. Server sentence on a 400 is not shown.** notify.js can return `result.message`; step 5 shows it, but the plan and UI-SPEC give Settings the exact lines "Couldn't turn this on. Try again.", so Settings shows only those.

**6. W1 gate.** The Home area note also requires a home area, since a stored Critical value without one leaves nothing to remove (the Remove button is hidden then).

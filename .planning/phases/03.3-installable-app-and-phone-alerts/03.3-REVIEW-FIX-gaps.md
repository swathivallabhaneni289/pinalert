## What each fix does

**CR-01.** `canOffer` in `web/static/js/changes-ask.js` also refuses while the root carries
`data-modal-open` (the report form, the Flag box and the reader window lock the page this way) or
while the dialog sits inside an inert part of the page. `offer()` then resolves at once and writes
no asked key, so the next post or vote can ask. The normal post path closes the form (unlock)
before it offers, so the main path still opens the pop-up.

One consequence for the owner: a confirm or dispute cast inside the reader window no longer opens
the pop-up there, because the reader locks the page. The pop-up is offered at the next post or
vote made outside a locked box.

**CR-02.** In `web/static/js/notify.js` `enable`, `getSubscription`, `unsubscribe` and `subscribe`
are each called at once and raced against the existing `withTimeout` helper. The permission prompt
has no limit and is still the only call made before `enable` returns. On a timeout `enable`
resolves `{ok: false, reason: 'failed'}`. Both Allow taps already treat that as an answer, so sign up
finishes and `settled()` resolves. This is proved by the existing failed or refused cases in
`welcome_alerts_test.mjs` and `changes_ask_test.mjs`. `PinalertNotify.enable(...)` is still the
first real statement of both Allow taps.

**WR-02.** `disable` waits for the pending page load check to settle before its own work, so a
re-register posted by the check always reaches the server before the Off. The re-register reads
the intent flag again right before its post, after the status answer, and stops if the flag was
cleared. `enable` waits on nothing.

**WR-03.**
- On `web/templates/index.html.tmpl` and `web/templates/low.html.tmpl`, the `changes-ask.js` tag
  sits inside the same `{{if .ChangesAsk}}` as the partial, after the dialog.
- Three pins were amended with comments: the pages contract (the "directly follows
  report-form.js" rule), the Low data script order pin (the "between trust.js and low.js" rule)
  and the handler test, which now expects the script only with the dialog, after it.
- `docs/MODERATION.md` now says honestly where the growth came from:
  - about 11.5 KB (11531 bytes) from the Phase 3.3 gap fix;
  - about 82 KB (82074 bytes) from earlier work since 2026-10-17 that was never re-measured.
  Whether that earlier growth was intended is still the owner's call.
- The numbers really changed: the budget page has no push key, so it no longer counts
  `changes-ask.js`. TestLowDataByteBudget was therefore re-measured by its documented procedure:
  676839 bytes, budget 779264, both constants set together.
- A page that shows the pop-up adds about 12 KB, which stays inside the budget.

**WR-04.**
- `pinalert.changesAsked` is now a JSON list of the account ids asked on this browser, holding
  the last 8.
- An old single id reads as a list of one.
- Ids stay as text.
- Every storage call stays inside the try.
- A stored value that is neither an id nor a list means no pop-up. This is fail closed, as
  before, and the value is left alone.

**WR-05.**
- **When it applies:** the home area picked in the sign up pop-up was not saved.
- **What the pop-up does:**
  - stays open and frees its buttons;
  - shows one line in the step 4 error style (`welcome-alerts-ask-error`, `.inline-error`,
    `role="alert"`): the server's sentence for a 400, the session line for a 401, otherwise
    "Could not save your home area. Try again in a moment.".
- **The buttons after it:**
  - Allow tries the save again. It does not call `enable` a second time, because `enable` runs
    once per visit, so the prompt is never asked in a loop. A person whose first `enable` failed
    for another reason turns the device on in Settings.
  - Not now still finishes sign up.
- **Reliable:** the tick is saved only after the home area is saved.
- **Older pages:** a page without the error line finishes as before.

**IN-03.** A `close` listener settles the pending wait and clears busy, so `settled()` always
resolves. `finish` takes the wait before it closes the dialog, so its own close event finds nothing
to settle. A late Allow answer of a pop-up that has already gone still turns Changes on, but it
closes and focuses nothing.

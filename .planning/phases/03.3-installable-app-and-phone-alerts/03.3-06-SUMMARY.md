# Phase 3.3 Plan 06: notify.js, install guide and copy contract Summary

notify.js gives step 5 and Settings one detector for this device (unsupported, needs-install, blocked, on, ready) with the server confirming every "on", the prompt-first turn on and server-first turn off, plus the single iPhone install guide partial with its two icons and the noise word contract tests.

## What was built

- **web/static/js/notify.js** (`window.PinalertNotify`): registers `/sw.js` (scope `/`, `updateViaCache: 'none'`) at load; `baseState()` (sync) gives unsupported, needs-install, blocked or maybe; `deviceState(key)` adds the server's word (POST `/api/me/push/status`, endpoint in the body only) so `on` is never decided by the local subscription alone; `enable(key)` calls `Notification.requestPermission` as the first call when permission is not yet asked, then `serviceWorker.ready`, `pushManager.subscribe({userVisibleOnly, applicationServerKey})` and POSTs `subscription.toJSON()` to `/api/me/push/subscription`; `disable()` tells the server first (`/api/me/push/unsubscribe`), then unsubscribes the browser and keeps the permission; `reconcile(key)` re-posts a subscription the server lost, only for the account that turned the device on, and never prompts. Every wait has a 10 second limit. It writes no text, adds no listener, and does not touch the browser's install prompt.
- **web/pwa_client_test.mjs**: 30 node cases in a vm sandbox, including the requestPermission same-tick ordering case and the iPad-as-Macintosh case.
- **web/templates/device_guide.html.tmpl**: `device_guide` with the UI-SPEC lead and three steps, three aria-hidden mask icons (share, square-plus, bell), no title, button or hint.
- **web/static/icons/share.svg, square-plus.svg**: hand written Lucide outline markup in the same file shape as the others.
- **web/static/css/device-guide.css**: box with hairlines, 40px tiles, the two literal mask urls; tokens only.
- **web/css_contract_test.go**: both icons registered in `nonCategoryIcons`; `phase33Icons` and `TestPhase33IconsRegisteredAndUsed`.
- **web/noise_words_contract_test.go**: `bannedNoiseWords` (eleven words), `noiseCheckedFiles` (this plan's two files only), `TestNoNoiseWordsInUserCopy`, `TestNotifyLeavesInstallToTheBrowser`, `TestDeviceGuideCopy`, plus `TestNoiseScannerFindsWords` which proves the scanner itself.

## Deviations from Plan

### Auto-added

**1. [Rule 2 - Security] Intent flag is tied to the account id**
- **Found during:** Task 1
- **Issue:** A plain "intent is set" flag in a shared browser would let reconcile re-register the first person's device under the next account, which is the exact shared phone leak UI-SPEC 2a warns about.
- **Fix:** `pinalert.pushIntent` stores the account id (read from `[data-account-id]` like position.js); reconcile posts only when it matches the page's account, and never on a page that carries no account id. The behaviour list ("the intent flag is set") still holds for the signed in account.
- **Files modified:** web/static/js/notify.js, web/pwa_client_test.mjs
- **Commit:** a20a567

**2. [Rule 2 - Missing detail] Extra result fields and guards**
- `enable` also returns `message` for a 400 that carries the server sentence, and returns early (no prompt) for unsupported, needs-install, blocked and offline devices; `disable` while offline returns reason `offline` without a request. A dismissed (not refused) prompt gives `{ok: false, state: 'ready', reason: 'refused'}`, a refused one gives state `blocked`.

None otherwise: the plan ran as written.

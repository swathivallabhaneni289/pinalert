# Phase 03.3 Plan 02: Push transport Summary

A new `internal/push` package that sends Web Push only to allowlisted push services, through a guarded HTTP client, with TTL, Urgency, Topic and VAPID subject fixed in one place, plus strict VAPID environment loading and a `go run ./cmd/vapidkeys` generator.

## What was built

- `endpoint.go`: `EndpointPolicy`, `DefaultEndpointPolicy`, `Check`, `CheckKeys`, `IsAppleHost`, `ErrUnsupportedService`, `ErrBadEndpoint`, `ErrBadKeys`. https only, no user info, port 443 only, no IP literals, at most 2048 characters, host on the list exactly or on a dot boundary. Errors carry no part of the endpoint.
- `payload.go`: `Payload` (v, kind, tag, title, body, url), `PayloadVersion = 1`, `MaxPayloadBytes = 1024`, `Encode`, `ErrPayloadTooLarge`, `ValidTopic`.
- `client.go`: `NewGuardedClient` (10 second timeout, redirects not followed, dialer Control hook refusing loopback, private, link local, multicast, unspecified, CGNAT and v4 mapped forms after name resolution), `ErrRefusedAddress`.
- `sender.go`: `Sender` interface, `WebPushSender`, `Subscription`, `Message`, `Result`, `Urgency`, `scrubURLError`. Send refuses TTL under one second, a bad topic, an unknown urgency, an off-list endpoint and malformed keys before any request; always passes the guarded client; drains at most 4096 bytes of the body; caps Retry-After (seconds or HTTP date) to 10 minutes; returns errors wrapped with the host only after unwrapping the `*url.Error`.
- `config.go`: `Config`, `LoadConfig(getenv)`. Both keys unset gives ok false and no error. One key, a malformed key, a mismatched pair or a bad subject is an error that never echoes a key. Subject: `VAPID_SUBJECT`, else `CONTACT_EMAIL`, else an https `BASE_URL`; `mailto:` is stripped, a display name or http URL is refused.
- `cmd/vapidkeys/main.go`: prints the pair to standard output, one reminder to standard error, writes no file.

2. **go.mod acceptance check does not read 0.** The plan says `go get ...crypto@latest` and an acceptance grep that no line outside webpush-go, golang-jwt and x/crypto changes. Raising x/crypto to v0.58.0 also raised three modules already in go.mod: `golang.org/x/text` v0.41.0 to v0.43.0, `golang.org/x/sync` v0.22.0 to v0.24.0 and `golang.org/x/tools` v0.48.0 to v0.51.0 (Go's minimum version selection follows x/crypto's own requirements). No new module was added beyond webpush-go; the grep (run against base 23d4b10, since the branch has no `main` ref in play) prints these three lines. Everything builds and the whole short suite passes. If the owner wants the minimal diff, x/crypto can be pinned to v0.55.0 (already in the module graph), at the cost of the bump the research asked for.
3. **Additions beyond the plan (Rule 2):** `ErrBadUrgency` for an unknown Urgency; `CheckKeys` also runs inside Send; the guarded dialer also refuses CGNAT and v4 mapped addresses; LoadConfig verifies the public key matches the private key.
4. The plan behaviour list says Check refuses "host notify.windows.com", but the GREEN text says a suffix matches the host itself. The code follows the GREEN text (the bare suffix host is accepted, `notify.windows.com.evil.example` and `evil-notify.windows.com` are refused). The test case that reads like the first reading uses the evil.example form.

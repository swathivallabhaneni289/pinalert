# Phase 3.3 Plan 01: Push storage Summary

**Migration 00011 and 39 sqlc queries lay all phone-alert storage: per-device subscriptions that move to the last account to register, an outbox with partial-unique dedupe and a lease-conditional claim, nearest-cell-first recipient selection and a send-time switch read, proven by 19 store tests on a real database.**

## Performance

- **Tasks:** 3 of 3, one commit each
- **Files:** 5 created, 3 modified
- **Verification:** full `go test ./... -p 1` green on the disposable database p33_01_a (dropped afterwards); `-short` run of web, service, api, store and testutil green with empty DATABASE_URL; store package run with zero `--- SKIP` lines; `TestClaimDuePushesLease` stable over 3 runs.

## Accomplishments

- Migration 00011: three tables, `reports.area_name`, `critical_push_on` (default true), `changes_push_on` (default false), `changes_enabled_at`, and `idx_accounts_home_area_cell`, with closed CHECK lists (no rolled up kind), the three partial unique indexes on the outbox, and a goose Down in reverse order. `TestMigration00011` covers both directions on a database, the SQLSTATE codes (23514 and 23505) the plan lists, and the Critical-on / Changes-off defaults of a bare settings row.
- `push.sql`: all 39 named queries. `ClaimDuePushesRow` carries `LeaseUntil` and `FirstKind`; `PushAccountHomeRow` carries `CriticalPushOn`, `ChangesPushOn`, `ReliableAlertsOn` and `Muted`; `BumpPushSubscriptionFailure` returns the new count and `last_ok_at`; `CountReporterFanouts` takes `ExcludeReportID` and counts a double-fanned report once.
- `PushHomeCandidates` orders by `array_position(cells, home_area_cell)` then account id before `LIMIT`, so a crowded area drops the farthest cells first (N1).
- Tests (19 top-level functions in `push_test.go`, the 15 named by the plan plus `TestAccountsWithChangesPush`, `TestEnqueueReliableFromUpdates`, `TestPushReportProgressAndRecent`, `TestPushOutboxWindowCountAndPrune`).
- `testutil.Truncate` names the three new tables; `TestMigrationsTruncateListsEveryTable` passes.

## Deviations from Plan

None in behaviour. Minor, no rule needed:

- `ClaimDuePushes` is shaped as `due` CTE, `claimed` UPDATE CTE and an outer SELECT (see key-decisions). Return fields are exactly as the plan lists.
- `ExtendPushLease` and the claim cast the returned lease with `COALESCE(..., now())::timestamptz` so sqlc generates a non-null `time.Time` rather than a pointer.

## Notes for later plans

- `push_subscriptions.session_id` references `sessions(session_id)`. Migration 00002 notes a signed cookie can exist with no `sessions` row (persist failure is log-and-continue). The subscription route (plan 08) must make sure the caller's session row exists before upserting, or it will hit SQLSTATE 23503. `testutil.SeedPushSubscription` inserts the session row `ON CONFLICT DO NOTHING` for the same reason.
- Logout / delete paths: `DeletePushSubscriptionsForSession`, `DeleteAccountPushSubscriptions` and `DeleteAccountPushOutbox` exist; wiring them into 3.2's logout, log out of all devices and `DeleteAccount` transaction is later plans' work (also `AccountDeleteQuerier`). `push_report_progress` has no account column, so account deletion needs no cleanup there.
- `ClaimDuePushes` does not check report expiry; `SkipStalePushes` is the sweep that does it, and the worker must still check remaining life for a row it holds.
- Rescheduled rows keep `attempts`; the retry limit lives in the worker.

Decisions made at planning (record them in the SUMMARY):
- P-1 Once per account on a browser, through the key pinalert.changesAsked holding the account id, the same pattern Phase 7.1 plan 13b uses for its install box. A server side asked flag would need a migration, and 00012 and 00013 are already named by later phases. Plan 21 renders the dialog only while the account's Changes switch is off, so an account that already said yes is never asked.
- P-2 The pop-up follows a confirm or a dispute the server saved, or a report the server accepted (held for the text check included). It does not follow Mark resolved, Reopen or a take back: they end or undo something, and asking about future changes there reads oddly. A queued report sent later by the offline queue does not ask either: the person is not in the flow then.
- P-3 offer() decides and opens synchronously, so settled() already returns the pending promise in the same tick as the vote or post success.
- P-4 Allow saves Changes whatever enable answered: Changes is an account switch, and another device of the account may be on. If the browser refused, Settings shows that device as blocked.
- P-5 No message is shown after an answer: the pop-up closes and the page is as it was. A failed save says nothing; Settings shows the switch.
- P-6 Focus goes back to the element that had it before the pop-up opened, when that element is still on the page, the way the Log out box does.

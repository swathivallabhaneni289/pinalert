# Phase 03.3 Plan 20: the "Tell you when this report changes?" pop-up

**A small pop-up, built but dormant, that asks the first time a person posts or votes: Allow calls PinalertNotify.enable first and then turns Changes on with one request; Not now and Escape send nothing. Plan 21 renders the dialog, which is when it goes live.**

## What was built

- `web/templates/changes_ask.html.tmpl`: the `changes_ask` define, a native dialog `#changes-ask` with the `.logout-confirm` classes, the title `Tell you when this report changes?` (tabindex -1, `#changes-ask-title`), and two buttons, `Not now` (`#changes-ask-later`) then `Allow` (`#changes-ask-allow`). No paragraph, link, input or autofocus.
- `web/static/js/changes-ask.js`: `window.PinalertChangesAsk = { offer, settled }`. It builds no markup. `offer()` opens only when all hold: the dialog can showModal, `data-push-key` and a valid `data-account-id` are on the page, `PinalertNotify.baseState()` is maybe or ready, `isMacDockApp()` is not true, no other `dialog[open]`, and storage does not already hold this account in `pinalert.changesAsked`. The key is written just before `showModal`; the title then takes focus and no button is focused. Allow: `PinalertNotify.enable(key)` is the first real statement of the tap (inside try), both buttons are disabled and `aria-busy` is set, then one PATCH to the alerts address with `{"changes_push":true}`, same origin, 10 s abort timeout, then finish. Not now and a cancel event (Escape, always `preventDefault`) are Not now when not busy. finish closes, un-busies, returns focus to the remembered element when still connected and resolves the wait.
- `votes.js`: `offerChangesAsk()` called in castVote's success branch right after the `pinalert:updates-refresh` dispatch, only for confirm and dispute. `report-form.js`: the same guarded function after the toast in the normal accepted branch and in the closed-while-out branch; never in the catch, queue or later-send paths.
- Tests: `web/changes_ask_test.mjs` (27 cases), `web/changes_ask_hooks_test.mjs` (6), 5 new cases in `web/report_form_session_test.mjs`, `TestChangesAskPartialContract` and `TestChangesAskScriptContract`; the two new files are listed in `noiseCheckedFiles`.

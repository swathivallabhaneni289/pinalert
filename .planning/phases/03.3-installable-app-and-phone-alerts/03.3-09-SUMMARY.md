## What was built

- `pushfacts.go`: `pushReportFacts`, `PushFactsQuerier`, `loadPushFacts`. The only push caller of the resolver. It sets `Moderation: ModerationState(...)` in the same body, then `ViewOf` and `ConfirmedByPeople`. A disputed Critical report comes out Live, active and unconfirmed straight from the resolver (N3); push code holds no dispute rule.
- `pushrecipients.go`: `candidateCells` (the report's own precision 5 cell first, then by distance to each cell's middle, ties by cell string; about 60 cells at 10 km), `PushRecipient`, `filterRecipients` (own distance from the middle of the home cell, author dropped, nearest first, at most 2000).
- `pushdispatch.go`: the interfaces, `PushDispatcher`, `EvaluateReport` (facts, evaluated mark, Critical, Reliable, changes with an actor, confirmed update), `SweepOnce`, `ChangesSweepOnce`, `Run`, the non blocking `ReportChanged`, and the once per report area lookup with the 2 second cap.
- Caps: 3 Critical and 2 Reliable reports per reporter in a rolling hour, counted without the report being evaluated (N2), a report counted once across both kinds (N4), capped is sticky and a fanned report is never turned into capped.
- Tests: 3 + 14 top level tests with fakes (the plan's list plus `TestDispatchSweeps`, `TestDispatchRunSweepsAndHandlesPokes`), and the 5 database tests `TestPushRecipients`, `TestPushDispatchResolver`, `TestPushReliable`, `TestPushChangedRaceWithBell`, `TestPushCaps` (with sub tests for the confirmed update, N2 and N4).

## Choices made where the plan was silent

1. **No reporter account, no push.** `ReporterAccountID` nil cannot be counted against the per reporter cap, so neither the Critical nor the Reliable branch runs (T-03.3-08 fails closed). Posting needs a verified account today, so this only meets rows that predate that.
2. **Nobody reached, nothing recorded.** `MarkCriticalFanout(fanned)` and `MarkReliableFanout(fanned)` are written only when at least one recipient was found and enqueued without error, and the area lookup only runs then too. A report in an empty area does not use up a slot; a later run looks again. `capped` is still written whenever the count says so, before the candidate read.
3. **Expiry of queued rows.** Critical: the earlier of the report's expiry and now plus `PushInitialWindow`. Reliable and confirmed update: the earlier of the report's expiry and now plus `PushOtherTTL`. Changed rows take the report's own expiry from the query.
4. **Sweep window.** `RecentReportsForPush` is asked for reports since now minus `PushChangedWindow`. Initial alerts are still limited to `PushInitialWindow` inside `EvaluateReport`, so the longer look back only serves the confirmed update and lost pokes.
5. **Serious reports in the Reliable branch.** Recipients want `reliable_alerts_on` and, for a serious report, Critical off. Critical-on accounts already hold their one initial alert; their bell note is written by their own poll.
6. **Refresh error text is not logged**, only the account and report ids (the error comes from a layer that reads reports and places). The reverse lookup error is never logged either; ErrReaderBusy and every other error mean "no name" (wave 1 note for plan 07).
7. **`candidateCellsMax` = 400** keeps a point near a pole from building a huge array; cells across the date line are not wrapped. Neither matters at real latitudes.
8. **The changes branch skips a Withheld report** and does not re check the Changes switch (the two selecting queries already require it, and the worker re checks switches at send time through `PushAccountHome`).

## Notes for later plans

- Nothing pokes the dispatcher yet. Wiring `ReportChanged(reportID, 0)` after `SubmitChecked` and `ReportChanged(reportID, voterAccountID)` after `CastVote`, and starting `Run` in the process, belong to a later plan. `*UpdatesService` already satisfies `UpdatesRefresher` and the geocode client (`ReverseArea`) satisfies `AreaNamer`.
- `ChangesSweepOnce` and the vote poke queue `changed` rows for any 3.2 event row of an account with Changes on, including a row about a report moderation later removed. The worker (plan 11) must read the report through `loadPushFacts` at send time and skip anything the resolver no longer shows (Withheld, hidden by the feed's rules, expired).
- The sweep repeats the reporter history read every 30 seconds for each recent report whose reporter is not Reliable (no state is stored for "not reliable", and the state CHECK list is closed). It is bounded by 50 reports and an hour of life each.
- A re run (sweep with actor 0) of a fanned Critical report calls `PushHomeCandidates` and up to 2000 no op enqueues every 30 seconds for the first hour. That is the intended N2 behaviour; if it ever shows up as load, a "last candidate count" guard would be the place to cut it.

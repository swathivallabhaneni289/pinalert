pin through the existing pin-placement path (D-03), and inline no-match and unavailable messages
that never block submission (D-04). Extend `resetForm` so no search state survives a modal close,
update the stale location validation copy, and add a contract test locking the sink discipline and
the single-pin-placement-path property in place.

lean on (this repo has zero JS test files). Its automated verification therefore comes from a Go
contract test reading the embedded `modal.js` bytes, in the style the `web` package already uses
for the basemap, icon and theme contracts.

Output: the location search module inside `web/static/js/modal.js`, a new contract test in
`web/js_contract_test.go`, and the backfilled `07-VALIDATION.md` verification map.

request is sent per typing pause rather than one per keystroke (D-01, D-02).

Add `runSearch(query)`: lowercase the query into a cache key, and when `searchCache` has that key,
call `renderDropdown` with the cached value and return without any network call. Otherwise
increment `searchSeq` and capture the new value in a local (`mySeq`), then
`fetch('/api/geocode?q=' + encodeURIComponent(query))`. Mirror `votes.js`'s `castVote` error idiom

query has since been issued, then store `body.results` in `searchCache` under the key and call

`showSearchStatus(err &amp;&amp; err.fieldMessage ? err.fieldMessage : SEARCH_UNAVAILABLE_MESSAGE)`.

can arrive last and overwrite the suggestions for the query the visitor is actually looking at

own click or dragend listeners, and never disable the search input, because every one of those
would violate D-04.

previous submission's dropdown, message, or cached results appear in the next one
